# 动态玩法证据：录像 + 输入 + 状态

单张截图能证明一瞬间的布局，不能证明单位持续移动、转向、采矿往返或玩家命令真的执行。按仓库边界操作，只录本轮确认身份的游戏窗口，不录整桌面，不抢其他窗口焦点。

给 DeepSeek/Harness 执行本机玩家审计时使用 [常驻后台录像试玩提示词](G:/AIRTS/AI_RTS/agent/prompts/deepseek-background-video-playtest.md)，其中包含开单人房轨迹、覆盖表和问题报告合同。提示词默认只审计；不授予产品修复或前台独占权限。本 skill 仍适用于已授权开发后的动态复验。

## 用户同时使用电脑：默认非干扰模式

这是用户明确要求：测试期间用户可以继续聊天、打字、移动鼠标和使用其他软件，不能要求用户一直把游戏保持前台，也不能把用户切窗口当游戏故障。

- Python/PowerShell/录制器/console 引擎等辅助进程从启动时就隐藏控制台：Windows Python 使用 `CREATE_NO_WINDOW`，PowerShell `Start-Process` 使用 `-WindowStyle Hidden` 并重定向日志。不能先弹 CMD 再隐藏；需要渲染的游戏窗口和辅助控制台是两种东西。
- 独立测试窗口默认后台、非激活显示；可将本轮窗口置屏外或使用可靠的离屏渲染，不能最小化后假定 GPU 仍在刷新。禁止循环 `SetForegroundWindow`、恢复窗口、置顶、模拟 Alt+Tab 或打开预览来抢用户当前窗口。用户要求看结果时再展示产物。
- 默认禁止系统级 `SendInput`/`mouse_event`/`SendKeys`/`SetCursorPos`，也禁止会移动真实光标的 DCS `Input.warp_mouse` 路径。这些都会干扰用户输入；“只在发送瞬间检查前台”也不能保证按住期间用户切走的安全。优先引擎内独立事件、命令回放、MCP/DCS 的不移动系统光标的接口。
- 后台输入仍需分层：正常 UI 事件确实走通才算 UI-player；直接 move/build/produce 命令只算 command-level。后台工具不支持框选/编组就标 blocked，不能偷偷抢前台补测试。确需原生 OS 输入时，先请求用户明确同意一个独占测试时段，否则停止该路径。
- 录像优先窗口独立捕获；用户切到聊天软件时仍应采本轮游戏窗口，不采聊天界面。`screen` 客户区截屏只适合经用户同意的独占前台时段，不能作为用户同时使用电脑时的自动 fallback。后台捕获黑/白/旧帧时换后台兼容方法或交付 blocked，不用反复拉回前台“解决”。
- 记录前台变化、实际画面刷新和模拟时间；失焦/最小化导致节流属于测量条件，不直接归为游戏卡顿。恢复键盘/鼠标释放不能把输入发给用户正在用的程序。资源开销过大时停止本轮测试，不能牺牲用户电脑响应来凑覆盖。

验收非干扰模式时，必须在目标游戏 `foreground=false` 的连续片段里证实画面或单位状态持续变化，结合驱动日志确认没有系统输入/光标移动/激活调用；单纯“窗口放后台了”不算通过。

本机已验证可用的引擎内 UI 点击来自 `autoload/mcp_interaction_server.gd` 的 `command=click`：按下和释放隔一帧，不调用 `warp_mouse`。先用 `get_instance_info` 的 PID/工程核验归属，再使用该实例的端口，不能盲连默认 9090。DCS `op=click` 与它不是同一个实现，不能混用。持续按键/拖拽/修饰键逐项再资格测试；蓝图依赖真实鼠标位置的路径仍可能 blocked。

本机 `Options.gd` 会按用户设置居中/调整窗口，可能覆盖引擎 `--position`/`--resolution`。命令行写了“屏外”不等于实际窗口始终屏外；启动及切场景要检查实际矩形和前台身份。`CREATE_NO_WINDOW` 只保证辅助控制台不弹，不保证游戏窗口不激活；不使用 `--help` 未列出的“no-focus”参数冒充已实现非激活启动。若无法保证启动阶段不干扰，先修启动器隔离或标工具限制，禁止循环抢回焦点。

## 先通过工具资格检查

试玩前用 15-30 秒小片段确认：正确窗口、画面有变化、单击选择、框选、右键移动、持续按键、修饰键编组和暂停/恢复分别有真实反馈。不支持某项就标该输入路径 blocked，不能用 DCS `Accepted` 证明 UI 通过，也不能长期挂机后宣称完成玩家试玩。

先读取 `agent/mcp/README.md` 和当前输入工具实现。DCS 鼠标失效与窗口焦点之间只有相关性时，不能直接断言因果；若需前置复验，必须先得到用户对独占前台时段的明确同意，否则保留 unknown，不抢前台。暂停时 DCS 不响应可能是控制端也被暂停，不等于整个游戏死锁。

## 录制与时间轴

- 默认 5 FPS、宽度上限约 1280、分段 60-120 秒连续录制；这是采集频率，不是游戏 FPS。保留正常 physics tick/time_scale/VSync/画质，不用 Godot 离线电影/固定帧导出模式代替实时试玩。
- 细小转向、窄口接触、攻击/短特效用 10-15 FPS、20-40 秒局部复验。5 FPS 相邻画面间隔 200 ms，不能验证比此更短的事件或真实 p95 卡顿。
- 每段从动作前数秒开始，保留完整响应、等待、卡住和恢复；超过一段的采矿/生产循环接续录制并注明间隙。不能只录成功结尾或把不同时刻截图拼成“连续录像”。
- 录制工具独立于游戏/DCS，暂停菜单仍能录像；不能逐帧调用同步 `op=screenshot` 让游戏自己成为录制瓶颈。记录采集方法、实际捕获/编码帧、重复/缺帧、窗口失焦/最小化与错误。
- 同一个 monotonic 时间轴记录动作（含按下/释放、修饰键、坐标系）、视频开始及状态数据。只读状态可用 1-2 Hz，遇交货/出生/攻击按需要提高；采样超时留空，不能无限积压。跨进程只有 UTC 时间时说明对齐误差。
- 窗口 capture 不含实际鼠标光标时，动作时间线注明，不能凭视频里没光标认为没操作。无音轨也要标未测音效。

## 本机工具

已有 Python 环境 `D:/software/anaconda3/python.exe` 带 OpenCV/numpy/Pillow。2026-10-10 已在本机真实 Godot 4.7.1 窗口做过后台烟测：窗口放到屏外且 `foreground=false` 时，PrintWindow 连续录制 5 FPS、20 秒、100 帧、0 补帧成功；仍须在每个新环境短测，不能把这个结果外推到所有 GPU/驱动。首次启动/切场景可能有抓取超时，先预热再录。

录制器：[record_playtest.py](G:/AIRTS/AI_RTS/tools/dev/record_playtest.py)。指定本轮 PID；多窗口时还要指定 HWND，不按标题猜当前实例。

```powershell
python G:/AIRTS/AI_RTS/tools/dev/record_playtest.py record --pid <本轮游戏PID> --fps 5 --seconds 120 --output G:/AIRTS/AI_RTS/agent/runs/<run-id>/video/clip-01.mp4
python G:/AIRTS/AI_RTS/tools/dev/record_playtest.py review --video G:/AIRTS/AI_RTS/agent/runs/<run-id>/video/clip-01.mp4 --start 0 --end 30 --step 0.2 --out G:/AIRTS/AI_RTS/agent/runs/<run-id>/review/clip-01-000-030
```

`record --dry-run` 只核对窗口，不录制。默认 `PrintWindow` 仅采指定窗口客户区，但 Godot/GPU 后端可能黑屏、白屏或画面陈旧；必须用动作片段验证。仅在用户同意独占前台时可换 `--method screen`，要求持续前台且无遮挡；失焦即停止，不能录到 Codex/桌面后当游戏证据。录制器不会恢复窗口或抢焦点。

输出 MP4（mp4v、无音频）、同名 JSON 和 `.frames.jsonl`；JSON 的 `start_monotonic_s` 是录像相对秒数的时间原点，逐帧日志记实际捕获完成时间和抓取耗时。同机动作驱动可用 Python `time.perf_counter()` 对齐；别的时钟来源需建立偏差，不能直接相减。迟到补帧明确写 `DUPLICATE / UNOBSERVED`，不可据此认定游戏卡住。`changing_observed_frames` 只是像素变化计数，不证明游戏玩法通过。编码器与抓取也有额外开销，性能结论需补录制关闭的同场景测量。

驱动启动录制子进程应使用现有隐藏窗口进程管理，异步录制后继续操作游戏；等待录制结束再操作只会得到挂机视频。设置外部超时，并在 finally 结束本轮录制进程；不终止用户进程。不覆盖已有证据。

## 必须实际回看

支持直接视频读取时按时间范围审阅。否则 `review` 解码逐帧图和按时间顺序的联系表，实际打开图；重要区间按 0.2 秒步长查看 5 FPS 的所有采集帧。长静态区间可先粗览，但命令、疑似停滞和边界交互必须密看；不能只看首尾帧或只有缩略图里读不清的小单位。

逐段写 `review.md`：视频路径、起止秒、已打开的联系表/帧、动作、观察到的位移/朝向/载货/HP变化、状态数据、缺帧/遮挡/未知项。工具生成联系表只代表 `extracted_not_reviewed`，不自动算模型已经看过。

动态问题必须附 `clip-XX.mp4 @ mm:ss-mm:ss`，并可定位至对应原帧和数据。视图不含单位/被 UI 遮挡或输入没成功时，结论只能是 blocked/未验证。快进、重复帧和录像 fps 都不能代替真实命令延迟或 profiler 帧时间。

## 覆盖与报告

报告分别列 UI-player、command-level、headless、日志观察的证据等级。只有某条链路操作与结果都完成，才填 pass。强杀后的新进程能开局不等于正常菜单退局/重开通过；分别记录正常退局、异常终止、进程清理。
