# AI_RTS 保画质性能优化

目标是减少无用工作和尖峰，不是把游戏内容删掉。遵循仓库 `AGENTS.md` 和 RSI 流程；本 skill 补充性能判断，不代替需求或授权。

## 先作判断

- 看帧时间与实际热点，不凭模型数量、整机 CPU 占用或温度猜 CPU/GPU。30 FPS 上限会掩盖容量差异，主线程满载也不等于整机 CPU 满载。
- 当前证据只证明 2026-10-07 的 53 实体场景曾被重复模型/骨骼遍历拖到个位数 FPS；一次调用内采样复用已取得等价改善。不能据此宣布其他场景或本 skill 中所有方案有效。
- 每个发现标为 `measured`、`structural-candidate` 或 `rejected`。代码上有循环是定位入口，不是瓶颈实测。先测最贵项，一轮一个候选；缓存维护成本也计入结果。
- 先修验证器口径，再判断性能。读取 [measurement.md](references/measurement.md)，检查已有工具的计时单位、丢帧过滤、假绿与进程所有权。

## 关键性能补丁的阶段性复验

性能代码尤其容易出现“FPS 变高但模拟、移动或旧功能坏了”。因此每一个候选补丁（包括缓存、线程、批处理、变换写回、导航筛选和调度顺序）都必须单独经过以下循环，不能累计多项改动后才测试：

1. 记录当前 champion 的源码 hash、配置、单位/建筑数和可运行基线。
2. 应用一个最小候选后立即解析/编译，并**重新启动独立的无头真实 Match**。必须让真实 Match 创建实体、执行命令并推进实际 physics tick；孤立函数、空场景或只读 profiler 不能替代它。
3. 在新局中验证受影响行为和至少一条旧功能链：实际位移/到达、碰撞/避障、攻击伤害、采矿/生产、建造/出生、退局重开按范围覆盖。性能改动还要记录模拟秒/墙钟秒、physics ticks/frame、命令延迟、长帧和错误日志，不能只报 FPS。
4. 失败立即拒绝候选，从 champion 重新开始。不得在失败候选上继续叠加第二个优化；不得用放宽断言、关闭系统或减少模拟内容“修绿”。
5. 同一候选至少在小规模和目标压力规模各复验一次；超过两轮出现新功能通过但旧链路退化，暂停优化并回到调用链/不变量诊断。连续三轮无 champion 提升则换方向。

无头真实 Match 的最小记录包括：新进程 PID/实例端口、地图/种子、实际实体数、开始/结束时间、wall-clock、模拟时钟、退出码、`cleanup_ok`、错误/警告摘要和新鲜产物 mtime。异常超时必须有 watchdog，只清理本轮拥有的进程，保留原始日志。

## 按任务读取

- CPU/大部队/避障/视野/副官/日志：读 [cpu-candidates.md](references/cpu-candidates.md)。这里是当前代码入口、候选与不变量，不是全部必须实施的清单。
- GPU/画面/模型/地形/阴影/粒子：读 [render-candidates.md](references/render-candidates.md)。已有导入 LOD、GPU 粒子和材质缓存，先核验运行时使用情况，不重做已有机制。
- 任一产品优化：读 [measurement.md](references/measurement.md)，建立同场景基线、性能与行为对照、截图和回归门禁。

## 不允许的捷径

1. 不通过关迷雾、关避障、缩碰撞盒、增净空容差、减物理 tick、改速度/射程/视野/尺寸获得“优化”。既有受限窄口规则保留原合同，不借性能任务扩大穿行权限。
2. 不把屏幕外/迷雾外单位停掉模拟。它们仍需移动、攻击、采矿、生产和参与权威同步；表现优化和玩法更新分别处理。
3. 不先开动态降画质、降分辨率、删除阴影/战斗反馈。优先同输出的批处理、共享、缓存、保守筛选；可感知的画面改动先明确容许范围，再截图/动画比较。
4. 不把所有兵、地形或粒子合成一个全图 MultiMesh，也不重写整个系统为 ECS/C++ 来替代热点证明。
5. 不把 SceneTree、节点变换、骨骼、导航/渲染对象随意搬到工作线程。只把稳定纯数据计算外移，明确快照、版本、取消和主线程提交。

## 每轮交付

保留基线与候选的文件 hash、负载、相机、画质、物理频率、帧时间分布、热点耗时/调用数、结果 rc、截图和行为结果；用同预算比较，不把不同地图/摄影机/内容版本混成 A/B。

每轮目录至少包含 `direction.md`、`baseline.md`、`patch.md`、`headless_match.json`、`verification.md` 和原始日志。`headless_match.json` 必须列出新开局的真实 Match 入口、实体/命令/位移/到达/伤害或产出计数、模拟速度和清理结果；只写“scene started”不算通过。

产品候选晋级要求：相同玩法和可读性、可重复的性能收益、不扩大错误/内存/延迟风险、单补丁无头真实 Match、相关测试与独立检查满足仓库门禁。全量已有失败必须如实归因；未全绿不能称全项目 champion。

只请求审计或 skill 时可交付文档，明确未实施/未跑的项目。优化不明显或失败，停止堆参数，保留最后已验证版本；只撤销本轮自己的改动，不回滚共享工作区。

真正测量通过的经验才进入长期 `measured` 记录，附负载和日期；未测项始终保留候选身份。下次开发先重读当前代码，旧行号和旧 FPS 不构成新证据。
