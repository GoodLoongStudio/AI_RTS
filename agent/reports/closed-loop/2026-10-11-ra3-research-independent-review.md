## v1 按严重性排序的发现（R3/R4 已在 batch2 修复）

### R1 / P1：把 RA3 距离原值 50.0 当成 AIRTS 的 50 米

定位：原报告 221、566、593、623 行（7.2 P1 直接建议实施）。官方 Schema `SkirmishAI/AssetTypeAIMicroManager.xsd:33-46` 中时间类型标明 `1s/30s/10s`，距离是 `xs:float default="50.0"`，没有米单位或跨引擎换算证据。报告前面承认 default 不等于运行值，后面却把它写成 `30s/50m`、`10s/50m` 的实施参数。

风险：正常行走但十秒位移未超过 50 米的单位会被误判停滞，重复重派可能打断路线/战斗/采矿。不能在未换算尺度、未验证实际配置时直接搬数值。

纠正：仅借鉴团队/单单位两级进展监控的结构。AIRTS 阈值从自己的速度、路径进度、单位尺度和任务状态测量得出；处理目标接近、路径剩余距离、等待/交战/采矿等正常状态，并做健康移动不误触发的反向验证。RA3 Schema 原值保留为原引擎默认值，不标米、不承诺实际对局使用该值。

### R2 / P1：没有运行轨迹就把副官停滞归因于导航预算

定位：原报告 612 行（7.1 问题 3）。从 `LOGIC_PATH_BUDGET_PER_FRAME := 6` 推出“先纠正一个事实……预算把大部队串行化”，没有对应副官实例的命令/排队/位移时序证据。

当前代码 `Movement.gd:802` 持续执行位移；`_request_logic_path:899` 预算失败只设置 `_logic_path_pending`，后续物理帧重试。预算控制路径请求数量，不能据此说每帧只让一个单位移动。`Movement.gd:71-76` 还记录了另一恢复预算提高后无收益的历史结果；它不是本次预算的直接否证，但明确提醒不能凭常量推断根因。报告检查的 `AutoAttackingBattlegroup` 与 Python 副官探索链也不能未经追踪当成同一入口。

纠正：该项降为待测假设，追踪实际副官入口和 command_id/接收时间/路径等待/首次位移/到达/重派原因。允许多个候选（调度、回执、目标刷新、路径等待、阻塞、主线程饥饿），实测再定位。当前长局 FPS 的通信连接对象泄漏已另有实测报告，不能用此旧预算猜测代替。

### R3 / P1：导出器把内部跳转混入调用图

定位：`D:/RA3_RE_Research/ghidra_scripts/DumpAiControlFlow.py:232-249`。callee 收集 CALL/JMP，随后 `getFunctionContaining(to)` 把函数内部 JMP 也归到函数自身。

独立 JSON 检查：1285 个有 to 的 callee 记录中，**176 条 JMP 的目标仍在原函数内且不是入口**。例如函数 `008bab40` 内 `008bab9b -> 008baba0` 被记作调用 `FUN_008bab40`。这些是控制流边，不是递归调用或跨函数依赖。JSON 的图不能按原样用于推导调用次数、递归、子系统关系或扩展目标。

纠正：分开保存 direct calls、经确认的跨函数 tail calls、函数内部 CFG 边和 unresolved indirect calls。不能把全部 JMP 丢弃，因为确有尾调用；逐条按函数边界/指令类型分类。加入已知内部跳转与尾调用的正反样例。

### R4 / P2：CFG 的指令数实际是字节地址数

定位：导出脚本 199 行，`insn_count = b.getNumAddresses()`。独立读取本体相同字节，用已安装 Capstone 解码 `0x8D3300..0x8D3324`：**37 字节、12 条指令**，JSON 却写 `insn_count=37`。

纠正：该旧字段只可解释为 block 地址/字节计数；真正指令数使用 InstructionIterator 计数。不能按现有 insn_count 比较算法复杂度或计算成本。伪代码行数也不是算法性能指标。

### R5 / P2：提取范围与验收标准不足以覆盖原目标

定位：导出脚本 42、45、385-396 行；原计划 123、134-139 行。关键词只有 5 项、只扩展一层调用者、上限 120。本次函数来源恰为 `caller_of=120`、`string_xref=18`、`vftable_slot=28`、`explicit_va=5`；120 的名额已经全部使用。该数量是有截断的提取结果，不是完整方法集或算法覆盖。

纠正：以问题覆盖而非函数数量验收。下一轮优先目标评分或 idle 重下令中的一条完整行为链，包含入口、字段来源、比较/分支、结果命令与证据缺口。然后单独调查可达性/路径搜索/局部避障/多线程，每项允许暂缺；不以更多析构/getter 充数。显式记录截断、间接调用未解析和选择理由。
