## 1. 推翻"全局冻结"：恢复时刻成簇，但那是**批次对齐**

round-20 我看到真停滞的 `continuation_tick` 成簇（如 `Unit_36/37` 都恢复在 13736），
第一反应是"全局冻结"。本轮用 [freeze_or_batch.py](agent/runs/2026-10-07-adjutant-continuity-fix/round-21/freeze_or_batch.py)
检验，**否掉了它**：每个簇的恢复时刻都正好落在一次**大批量生成**上
（该批次共 15~26 个单位，其中其它单位 13~23 个）。所以不是"全体一起停"，
而是"**等到下一次批量下发才恢复**"。

关键细节：同一簇内**到达时刻差几百 tick、停滞时长也依次差几百 tick**：

```
恢复 tick≈7017  Unit_38/37/33  到达 5437/5608/5672（跨度 235）停 26.3/23.5/22.4 秒
恢复 tick≈7233  Unit_7/41      到达 5001/5143（跨度 142）    停 37.2/34.8 秒
```

先到的停得久、后到的停得短 ⇒ 这是**排队**的形状，不是冻结（冻结会让所有人停一样久）。

## 2. 定位：服务顺序是**固定字母序**，靠后的单位每次都被截断

`rotation_fairness.py` 统计每轮推进意图在列表里的**平均排名**：

| 档案 | 平均排名跨度 | 排最后的（= 停最久的） |
|---|---|---|
| `9e5627fe`（round-20） | **0.0 → 16.7** | `Unit_41` 16.2 / `Unit_36` 11.5 / `Unit_37` 12.4 / `Unit_38` 13.2 |

**跨度 16.7，完全没有轮转。** 成因是两个早已存在的实现叠加：

1. `nodes.py` 里 `state["ai_controlled_units"] = [u for u in sorted(observed_own) …]`
   —— **固定字母序**；
2. `rules_fallback` 军事轨每轮有产出上限 `PARALLEL_FILL_CAP = 8`，按 `ai_units` 顺序取。

⇒ 靠前的单位每轮先被服务，靠后的**每轮都被截断**。
注意这**不是**"拿不到意图"（每个单位累计仍拿到 30~140 条），而是"**要等前面的人轮完**"——
round-11 我观测到"每个单位都拿到 ≥31 条"就搁置了这个怀疑，那是因为我只看了**总量**、
没看**排名**。

## 3. 修复：持久游标旋转起点

```python
start = int(state.get("advance_cursor", 0) or 0) % total_units
ordered_units = ai_units[start:] + ai_units[:start]
state["advance_cursor"] = (start + max(1, PARALLEL_FILL_CAP)) % total_units
```

**只改顺序**，不改任何筛选判据、不改上限（与 `lanes.interleave` 的 cursor 同一思路）。

守门测试（`test_safe_movement.AdvanceRotationFairnessTest`，2 例，全绿）：
① 连续多轮后**每个作战单位都轮到过**（24 个单位 > 上限 8，固定顺序下末尾的永远轮不到）；
② 轮转**不改变谁合格**（反向保护）。第二例我第一版写错了 —— 我把"所有意图里的单位"
当成军事轨产物，于是把**侦察轨**给无人机的 `rule-fill-scout` 误判成"军事轨推进了无人机"；
已改成只看 `rule-fill-advance` 前缀。

## 5. ⚠ 一个我没能解释清楚的读数（如实记录）

轮转之后**平均排名跨度反而变大了**（16.7 → **21.5**）。按"轮转应当压缩跨度"的预期，
这是**反向**的。两种可能：

- **A**：`rotation_fairness.py` 度量的"列表位置"**不是**真正的服务顺序 ——
  若一轮里被"截断"的单位很多，它们在列表里仍出现在很后面，跨度自然大。
  换句话说这个指标本身有缺陷（它量的是"出现在第几位"，不是"多久被服务一次"）。
- **B**：轮转真的没起作用（那 p95 的改善就另有原因）。

**我倾向于 A**，因为：p95 **减半**（8.20 → 4.95）是同一套口径、同一窗口下的读数，
而如果轮转没生效，这个数字不该动。但我**没有**独立证明 A，
所以这一条标为**未解释**，下一轮应当换个指标（"两次被服务之间的**间隔**"而不是"平均排名"）
重新量。
