## 2. 逐例追一个 4.23 秒样本（`Unit_25`）

```
t=2836  attack_move Accepted  rule-fill-advance-Unit_25-2836
t=2871  （到达，见下）
t=2917  advance_skipped busy  blocker=rule-fill-advance-Unit_25-2836   ×2
t=2989  advance_skipped busy  blocker=rule-fill-advance-Unit_25-2836
t=3065  advance_skipped busy  blocker=rule-fill-advance-Unit_25-2836   ×3
t=3125  attack_move Accepted  rule-fill-advance-Unit_25-3125            ← 4.23s 后
```

形态与 round-23 的 `Unit_16` **一模一样**（到达后旧意图继续把它算成 `busy`）。
**但**：

- 空档 **2871 → 3125 = 254 tick**，按实测周期 **0.395s** 折算 ≈
  **0.72 秒的到达→释放口径**；
- 而"被 busy 挡住的最后时刻"是 **3065**，距下一条命令 **3125** 只有 **60 tick（0.40s）**
  —— **退役已经发生**（否则会一直挡下去）。

⇒ **释放链是通的**，这 4.23 秒**不是"释放失败"**。

## 4. 逐样本检验 2–5 秒带：**几乎全是"被自己的前压意图挡住"**

对 2–5 秒带的 **149** 个样本，逐一查空档期内的 `advance_skipped`：

| 检验 | 结果 |
|---|---|
| 空档期内有 `advance_skipped` 记录的样本 | **121 / 149 = 81.2%** |
| 这些记录的 `reason` 分布 | **`busy` 303 条** vs `en_route` **8 条** |
| 其中 `blocker_action` 的分布 | **`attack_move` 303 条（100%）** |
| 其中 blocker 是**该单位自己的**前压意图 | **258 / 303 = 85.1%** |

⇒ **这一带几乎全是"单位被自己上一轮的前压意图算成 `busy`"**，
**不是**别的轨抢名额，**也不是** `en_route`（半路改令被挡）。

**这与 §3 的"释放链是好的"并不矛盾**，两者要合起来读：
`_close_movement_intents` **确实**在到达时结束了意图
（`matched == released` = 509 = 509），
但**单位随后没有在下一轮立刻拿到新命令** ——
它被排到队尾，等下一轮（或下几轮）才被服务。
而在**等待期间**，那条已被结束的意图仍以 `busy` 的形式出现
（`busy_units` 读的是活跃意图表，而新命令还没产生）。

⇒ **真正要治的是"到达之后立刻重新排队/服务"，不是"释放"**（释放已经对了）。

## 5. 这与 round-32/36 的名额结论怎么合**

- round-32 量到 **45~61% 的轮名额被吃光**（`advance_batch_full`，`emitted` 恒为 8）；
- 一局 **40~60 个作战单位**争 **8 格**；
- round-47 量到 **p50 = 0.93 秒 ≈ 2.3 个协调轮**；
- 本轮：2–5 秒带 = **5~13 个协调轮**，且受困者都指向**自己的前压意图**。

⇒ **名额不足 ⇒ 单位要排队 ⇒ 排队期间仍显示 `busy`** ——
**2–5 秒带就是这个队列长度**。

**round-32 §4 那个"名额截断不驱动 p95"的判定需要精细化**（不是推翻）：
- 它用的是**跨局** `full%` 与 p95 的相关（`full%` 极差仅 15.8pp，局间比不出来）；
- 本轮是**局内**逐样本追踪 ⇒ 名额截断**在局内**确实构成 2–5 秒带。
**口径不同，两者可以同时成立。**

## 6. 这对"候选"意味着什么

用户 round-39 已授权我做 **`PARALLEL_FILL_CAP` 的性能门禁**。本轮证据让它更有理由：
**提高 cap 应当压掉 2–5 秒带**（进而把 p95 拉进门禁）。

**但**：提高 cap 会**直接推高** `elapsed_ms`（p50 已 316ms、max 3104ms）与协调负担，
所以**必须先走性能门禁**（这正是用户授权的）。

**另一个更小的候选**（本轮新线索，值得先试）：
让"**刚被释放的单位在下一轮优先重排**"（round-27 的到达优先层已有雏形，
但它按 `unit_arrival_tick` 排序，可能被"到达优先窗口 300 tick"或轮转游标稀释）。
这**不动名额总量**，只改队列顺序 —— 风险远小于改 cap。
