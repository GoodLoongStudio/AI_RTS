# 阶段 1 战略聊天独立复核

日期：2026-10-03

结论：阶段 1 的核心用户闭环已基本成立，可以进入用户验收；暂不建议标记为“完全收尾”或“全量回归通过”。

## 已确认

- 游戏内可以打开“战略聊天（只讨论战略，不执行命令）”面板并发送消息。
- 本地真实模型连续 5 轮请求成功，历史与 `conversation_id` 正常维护。
- 运行中和暂停中都能继续聊天；暂停时模拟时钟保持不变。
- 超时、HTTP 503、空输出、非法输出、重复发送和迟到响应都有错误或抑制路径。
- 聊天适配层没有接入命令、计划、任务或 Laya 执行入口；可见探针中资源未扣减、活动订单为空。
- 独立重跑 `StrategicChatServiceSmokeTest`：RC=0，53 项断言通过。
- 独立重跑真实模型探针：RC=0，5 轮通过。

## 尚未收尾的问题

1. **没有跑全量回归**：当前工作区存在大量并行改动和既有红灯，因此只能确认定向套件，不能声称整个项目无回归。
2. **测试日志不干净**：非法 JSON 的预期分支会直接打印 Godot `ERROR: Parse JSON failed`，虽然断言为绿，但应改成静默解析或结构化错误，避免把预期输入看成引擎错误。
3. **界面仍有旧入口**：底部旧的“对岚说”规则 mock 输入条与新战略聊天并存，玩家容易误以为有两个副官入口；报告已把它列为后续 UI 收敛项。
4. **状态文案有歧义**：面板能正常调用本地模型时，顶部仍可能显示“副官尚未启动”，需要在阶段 1 收尾时统一“副官运行状态”和“战略聊天服务状态”。
5. **探针退出有引擎噪声**：可见 UI 探针曾出现资源释放/场景清理类错误输出，虽然场景完成且功能断言通过，仍应清理后再做一次干净验收。
6. **无战局摘要时模型会复述占位文本**：独立真实模型探针中，模型多次原样带出“暂无战局数据”提示。这不影响传输和执行边界，但属于提示词/输出质量问题。
7. **连接拒绝路径没有稳定复现**：当前以 503 和挂起桩覆盖错误管线；真实端口拒绝在本机被防火墙转成超时，尚未单独证明 `model_unavailable` 的真实网络路径。

## 建议验收门槛

先收掉第 2、3、4、5 项，再重跑定向套件和可见 UI 探针；之后由用户在真实游戏中连续进行 5 轮以上战略对话，并确认暂停聊天、错误重试、切局隔离和“不产生任何命令”四项。通过后再进入阶段 2 的结构化计划讨论，不要在当前阶段提前接入 Laya 执行。
