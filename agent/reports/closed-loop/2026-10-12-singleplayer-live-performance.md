# 单人对局约 300 FPS：实测开销与长帧

2026-10-12。用户授权自行开单人房进行诊断。未实施产品优化。

## 已经证明的结论

1. 正常 Play 页开局可以复现约 300 FPS：r02 的前两段平均 **325.1 / 322.1 FPS**，墙钟平均帧间隔 **3.076 / 3.105ms**。主画面 GPU 渲染平均 **1.87 / 1.83ms**，CPU 渲染提交平均 **0.48 / 0.55ms**，是持续性开销。
2. 严重长帧有明确 CPU 调用关联。r03 同帧数据：**648.887ms 帧中，电脑 AI arbitration 为 638.681ms**；另外 **315.306ms 对 313.505ms、140.321ms 对 138.333ms**。这个桶包住资源检查与同步 provision 执行，不能把它误解成只花在排序上。
3. 当前小规模场景没有重现旧的 RVO 巨大瓶颈。r02 detailed 移动 _physics_process 合计约 **0.129ms/渲染帧**，避障回调合计 **0.036ms/渲染帧**；导航监控均值 **0.011ms**。这是本场景数据，不推广到 300/1000 单位。
4. 副官自动启动的 Python runner 是额外资源负载：r02 PID10796 采到瞬时约 **1215% 单核等效 CPU**，r03 PID40100 约 **1244%**，即约 12 核同时忙。它们的命令行是本轮端口目录 p25597 / p25637 的 runner_bootstrap.py；不是把整个游戏 CPU 都算给它。尚未区分 Python 导入/数值线程池/模型调用各占多少。
5. GPU 总遥测在 r03 平均 **94.3%**、范围 **78–99%**，模型和其他 GPU 程序在同时运行。这是整卡负载，不能声称全由游戏、全由副官或全由地形引起。

## 帧时间与业务负载

| 样本 | 实体变化 | 平均 FPS | p50 / p95 / p99 (ms) | 最长帧 |
|---|---:|---:|---|---:|
| r02 early 25s | 8→19 | 325.1 | 2.611 / 4.933 / 8.017 | 452.303ms |
| r02 detailed 25s | 20→33 | 322.1 | 2.468 / 6.711 / 12.560 | 126.228ms |
| r03 correlated 30s | 8→25 | 229.0 | 3.563 / 6.315 / 11.494 | 648.887ms |

r02 early 有 8 帧超过 33.33ms、3 帧超过 100ms；detailed 对应 7/1。长帧未过滤。r03 并行 GPU 演示 PID43036、另一 Python 任务、后台程序和副官冷启动同时发生，因此 229 FPS 不能当成同条件退化或优化前后差值。r02 采样中途也出现其他 Agent 的 dotnet 构建与 Godot 回归。

r02 later 虽显示 338 FPS，但 8460 个渲染帧只对应约 1050 次相机/小地图更新及 99 次业务物理更新；这符合期间世界暂停的表现，原采样未记录 tree.paused，不能确定暂停原因。已排除该段容量结论。旧 summary 的 sim_wall_ratio 只来自 Engine.get_physics_frames，这个计数在暂停时仍会推进，**不代表真实模拟速度**。工具已改名 engine_physics_tick_wall_ratio，补测额外记录 tree.paused；r03 的 6872 帧 paused 均为 false。

## 哪些系统在消耗时间

以下为 r02 detailed 的累计耗时除以实际渲染帧数；按桶覆盖范围解读，**不是互斥饼图，不能相加成总帧时间**。

| 系统 | 平均 ms/渲染帧 | 说明 |
|---|---:|---|
| 主视口 GPU | 1.832 | 稳定持续开销，尚未拆阴影/几何/材质/后处理 pass |
| 主视口 CPU render | 0.552 | 渲染提交；不是整个主线程 |
| DCS _process | 0.156 | 包含自动快照及实际副官请求；采样本身仅阶段间请求 |
| 移动 _physics_process | 0.129 | 所有单位累计，回调另计 |
| OffscreenVisualCull | 0.100 | 每渲染帧遍历单位并判断视锥，负载随单位数增长 |
| 小地图 _process | 0.074 | 每渲染帧业务 |
| 相机 | 0.044 | 当前相机更新 |
| 避障回调 | 0.036 | 包含推开/旋转等子项 |
| 视野显隐 | 0.034 | 20Hz，每次平均约 0.549ms |
| 步兵动画 _process | 0.025 | 包含脚部/枪口等子桶 |
| 电脑经济规划 | 0.037 | 每次约 5.98ms，约 2Hz |
| 电脑情报 | 0.008 | 每次约 1.34ms |

两个迷雾子视口 GPU 平均约 **0.052 + 0.008ms**；各自 CPU 提交约 0.072/0.062ms。小地图 SubViewport 返回全零，标记未取得有效计时，不能把它当作确认零成本。

r03 逐帧采样工具自身平均 **43.2μs/帧**、p95 **76μs**，有扰动但远小于被定位的 639ms 调用。GPU 时间是 RenderingServer 原生毫秒，无重复除以 1000。TIME_PROCESS、TIME_PHYSICS_PROCESS、DCS ring 与帧间隔采样不同，不相加；physics_script_ms 约 50ms 的 bookend 含物理拍之间等待，不能视为独占脚本成本。

r02 90 秒外部线程采样中，Windows 主窗口线程34176平均约 **68% 一个核心**，最忙其他线程约 **7.5%**。r03 主窗口线程15956平均约 **47%**，最忙其他线程约 **9.8%**。它们显示主要游戏 CPU 工作集中在主线程，也包含等待和外部竞争；不证明主线程每时每刻满载。OS.get_thread_caller_id 返回引擎线程 ID，不能直接拿来匹配 Windows TID。

当前全帧 primitives 为约 **72.8万–88.9万**，draw calls **179–366**。实际 PlainAndSimple 地形日志是 **257×257、66049顶点、131072三角形**，不能沿用“所有512地图都是524288三角形”的旧推断。仍为单地形网格，分块是候选；未实测它能省多少 GPU 时间。

## 代码入口与下一步

**P1：电脑 AI 单帧长任务（measured）。** SimpleClairvoyantAI.gd 的 _try_fulfilling_resource_requests_according_to_priorities 在 _process 内 while progressed 同步完成多个请求；_provision 直接进入经济/防御建造，FindAutoSpot 同帧逐候选评估，最多256次。先用现有 WorldQueryRuntime.GetQueryPerfStats 再拆资源查询、候选生成、评估、放置/实例化各子阶段。当前已证明仲裁包含的执行链很贵，**还没有证明这639ms中某个子函数的独占比例**。

候选设计：预算可续的请求/选址任务，保留优先级、公平性和待处理请求；复用一次任务内稳定场景数据，廉价拒绝先于精确评估。完整搜索预算跨帧续，不把本拍耗尽误当 NoValidSite。最终放置必须主线程重新核验余额、建筑状态、地形/导航/占用版本，禁止把 Node/SceneTree 或 Godot 查询直接搬进工作线程。纯候选/几何数据计算经快照与版本合同才可工作线程化。不得通过少造建筑/放宽碰撞变快。

**P2：副官/模型资源竞争（measured进程负载，内部原因未测）。** 检查 runner 冷启动的数值线程池、实际模型GPU推理和游戏渲染并发。优先减少重复初始化、给可并行纯计算合理线程预算、模型服务共享、异步调用与批量观测；不能默认停掉副官。整卡94%不能单独给某模型分账，后续要记录推理时间线及游戏GPU队列延迟。

**P3：持续渲染与每帧扫描（measured总体，子项候选）。** GPU pass 拆分后再决定地形分块/材质或阴影代理；视锥筛选和小地图可考察稳定引用、保守空间批处理。保留现有画质、显隐、动画/战斗正确性，不一键关闭阴影或降低物理频率。

仍有未解释长帧（r03 142.602ms 等），未测 GPU 各 pass、纯 native RVO 独占、C# 分配/GC、模型内部、正式大部队或战斗。此报告不是全部瓶颈定位完成或性能认证。
