## 2. C-132 的结构性证据：名额占满时**根本不走 `busy` 判定**

| 指标 | `81893e7b` | `ab487d43` |
|---|---|---|
| 有 `advance_batch_full` 的 tick | 131 | **147** |
| 有 `advance_skipped` 的 tick | 63 | 71 |
| **两者都有** | 35 | 41 |
| **只有 `batch_full`（没走 busy 判定）** | **96** | **106** |
| 只有 `skipped`（名额没满） | 28 | 30 |
| 合并 = 军事轨有动静的 tick | 159 | 177 |

**读法**：名额没满时，单位会被逐个评估（留下 `advance_skipped` 记录）；
名额占满时，循环在**第一句** `break`（C-113 已定位），**连"这个单位被 `busy` 挡了"都不记**。
`ab487d43` 里 **106/147 = 72%** 的"名额占满轮"属于这种"评估都没发生"的情形。

⇒ **round-34 观察到的"拖尾样本看不到 `busy` 记录"由此得到机制解释**：
不是当时没有 `busy`，而是**那一轮压根没评估到任何单位**。

## 3. 量化的相关性：**19/19**，但对全体也是 96.5%

对 `81893e7b` 的 `>10s` 样本，检查空档期内是否含"名额占满的轮"：

```
>10s 样本 = 19
  空档期内至少有一个名额被占满的轮 = 19      ← 100%
  空档期内完全没有名额占满记录     = 0

对照：全部 426 个接续样本中，空档期含名额占满的 = 411 (96.5%)
      >10s 样本中该比例 = 100.0%
```

**诚实读法（两条，缺一不可）**：

1. **19/19** ⇒ 名额截断是拖尾的**必要背景**：凡是拖尾，空档期里必然有名额占满的轮。
2. **但全体样本也有 96.5%** ⇒ 它**区分不出**"会拖尾的样本"与"不拖尾的样本"。
   所以它**不是充分原因**，不能单独解释"为什么是这些单位、这些时刻"。

这与 round-32 的结论**一致**：名额截断是**恒定背景**（45~61% 的轮，
cross-run 极差仅 15.8pp），不是 p95 变动的解释。

## 4. 现在把整条链拼起来（我认为可以定论的部分）

```
决策周期 ≈ 1.4s（round-26 量）        ← 门禁 p95≤1s 已低于它
   ↓
每轮总名额 PARALLEL_FILL_CAP = 8，
   全轨共享、军事轨最后跑（round-32 量）
   ↓
45~61% 的轮名额被前面的轨吃光            ← round-32 量
   ↓
其中 72% 的轮，军事轨在第一句 break，
   连单位都没评估（round-36 量，C-132 成立）
   ↓
60 个作战单位争 8 个名额
   ↓
单位平均多等 2~3 轮（round-26 量）
   ↓
等不到的那些，由 HOP_HOLD_MAX_TICKS = 1800 tick = 30s 兜底放行
   （round-32 量：四档案 >10s 中位 30.1~31.3s）
```

**这条链每一环都有实测支撑。** 它是"走一小段后等很久"的**结构性解释**。

## 5. 下一轮（round-37）：从"测量"转向"改动"

链条已经量清，**继续测量边际收益在下降**。下一轮应当动候选，且我会遵守三条：

1. **一个候选**：针对 §4 的"名额被前面的轨吃光 ⇒ 军事轨整轮停摆"，
   给**作战单位的推进**一个**独立的最小名额**（不是把 `PARALLEL_FILL_CAP` 乘倍率）。
   **理由已核到代码级**：这个机制**本来就有**，只是**只给了侦察轨、没给作战轨** ——

   ```
   rules_fallback.py:3143   scout_reserve = 1 if scout_pick else 0
   rules_fallback.py:3176   if not _room(reserve=scout_reserve):   # 经济轨让位给侦察
   rules_fallback.py:3234   if not _room(reserve=scout_reserve):   # 建造轨让位给侦察
   rules_fallback.py:3462   if not _room():                        # 军事轨：没有预留
   ```

   即：**侦察轨有一格保底，作战轨一格都没有**。
   ⇒ 候选 = **对称地给军事轨一格保底**（`_room(reserve=military_reserve)`），
   **复刻既有设计**，而不是发明新倍率或改 `PARALLEL_FILL_CAP`。
   这也解释了为什么"侦察单位能动、作战单位不动"。
2. **先量开销**：改前必须量"每轮下发条数 / 寻路调用 / 帧率"
   （prompt 明文禁止盲目乘倍率；AGENTS.md 要求这类改动走
   `airts-performance-optimization` skill 的候选/门禁流程）。
3. **目标指标先写死**：本轮改动的目标指标是
   **`advance_batch_full` 的轮次占比**（应从 45~61% 下降）
   与**军事轨 `emitted_advance` 条数/轮**（应上升）。
   **不是** p95 —— C-118 已证名额截断不驱动 p95，所以我不拿 p95 当这次的目标。
