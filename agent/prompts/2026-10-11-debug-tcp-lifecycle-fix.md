# 修复长局 FPS 下跌：调试 TCP 对象累积

先读仓库 AGENTS.md、工程边界、RSI 与性能 skill，以及 `agent/reports/closed-loop/2026-10-11-live-fps-drop-audit.md`。这是已经实测的根因，不要先去改寻路、降画质或重写多线程。

目标：修复 `source/net/DebugControlServer.gd` TCP 连接生命周期。当前服务端没有 poll 就检查状态；合法短连接关闭后仍被当作 CONNECTED，_clients/_buffers 累积约 11,100 条，每帧空扫描约 22.5ms。抽样 poll 后 8/8 连接变为 NONE，debug_process 占测量窗口约 82.5%。

实施前读当前文件并核验并行改动。最小补丁刷新 peer 状态、处理错误/断开并同步回收 buffer；批量回收避免逐个 Array.erase 的二次复杂度。审查截图排队和当前客户端引用，保留协议、权限与副官命令语义。合理上限与背压按报告要求实现，不能吞合法请求。连接复用属于可选后续，不得用它掩盖服务端生命周期缺陷。

禁止打断用户运行对局。用独立隐藏实例开展验证，不抢桌面输入。每次关键补丁先解析/编译，再真实无头 Match 连续完成至少 10,000 次短连接请求，记录 clients/buffers 是否回归稳定基线、成功率、内存及维护帧耗时。覆盖持续连接、半包、多行、异常断开与重连；运行副官探索移动和玩家选中接管行为回归，退出再开第二局。不能用空场景或截图代替压力和行为证据。

修复后做相同负载/视角/画质的持续可见运行复验，报告实际帧时间，不预报 400 FPS。不采用 Match.physics_script_ms 作脚本独占时间，它目前计入帧间等待。保留原始结果，更新计划和闭环报告，如实列出失败/未测项，不撤销他人修改。
