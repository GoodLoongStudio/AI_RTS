## 3. 你必须像玩家一样操作

1. **主线用有画面的真实游戏实例，不是 headless。** 从主菜单进入单机/自定义对局，选地图和槽位，点击开始。确认加载结束、HUD 出现、自己的开局单位出现并可操作，不能把房间状态或 `Match` 节点存在当作成功。
2. 优先用实际可用的 Godot MCP/运行时输入工具执行点击、框选、键盘和拖动。先检查工具真实能力，不编造工具名、返回值或“已点击”。每次关键操作按“看当前截图 → 操作 → 等待实际反馈 → 再截图/采样确认”的闭环。
   正式试玩前用短录像验证单击选择、框选、右键移动、持续按键和修饰键组合。每个输入分别记录成功或 blocked；某关键路径未通就先交付工具资格失败，不挂机几十分钟后将整阶段标完成。后台是否影响 DCS 合成与 OS 注入需分别实测，不能只凭失焦截图断言工具失效根因。
3. 若 MCP 某路径无法控制，标该项工具阻塞，最多两次有依据的重试；只可改用不影响 OS 光标/焦点的后台兼容接口。禁止自动 fallback 到原生窗口输入、DCS warp_mouse 或 screen 抓屏，用户会同时聊天和使用电脑。原生 OS 输入/前台抓屏仅在用户明确同意独占时段后使用；未经同意宁可交部分报告，不虚构试玩。
4. DCS/项目实例工具可用于只读状态和日志取证。只有确认命令入口与玩家权威命令一致时，才能作为有限补充，且报告注明 `command-level`；它不能证明鼠标拾取、框选、HUD 或菜单交互正常。
5. 无头真实 Match 可以补充重放某个已发现问题，但不能取代本次可视试玩；headless FPS 不代表玩家画面 FPS。
6. 禁止刷钱、瞬移、直接 spawn 单位、直接修改 HP/速度/碰撞、开全图替代探索或调用内部方法强行使建造/采矿成功。单位和建筑必须从玩家正常生产与建造获得。
7. 使用现有实例/端口管理能力时先读其实现。`tools/dev/match_instance.py` 的 server+client 自动开局不能替代单机菜单本机房主链路。当地 listen server/本地端口是当前单机实现的一部分，不能仅因为存在服务器对象就误报“单人房是僵尸房”。

## 4. 三轮试玩，阶段性复验

建议总墙钟预算约 45 分钟，不能无限等待。先完成第一轮，再逐步展开后续覆盖；时间/资金/故障造成未测必须记录。

### A：纯单人练习局，约 5-10 分钟

在正常单机菜单只保留一个人类指挥官，其他槽位设为空。选一张正常可用地图，记录实际地图与种子。验证开房、探索、建造、采矿、生产、移动和主动退局。

**当前单人练习规则不判胜负，主动退出才结束；没有胜利弹窗不能直接判 BUG。** 若所有槽位设置后实际仍生成 AI/错阵营，单独取证。

### B：一个真人对简单 AI 的单机局，约 10-20 分钟

通过同一个单机入口，在菜单增加一个简单 AI，正常发展经济和部队，探索敌人、进攻、撤退并观察损伤/死亡/结算。只使用游戏现有槽位选项。不要连云端联机房，也不要将此局误称为“纯单人无敌人局”。

完成一段连续玩法链：**开局 → 探索资源 → 合法建矿场/其他必要建筑 → 矿车采矿并交货 → 正常产兵 → 编组移动 → 接敌攻击 → 撤退/补充 → 退局**。链路断在哪就记录在哪，不能用作弊跳过。胜败/结算达不到时记录未测，不能编造结果。

### C：换地图重开与问题复现，约 5-10 分钟

退回菜单再开新房，优先选地形/通道不同的地图。检查旧单位、资金、选中状态、AI 任务、房间连接和画面是否残留。对 P0/P1 问题优先在新局最小步骤复现，统计复现次数/尝试次数。

每个阶段结束，保存报告和覆盖表，核对日志/截图新鲜度及当前版本。若发现某链路失败，在下一阶段再尝试一次；只审计，不改代码去把它“测绿”。

## 6. 截图、数据和安全收尾

- 动态证据为连续录像 + 动作时间线 + 状态数据。默认 5 FPS、宽度上限约 1280，60-120 秒分段；短转向/碰撞/攻击/特效用 10-15 FPS 局部复验。录制在独立子进程持续进行，驱动同时玩游戏；不用逐帧 DCS 截图，不把游戏 tick/FPS 改为录像 FPS。
- 读取 `skills/airts-temporal-playtest/SKILL.md` 使用 `tools/dev/record_playtest.py`；先验实际游戏窗口是否黑/白/冻结，不能把合成窗口测试当游戏验证。录像元数据、缺帧/重复帧、失焦、无音轨均记录。分段实际回看或解码联系表逐帧查看，填写 `review.md`；只生成 mp4 或只打开首尾帧不算通过。
- 关键状态截图：开局、建造范围/贴边放置、矿车交货、生产出口、编组窄口、战斗、副官执行、退出重开；发现问题时补截图，实际打开查看，不只检查文件存在。
- 持续行为如单位不转向、停走、采矿循环，用前后两帧/短视频/时间序列支持，不用单张截图证明移动正确。
- 每个动作记录时间、局号、选中单位/建筑 ID、命令目标、预期和实际反馈。原始证据 mtime 必须晚于本轮启动，证据路径使用绝对路径。
- 帧时间记录 p50/p95/p99、最长帧、样本数和观察窗口；正常画质/实体数/模拟速度一并记录。工具读不到的字段写 `unavailable`，不能填 0；不丢弃 >500 ms 长帧，不凭整机 CPU 占用断言主线程/RVO 瓶颈。
- 自然发展未达到 100/1000 单位，不伪造压力结果。截图读回可能造成停顿，标出采集事件，不把工具延迟直接归给游戏，也不删掉不利样本。
- 开局加载、截图与输入工具都设置有界超时；持续无进展/崩溃时保留现场，停止对失效实例盲发命令。最多两次重开尝试后交付阻塞报告，不擅自修启动链路。
- 优先通过菜单正常退局/退出，再核对本轮 PID、子进程、监听端口和实例登记；只有确认归属本轮的残留才能清理。报告 `cleanup_ok=true/false/unverified` 及证据，不按 Godot/ollama 映像名或端口批量结束进程。
