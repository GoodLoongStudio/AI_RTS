## 4. P1：修游戏真实客户端的长度帧解析

生产入口是 `source/ui/AdjutantButton.gd::_authority_call -> _tcp_json`。当前 `_tcp_json` 在 raw 中发现任意 `0x0A` 就停止收包，随后只有正文收全才剥前缀。这个判断与协议冲突。

现有协议必须保持：

```text
请求：UTF-8 JSON + 换行
回应：4 字节小端无符号正文长度 + 指定长度的 UTF-8 JSON 正文
长度包含服务端追加的末尾换行；该换行不是接收完成判据。
```

可确定复现：合法正文恰好 65546 字节，长度前缀 `0A 00 01 00`；第一次收到 65536 字节的帧片段时，raw[0] 已是换行，但总帧应为 65550 字节。旧客户端提前结束，不剥前缀，导致 JSON 解析失败。正文 266 字节的前缀 `0A 01 00 00`，只先发送四字节头再延迟正文，也可确定触发。

按以下合同最小修复：

1. 先累计足够四字节，按小端读取 declared_length；接收完成仅以 `received_body_bytes >= declared_length` 判断。头和正文跨任意 TCP 分片均合法，不能依赖单次 recv 的边界。
2. 长度先检查有效范围，再申请/累计对应正文。上限与实际服务端政策明确对应：当前 DCS 正文上限为 1MiB（包含末尾换行），不能接到巨大声明就无界分配，也不为了测试把上限无限放大。
3. 完整正文只解码一次 UTF-8，再解析 JSON Dictionary；中文码点切包不能出现替换字符/Unicode 错误。返回类型与 `_authority_call`、面板调用方兼容。
4. 不足四字节、不完整正文、EOF/RST、超时、非法长度、非法 JSON 均显式失败并释放连接；不把截断长度帧回退为“可能是裸 JSON”。失败路径仍清掉查询重入守卫，不能让面板永久 in_flight。
5. 保留非阻塞/异步等待和有界内存，按单调墙钟记录实际 deadline，不忙等，不每次收到一字节无限延期，不引入主线程阻塞等待。先验证当前超时合同，不以把 1 秒变成 60 秒解决截断；需要调整时独立证明原因与响应影响。
6. 检查发送/读取的返回错误并安全结束；错误不是命令未执行证明。请求发出后，响应未知、超限或断开不能自动重放非幂等建造/生产/命令。保留 `execution_status=unknown / retryable=false` 语义。
7. 本入口是一问一答，不趁机改成长连接或请求流水线；不改变服务端截图异步排序、不重写服务端发送协议。

Python 的 `tools/dbgctl.py` 与 `tools/dev/debug_tcp_lifecycle_probe.py::receive` 可作为独立格式参照，**不能替代 GDScript 真实客户端测试**。runner 的实际导入/装配另核对；不要因为某个 Python 文件被命名 tcp，就认定它是生产路径或把所有消费者一并重写。

### 必须针对真实方法做分包回归

用本轮拥有的可控 TCP 发送端，调用 Godot 中真实 `_tcp_json`。允许在测试中隔离按钮启动/模型等无关副作用，但不得把待测网络方法替换成假的 helper 或只测 Python 接收器。

| 场景 | 必须断言 |
|---|---|
| 266 字节正文，只先发四字节带 `0A` 的头 | 正文未到时仍等待，最终返回原字典；旧实现同样本失败 |
| 65546 字节正文，首片65536字节，尾片延迟 | 接收65550字节完整帧，内容逐字节/字段一致，无提前退出 |
| 头按1/2/3字节切分，正文中文码点切分 | 完整正确解码；延迟在原deadline内 |
| 合法小包、接近上限及当前上限正文 | 与参照一致，时限/内存有界；记录包含末尾换行的长度 |
| 零长度、超上限声明、残缺头/正文、断开、非法JSON | 不返回成功、不解析截断正文、不无限等待，连接/守卫回收 |
| 超时后下一次合法查询 | 面板能继续更新，旧结果不污染新 Match，不自动重放命令 |

发送方记录每片长度/时间和总帧字节；旧版先失败、新版再通过。测试必须有实际时序/结果断言，不只查源码有没有 decode_u32。纯协议测试后再新开无头真实 Match，通过真实 DCS 调用同一客户端取得 status/规则/租约等代表响应，验证 schema、控制权与一条旧功能轨迹。
