# DeepSeek 实施提示词：大部队移动的质变优化

你要处理的是 AI_RTS 的大规模单位 CPU 卡顿。最终目标沿用交接报告：目标硬件上 1000 单位、正常画质、AI/副官持续指挥与持续战斗，稳定 30FPS，frame p95 <=45ms，同时模拟时间、命令响应和移动/战斗/生产保持正确。不要只做一个微基准变快就交差，也不要保证未经测量的倍数。

## 先读且纠正旧假设

先读仓库 AGENTS.md、闭环验证/RSI 工作法、agent/manifest.json、性能 skill 及 measurement/cpu-candidates；再读：

- `agent/reports/closed-loop/2026-10-07-rvo-scalability-design-review.md`（本次复核与推荐架构）。
- `agent/reports/closed-loop/2026-10-07-rvo-push-bottleneck-handoff.md`（历史测量资料，不是所有归因都成立）。
- `agent/plans/2026-10-07-rvo-scalability-design.md`。

这些路径相对于 `G:/AIRTS/AI_RTS`。先看 git status、目标文件 mtime/hash，保留所有其他 agent/用户改动；本轮交接没有改产品源码。

重要版本警告：复核开始 Movement 的 hash 是 `B4E4F4A...`，收尾时已变成 `9690F7FC6EBD069D893AA9771CDE9B910219C61869C8BED2E9C35D9D8422DBC1`。新版本加入 `_pcache_*` 并撤掉 R16 保守前置剔除，外部修改未被本轮覆盖。第一件事确认当前版本和修改归属，重测当前基线，旧 R16 性能数字不是当前新版证据。已有缓存须增加同帧新增、重挂、空列表失效用例；不能只看引用未删除。不要未经授权回滚外部改动，也不要再次重复声称“句柄缓存必然提升”。

必须记住：

1. 当前 Movement 没有注册进静态障碍组；障碍主要由 MovementObstacle 注册。不能把 mover=N 自动当静态障碍 S=N。运行时统计每域真实组成员及类别后再判断。
2. `_AiArmyStressProbe` 的 20x20 周期出生公式使 1000 请求只对应 400 输入位置。实际对齐/分散后的重叠量未测。先修正常负载夹具，异常堆叠保留单列，不删除它来掩盖鲁棒性问题。
3. `_ScriptAggProfile` 的 8.3ms 不包含晚到的 GDScript velocity 回调，不能排除脚本。断开信号也不是关闭引擎 RVO，且停止位置落地、改变后续状态。
4. 回调包含旋转、推出、位置提交和事件，不是只包含 hull。135.8us 是历史手动回调微基准，不能直接当真实 1000 单位精确成本。
5. 正常 60Hz 模拟/30FPS 显示平均两步。max_steps=8 是上限，不是每帧实测；用真实物理计数差与墙钟时间计数。不要减 tick 或 max_steps 让模拟变慢来达 FPS。
6. 先保留 RVO。Godot 已有 KD-tree 和可选多线程，不要再添加一个对全军逐对的分离力或手写新 ORCA。

## 阶段 P0：纠正测量，明确最大热点

为本实施任务建立独立计划、run/checklist/champion。先改验证工具，不同时改产品。正常压力夹具应合法、不重复、不过地图边界、不先让所有单位相互穿透；用实际尺寸核验出生间距。异常重叠、狭路对冲、建筑出口拥堵另作 adversarial。

分别统计静止、开阔持续移动、近建筑、窄口/拥挤、持续交火/采矿/生产、真实副官命令回放。确认受命单位真的在执行，记录总 mover、active mover、actual displacement、到达、卡住、开火/伤害、产出、command_id。AI_EASY 自行运行与副官指挥不是同一验收场景；副官测试可用固定本地轨迹经真实入口，不额外付费调用模型。

仪表按原调用处采集低开销聚合，不逐单位打印：组成员数、全扫数、候选数 K、hull/骨骼采样数、shape 搜索、精确推出、旋转/变换写回、回调、RVO、路径重置/求路/重烘、物理服务器与脱困全扫。inclusive/exclusive 不重复相加，主循环 monitor 不冒充即时阶段值。保留真实物理步/帧、模拟秒/墙钟秒和所有长帧。

原 rvo A-B-A 说明回调/后续管道是嫌疑，不足以决定删除哪一层。使用受控记录/重放与影子纯数据求解拆出成本；被禁用模块的成绩只作诊断，不用于正式性能达标。

## 阶段 P1：先让绝大多数单位不碰昂贵几何

优先目标不是缓存一个 find_children，而是改变工作结构：

`全组遍历 + 先采当前 hull` → `保守范围筛选 + K 个可能接触障碍才精算`。

保留旧 `_push_out_of_static_obstacles` 作独立 oracle，不直接复制优化版自比较。静态/资源障碍的形状描述通过生命周期/dirty 维护，保存原处理顺序、域与 geometry generation。大建筑按实际 shape 的世界 AABB 覆盖多个格，或成熟 AABB tree；不能仅按中心或索敌业务的固定半径 allowance。

每单位 cheap-query 的上界必须覆盖现有 support、偏心、旋转、缩放、形状组合、个人空间、临时窄口半径等。保守 envelope 仅筛选，不能拿它改碰撞盒/导航 carve 或扩大空气墙。未知形状/无法保证时立刻回退旧路径并计数。

候选可能为空时，必须能在不采骨骼/模型的情况下证明旧算法也不推动。候选非空再在原时序采真实 pose 与 exact support。连续推出改变点时重查后续候选，并保持旧组顺序和已访问游标，不随意重排、不遗漏接力推出。不要用零速度一刀切跳过：静止单位也可能被新建筑/其它来源位移嵌入。

缓存要覆盖 same-tick queue_free/free、离树、disabled、shape resource changed、父链 transform/旋转、施工完成、同帧换形状和换局。`is_instance_valid` 不代表未 queued-for-deletion；只改这一点也不代表缓存一定快。资源动态或无法稳定跟踪时用 uncached 回退。

用正常/异常夹具跑逐调用差分和现有严格等价门禁，再对照整帧 A/B。既测候选查询收益，也测注册/失效/维护开销与 fallback 比例。不要把军团密度当作建筑索引必然无效的证据。

## 阶段 P2：只把已测热点迁成纯数据 C#

P1 后若 GDScript 数学、动态字典、骨骼读取或重复 transform inverse 仍占大头，利用既有 C# 工程实现局部纯数据 service。首版同步单线程原算法，先证明参数和返回值一致，再按 profile 分块；不能把 N 个任务扔线程池。

主线程读取真实 pose/生命周期/稳定 shape 描述，工人只操作本轮不可变数组和自己的输出，主线程按原物理 tick/回调顺序提交。修改采集/提交阶段会改变旧逻辑时序时，显式说明并回退到保持时序的实现，不拿快照同名掩盖行为改变。

全部结果带 match/unit generation、tick、geometry revision。取消/死亡/换局丢弃结果，有界等待与内存复用，禁止用滞后碰撞结果异步补交。总成本包含桥接、采集、worker 等待、提交与 GC。节点、骨骼、SceneTree 和共享资源不在工作线程读写；不改其它单位半径或订单。

每单位 stable chassis/本体接触代理是后续资产健康方向，但当前 pose-dependent hull 不能未经批准替换；骨骼原点不等于真实蒙皮表面。先修权威碰撞代理覆盖和误差合同，按车型/动画截图与数据验收，再另列行为重标定候选。不要改模型尺寸来省计算。

## 阶段 P3：重新 profile 后决定群体导航

不因报告标题含 RVO 就继续只改 RVO。核对剩余开销：

- 已确认源码有 `_nearby_unit_stats` 脱困时全扫 units；拥堵时测其调用量，保语义改为空间候选。现有 TargetAcquisitionGrid 可以复用机制，但它的帧时序、范围和支持类别需要核验，不直接接入一份旧快照。
- 路径/到达：保留订单完成/失败语义，避免没必要的 target 重置、重复 UI 和权威求路；到达后无任务的路径更新按实际版本验证，不让方法调用顺序产生假到达。
- 无变化 transform 提交、Area 接触/物理同步、动画更新和日志是否成为热点；只有严格输出/事件等价才省掉无效工作。
- 若全局 path query/命令尖峰成为大头，先同域/同净空类/同 map revision 的共享 corridor；高重复同目标军团再考虑分块 Flow Field，保留个体最后一段与局部碰撞。不要把现有 FLOW_BIT_* 让行实验当成目标共享 Flow Field，也不要默认开启量纲/软穿行开关。
- 槽位、编组终点、窄口通行和死锁协调能改善行为，但与性能等价优化分开；不擅自改速度/碰撞/攻击/视野。需要变更产品规则先报影响并取得批准。

算法资料见复核报告链接。保留 Godot 已有成熟算法，只有本机版本 native RVO 求解确为瓶颈且现有优化无效，才考虑经过商业许可/版本审查的 RVO2 原生服务，不自行手写 core，不同时重写导航与碰撞。

## 验收和防糊弄

严格等价阶段保留现有 MovementPushEquivalence，不改 oracle/阈值“修绿”。补索引漏候选、偏心 OBB、same-tick 删除/换 shape、连续推出、已在内部、静止被嵌入、软/窄口还原、到达与卡住的正反用例。行为重标定阶段单独批准，不混入性能补丁。

编译/解析后按实际依赖串行跑 movement-push-equivalence、navigation-stability、movement-recovery、local-avoidance，再执行全量回归与独立 verifier。rc=0 + expected marker + forbidden 为空 + 新产物 + 无超时/崩溃 + cleanup_ok 才算通过；错误日志不是“噪声”。

阶梯 100→200→400→700→1000，严重超时/崩溃早停；固定 seed、负载、相机、模型、阴影、迷雾、特效和模拟频率。每档预热后 A-B-A/至少三次，记录墙钟 p50/p95/p99/最长帧、hitch、实际物理 ticks/s、模拟时间比例、命令响应、伤害/产出/到达。解锁 cap 看容量后恢复原 VSync+30FPS 实测，不改玩家设置落盘。

全图视野与正常迷雾都测；近距离截图/视频检查模型、转向、动画、贴边、窄口、采矿和战斗，不用隐藏视觉的成绩达标。截图放采样窗口外，打开检查。长时运行和退局重开检查内存/索引清空/僵尸房；只清理本轮拥有进程，不能按名字盲杀。

目标是 1000 单位达到原合同，不能因 100 单位变快就宣布完成。每个候选写 direction/exploration/patch/verification，与 champion 比较。连续三轮无晋级时停止堆参数，换已被 profile 支持的高层方向；未达标则 needs-review，并准确交接剩余热点。

最终交付报告必须给出当前 champion 的 hash/版本、同夹具 before/after、计数变化、测试 rc/forbidden/cleanup、截图和独立实测、未达标项。只测到多少就说多少，不把理论复杂度/论文数字当本游戏的新 FPS。
