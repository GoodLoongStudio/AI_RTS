# AI 副官 2B 战略层只读审计

本提示词用于重做证据审计，不授予修改产品、切换模型、启动/结束用户对局或发送消息的权限。

先读取 `G:/AIRTS/AI_RTS/AGENTS.md`、工作区边界、闭环工作法、RSI 和 manifest。检查 Git 根与目标，保留共享工作区未提交改动。配置只输出白名单模型、超时、后端字段，不输出凭证。

1. 从实际启动日志确认 strategy 模型、模式和超时，不只依赖默认值或源码注释。
2. 从每局原始 `model.jsonl` 统计战略调用、成功、超时、非法输出、延迟；从原始 `decisions.jsonl` 统计计划采纳/保持。核对 match_id，避免把提示词关键词当真实产量。
3. 若计划采纳为零，说明本局无法证明“错误战略驱动乱跑”；继续查规则/campaign/Laya 与移动任务链的来源，不从 HUD 文案推断模型已成功。
4. 读取 `graph/model_context.py`、`graph/pydantic_agents.py`、`graph/contracts.py`、`graph/nodes.py`。分别列输入、输出、程序已计算而让模型重复填写的机械字段。
5. 判断要区分：服务/延迟故障、结构化合同失败、合法但不合理的战略、计划到执行的偏差。没有原始输入/响应和服务端指标时明确写未知，不把 timeout 等同于容量不足。
6. 工程建议优先复用 campaign 已有决策候选：程序提供少量合法战略方案，2B 只选择候选或保持；元数据、预算、单位分配、完成条件与安全执行仍由现有程序维护。不新建第二套指挥中心。

若用户后续授权容量实验，先用冻结的相同快照离线比较，再进入真实 Match：

| 条件 | 要回答的问题 |
|---|---|
| 规则策略 + 同一 Laya 执行层 | 没有生成模型时，现有指挥链能否稳定推进？ |
| 2B + 当前完整 StrategicPlan 接口 | 当前接口的成功率、延迟与战略错误是什么？ |
| 2B + 小候选选择接口 | 收缩职责能否改善成功率与战略质量？ |
| 较强模型 + 同一候选接口 | 同一信息与动作空间下，容量提升还能带来多少收益？ |
| 较强模型 + 当前完整接口（必要时） | 完整规划接口的复杂度与模型能力能否分开归因？ |

比较同时覆盖正确的经济点火、防守响应、侦察配额、无敌情时的主力行为、目标稳定性、玩家接管、路径失败和模型故障。冻结快照不能证明实际执行效果；真实对局结果不能代替接口成功率统计。输出长度、上下文大小和模型算力预算单独记录，不承诺未经测量的秒数。

输出保存到本机诊断报告，标出事实、推断、建议与未验证项。没有新真实 Match、截图/录像、相关回归与独立复核，不宣称副官已修好。
