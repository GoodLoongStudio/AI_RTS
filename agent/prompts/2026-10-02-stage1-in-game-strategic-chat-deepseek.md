## 0. 本阶段唯一目标

本阶段只实现：

> 玩家进入正常游戏，在游戏内打开 AI 副官面板，输入一条战略问题，收到真实战略层模型回复，并可以继续多轮战略对话。

本阶段完成后，玩家应该能够看到真实 UI、真实请求、真实回复、真实状态、真实错误和真实回退。

本阶段**不实现**战略计划草案、任务卡、计划确认、单位命令、任务租约、Laya 决策、Laya 实控、事件重规划或任何新的战术能力。

## 2. 用户可见验收流程

必须让下面的流程在真实游戏中成立：

1. 按项目正常方式启动游戏并进入一个可操作的 Match。
2. 找到现有 AI 副官入口，打开战略聊天面板。
3. 输入：`这局的战略重点应该是什么？`
4. 点击发送，看到明确的“发送中/等待战略层”状态。
5. 收到战略层真实回复，并显示消息来源、当前状态和必要的耗时/失败信息。
6. 再发送至少两条追问，确认同一会话保留上下文。
7. 在战斗运行中和暂停状态各至少验证一次；暂停时聊天不能推进游戏时间。
8. 验证模型超时、模型不可用、空输出或非法输出时，UI 明确显示错误/降级，游戏继续运行。
9. 证明聊天没有产生任何单位命令、资源扣除、任务变更、租约变化或 Laya 选择。

如果当前项目入口无法完成某一步，先记录真实阻塞原因，修复最小必要链路后再继续；不要用独立假 UI、预置回复或单独 Python 脚本冒充产品闭环。

## 3. 现有链路的复用边界

优先复用：

- `AdjutantButton.gd` 作为对局内副官 UI、runner 启停和状态数据源；
- `AdjutantRunnerLauncher.gd` 作为 runner 配置、路径、pidfile 和日志目录的唯一发现入口；
- `AdjutantModelService.gd` 作为本地 Ollama/模型服务启动、预热和状态文案的唯一口径；
- 现有战略角色/模型配置和 `chat_client.py` 的 Chat Completions 适配；
- 现有结构化日志和测试辅助工具。

先判断现有面板是否已经有可复用的消息/状态区域，再决定是扩展还是增加子面板。不得复制第二份 runner 配置探测、模型端点、模型启动逻辑或日志目录逻辑。

UI 到战略模型的通信必须经过明确的战略聊天适配层；不得让 UI 直接调用战术模型、Laya、`adjutant_intent`、`adjutant_command` 或任何单位执行入口。若现有 runner 没有聊天请求通道，增加最小的只读/对话通道，要求它只返回文本结果，不能携带命令或计划。

建议的语义契约如下；若现有协议已有等价定义，复用现有命名，不要重复造协议：

```json
{
  "request_id": "chat-...",
  "conversation_id": "...",
  "match_id": "...",
  "player_id": "...",
  "paused": true,
  "message": "这局的战略重点应该是什么？",
  "history_tail": []
}
```

返回至少能区分：

```json
{
  "ok": true,
  "request_id": "chat-...",
  "conversation_id": "...",
  "assistant_text": "……",
  "model": "……",
  "elapsed_ms": 1234
}
```

失败返回必须有稳定的 `error_code` 和面向玩家的中文说明。响应中禁止出现可执行命令、计划提交标记、单位 ID 批次、Laya 选择或“已执行”字样。

## 4. 战略聊天的模型职责

为本阶段单独定义清晰的战略聊天 system prompt：

- 角色是“战略讨论副官”，负责分析目标、风险、资源取舍和可能的战略方向。
- 可以提出建议和澄清问题，但不得声称已经下达命令、控制单位、修改任务或执行计划。
- 当前没有计划结构化输出，不要强迫模型返回 JSON 计划。
- 回复应面向玩家，简洁但有依据；优先使用当前对局提供的事实，不把未知信息说成事实。
- 如果状态不完整，明确说明缺少什么；不要编造隐藏敌情、资源、路径或单位能力。

战略聊天上下文至少带上：`match_id`、玩家身份、暂停/运行状态、任务目标或模式、可用的安全战局摘要（若已有稳定只读来源）。上下文不应包含完整大 JSON 以免阻塞或超出模型窗口；先使用紧凑摘要。没有可靠状态时宁可标记“当前状态不可用”，不要伪造。

## 5. UI 要求

必须使用现有游戏内入口和项目 UI 风格，不能做脱离游戏的网页或临时窗口。

至少包含：

- 消息历史：区分玩家和副官；长消息可滚动；
- 输入框和发送按钮；发送中禁用重复提交；
- 当前会话/对局标识；
- 状态：未连接、连接中、等待战略层、已回复、超时、错误、已降级；
- 重试或重新发送；
- 暂停时仍能聊天；
- 明确显示“本阶段只讨论战略，不执行战斗命令”。

优先适配现有副官左上角专属区域，不遮挡帧率、侧栏、地图和主要战斗信息。若当前空间不足，做可折叠/可滚动面板，而不是硬编码一个会遮挡主界面的固定大窗口。

不要在本阶段加入任务卡、确认计划按钮、执行按钮、Laya 状态卡或新的单位控制按钮。

## 6. 生命周期和并发规则

- 一次会话必须有稳定 `conversation_id`；切换 Match 时不能串用上局历史。
- 同一会话最多一个在途聊天请求；重复点击不能产生重复模型调用。
- 超时后允许重试，但迟到回复不能覆盖新一轮回复。
- 关闭面板、暂停/恢复、返回主菜单、结束 Match 时，所有在途请求都必须安全失效或被标记为陈旧。
- 战斗模拟线程不能被 UI 等待模型同步阻塞；模型慢时游戏继续运行。
- 不在主循环高频轮询战略聊天；聊天只由玩家操作触发。
