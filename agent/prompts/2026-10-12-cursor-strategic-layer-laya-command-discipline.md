## 目标架构：慢而稳的战略层，持续执行的 Laya 层

按三个可验收阶段交付：①全局态势能解释当前大目标；②稳定目标交给Laya后编组持续推进；③遇敌、路径失败、玩家接管与模型故障仍正确，且性能同开通过。阶段内可以多轮迭代，不需要每个小补丁都让用户选择方案。原建筑/采矿收尾和性能P0/P1/P2继续保留，把本需求纳入副官行为门禁，避免另开互相覆盖的工作线。

### A. 战略层只负责全局计划

战略层每次必须基于同一观察周期、可追溯snapshot/tick的全局态势生成计划；若各视图无法原子采集，明确记录时间差与失效条件，不伪装成同一时刻。全局数据先由程序解析成有界摘要，小队和区域可以聚合；摘要至少包括：

- 地图边界、可通行/危险区域和关键通道；
- 我方指挥部、分基地、生产建筑、矿场、工人、战斗单位、侦察单位及其状态；
- 资源点位置、剩余量、已覆盖/未覆盖矿点和扩张价值；
- 已确认敌人、最后看见位置、时间、单位/建筑类型和情报置信度；未知、未发现、已失去视野必须区分；
- 我方兵力按编组、角色、数量、血量、位置、当前任务和路线进度；
- 当前经济、生产队列、人口/单位上限、防御缺口和基地威胁；
- 现有任务完成度、阻塞原因、权威回执和最近重大事件。

全局态势遵守玩家可见信息：地图与静态资源按现有权限提供；未侦察的敌军不能从调试全知视图泄露给副官。敌情记忆带最后确认时间，不能把过期坐标当敌人当前位置。缺数据明确为unknown，不能默认“没有敌人/没有资源”。

战略输出是有限数量的长期任务，例如经济扩张、基地防守、侦察扇区、主力集结、推进/撤退、重点目标打击。初始可同时保留2–4个互不争抢单位的主要目标，数量按实际场景验证，不把“必须包含若干类任务”变成派全军探路。每个任务必须有稳定 `task_id`、负责编组、目标区域/目标实体、优先级、开始条件、完成条件、失败/重规划条件和允许动作。没有足够情报时输出“侦察/集结/防守”等有边界的任务，不凭空编造敌人位置。例：无人机持续侦察北侧未确认区域，主力守矿场并集结，经济线扩远矿；主力不追着无人机每个路点换目标。

### B. 战略计划必须有提交、保持和失效机制

- 保留当前有效计划，不能每次观察都生成新目标。
- 首次启动、重要任务完成、目标消失、基地/矿场/关键单位损失、确认重大敌情、持续路径不可达、资源枯竭、玩家改变战略意图或普通复核周期到达时，触发一次复核。普通单位到达、单条可恢复路径失败与局部接管优先局部处理，不全部升级成重新规划整盘；复核不强制生成新计划。
- 将“程序检查”“模型复核”“计划保持”分开。复用已有快照/10Hz scanner和事件通道，**程序约每1秒检查**（1–2秒可配置），只读取缓存和增量事件、整理有界的区域/编组变化，不每帧重新遍历所有实体或调用模型。
- **战略模型先以10秒普通复核为目标，5–10秒作为验证候选**，按本机单次推理耗时、Laya响应与GPU竞争实测决定。第一次对照可用30秒现状→15秒解耦候选→10秒；10秒稳定且有需求再试5秒，阶段内自动迭代，不要求用户逐项确认。没有实测通过前，不宣称5–10秒已安全或一定更好。
- 周期以对局有效模拟秒定义，并记录实际physics tick rate和墙钟时间；暂停时不自动反复推理，玩家战前/暂停讨论可以显式触发。60Hz与20Hz地图按各自真实频率换算，不能统一写死300/600 tick或降低物理频率来达到目标。工作请求超时、退避用单调墙钟；游戏运行很慢时不按墙钟不断补发“错过”的请求。
- 重大事件在下一次程序检查时登记一个**去抖/合并后的提前复核请求**，不用等10秒周期。基地受袭、生存撤退、路径避险和玩家命令由现有执行/事件安全链及时处理，不等战略模型。统计事件发现→安全动作、事件发现→模型发起、模型发起→结果提交三段延迟。
- 检查命中普通复核周期也可以选择“无重要变化，维持任务”。保持时间独立于复核间隔，任务仍可持续几十秒或数分钟；禁止为了兑现10秒周期就每10秒给全军换目标。
- 加入最小保持时间和目标切换滞回：新方案必须明显优于当前方案，或者当前方案满足失效条件，才允许替换。保持时间是普通切换约束，基地受袭、目标毁灭、玩家命令及生存危险可立即打断相关任务。
- 明确支持“维持现计划/未变更”的复核结果；复核可以更新last_review和情报，不下发新命令。`plan_version` 只在真正提交新计划时递增；同一计划的观察、进度和局部路点更新不得递增版本。同步检查模型提示、schema、采纳器、过期条件与intent仲裁，不能只改版本字符串让旧命令冒充新命令。
- 新计划只替换发生变化的任务，未改变的经济/防守任务保持身份、编组和在途执行；用显式映射验证版本衔接，不能换全局版本就让所有正常任务作废。
- 玩家局部接管只冻结相关单位/任务，不清空整盘战略计划。
- 战略模型超时、格式错误或信息不足时，继续执行仍有效的已验证任务；失效/危险任务局部暂停、撤退或请求侦察，不能无限沿旧目标送兵。由规则层提供有限安全降级，不生成随机移动。
- 战略推理期间Laya和规则安全执行仍能推进；至少单个在途战略请求，合并重复触发，有界队列与超时退避。只采纳身份、请求代际、计划基准和重大事件仍有效的结果，迟到结果不得恢复过期目标；timeout不代表底层推理已取消，不能叠加多个GPU请求。
- 模型p95耗时接近或超过目标周期时采用背压与自适应间隔，不并发补跑；最多一个战略在途请求和一个最新待处理摘要，超时后底层工作未结束时槽位仍占用。紧急事件合并到最新摘要，返回结果若已不适用则拒绝，在原请求结束后按新态势处理。共享模型后端/GPU时协调战略与Laya推理预算，不以两个线程池就视为资源隔离。
- 只读快照交给工作线程，工作线程不得修改LangGraph状态、coordinator或Godot对象；协调线程收结果、检查版本/控制代际/目标有效性，再唯一写入计划。退局/重开后旧局future不能写进新局；checkpoint保存可恢复的请求信息，不序列化线程/future。

### C. Laya/战术层只执行任务

Laya每次决策在宿主侧必须绑定当前 `plan_version`、`task_id`、编组、目标和控制代际；模型文本给出任务目的、阶段、已在执行的动作、完成条件、可选合法动作与局部事实。沿用现有四列协议和程序生成引用，元数据由宿主校验，不能要求Laya凭空生成新的任务/版本字段。候选动作先受战略任务范围约束；涉及战略分支的选择可以作为建议或明确授权的子分支，不能在执行层悄悄换整局目标。它负责：

- 把长期任务拆成少量可执行路点、编队、集结、攻击/防守/侦察动作；
- 维持编组，等待掉队单位重新集合，避免单兵被逐个派往不同位置；
- 在目标区域内选择安全路点、避障、追击、撤退和攻击顺序；
- 根据真实回执推进任务，不用“命令已发送”冒充“单位已到达”；
- 只有遇到紧急生存/路径安全问题时临时覆盖局部动作，并记录覆盖原因，不能擅自改变战略目标。

检查真实渲染文本和token截断：当前战略任务不能被少样本示例、发展菜单或局部单位表挤掉。使用有界的任务摘要和引用，保证模型实际看到任务；仅在Python对象里新增字段不算接通。

Laya 不得在每个 tick 重新选择战略目标、把所有单位当成独立游标、用随机探索填充空闲状态，或在无敌情时让全军无目的移动。没有新任务时，单位应保持防守、集结、采矿、生产或有限侦察，不得持续刷新直线移动命令。

### D. 解决“无头苍蝇式乱跑”

按小队分配单位：主力、基地防守、工人/运输、侦察/无人机、机动支援至少分开。一个小队在当前任务有效期间只有一个主目标和一条当前路线；局部路点可以更新，但不能频繁改变任务目标。

复用已有守卫并补齐以下约束，记录实际命中和未命中原因：

- 相同 `task_id + 编组 + 目标` 的重复命令合并；
- 目标位置只发生小幅变化时保留原目标，不能把每次观测噪声当成新命令；
- 单位正在移动且路线仍有效时，不重复下发同方向命令；
- 到达、失败、目标死亡、路径失效才推进或替换当前路段；
- 没有确认敌情时，侦察优先用指定少量无人机，按能力和生产条件有限补充无人机；不可用时才用有限地面侦察，不能全军当侦察兵。侦察按扇区维护终点、覆盖与重访间隔，战术路点短不代表战略目标也短；其他部队集结或执行经济/防守任务；
- 队伍过大时先集结再推进，避免队伍被拆成许多短命单元；
- 对每个单位/小队统计命令率、短时间重复目标计数和反复改道告警。普通重复动作合并并使用有界预算；紧急撤退、玩家接管和权威回执不能被统一节流挡住，也不能把“命令更少但单位发呆”当收益。

这些约束必须在权威命令入口和 Laya 执行层生效，不能只在 HUD 隐藏命令，也不能靠降低模型频率掩盖重复下发。

## 观察视图和性能要求

- 战略层比执行层慢，但不能固定几十秒才检查受袭。程序检查、战略模型复核与紧急响应分开；每次战略输入仍必须是完整、时间一致的全局态势，必要时采用“全局有界摘要 + 紧急事件增量”，不能为了省性能删掉敌情、资源和基地关系。
- Laya 高频执行使用已提交计划和增量回执，禁止每个单位都触发一次战略模型调用。
- 持续执行依靠Godot既有动作、行为树和路段进度，不要求Laya每physics帧重新推理。只有任务/局部态势确有变化时请求模型修改任务；Laya不可用的降级路径遵守相同战略目标。
- 统计战略模型调用频率、单次耗时、输入快照大小、计划变更率、Laya 命令率、重复命令率、长帧和模拟速度。战略层慢下来不能造成主线程同步阻塞；模型超时不能卡住游戏。
- CPU/GPU 优化遵守现有性能规则：不关闭副官、不减少单位、不降低 physics tick/模拟速度、不用降低画质换性能，不把 Godot SceneTree/导航/渲染对象随意放到工作线程。

## 必须新增或完善的证据

至少覆盖以下真实 Match 场景，并保存到新的 `agent/runs/<run-id>/`：

1. 开局无敌情：经济、生产、防守和指定侦察按计划推进，非侦察部队不会全图乱跑。
2. 发现远处敌人：战略层提交一次带敌情和兵力判断的计划，Laya 让编组集结/推进；计划保持期间不频繁换目标。
3. 敌情消失或路径失败：只触发相关任务重规划，其余经济、基地防守和采矿任务继续。
4. 敌人突然攻击基地：紧急防守能快速覆盖局部行动，但不会让全军目标在每个 tick 重置。
5. 玩家接管一支部队后：该编组停止被 Laya 发送命令，其他任务和全局计划保持有效。
6. 至少一张不同地图/不同出生点，确认战略观察不是写死坐标。

```text
unique_task_ids, target_changes_per_squad, duplicate_command_rate,
idle_or_unassigned_units, wander_distance, emergency_overrides,
arrived/failed receipts, simulation_seconds/wall_seconds,
long_frame_p95/p99/max, cleanup_ok
```

为wandering/wander_distance给出可复现定义：无所属任务、无安全原因的位移/目的地改变，或短窗口内围绕原点反复折返。合法巡逻、侦察覆盖、绕障、交矿与战斗撤退不算乱跑。相同种子/事件脚本比较目标变化与重复率，同时确认推进、采矿、战斗和应急响应不退化。补验等价复核保持版本、迟到战略结果、故障降级、checkpoint恢复、LangGraph与fallback状态往返，新增字段必须完整声明和持久化。

用 5 FPS 录像实际回看开局、集结、侦察、发现敌人、推进、撤退和基地受袭时段；录像采集率不能代替状态数据，也不能修改物理频率。至少由独立探针检查“计划稳定、编组不散、重复命令被合并、无敌情时无全军乱跑”。

必须有一个受控慢战略推理（例如8秒/超时）、事件风暴与旧局迟到结果的用例：思考期间采矿/移动/生产仍有真实进度，Laya决策、事件与权威回执仍在推进；重复事件不会堆多个战略请求，旧结果不会接管新任务。实际GPU模型同开至少做一局正常生产/压力负载实测，模拟故障通过不能替代这条证据。

## 实施和验收闸门

1. 先用日志/状态/录像复现“战略失焦”和“重复乱跑”，再编辑；不能凭现象直接重写战略系统。
2. 每次只改一个高层假设：观察完整性、计划保持/重规划、编组分配、Laya 执行去重四者分开验证。
3. 修改后逐文件解析/编译；新开真实 Match，重放至少一条旧的采矿/建造/生产/移动/退局链。
4. 失败候选立即拒绝，从当前 champion 重新开始；不通过放宽测试、隐藏移动或过滤日志“修绿”。
5. 更新 AI 副官闭环报告、计划、checklist 和可复现提示词，明确 candidate/champion、数据、录像实际回看片段和未验证范围。

完成后给出：实际根因、改动文件、战略观察字段、单次推理耗时与实际发起间隔、计划提交/保持规则、Laya执行规则、30秒基线与15/10秒（按需5秒）候选对照数据、命令/长帧变化、测试rc、录像路径和剩余风险。没有证明完整地图态势和计划稳定之前，不要宣称战略层已经修好。

## 改动范围控制

本轮按**中等规模、现有架构内的改造**安排；不能只改间隔参数就结束，也不需要从头重写副官。优先改现有Python副官链路：runtime/nodes的战略submit/poll调度、状态/GraphState通道/checkpoint的请求及复核记录、runner实际配置、计划采纳的保持/变更判断，以及Laya任务摘要/合法候选映射。现有coordinator、schema、squads、movement保持与去重逻辑尽量复用。

不新增第二套指挥中心、地图数据库或任务协议，不升级模型/引擎，不重写单位移动、导航、渲染。只有现场证明权威观测漏了必须字段才扩展最小Godot导出；只有证据证明原去重/任务继承漏路径才修对应入口。调度、任务稳定与观察改造每一项独立提交候选并复验，保留原建筑/分基地/采矿成果。

不要通过每秒调用模型、每单位单独调用、清空全军任务、降低超时后随机移动、关闭副官或减少单位来实现“更快”。一次复核更频繁的收益必须表现为更及时的有效决策，同时部队少折返、任务进度持续，应急和性能不退化。
