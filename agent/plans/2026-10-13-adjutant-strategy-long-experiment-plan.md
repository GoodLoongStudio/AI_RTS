# AI 副官战略层长期对照实验计划

日期：2026-10-13（北京时间）。状态：`ready-to-run`，方案尚未运行。目标执行者：由用户启动的另一个 AI。本文是方案、预算和验收口径的唯一来源。

执行入口：[长任务提示词](../prompts/2026-10-13-adjutant-strategy-long-task.md)。记录入口：[实验跟踪表](2026-10-13-adjutant-strategy-experiment-tracker.md)。背景：[2B 诊断](../reports/closed-loop/2026-10-13-adjutant-2b-capacity-diagnosis.md)。

## 1. 要解决什么

副官需要正确发展经济、有限侦察、合理防守，并让主力按稳定目标持续作战。长期任务的成果应是一套在本机真实对局中可用、可回退的组合，以及其他候选为何不合适的证据。生成合法 JSON 和成功调用 Laya 都不等于正确指挥。

只验证两个主要判断：

| 判断 | 最少需要的证据 | 可能的反证 |
|---|---|---|
| C1：收缩战略模型职责能提高可用计划率和指挥稳定性 | 同一冻结态势、同一模型对比完整规划/模板/候选选择；再在真实 Match 重放 | 精简接口仍不稳定，或固定战略也执行乱跑 |
| C2：小模型只在确有歧义时参与，比每次自由规划更适合本机 | C 与 D 使用相同信息、相同候选，比较行为、模型调用数和延迟 | 规则评分自身偏置导致漏掉好方案，或仲裁没有实际收益 |

排除三个误判：把服务未就绪当模型能力差；把合法选择当战略质量；把关掉全部副官后变快当成功。

## 2. 当前工程与已有机制

默认开发根为 `G:/AIRTS/AI_RTS`。先读取 AGENTS、边界、闭环、RSI、temporal-playtest、manifest 和 MCP 入口。性能比较另读 performance skill 与 measurement。用主工程检查器检查每个目标。

2026-10-13 本轮读盘时，`campaign.py` 已有 `RulesSafeStrategy/rules_safe_plan`，runner 已支持 `--strategy-mode rules`。它把程序主线投影为计划，第一次采纳、以后保持；不能预设它的空单位任务已经能有效指挥 Laya，也不能因 plan_hold 出现就认定防守/生产通过。执行前重新读盘核验，其他会话正在修改这些文件。

已有凌晨对局记录战略 5/5 超时、采纳 0；这是历史线索。新基线必须建立在执行时实际源码/DLL/模型配置上，不能从旧数字开始宣称改善。

复用 `campaign.context_view` 的主线、前沿、`available_routes`、经济态势和已存在仲裁、资源、任务、movement/squads、玩家优先权合同。合法候选不只代表 available_routes：涉及经济/防守/作战的选项先核验已有表示覆盖，缺少的表示在现有层最小扩展。候选不足记为候选生成缺陷，不能误诊为模型选错。

## 3. 五套组合与对照

所有方案使用同一个 Laya/规则执行层、同一观测权限、同一资源/前置条件、同一默认强度、同一移动和玩家接管合同。对照中的“规则战略”仅替换战略决策来源，副官仍开启。一次只运行一套组合。

| ID | 组合 | 模型承担的工作 | 必须保持的程序职责 | 次序 |
|---|---|---|---|---|
| K0 | 当前 2B 完整规划 + Laya | 现有 StrategicPlan | 当前全部约束与兜底 | 新鲜对照；严重超时则有限取样 |
| A | 规则/campaign 战略 + Laya | 无战略推理请求 | 合法计划、预算、任务连续性与紧急响应 | 首先验证执行地板 |
| B | 2B 精简战略模板 + Laya | 选模板及一个有限枚举重点 | 补元数据、实例化任务、预算与单位分配 | 低成本候选 |
| C | 程序合法候选 + 2B 选择 + Laya | 选一个候选或保持 | 同上，并保证候选可执行 | 默认重点 |
| D | 程序评分 + 歧义时 2B 仲裁 + Laya | 只在候选接近时做 C 的选择 | 程序先筛选和排序，明确局面直接推进 | 与 C 对照 |
| E | 两步窄任务 2B + Laya | 先辨主瓶颈，必要时再选局部方案 | 同一快照/预算/总期限，合成一次计划 | 有证据才试 |
| T | 已可用的较强模型诊断参照 | 同 C 的候选选择，必要时另测完整接口 | 同一信息与候选，无额外全图/未来信息 | 可选，仅离线；不决定本机默认模型 |

### A：有用的执行地板

使用已有 `--strategy-mode rules`，`AIRTS_S1_BACKEND=laya`，保持 `--model on`。`--model off` 同时去掉战术模型，不能替代 A。先核验 runner 的实际配置与规则计划来源，计划维持时既有任务继续推进。

若 A 的经济、侦察、生产或主力执行本身不成立，先定位这一条失败链；先修一组最小相关改动并过仓库门禁，再评估 B/C/D。不要让各候选各自修一套执行层。A 的收益证明程序/执行问题可修，不证明 2B 战略已修好。

### B：精简模板

模板初始只有 economy/recon/defend/prepare_attack/attack/expand，具体枚举映射到现有任务。可输出例如 `{"template":"defend","focus":"base"}`；focus 必须来自当次给定枚举。模板可用性由程序判断，不能选择未满足前置条件的 attack/expand。

让程序生成 plan_id、版本、match/player/rules、有效期、单位、预算、完成和中止条件。复用现有 StrategicPlan 作为内部合同，模型接口缩小，不更换权威命令协议。输入聚合经济、可用兵力、已知敌情及更新时间、当前目标和前置条件；unknown 仍为 unknown。旧计划合法时模板相同应保持，不重新分配整军。

聚合需要保留全局决策所需事实：各区域探索/资源与扩张机会、我方兵力分布和职责、已知威胁、生产/科技前置、经济瓶颈与路线阻塞；每份摘要带观测范围、时间和截断/缺失标记。减少逐单位细节与机械字段，不把模型变成只看基地的一小段状态。摘要来源复用现有权威缓存，若字段欠缺先证明需要，再做有界导出；禁止额外按单位重复全场扫描。

B 回答“去掉机械字段是否已经够用”，并非无限制的自然语言战略生成。

### C：候选选择（优先）

程序每次提供最多 4 个已验证可执行的完整方案，另含 `KEEP`。每项含候选 ID、目标、必要代价/兵力、影响和风险的短摘要；ID 只绑定此请求快照。模型只输出 `{"choice":"C2"}` 或 `{"choice":"KEEP"}`，不给坐标、单位 ID、预算数字和版本。

复用主线与决策节点，不用“永远只允许规则第一名”制造虚高正确率。候选集合要覆盖该局面合理取舍，并单独评估生成器是否漏掉有效路线。若当前计划失效，KEEP 明确标不可选；错误/空响应保留仍合法任务，由既有紧急/恢复链处理失效部分。

采纳时核验快照/对局/控制代际/计划代际，重查当下前置条件。不能把迟到结果按当前快照重新解释。日志保存候选列表和 choice、筛选/拒绝原因，但不保留凭证。

### D：评分与按需仲裁

在 C 的同一候选集合上，复用既有规则优先级，把可行性、经济瓶颈、基地威胁、兵力与情报时效转成可解释评分。候选明显占优则程序选；接近、事实不足或规则冲突才请求 2B。记录每项评分贡献、是否仲裁和理由，避免模型自行给“高置信”就绕过约束。

歧义阈值在 pilot 上确定并冻结，不在验证集调参。安排“不调用模型、同一评分”消融 D0，以判断 D 的收益到底来自评分还是 2B。D0 是 C/D 的消融，不另开一套系统。省调用而不损害行为可以成立；若 D0 同样好，就不强行给仲裁寻找存在感。

### E：两步窄任务（条件候选）

仅当 C/D 格式与延迟已稳定，但在多个独立局面重复分不清经济、防守或进攻瓶颈时试。第一步从有限事实标签辨别瓶颈；只有需要取舍才第二步选方案。两步共享同一冻结快照和总期限，最多 2 个顺序请求，不按单位/业务线各起一轮，也不并行多代理辩论。

与 C 同总推理期限、同信息比较，另报调用数/输出 token。第二步失败或超时回到合法规则方案，不采用半成品。E 没有超过 C/D 的收益就删除该候选。

### T 与训练后置

只使用已有可用且获授权的模型/凭据；不购买、不申请新账户、不新增下载或擅自改云端配置。没有可用参照就标 unavailable，其他阶段继续。较强模型建议不自动当真值，仍按事实与实际执行评价。

本轮主任务不训练。稳定接口选出后才讨论训练：先存局面、候选、选择理由、执行结果和失败标签；训练/验证按整局、地图 seed 和时间段隔离，不把同局相邻帧随机分到两侧。保持未训练 2B 与规则对照，避免仅学会复述手册。训练成本另立测量预算，未有数据不承诺收益。

## 4. 先处理基础设施与记录

S0 至少区分服务健康、冷加载、输入处理、输出解码、结构/语义校验、调度排队和迟到拒绝。能测哪项报哪项，缺数据用 unavailable；`ModelTimeout` 不等于模型在思考。只读元数据与小请求都针对本轮确认的端点，不改/重启用户服务。

先记录 6 个小请求（预热与稳态分开）。当前 15 秒超时的完整接口若失败，可以在同快照/同输出预算上有限诊断 30/45 秒，每档最多 3 个请求；同步记录 provider timeout、调度 deadline、在途完成时间和服务端状态。只改变一项预算，超过调度上限不能自动放宽全部层。已发请求未真正结束时不叠新请求。

最长 45 秒只是一次诊断上限，不是产品目标。超时延长后成功只能说明等待预算变化，不能算战略更准确或满足 10 秒复核。小请求也不能成功，则修服务/接线后重建基线，再评估模型职责。

保存原始请求（不含凭证）、输入 hash/字符/token 统计（tokenizer 不可用则 unavailable）、原始正文、finish_reason、输出 token、校验错误、provider 与 scheduler 的分别耗时、请求 ID 和版本。详细正文只在有界实验留档，常驻日志用摘要，不能每拍复制全局状态造成卡顿。

## 5. 场景、分组与公平比较

| 场景 | 可复现局面 | 主要判据 |
|---|---|---|
| S01 | 开局暂无敌情、经济未点火 | 合法经济链推进；少量无人机侦察；主力有集结/防守目标 |
| S02 | 资金紧张、矿场/生产前置不足 | 不反复下不可行订单；预算不挤掉必要经济 |
| S03 | 小规模已确认敌情 | 主力按已确认目标持续行动，侦察与作战分工 |
| S04 | 兵力劣势或基地受袭 | 紧急链立即运行，保护/撤离，不等战略模型 |
| S05 | 集结推进，途中正常复核 | 保持目标、task/plan 代际，无理由不折返 |
| S06 | 路径失败或目标失效 | 有界恢复/重规划，不无限重复被拒命令 |
| S07 | 玩家接管或局部手动命令 | 模型迟到结果不能夺回控制或覆盖玩家 |
| S08 | 推理超时/空/非法、暂停/退局重开 | 合法旧任务继续；失效任务恢复；旧局结果拒绝；无请求积压 |

先正常开局通过真实经济和生产到达局面，保存权威快照。受控故障注入、脚本化敌方命令可作独立边界测试，明确记录；不能用刷钱/瞬移/全图偷看认证自然开局体验。暂时无法到达场景就写 blocked，不编快照。

pilot 为 8 类场景 × 3 个独立局面，共 24 个冻结快照，每方案一遍。验证集再收另 24 个局面，与 pilot 整局/seed 隔离；入围方案每快照跑 3 种候选排列/ID 映射，共 72 个请求。稳定 seed 固定3个，具体值、地图和敌方强度在执行时核验可配置入口后冻结，不虚构已存在的启动参数。

保持情报权限、输入事实、当前计划、输出能力和总期限一致。候选次序/ID 置换防止“总选第一项”；评估看实际方案，不看 ID。K0/B 与 C 输出形态不同，其推理成本差异属于接口效果，必须分别报告；要归因模型容量，用同 C 接口比较 2B 与 T。同一局内多次决策是相关样本，不能报成独立局数。

## 6. 指标与准入门槛

下面是预先定义的工程筛选线，不是已测保证或统计显著性。若初始基线证明测量不可用，先修测量/场景并在跑候选前记录修订；不得看到失败后放宽。

| 指标 | 正确定义 | 门槛/用途 |
|---|---|---|
| 可用响应率 | 成功解析且选择/模板在本次合法集合内 ÷ 全部发起请求；失败/超时计分母 | pilot 至少 21/24；验证至少 69/72，两个阶段都需关键错误 0 |
| 战略质量 | 每场景依据预先写的允许集合/必要进度/禁止行为判定；多种合理策略可共存 | S01–S08 必要条件全部满足；不以程序打分为真值 |
| 计划到执行一致性 | request→选择→计划/task→Laya实际frame/候选→接受命令→实际进度 | 必须能追踪；缺采样不能填 pass |
| 无理由目标反转 | 同单位/编组实际目标变化，排除敌情、目标死亡、路径失败、求生与玩家命令 | 入围者比 K0 明确改善，且不劣于 A；K0无有效计划时只与A比较 |
| 非法命令被接受、夺回玩家、旧局结果采纳 | 实际权威回执与后续状态 | 0；发生即拒绝本候选 |
| 经济/生产/侦察 | 完工矿场、矿车真实交货入账、有效生产、无人机和战斗机分别统计 | 相同局面不劣于 A，必要方向有真实进度 |
| 空闲/停滞 | 可行动单位最长停滞及职责；允许守卫/等待生产，不一概算 idle | 去掉无目的游荡，也不能变成全军永久静止 |
| 延迟/负载 | provider、排队、采纳、命令、实际动作；首轮与稳态分开；有效样本数 | 稳态战略 p95 目标≤10s，紧急链保持原预算；慢候选单列不冒充达标 |
| 运行性能 | 同画质/实体范围/镜头的可见帧p95、>100ms计数、权威模拟速度、内存 | 相对A默认容差10%；3次配对复验确认超界即拒绝；未知标未验证 |

6 条规则不能省：

1. 命令日志先按 command_id/回执身份去重；相同 intent 多条留档不能算多次改道。重复下发与目标反转单独算。
2. Laya 调用成功不证明计划遵从。模型候选、baseline 补发、紧急和恢复命令分别标来源，追踪实际位移/交货/伤害。
3. 没有已确认敌情/目标时，不把无目的 attack_move 当侦察；基地回防仍走紧急合同。
4. 不给模型“自评正确率”当成绩。可邀请独立复核对盲化录像判定，必须有具体证据。
5. 战略 p95≤10s 为当前节奏的目标，复核周期与思考时长分开；慢结果期间执行仍必须推进。首轮加载单列，不能删除坏样本。
6. 模拟秒取已验证的权威模拟时钟。只记录 tick 时，先验证与当前 physics/time_scale 的换算和暂停行为；实测 tick/墙钟秒是运行吞吐，不能直接当权威模拟秒。每局同时记墙钟时间、模拟进度与暂停。

筛选期间各方案保持同一普通复核节奏，先实测当前10秒配置的实际发起/收取间隔和失败退避，不把1800 tick或deadline叫作思考周期。优胜接口稳定后，再对30/10模拟秒做独立节奏对照，只有收益和同开性能都过线才试5秒；不能把模型、接口、节奏与评分同时改变后归因单项。重大事件用已有去抖/紧急链，暂停不补发。

## 7. 执行顺序与成本

先串行做最小有意义对照，再让优胜方案进入长局。预算是工作规划，不保证墙钟完成时间；不要为了表格凑齐全部候选。

| 阶段 | 内容 | 建议规模 | 进入下一阶段条件 |
|---|---|---|---|
| M0 | 身份/服务/输入和录像资格、真实开退局、指标自检 | 15–30秒后台录像资格；6小请求；1个真实Match | 基线与测量可信；blocked路径有替代证据等级 |
| M1 | 新鲜 K0 + A，建立同地图同配置执行基线 | 各1局约5模拟分钟；基础故障/接管轨迹 | A 执行链可用，否则先修唯一地板故障 |
| M2 | B/C 最小接口逐个实现与 RSI 闸门；离线pilot | 24快照/方案；每逻辑补丁新3分钟冒烟 | 门槛通过；最多保留2个复杂候选 |
| M3 | C/D/D0、条件E、条件T；独立验证集 | 各入围者72请求；D先做pilot；E/T可跳过 | 有可解释收益，非纯JSON改善 |
| M4 | A + 至多2个入围者真实开局筛选 | 3方案×3seed×5模拟分钟，至多9局 | 行为过线，选1个本地优胜者 |
| M5 | A 与优胜者跨地图/强度配对验证 + 长局 | 2地图×3seed×2方案×10分钟=12局；再各1局20分钟 | S01–S08、正常退重开、同开性能与独立复核 |
| M6 | 优胜者相关/全量回归、总结、可回退落地 | 当前manifest全量；只对稳定最终候选跑一次 | 全部硬门禁通过才晋级产品champion |

不同地图的一半 seed 可作 held-out：在 M4 前明确哪张/哪个 seed 用于开发，M5 未运行的组合保留为验证，不根据结果调整评分权重。M5若退化，reject该版；再次迭代须增加新未见局面或明确已用于开发，不称原held-out仍独立。

成本核算：M4约45模拟分钟；M5约120+40=160模拟分钟；M1约10，加每逻辑补丁3分钟，不包含启动、录像回看、接口开发、离线推理和回归。墙钟估计先测模拟秒/墙钟秒再换算。若每个请求p95=10秒，72个串行请求的参考上界约12分钟；真实成本按每次实测相加，冷启动/超时另计。不把所有备用组合加入笛卡尔积。

每45–60墙钟分钟保存一次摘要/状态/checklist。单局watchdog建议：启动180秒；5分钟局墙钟最多20分钟，10分钟局最多40分钟，20分钟局最多60分钟；这只是运行保护，超时则记录吞吐/阻塞并清理本轮进程，不能把超时局算完整。发现吞吐过慢先诊断，不提高time_scale或降低physics。

## 8. RSI、回退与工作区保护

每轮一个可证伪方向：direction→baseline→精确补丁→静态校验→新真实Match→至少一条旧链路→相关回归→对照。S1冒烟失败不得继续下一项编辑，回到champion；阶段未过S2不晋级。关键改动独立复核与全量回归未过只能 needs-review。

优先运行时参数/已有接口做候选，缺入口只在现有策略provider/adapter加最小开关，默认行为与当前champion保持。不要把 A-E 全部先写进默认启动链。失败候选仅精确撤销自己记录的修改；未提交共享文件保存基线hash/补丁，不能reset/checkout清掉他人工作。活跃冲突无法安全隔离时写blocked: workspace，并先做不依赖冲突的离线/文档工作。

任何共同守卫/采纳器/执行层修复都要重新验证A与当前模型基线，之后全部候选共享这一版；把共同修复收益与策略选择收益分别报告。实验配置和状态明确标出实际策略来源（rules/template/choice/arbitration/two-step），规则降级不能在报告或HUD诊断中冒充模型战略成功。

源码/DLL/关键配置在测试期间变化，该局标版本污染，不混进A/B成绩。每个run-id记录源hash、模型实际别名/量化/上下文与设备（不可得标未知）、工作树状态、地图seed和对手设置、PID/端口/日志路径。保留 `build/adjutant_runtime`、已有venv与控制器。正式打包版不动。

## 9. 录像、命令与正常退出

复用 `tools/dev/match_instance.py` 的身份/端口/所有权及 `tools/dev/record_playtest.py`。读实际实现再调用。旧 `run_acceptance.py` 只用作参考：它的 headless server+client、和平配置、墙钟等待及 finally强制结束，不能代替单人可见/正常对战/菜单退重开。

可见验收默认后台非激活窗口、隐藏辅助控制台、5 FPS分段录像，实际打开解码帧回看。采指定游戏窗口，禁止录整桌面、循环抢焦点或系统输入/移动用户光标。录像门禁失败只标工具blocked，继续无头逻辑和离线工作，不能宣称视觉/玩家UI已通过。

先通过15–30秒正确窗口、持续刷新与输入资格；独立录制，读状态1–2Hz，不能逐帧同步截图。关键异常按时间码密看；记录 actual-reviewed/extracted-not-reviewed。性能比较补录制关闭的配对测量。

自动Match/command-level用于逻辑与控制轨迹，至少一次优胜者通过正常菜单开局、交给副官、局部手动接管、正常退局与换图重开。UI事件不通与产品命令失败分开，不能用接受回执冒充玩家体验。只清理本轮确认所有权的PID，优先正常退出；异常强制结束单列，不能填正常生命周期pass。

## 11. 停止与选择

- 单请求超时不无限重试；按S0有限预算判断接线/体积/输出，连续失败进规则恢复。
- 关键错误出现一次，候选reject并保留原始证据；先复现解释，不能吞日志。
- 同问题失败2轮换诊断角度；连续3轮champion无提升换到下一条方案/机制；不继续加手册、例外条件或提高timeout。
- 初次筛选最多保留2个复杂候选，最终至多1个本地默认组合。硬门禁第一，策略质量第二，同质量选更少请求/更低成本/更容易恢复的方案。
- C 已稳定且D没有收益，选C，不进入E。D0 与D相当，优先更简单者。所有2B组合未过门槛而A可靠，可保留A作为经验证的稳定模式，明确模型战略仍未达标；副官仍执行经济/侦察/作战。
- 与本任务无关的导航/碰撞/建筑/画质问题单列，只有阻塞本次轨迹的唯一依赖故障才做最小修复并重建双方共同基线，不扩展成全游戏重构。
- 用户停止或运行预算耗尽时保存champion、状态和残留清理结果；等待新任务启动时从状态续跑，不能用预算到期宣布完成。
