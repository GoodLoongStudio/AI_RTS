# 战略模式（测试）：封闭战略层测试计划

状态：DRAFT，供用户审核后交给 DeepSeek。

## 目标

在单机模式设置页的“开始游戏”和“返回”之间增加“战略模式（测试）”。玩家点击后进入独立的战略讨论房间，不创建 Match、不生成地图、不启动战斗、不建立玩家槽位和资源系统。战略层先在这个封闭环境中完成对话、上下文、异常和安全边界测试，后续再移植到真实对局。

## 设计边界

- 入口从现有 `Play.tscn` / `MatchSetupPage` 进入；首期只在单机模式显示。
- 测试房间是独立菜单页面，例如 `StrategicSandboxPage.tscn`，继承统一菜单页的返回/ESC 约定。
- 测试房间可以复用 `AdjutantChatService`、`AdjutantModelService` 和战略 system prompt，但不能复用依赖 Match 安装的 `AdjutantButton._install()`。
- 测试房间使用固定会话标识（例如 `strategic-sandbox`）和明确的“无对局上下文”状态；不得伪造资源、单位、敌情或已执行动作。
- 测试房间不能调用 `NetSession.host()`、`Loading.tscn`、`Match.tscn`、`SimulationClock`、单位命令、任务、租约或 Laya。
- 返回测试房间时只回到对局设置页；不产生残留 Match、端口、模型请求或旧聊天实例。

## 阶段 1：入口和封闭聊天房间

### 玩家验收

1. 在截图所示单机设置页看到三个纵向操作：`开始游戏`、`战略模式（测试）`、`返回`。
2. 点击“战略模式（测试）”后不进入地图、不显示资源/单位/HUD，进入独立战略讨论页面。
3. 页面有清楚标题，例如“战略模式（测试）/ 封闭战略层实验室”，并显示“当前没有真实对局，不会执行命令”。
4. 玩家可以打开/继续战略聊天，看到发送中、模型预热、回复、超时、错误和重试状态。
5. 点击返回或按 ESC 回到单机设置页；再次进入时会话、在途请求和旧回复按产品口径处理，不得污染下一次进入。

### 阶段出口

- 入口截图和测试房间截图已打开检查。
- 进入测试房间的运行日志证明没有创建 Match、地图、玩家、资源、SimulationClock 或 NetSession host。
- 至少连续 5 轮真实战略对话成功；回复只讨论战略，不声称执行命令。
- 模型冷启动时首条消息必须排队或禁用到 ready，不能先让玩家得到一次超时；模型不可用、超时、空输出、非法输出可重试。
- 返回/重进不会留下旧请求、旧面板、旧回复或残留进程。

## 阶段 2：封闭测试剧本和可控上下文

在阶段 1 稳定后，再为测试房间增加“测试剧本”选择，不接真实 Match：

- 无情报基线：验证模型承认未知，不编造。
- 经济压力：固定资源、收入和消耗事实。
- 敌情可见：固定敌方构成、方位、距离和射程。
- 暂停/战前讨论：用测试状态模拟暂停或战前，不推进真实时间。
- 冲突/追问：验证模型能引用上一轮并解释战略取舍。

每个剧本都必须显示“模拟战局事实”，并和真实 Match 状态明确区分。先用固定 fixture 验证战略层，再考虑接入实时战局摘要。

## 阶段 3：封闭房间的战略层质量验收

- 固定问题集、多轮追问、提示注入、离题、乱码、超长输入。
- 记录回复延迟、失败率、重复率、事实引用率、越权表述次数和上下文保持率。
- 只有质量和安全边界稳定后，才制定移植到 Match 的接口；本计划不在测试房间阶段接入 Laya 或单位执行。

## 本次只实施阶段 1

阶段 2/3 作为后续方向保留。本次交付只做入口、独立页面、真实战略聊天、返回/重进和无对局证明，禁止顺手实现计划卡、任务确认、单位命令、Laya 控制或实时战局读取。
