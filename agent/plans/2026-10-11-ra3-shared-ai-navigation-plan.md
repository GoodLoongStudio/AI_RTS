日期：2026-10-11。状态：`ready-for-implementation`。本轮只编写计划/提示词，尚未实施游戏补丁。

2026-10-11 补充：根据用户“不能出现一堆 BUG 或更卡”的要求，加入渐进启用、可验证回退、预先锁定的性能/行为门禁及故障注入。分层/worker 必须评估和验证，不强制启用未证明有效的复杂方案。文档复核记录：`agent/reports/closed-loop/2026-10-11-ra3-shared-ai-navigation-prompt-review.md`。

执行提示词：`G:/AIRTS/AI_RTS/agent/prompts/2026-10-11-ra3-shared-ai-navigation-deepseek.md`。研究依据：`G:/AIRTS/AI_RTS/agent/reports/closed-loop/2026-10-11-ra3-scalability-mechanisms.md`。

## 目标

将 RA3 的分层团队决策、到期/事件调度、有界模式化寻路、区域/局部搜索、持续执行与 Job 计算优势落到 AIRTS。副官和电脑都遵守共用合同，玩家命令沿同一导航服务执行；各来源保持现有权限与决策方式。

保持画质、实体尺寸/碰撞、物理频率、速度/射程/视野、难度/生产/出击和模型配置。持续推进、合理编组与及时反应是目标，不能以让 AI 更迟钝获得 FPS。1000 单位 @30 FPS 保持压力目标，达成情况以实测为准。

## 当前基础与不重复开发的部分

- 电脑：Controller、AiCadence、AutoAttackingBattlegroup、battlefield_scan/own_forces_scan 同帧缓存；已有性能候选须读取当前报告及代码，不抹掉。
- 副官：真实入口 deploy/agent_runner.py、graph/runtime.py、async_scheduler.py；已有默认有界 async、单在途/合并、代际、意图/回执和玩家租约。host.py 不是默认真实装配证据。
- 编组：squads.py 接受 authoritative_squads，缺省 ref 同观察稳定；需查权威跨 tick 编组是否实际提供。
- 导航：Movement.gd 预算/pending；GeneratedTerrain.gd 的 AStarGrid2D/缓存/简化；现有 bake_revision 与安全移动门禁。副官安全中继当天已有修改，旧 14m 报告不是修改依据。
- 执行：RuleAiCommandGateway、CommandRuntime、稳定实体 ID、合法 QuerySession 和共享观察快照。不能另建绕过权限的命令入口。

## 共用合同与责任

| 层 | 应负责 | 不应负责 |
|---|---|---|
| 副官/电脑决策 | 当前合法观察下选择战略/目标/队伍任务 | 每单位每帧全局求路或无限下单 |
| 权威 Team/任务状态 | 持久 ID、成员、代际、生命周期、进展与反馈 | 让 Python/GDScript 分别成为权威账本 |
| 到期/事件调度 | 模拟 tick、确定性相位、事件合并、公平优先级 | 拉长难度节奏，模型等待锁死执行 |
| 路径调度 | 总预算、分类、去重、排队、取消、结果版本 | 为每种命令来源独立新建无界池 |
| 区域/局部导航 | 合法走廊共享、净空/能力、细化、修补/失效 | 全军复制第一辆车路径或删掉安全检查 |
| worker | 有界纯数据批次、同算法计算、完成队列 | 操作 Godot Node/SceneTree/共享导航对象 |
| 主线程执行 | 权限/版本复核、物理/订单/阵位、权威写回 | 同步 Wait/Result 等待后台大搜索 |

共用机制与状态实例分开：每个玩家/对局数据隔离，两个 AI 的策略与模型保持不同；玩家操作即时改变代际并阻止旧结果抢回。

## 防回归的执行合同

1. champion 取当前已验证工作树，不默认回到 HEAD；记录未提交内容、源码/DLL/config hash 与可重放命令。只保留/撤销自己精确改动，不覆盖共享工作。
2. S0 在本轮证据目录写 `acceptance-contract.md`，先锁定每档负载的响应、队列年龄、模拟速度、路径/玩法、帧时间与内存/退出预算。基线旧 BUG 单列，无法有效测量的链路先修验证入口；测量期间文件改变使该组无效。
3. 新高风险后端按既有配置做每局选择，保留最后通过的实现。启用顺序：独立数据对照 -> 小规模电脑 -> 副官 -> 共存 -> 玩家受影响导航 -> 压力/长局/联机。最终两个 AI 都接入已接受机制；过渡测试的范围开关不成为永久两套权威系统。
4. 任一请求只走一条权威执行链。影子对照只算少量纯数据，不下命令、不调用第二份模型、不改变经济/单位状态；正式性能采样不双跑重搜索。插桩/日志/录像成本分开，低开销计数器本身也需核验。
5. 配对 A/B 或 A-B-A 至少 3 组并锁条件。p95/p99 可重复退化超过 5% 直接拒绝；波动超过 5% 先稳定环境/补样本，不放宽成退化许可。已达玩法预算的场景不能越界；未超过 5% 也不是自动接受。基线已超预算的压力档允许净改善作为局部晋级，目标仍标未达。5% 是工程门禁建议，并非实测性能；不能拿小规模变慢换压力局平均数漂亮。
6. 无新增非法路径、穿行、权限泄露、重复执行、接管抢回、解析/崩溃、僵尸房；队列公平且可排空，模拟/探索/经济/生产/战斗符合预先合同。FPS 不能抵消任一正确性失败。
7. 共享后端/线程默认启用前及最终候选进行长时样本：正常负载至少 15 分钟模拟且不少于 5 分钟墙钟，退局重开另测 3 次。无持续队列/缓存/任务/内存累积；严重超时停止扩容，不盲目跑更大规模。
8. 验证开关关闭和取消后晚到结果，默认不在用户活跃对局热换后端。回退也受预算限制，不用每单位同步完整搜索形成“回退风暴”。候选失败只撤当前候选，保留此前晋级的改进。
9. 对照分为固定合法命令的执行等价和正常 AI 的效果两层；提前锁定浮点/路径容差及玩法响应。相同权威裁决输入的结果应一致，但不同合法路径和正常 AI 决策可改变交战时序，不以随机战斗逐帧一致或单一胜负作为全部判据。
10. 分开路径计算与局部避让/RVO、物理追帧、模型等待和渲染，记录热点占比及整局收益上限。目标保持不变，但共用调度/分层/worker 的存在不保证解决所有剩余成本。

既有部件若实测满足合同，记录复用及其入口；不要改名重写凑“已移植”。按顺序推进，各阶段可拆多个小候选，不把整个阶段一次性大改。

机制状态统一为 `reused-verified / implemented-verified / rejected-with-evidence / unverified`。评估/拒绝不算实现；完成本次优化不要求把无益候选硬上生产，性能压力目标仍按实测判定。首次实施报告先给 S0 与一个小候选的证据，后续逐闸门继续。

## 调度与线程的不变量

1. 模拟 cadence 不受 FPS/模型响应速度驱动；IO/watchdog 使用单调墙钟。暂停不误判部队停滞。
2. Accepted、计算完成、路线可用、开始移动、到达是不同阶段，缺回执不直接当失败/空闲。
3. 一个 Match 统一路径总额；优先级有界、正常请求有公平老化，同一目标/代际请求去重，新命令取消旧工作。
4. 同步 AStarGrid2D 整次搜索不可自动暂停；若长帧来自单次搜索，须引入可验证的切片/后台批次，不能只把每帧次数由 6 改为别的值。
5. 队伍共享区域走廊条件覆盖地图、导航依赖、域/能力/净空及搜索语义；单位自己的接入、阵位、碰撞仍执行。
6. 线程输入是合法过滤的深度不可变纯数据；主线程不阻塞等结果，也不接受旧对局、旧控制代际和失效路线。
7. 完成时 snapshot_id 不必机械等于当前帧；验证任务真正依赖的版本并重查动态安全，避免所有后台结果永远过期。
8. 同算法同步/worker 开关；批任务统一额度，先 1 后 2 活跃 worker。计入快照、提交、模型/BLAS、Godot 池与 GPU 竞争，不改共享模型/系统配置。
9. 不依线程完成先后改变权威仲裁；稳定排序不解决提交 tick 差异。主机权威只由主机提交；锁步不能由各机 worker 就绪墙钟决定提交。相应协议/状态摘要未验证时该模式保留旧确定性后端。
10. 退出取消/排空及生命周期令牌必须验证，不用无限缓存/任务/连接留下下一局污染。
11. 同一批快照不能自动替代顺序依赖；后项读取前项写入的算法保留串行或证明阶段化等价。按原顺序提交不足以恢复计算依赖。
12. 队列、活跃 worker、单批、结果、快照/缓存字节均有上限，慢消费者背压；取消后等待安全归还缓冲区。快照、跨语言转换、锁/等待、提交与维护成本都计入，不仅计 worker 搜索。
13. 队列满返回明确等待/拒绝原因，不静默丢已受理任务。队列忙不等于不可达/空闲，禁止上层每 tick 重派形成请求洪峰。

## 验证安排

每个关键补丁：champion/hash → 最小候选 → 解析/编译 → **新进程无头真实 Match** → 受影响正反场景和至少一条旧链路 → 同场景 A/B → 相关回归。硬门禁失败拒绝候选，仅撤自己的精确补丁；连续三轮未晋级换诊断方向。

代表性轨迹：

- 电脑单独：1AI、3AI 正常发展/交战，不能用 peaceful/passive 当进攻验收。
- 副官单独：真实正常模型、延迟/超时/无效和规则回退；已有有效任务不等待新模型，探索/主力分工持续推进。
- 共存：3AI + 真实副官，完整经济/生产/战斗轨迹，线程/模型等待分桶，不关闭模型评分。
- 玩家：移动/Stop/改目标和接管，中途队伍死亡/增援；每种来源都到同一导航服务但控制权不混淆。
- 地图：512×512 正常图，窄口/桥/出口/U形、动态建筑/拆除、目标不可达/失效，空地和大小/速度混合单位。
- 生命周期：暂停恢复、退局重开、runner 断线恢复、迟到旧回调、支持的联机权威。
- 规模：50/100/300 再到 1000，合法真实实体与命令；不把测试扩容配置写入普通生产/平衡。

强制故障注入：计算中 Stop/改目标/接管、旧局结果晚到、成员死亡/换队、动态封路且缓存命中、队列满/结果积压、worker 异常/慢任务/取消、模型长期不返回、少 worker 回退。检查实际未写入旧结果、未重复执行、等待可结束，不能只检查 cancel 日志。

锁定指标：整局与主线程 frame p50/p95/p99/max、长帧、模拟速度、physics ticks/frame、命令至首次位移/到达、队列年龄和最大等待、查询/展开/命中/取消/过期、CPU/worker/GPU/模型等待、内存/任务/连接、经济/产兵/伤害/新覆盖/重派率。代表性 A/B 至少 3 次，不能过滤严重长帧，不把重叠监控相加。

无头用于逻辑和 CPU 吞吐，可渲染非干扰样本用于真实 FPS/画质；性能采样与 5 FPS 录像分别测，不把录制开销算成玩法收益。完整玩家试玩按用户意愿由用户进行，提供短明确轨迹；自动验证不抢系统输入。

每局核验 --path、PID/端口/Match 身份、模块/hash、mtime、真实实体/命令/结果、watchdog、rc、marker、forbidden 和 cleanup_ok。相关 tests/core、副官 Python 合同与当前回归清单全量执行按影响安排；未通过项如实分类，不能改绿断言。

## 最终完成标准

“副官 × 电脑 × 真人受影响导航”接入表全部有实际入口/配置/轨迹；Team、任务反馈、到期、路径队列、代际/生命周期双 AI 合同覆盖；分层/修补与 worker 有实际验证或否证，不强行启用无益候选。整局收益超过噪声，任务/模拟/命令/画质不越界，默认启用配置及回退均通过；完整回归与独立复核闭合后才称本次优化完成。未达规模目标、联机或其他未验证范围分别标明，不能把局部 champion 当全项目完成。

1000@30 未通过就保留目标和剩余热点，不能下调规模宣布成功；局部优化也按实际范围报告，不能把分项 CPU 改善当整局质变。

报告位于 `agent/reports/closed-loop/<run-id>-stage-N.md` 和最终总报告；证据位于独立 `agent/runs/<run-id>/`。验证成功的共用合同写入现有相关 skills 并给双入口导航；未测机制保持 candidate。
