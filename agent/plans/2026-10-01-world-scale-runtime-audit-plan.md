## 1. 已确认的基线

当前运行场景实测，不采用旧表里的“坦克 9m”：

| 实体 | 视觉模型 AABB（长×高×宽） | 其他口径 |
|---|---:|---|
| 坦克 | 2.57 × 1.75 × 3.80m | 碰撞半径 1.4m；移动半径 2.0m |
| 重型坦克 | 3.86 × 2.51 × 3.89m | 必须继续用运行时探针确认碰撞/避让 |
| 装甲车 | 2.40 × 1.78 × 5.30m | 必须继续用运行时探针确认碰撞/避让 |
| 运输车 | 2.41 × 2.04 × 4.54m | 必须继续用运行时探针确认碰撞/避让 |
| 直升机 | 4.40 × 1.64 × 4.57m | 空中离地高度单独验证 |

坦克当前权威平衡值是速度 2.75m/s、炮击基础射程 7.5m、视野 13m。它们不能因为“9m 坦克”这个错误假设被自动乘系数。

步兵的旧 AABB 探针结果无效：蒙皮网格在骨架就位前返回接近零值。步兵必须改用 `Skeleton3D` 骨骼包围盒或稳定的运行时网格包围盒后再进入尺寸表。

## 2. 必须区分的七个口径

1. 视觉：真实 `GeometryInstance3D` 世界 AABB，不含血条、选中圈、炮口标记和特效。
2. 物理碰撞：`CollisionShape3D` 的形状与世界包围盒；移动单位通常用圆柱，建筑按本体使用盒体或明确的简化体。
3. 导航 carve：`MovementObstacle` 顶点/半径外扩 `NavigationMesh.agent_radius`，不等于物理碰撞体，也不等于模型 AABB。
4. 移动避让：`Movement.radius` 与个人空间/脱困阈值；不是视觉长度。
5. 建造占地：施工定义的 footprint；必须和权威放置、白色预览、相邻判断同源。
6. 游戏玩法距离：移动速度、攻击距离、视野、采矿服务半径、出生/集结距离；必须用米和米/秒直接表达。
7. 特效：粒子、爆炸、移动点击、采矿闪光、弹道、炮口火焰、血条和命中特效的世界尺寸、速度、寿命与锚点。

## 3. 现有已知问题

- `Unit.gd` 已有“攻击/视野基础距离 + 双方半径”的中心距补偿，但攻击范围圈仍直接画原始 `attack_range`，显示口径可能与实际判定不一致。
- `FogOfWar` 的圆形绘制使用基础视野半径，而单位可见性判定还会加入目标/观察者半径，需要决定这是“地图控制圈”还是“针对目标的有效距离”，不能混称。
- `StructurePlacementRuntime` 和 `GodotStructurePlacementWorldPort` 已共享建造范围常量，但仍需确认预览、自动选址和权威落位全部只读取这一处。
- `ShellExplosion.tscn`、`SparklingAnimation.tscn`、`MouseClickAnimation.tscn`、火箭/炮弹/步枪弹场景有独立的粒子尺寸和时间，不会因为单位模型改变而自动同步。
- 出生点、集结点、炮口、弹道落点和建筑工人站位使用 Marker/Transform，必须测量其相对本体边界的距离，不能只看节点名称。

## 4. 实施阶段

### 阶段 A：建立可信审计表

- 修复或补充真实运行时尺寸探针。
- 输出每个单位/建筑的视觉 AABB、碰撞 AABB、Movement 半径、Obstacle carve 外缘、出生/炮口/集结偏移。
- 每条记录注明来源：场景、运行时属性、平衡 JSON 或探针测量。
- 任何无法稳定测量的实体标为 `unknown`，不得用猜测值填充。

### 阶段 B：修复四类几何断裂

- 视觉与碰撞不一致：优先调整碰撞形状/节点位置，不先缩放模型。
- 碰撞与导航不一致：修复 obstacle vertices、agent radius 和 carve 逻辑。
- 碰撞与移动半径不一致：不要把 `Movement.radius`、`MovementObstacle.radius`、施工 footprint 强行设成同值；先分别定义它们的语义，再用逐单位地面 hull、导航配置空间和实际贴边路线验证各自余量。详细执行协议见 `agent/plans/2026-10-01-per-unit-collider-clearance-plan.md`。
- 出生/集结/炮口错位：只修 Marker/Transform 的世界米位置，禁止给整棵 UnitRoot 追加缩放。

### 阶段 C：重新标定玩法数值

- 用固定 20m、40m 测试路线测移动时间，按“米/秒”决定速度；不使用全局缩放系数。
- 用固定目标半径测试攻击：确认基础射程是“表面到表面”还是“中心到中心”，然后让权威判定、攻击范围圈、AI 索敌和 HUD 使用同一口径。
- 用 Fog probe 验证基础视野圈、目标可见性和迷雾更新是否一致。
- 只有实测证明手感不合理时才改 speed/range/sight；每个单位逐项记录旧值、新值和依据。

### 阶段 D：重做特效世界尺度

- 采矿闪光：以矿点模型和工人半径为参照，测粒子发射半径、粒子尺寸、寿命和高度。
- 爆炸：以对应弹体和目标单位为参照，分别测火焰、烟雾、冲击环的 AABB、速度和寿命；炮弹、火箭、建筑爆炸不能共用一个未经验证的尺寸。
- 右键移动点击：以一个步兵/坦克脚印为参照，验证贴地高度、直径、淡出时长和相机远近可读性。
- 炮口火焰、曳光、弹道和落点：保证发射点来自真实 muzzle，飞行速度用 m/s，命中点与权威结算一致。
- 血条、选中圈、攻击圈和建造白色区域：作为 HUD/地面表现单独测量，不把它们计入实体模型尺寸。

### 阶段 E：闭环验证

- 静态：GDScript 校验、`dotnet build OpenRTS.sln --no-restore --nologo`。
- 运行时：真实 Match 探针输出 JSON/日志。
- 可见性：MCP 启动可见对局，截图并打开截图检查，不只看状态查询。
- 回归：运行受影响套件，再运行全量回归；记录 rc、marker 和 forbidden output。
- 独立复核：用另一探针或另一 Agent 重新测量至少一个单位、一个建筑、一个移动特效和一个爆炸特效。
- 报告：写入 `agent/reports/closed-loop/`，未通过时标记 `blocked` 或 `needs-review`。

## 5. 停止条件

- 发现当前场景被其他 Agent 在近几分钟内修改，先暂停该文件。
- 探针不能区分蒙皮绑定包围盒和运行时姿态时，先修探针，不调数值。
- 视觉、碰撞、逻辑或特效只有一项能证明时，不提交“尺寸修复完成”。
- 没有截图或独立复核时，只能报告“代码已改，尚未闭环”。
