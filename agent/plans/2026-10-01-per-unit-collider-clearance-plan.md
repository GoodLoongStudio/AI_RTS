# 逐单位碰撞包围与空气墙修复计划

- 状态：`ready`
- 版本：`v2-shape-pipeline`；必须先验证形状读取与消费链路，再逐实体修复，不能只修改场景碰撞资源。
- 目标：修复模型外仍有明显不可通行空隙的问题，并证明每个单位、建筑、资源点的边界来自实际几何，而不是统一放大的圆。
- 关联提示词：`agent/prompts/2026-10-01-per-unit-collider-clearance-execution-prompt.md`
- 前置诊断：当前代码至少存在五种边界：视觉模型、`CollisionShape3D`、`Movement.radius`、`MovementObstacle`/导航 carve、逻辑占位与推出。它们不能因为名字都叫 radius 就强行相等。

## 1. 当前静态证据与假设

以下是代码读取到的候选根因，必须在运行时逐项证伪，不能直接当成最终修复值：

| 层 | 当前证据 | 可能造成的现象 |
|---|---|---|
| 工人移动 | `Worker.tscn` 圆柱碰撞属性 `radius=0.92m`，`Movement.radius=1.41m`（2026-10-01 已按「地面半宽 1.26 + 0.15」定值；旧值 2.0m 已废弃），模型地面半宽实测 0.92×1.26 | 可能存在过大的个人空间，实际空隙需按模型轮廓测量 |
| 指挥中心 | `CollisionShape3D` 半径 `3.48m`，`MovementObstacle.radius=3.48m`，导航代理还会外扩 `agent_radius` | 调试图的红色 carve 圆比建筑本体大；贴边路径可能再叠加单位半径 |
| 导航 carve | `MovementObstacle` 可由 `vertices` 或半径生成，导航洞还外扩 `NavigationMesh.agent_radius` | 视觉、物理和导航边界不一致；“红圈”不等于物理碰撞 |
| 逻辑推出 | `Movement._push_out_of_static_obstacles` 使用障碍半径 + 单位半径 + margin | 即使导航可走，目标也可能被逻辑层推远 |
| C# 放置/占位 | `GodotStructurePlacementWorldPort` 使用结构半径、采样圆和 carve 区域 | 建造/资源站位可能被更大的圆形规则限制 |
| 多边形形状读取 | `MovementObstacle`、`CollisionVolumeOverlay`、C# `ShapeBounds` 仅识别圆柱/球/盒/胶囊 | 换凸体后可能返回空 bounds/null、漏掉障碍或按旧圆回退 |
| 实际移动 | 单位是 `Area3D`，`Movement._on_velocity_computed()` 直接更新位置 | 贴合的检测 shape 不会自动修好实际移动阻挡 |

这些是排查入口，不是要求把所有数字改成 `0.92` 或 `3.48`。长方形车辆、建筑悬挑、炮管、旋翼和地面接触面的语义必须分别决定。

## 2. 交付物

1. `agent/runs/<run-id>/per-unit-collider-matrix.json`：每个实体一行，禁止 `unknown` 被默认为通过。
2. 每个实体的独立 Godot 检查场景或同项目独立可运行场景。可以复用主项目资源，但不能复制出无法回写主项目的“演示工程”。
3. 每个实体至少三张可查看截图：俯视叠加、侧视高度、正常游戏视角。截图中同时显示模型、真实碰撞几何、Movement/Obstacle/导航 carve 的不同颜色和米制标尺。
4. `agent/reports/closed-loop/2026-10-01-per-unit-collider-clearance-report.md`：记录每个实体的测量、改动、失败循环、截图文件、命令与 rc。
5. `agent/runs/<run-id>/shape-support-matrix.json`：引擎支持与项目支持分列，覆盖每种实际使用形状在各消费模块的读取、回退、数据和测试状态。

## 3. 阶段与验收

### 阶段 A：只读基线

- 先读 `AGENTS.md`、`skills/闭环验证工作法.md`、`agent/manifest.json` 和本计划。
- 检查 `git status`、目标文件 mtime、Godot/MCP 进程和端口；不要覆盖其他 Agent 最近的改动。
- 运行时枚举所有可生产单位、建筑、炮塔、资源点，不能只测用户截图里的两个对象。
- 对每个实体记录：模型世界 AABB/局部 OBB、碰撞形状、地面投影 hull、`Movement.radius`、Obstacle vertices/radius、导航 agent 半径、逻辑 blocker、建造 footprint、出生/集结/服务站位。
- 排除血条、选择圈、UI、阴影、粒子、炮口 marker；旋翼/炮管等悬空部件是否算地面阻挡要写明规则。
- 记录碰撞所属的 `Area3D`/物理 body、用途、启用状态；读取初始化后实际 vertices，而不是只看会被脚本覆盖的 authored vertices。

### 阶段 A1：形状选择与完整支持链路

这一阶段不可跳过。优先打通一个窄长单位和一个非圆形建筑，再复用于全实体；不是要求为了形式使用全部形状。

| 形状 | 选用和验收 |
|---|---|
| 长方体 `BoxShape3D` | 长宽高可独立设置，允许贴合车身的旋转盒；不是世界 AABB。 |
| 圆柱/球/胶囊 | 圆形底座、球形主体、人物等候选近似，按实体地面轮廓和轴向验证，不能按类别强制使用。 |
| `ConvexPolygonShape3D` | 简化凸多面体读取 points 和完整变换；单一凸包不能填死需要通行的凹口。 |
| 多简单体/凸体组合 | 分别读取有效 shape，以并集作窄相位；不要把组合重新合并成巨大 AABB/整体凸包。 |
| `ConcavePolygonShape3D` | 仅按经验证的静态用途采用；不要求所有单位使用高精度三角网格，不能把空心凹网格直接当作 Area 实体占用体。 |

必须检查的消费模块：

1. `MovementObstacle.gd::_shape_local_aabb`/carve vertices：支持实际采用的凸体、组合及完整变换，不静默返回零 bounds。
2. `CollisionVolumeOverlay.gd` 和探针：显示真实形状/轮廓；AABB 只显示为粗框，按各用途过滤 disabled shape 和子 Area 的检测圈。
3. `GodotStructurePlacementWorldPort.cs::ShapeBounds`/重叠/相邻/预览：已有四类兼容，新增形状读取与窄相位正确，不只扩展 switch 后继续用大矩形判相撞。
4. `Movement.gd`/实际每步运动：证明贴模形状参与真正阻挡，而不只是检测或调试；RVO 可保留简化圆，但它不是实体硬占位的权威。
5. `GeneratedTerrain.gd::set_structure_blocker`：当前中心+radius 接口仍需检查非圆形轮廓，量化逻辑格子造成的空隙，验证逻辑地图与普通导航图。
6. 出生/集结/采矿卸矿/建造：检查站位与释放点是否仍按旧 radius 推远，白色预览和最终判定一致。

不支持的形状必须显式告警/失败并记录 entity、class、节点路径、原因；不得默默当作“无障碍”或自动套大圆。采用共享几何读取时优先复用现有工具和 Godot API，保持 C#/GDScript 分层，不引入不必要的新架构；配表扩展必须同步 schema/DTO/加载器/测试，不能随意新增非法 JSON 字段。

形状链路夹具至少覆盖：四类原始形状、实际采用的凸体和组合、偏移与嵌套变换、四种 yaw、禁用形状、子 Area、未知形状失败；AABB 相交但实际几何不相交须放行，实际几何相交须拒绝。L/U 组合可通行凹口、转向、薄障碍 swept/每步检查、出售销毁后的 blocker 清理必须实测。预算复杂度和性能，不给所有实体直接挂完整高面数模型。

### 阶段 B：单实体独立测量循环

对每一个实体分别执行，不允许“改一批后只抽查一个”：

1. 在独立场景实例化实体，等待资源加载、蒙皮、动画和父节点变换稳定。
2. 在 yaw `0°/45°/90°/135°` 测局部几何；对有动画/炮塔/旋翼者至少测静止、移动姿态和攻击姿态。蒙皮网格不能用未就位的骨骼包围盒代替完整 skin envelope。
3. 生成实际地面投影 hull。窄长车辆不得用覆盖全长的圆冒充物理包围；可用盒、胶囊、凸分解或明确的复合形状。AABB 只能作为 broad-phase，不能作为最终贴边窄相位判定。
4. 对每个候选边界标注语义：`visual`、`physical`、`movement_personal_space`、`nav_carve`、`logic_occupancy`、`construction_footprint`。记录来源节点/属性和单位。
5. 实际运行贴边路线：从四个方向向实体靠近、沿边横向通过、从实体一侧穿到另一侧；至少重复三次。记录最后一个可行位置、中心距、模型 hull 到障碍 hull 的最小表面距离、速度、停顿原因和第一限制层。
6. 进行“点击目标在模型内部/边缘/外部”的目标钳制测试，避免 `closest_point`、RVO、逻辑推出互相二次外推。
7. 保存修改前截图和修改后截图；必须实际打开查看图片，不得只检查截图文件存在。

### 阶段 C：修复顺序

按第一限制层修复，禁止一上来调大/调小全局半径：

1. 视觉与 `CollisionShape3D` 不符：先修碰撞形状、位置和旋转。
2. 物理与移动空间不符：只为该实体改 `Movement.radius` 或换成合适的移动 hull，并以实际贴边距离验收。
3. 物理正确但导航洞过大：核对 `MovementObstacle.vertices`、世界变换、`agent_radius` 外扩和烘焙结果。报告“本体边界”和“某类单位可通行边界”两条线，不能把红色 carve 图当作碰撞盒。
4. 导航可走但仍被推开：追踪 `_push_out_of_static_obstacles`、逻辑 occupancy、stand-off、arrival/服务站位，消除重复膨胀。
5. 建造/资源服务受限：检查 C# 放置 footprint、相邻判定、矿点服务半径与站位公式，不能用视觉圈或导航洞代替。

导航洞是单位中心的配置空间，正常包含单位尺寸；禁止把它当成本体又额外加一次单位半径。共用最大 agent radius 对小单位可能过于保守，修复必须同时验证大单位不穿墙。地面/空中域和高度接触范围分别验证，不允许把悬空旋翼/炮管强制投影成地面空气墙。

### 阶段 D：数值门槛

- 边界余量必须来自测量；默认只允许小余量，候选为步兵/工人 `0.05–0.15m`、车辆 `0.10–0.25m`、建筑 `0.10–0.30m`，并要求总余量不超过实体最长地面尺寸的 5%，除非报告给出几何原因。
- 不能以“中心点距离”代替表面距离。矩形实体要报告最小 hull-to-hull 间隙；圆形 RVO 半径不能作为物理模型真相。
- 对图中空气墙，必须同时报告：模型边缘、物理边缘、导航可行边缘、逻辑推出边缘的坐标；找不到第一限制层就标记 `blocked`。
- 允许边缘保留少量安全间隙，但不允许出现单位尚未接触模型投影就停止，或单位可以穿过已占用模型。

### 阶段 E：回归

- 运行 GDScript/场景解析、相关 C# 构建和 manifest 指定的回归测试。
- 先运行形状链路夹具并检查支持矩阵，再运行每个正式实体的运行时场景；shape 被读到不等于实际移动已采用它。
- 固定种子验证：四方向贴边、狭窄双单位走廊、建筑相邻建造、矿点服务、单位出生/集结、攻击距离、视野和效果锚点。
- 对修过的每个实体再次截图；至少由独立探针或独立复核重新测量一个单位、一个建筑、一个资源点。
- 相同地图/实体数/环境记录修改前后帧时间、停滞、通行误差；不能只看 FPS 或只跑 headless 声称贴模通过。
- 任一实体未测、截图未打开、第一限制层未知或存在回归，整体不能写“已完成”，只能写 `needs-review`/`blocked`。

## 4. 明确禁止的伪修复

- 不得缩小模型来迁就错误碰撞，不得给整棵 UnitRoot 再加世界缩放。
- 不得把所有实体改成同一个圆、把所有碰撞改成 AABB，或把所有 `radius` 强行同步。
- 不得只更换 shape 而忽略项目读取器/真正移动/逻辑占位；不支持形状不能静默丢弃或圆形回退。
- 不得通过关闭碰撞层、关闭导航/避让、扩大目标容差、传送单位或隐藏调试几何来“通过”。
- 不得只改测试期望值、只看一张总览截图、只跑 headless 状态、只检查截图文件存在。
- 不得把旧尺寸表、旧 Agent 报告或插件自动推断当作权威；必须以当前场景和运行时数据为准。
