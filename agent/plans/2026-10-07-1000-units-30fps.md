# 计划：1000 单位 / AI 副官指挥 / 稳定 30 FPS（2026-10-07 起）

## 目标口径（可测 ✓）
- 场景：人 + AI_EASY ✓，**AI 一方 1000 个作战单位** ✓，全线推进/持续交战 ✓；
- 口径：**生产配置**（`run/max_fps=30` + vsync ✓）；
- 通过标准：**frame p50 ≤ 33.3 ms 且 p95 ≤ 45 ms**（≈ 稳定 30 FPS ✓），实体数量全程不下降 ✓；
- 门禁：`MovementPushEquivalence` 0 failure ✓ + 移动/导航相关回归 rc=0 ✓ + 截图已打开 ✓；
- **禁止**：降画质/关迷雾/停模拟/改射程视野速度尺寸/改断言 ✓。

## 已知瓶颈清单（按证据 ✓，逐个攻）
1. **移动回调路径 = O(n²)** ✓（R15 实测：`_on_velocity_computed` 135.8 µs × 0.99 次/单位/帧 ✓）
   ⇒ R16 已做**保守前置剔除** ✓（100 单位 −40% ✓）；仍需继续（如空间索引/近邻集合 ✓）；
2. **`process` 114~134 ms** ✗（300 单位 ✓）**未拆开** ✗ ⇒ 下一测：单位渲染 vs 小地图 `UPDATE_ALWAYS` 视口 vs HUD vs 脚本 `_process`；
3. **`physics` 49~63 ms** ✗（300 单位 ✓）⇒ 除移动回调外还有谁；
4. **node 数 9395** ✓、**draw 445** ✓（不高 ✓ ⇒ 渲染 draw 层暂列候选，不是首要 ✓）；
5. 每单位每帧的**其它** O(n) 扫掠（索敌/可见性/采集/UI 图标 ✓）待测。

## 方法（R1–R21 的教训 ✓ 固化为纪律）
1. **先测后改** ✗ 不猜（两次猜错方向各废一轮 ✓）；
2. 一轮一个候选 ✓；失败立即**逐字节撤销** ✓（用备份 ✓ 不要 git checkout ✗ 工作区含他人工作 ✓）；
3. 门禁：等价性 0 failure ✓ 是硬门槛（前两个候选死于此 ✓）；
4. **非侵入优先**：外部探针 + 只读开关（隐藏 Geometry / 断信号 ✓），不改游戏代码做测量；
5. 探针一律 `-WindowStyle Hidden` ✓（不打扰用户 ✓），回归**串行** ✓（skill 禁止并行跑回归 ✓）；
6. 每轮记录：负载、相机/画质、physics tick、文件 hash、frame p50/p95/p99、热点调用数与耗时、rc ✓。
