# 战略模式（测试）第二阶段计划：地图情报、四出生点与战前战术讨论

状态：DRAFT，供用户审核后交给 DeepSeek。

## 目标

把现有的“战略模式（测试）”从无上下文聊天页升级为一个可验收的战前战术讨论室：

1. 从单机设置页带入玩家当前选择的具体地图。
2. 在战略模式中展示这张地图的真实预览、尺寸、已知地形/资源事实和四个出生点。
3. 玩家先从四个真实出生点中选择自己的出生点，再和 AI 副官进行战前战略讨论。
4. UI 达到可长期使用的 RTS 战区简报室审美，不再出现聊天控件挤在左上角、主面板空白的问题。
5. 继续保持封闭测试：不创建 Match、不启动战斗、不生成玩家/单位/资源实例、不执行命令。

## 参考事实与数据边界

- 当前单机设置页已经有 `_map_select`、`selected_map_path()`、地图摘要和离线预览图。
- 具体地图场景包含 `SpawnPoints` 下的 4 个 `Marker3D`，出生点坐标必须从所选地图的权威场景数据读取，不能在 UI 里硬编码一套通用坐标。
- 具体地图场景包含 `Resources` 节点。资源位置、数量/类型只能从地图场景或已有地图数据读取；无法可靠读取的字段必须标记为“未知”。
- 地图预览图优先复用 `MatchSetupShared.preview_path()` 和现有真实地图预览资产。
- “出生点 1/2/3/4”是地图设计中的四个可选起点，不等于敌方基地、敌方玩家或已占领位置。
- 空槽位、AI 槽位、其他出生点都不能自动写成敌情。战略上下文只能声明“本测试没有敌方单位/实时战局情报”。
- 随机地图在单机页只是“开局时生成”的意图，没有确定地图可供战前分析；战略模式必须要求先选具体地图，随机地图时按钮禁用并说明原因。

## 阶段 2A：入口数据传递与地图情报读取

### 目标

从 `MatchSetupPage` 打开战略模式时，准确传递当前具体地图路径；进入页面后能建立一个只读的地图情报对象。

### 情报对象最低字段

```text
map_path
map_id / map_name
map_size
preview_path
spawn_points[4]: { index, world_x, world_z, facing, label }
resources[]: { type, world_x, world_z, amount? }
known_facts[]
unknown_facts[]
selected_spawn_index
```

实现可以使用新的 `StrategicMapIntel` 纯数据服务，也可以复用已有地图工具，但必须满足：

- 不依赖 `Match`、`SimulationClock`、`NetSession.host()` 或 Loading 链路。
- 不为了读取数据而创建完整对局玩家、单位、资源系统。
- 读不到数据时显示“未知”，不能用随机值、默认值或模型生成值补齐。
- 传入的地图路径在 UI、日志和发送给模型的上下文中保持一致。
- 地图场景加载失败时，页面保留可返回状态，明确显示错误，不进入空白聊天页。

### 阶段出口

- 选择两张不同具体地图进入战略模式，地图标题、尺寸、预览图和出生点坐标随地图变化。
- 选择随机地图时，按钮状态和说明清楚，不进入没有地图事实的战前讨论。
- 日志能证明没有创建 `Match`、`SimulationClock`、玩家/单位/资源实例或调用 `NetSession.host()`。

## 阶段 2B：战区简报室 UI

### 信息架构

在 1280×720 基准下使用安全区内的双栏布局，窄屏时允许上下堆叠：

```text
┌────────────────────────────────────────────────────────┐
│ 战略模式（测试）   战前战术讨论 · 地图名       返回/ESC │
├──────────────────────────┬─────────────────────────────┤
│ 战区简报                  │ 副官席                      │
│ [真实地图预览 + 4 个点]   │ 出生点确认状态              │
│ [1][2][3][4] 出生点选择   │ 聊天历史                    │
│ 地图事实 / 已知与未知     │ 输入框 + 发送                │
└──────────────────────────┴─────────────────────────────┘
```

### 左栏：战区简报

- 顶部显示地图名称、地图尺寸、`地图事实来源：所选地图`。
- 显示真实预览图，不使用空白占位块；预览图上叠加 4 个编号出生点标记。
- 四个出生点都必须是可聚焦、可点击的 44px 以上交互区域；编号、形状和文字同时编码，不依赖颜色区分。
- 未选择时四个点为可选状态；已选点使用高对比青色边框/外发光、`已选出生点`标签和明显焦点环。
- 预览图旁或下方显示 4 张简洁出生点卡片：编号、方位/边缘描述（能计算才显示）、坐标、附近已知资源概览；未知写“未知”。
- 下方显示“已知地图事实”和“当前未知信息”两组，严禁把未知敌情写成事实。

### 右栏：副官席

- 标题包含“战前战术讨论”，并始终显示当前地图名和已选出生点。
- 没有选出生点时，聊天输入和发送按钮禁用，显示“请先选择一个出生点”。
- 选定后显示一条确认摘要，例如“你选择了出生点 2 · 坐标 (x, z)”，再启用聊天。
- 聊天历史、输入框、发送、模型预热/等待/错误/重试状态必须全部位于右侧面板内部；禁止把运行时控件直接挂在页面根节点导致左上角堆叠。
- 首次进入显示副官欢迎语：说明地图事实来源、当前选点、没有实时敌情、不执行命令，并主动提出 2~3 个基于已知地图事实的讨论方向。
- 返回按钮固定在统一安全区内，ESC 与返回语义一致。

### 视觉验收

- 沿用 `SystemUIStyle` 的深色工业科幻色板、玻璃面板、细描边和青色主焦点；不要另起一套随意颜色。
- 标题/关键状态至少 24px，正文至少 16px，次要信息至少 14px；重要文本有面板或描边/阴影保证对比度。
- 所有静态 UI 落在 5% 标题安全区内；窗口缩放到 1280×720、1920×1080、2560×1440 时不重叠、不裁切。
- 键盘、鼠标和手柄都能走完整流程：地图 4 点 → 返回/ESC；焦点有明显环，不能只有颜色变化。
- 视觉上要让玩家一眼区分：地图事实、玩家选择、模型建议、未知情报。

## 阶段 2C：上下文与聊天行为

选点后发送给战略模型的上下文使用独立区块：

```text
[战略测试地图]
地图=<name> 尺寸=<size> 来源=所选地图
玩家出生点=<index> 坐标=(x,z) 朝向=<facing>
已知地形/资源=<由地图数据提取的事实>
其他出生点=<四点列表，只说明位置，不声明敌我>
未知=敌方单位、敌方意图、实时占领状态、实时资源变化
模式=战前讨论；不执行命令；不创建任务或计划对象
```

模型规则：

- 先引用地图事实，再给战术判断；不能因为地图上有四个起点就说敌人在哪个起点。
- 建议可以讨论开局侦察、经济路线、桥梁/水域/资源点风险和防守方向，但必须使用已有数据并标明推断。
- 不得声称已开始、已侦察、已派遣、已执行或已经知道敌情。
- 用户改变出生点后，后续上下文和 UI 必须同步；旧选点的迟到回复不得写入新选点会话。
- 地图事实上下文和聊天历史要有长度上限，避免长对话吞掉当前选点。

## 明确不做

- 不启动真实对局，不进入 Loading，不生成单位或玩家。
- 不接实时战争迷雾、敌军单位、资源变化、任务卡、计划 JSON、确认执行、租约、命令或 Laya。
- 不把本阶段做成全屏地图编辑器；只做可读地图简报和四点选择。
- 不用假数据填满空白；缺失事实必须显示“未知”。
