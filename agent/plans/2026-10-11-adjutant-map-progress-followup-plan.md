## 执行阶段与验收闸门

### 阶段 0：基线锁定

读取工程规则、地图工具规则、动态试玩规则和性能规则；保存当前 champion 的工作树/目标文件哈希、C# DLL mtime/hash、测试基线和现有失败归因。只在主工程源码内编辑。

### 阶段 1：副官经济与首座矿场

建立一局新 Match 复现：车厂或其他首个产能建筑出现后，首座矿场是否仍被当成远端扩张而无法落地；记录建造回执、真实建筑实体、工人携矿、矿点库存、余额变化。

修复原则：

- 首座 `ore_refinery` 必须是经济启动链，不得因为已经有 `vehicle_factory`、普通 `worker` 或“有一个工人”就被判定经济已点火。
- 经济阶段必须区分建设、可采/可交付和收入发生；不能使用单位存在作为收入证明，也不能用首笔交付锁死必要防御或最低视野恢复。
- 首矿使用最近可见且可采的资源点；远端矿场/分矿必须等建造网络或前哨规则成立，不能反复下单后耗尽余额。
- 第二兵营/第二车厂、机场和额外生产只能在经济条件、队列负载、战损或明确战术需求成立时开放。

闸门：新 Match 中首矿真实完成、矿点库存减少、至少一笔交付发生，且低资金时不会无限重复提交失败建造。

### 阶段 2：建筑选址、出口和通行

修复自动选址，使建筑间距、建造网络、地形、导航 carve、生产出口和资源站位使用各自权威规则。候选点必须通过“出生点→集合点→基地出口→资源区→返回”的真实路径检查；不能只把单一净空常量调大。

必须覆盖施工前、施工中和完工后三个状态；验证步兵、坦克、矿车能出生、离开、到达、返回。若远端矿场需要前哨/扩张节点，必须实现有界、可解释的前置链，或明确拒绝该候选并保留经济，不得让矿车满载堆死。

闸门：新 Match + 5 FPS 视频回看 + 导航/建造相关测试；所有未通过项要区分行为回归、过期判据、环境错误和真正未验证。

### 阶段 3：无人机侦察与主力推进

- 512m 地图在经济稳定后副官本阶段目标为两架专职无人机，两个方向必须产生可量化的新视野覆盖；小地图不强制多机，不限制真人手动生产，不夺回玩家接管单位。
- 机场缺失时有一次建造路径，机场被毁或无人机损失后有节流、有界补造；已排队/在途/存活数量按身份去重。
- 无人机覆盖充分时不反复抽调小兵执行 `scoutconfirm`；只有专职侦察不足或局部确认时才允许应急抽兵，并记录原因和比例。
- 重新核实 `movement.py` 的 `RELAY_MAX_HOP_M=24` 是否实际加载，重跑主力推进统计；侦察、推进、攻击移动分别统计，不把历史 14m 与新口径混在一起。
- 先修复第一个不可见点之后重新可见的分离视野反例：可见圆盘并集不一定连续，禁止以端点可见或单调二分跳过盲区；保持计算有界和旧安全回归。

闸门：无人机损失、机场损失、模型 timeout/off、至少两个出生点；记录无人机覆盖、新区域数量、补造次数、小兵侦察占比和主力实际位移。

### 阶段 4：地图生成总进度流程图

在 `MapGeneration` 中央现有进度区域增加可读的总流程图，数据只来自真实 job/stages/progress：

`G1 出生布局 → G2 地形生成 → G3 资源与素材 → G4 游戏场景导出 → 引擎加载与导航验收`

每个节点显示编号、名称、状态文字和图标/形状；节点之间有方向连接线。状态必须同时有颜色和文字：完成、进行中、等待、失败、跳过。当前节点要有明显高亮和阶段细节；`attempt/limit`、耗时、错误或重试原因可在当前节点下显示。

进度口径：完整任务按五阶段显示；G2 快速预览按 G1/G2 显示，其余明确标为“快速预览未运行”；游戏内 `skip_engine_check` 必须显示“跳过：游戏内生成路径”，不得显示完成。done/pass=false 不能涂成绿色通过；失败阶段后续节点不能伪装成完成；重试/布局轮换/切历史时按对应 job 重算状态，终态保留全流程结果。

UI 保持截图中的暗色科幻风格：深色面板、青色当前、绿色完成、琥珀等待/提示、红色失败、灰色跳过；颜色必须配合编号、状态文字和图标，不能只靠颜色。中心流程图与右侧阶段检查共用同一状态源；窗口窄化时仍能读清，不能挤压地图预览和左右栏。

### 阶段 5：完整复验与报告

至少执行：Python 相关单测、地图工具阶段测试、C# 显式编译、地图 UI 脚本解析、相关 Godot 套件、真实 Match、5 FPS 视频录制和实际逐段回看。关键修复需要独立探针/独立会话复核。若全量回归仍有历史失败，必须附 rc、失败行、归因和是否新增。

## 停止条件

- 任何真实 Match 启动/结束异常、关键链路失败或相关回归失败时，候选立即拒绝，从 champion 重新开始。
- 连续三轮没有提升 champion 时停止重复微调，换诊断方向或结束当前阶段。
- 没有新鲜视频/截图、没有确认实际加载最新 DLL、或只靠静态代码推断时，状态保持 `needs-review`。
