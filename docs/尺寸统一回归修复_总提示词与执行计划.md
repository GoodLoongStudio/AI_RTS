## 统一尺寸模型

先建立每个单位的尺寸表，明确四个值：

1. visual_world_bounds：实际 GeometryInstance3D 世界包围范围。
2. collision_world_bounds：CollisionShape3D 经完整 global_transform 后的范围。
3. logical_world_radius：Movement 或 MovementObstacle 供游戏逻辑使用的世界半径。
4. navigation_world_bounds：导航障碍实际送入 Godot 烘焙的范围。

这四个值允许不同，但差异必须有明确用途，不能因为名字相同就假设数值相同。

当前建筑根节点使用 scale=3 时，CollisionShape3D 的本地半径应先按以下已知目标核对：

| 建筑 | 本地 CollisionShape 半径 | 逻辑世界半径 |
|---|---:|---:|
| CommandCenter | 2.333 | 7.00 |
| VehicleFactory | 2.217 | 6.65 |
| Barracks | 2.083 | 6.25 |
| OreRefinery | 3.267 | 9.80 |
| AircraftFactory | 2.667 | 8.00 |

这些数值必须通过运行时 global_transform、物理查询和截图复核，不能只相信注释或静态字符串。

重点检查：

- source/match/Match.gd 的实例化变换是否保留场景 root scale。
- source/match/units/traits/MovementObstacle.gd 的父缩放补偿是否和场景显式 scale 补偿重复。
- GodotStructurePlacementWorldPort.cs 是否对 MovementObstacle.radius 再次乘 scale。
- tests/automated/SizeAuditProbe.gd 是否把本地 shape 半径错误当成世界半径。
- 车辆、Worker、建筑的模型局部缩放是否造成视觉与逻辑尺寸脱节。

## 建造、碰撞和导航

普通建筑的相邻条件使用世界半径：

distance(candidate, own_structure) <= candidate_world_radius + existing_world_radius + 0.75

指挥中心可以作为远程锚点。建筑与建筑、建筑与资源的重叠必须硬拒绝。只有带 Movement 的己方机动单位才允许进入驱逐规划；建筑不能被当作可驱逐单位。

界面文字 “Something already occupies that spot” 不是根因。必须记录 primary issue、候选中心、候选世界半径、被检测节点和实际距离。

导航 carve 必须先确认 Godot 4.7.1 实际使用的是 NavigationObstacle3D 的 radius、vertices 还是两者组合，以及障碍 global scale 是否参与计算。用单障碍场景和 map_get_closest_point_owner 测量实际边界后，再统一 C#、GDScript 和审计脚本。禁止只根据注释决定公式。

导航图未完成时，测试必须等待有效 iteration 和 closest point；导航图完成后仍无导航面的候选点必须保留为真实失败。不能把所有 SurfaceNotBuildable 都归咎于初始化。

## 出生点和移动

生产出生点使用生产建筑的实际世界几何外缘，并满足：

distance(producer_center, spawn) > producer_world_bounds + produced_unit_world_radius + spacing

随后还必须复验：

- 不与其他单位、建筑和资源重叠。
- 在地图边界内。
- 四周采样点符合当前地形/导航规则。
- 单位从出生点能走到测试目标。

如果没有合法位置，生产项保持待部署或进入可重试状态；不要生成在建筑中心，也不要返回未验证的“建筑前方一点”。

先修正根节点缩放、CollisionShape 本地值、Movement/MovementObstacle 世界值和实例化 transform。修完后重新运行尺寸审计，再进入放置逻辑。

### 阶段 3：修复建造链

沿着 StructurePlacementHandler -> StructurePlacementRuntime -> StructurePlacementService -> GodotStructurePlacementWorldPort 追踪一次真实蓝图评估，修复相邻、Overlap、建筑硬阻挡、机动单位驱逐和 primary issue 记录。

用单障碍实验测量 carve，统一实际公式。验证基地旁、资源旁、地图边缘、窄通道和障碍移除后的导航恢复。

### 阶段 5：修复生产出生点

修复 UnitPlacementUtils.production_spawn_spot、ProductionQueue.gd 和 OreRefinery.gd。重点验证第一辆、连续三辆、建筑转向、被围堵和地图边缘。

### 阶段 6：闭环验证

每轮修改都执行：编译 C#、headless 定向测试、新进程启动、可见单机真实操作、状态读取和截图、实际打开截图检查、对比修复前后证据。

失败时分类为源码、测试夹具、旧程序集、导航异步、相机、插件或进程管理问题；分类后继续修复，不把失败隐藏成环境噪声。

## 最低验收清单

- 建筑相邻可建，脚印重叠拒绝。
- 建筑之间不会物理穿透。
- 建筑不会被错误的超大导航圈隔离。
- 己方机动单位可被安全驱逐，建筑不可被驱逐。
- 生产单位不在建筑内部、不越界、不进资源和水域。
- 被围堵时不强制生成，能重试或保留待部署。
- 单位真实到达移动目标。
- 单机 UI、蓝图、生产和选中流程均可用。
- headless 返回码、日志和截图检查全部通过。
- 新进程重复验证成功。
