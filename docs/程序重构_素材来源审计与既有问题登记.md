## 1. 统计口径

本文把素材分为四类：

- **外部导入源素材**：仓库中已有的 GLB、PNG、OBJ、音频等文件，且目录、Credits 或文件名能确认外部来源；
- **程序/工具生成素材**：仓库内存在明确生成脚本，并由脚本输出为文件；
- **引擎原生或程序构成**：Godot Control、PrimitiveMesh、Shader、场景节点和运行时代码组合，不是独立外部美术文件；
- **来源待确认**：仓库没有足够的版权或生成记录，不能仅凭观感推断。

“Godot 场景由程序员搭建”不等于“模型由程序生成”。例如 CommandCenter 是团队在场景中组合多个外部模型，但底层几何仍属于外部素材。

Godot 自动产生的 `.import`、`.godot/imported` 和 `.translation` 不计为原创美术素材。

## 2. 总体结论

### 2.1 单位和建筑模型

- `assets/models/kenney-spacekit` 包含 153 个 GLB，目录名及游戏 Credits 表明来自 Kenney.nl 的 3D Space Kit；
- 当前单位/建筑场景实际引用其中 21 个不同 GLB，共 22 次引用；
- 当前九种可玩单位/建筑全部依赖外部 Kenney 模型：4 种移动单位和 5 种建筑均不是从零程序生成；
- 建筑通常由程序员在 Godot 场景中组合、旋转和缩放多个 Kenney 部件；
- Helicopter 是混合构成：主体为外部 `craft_racer.glb`，旋翼使用场景内两个 BoxMesh 和一个 CylinderMesh；
- 碰撞体、选择圈、生命条、导航障碍等为引擎原生/程序构成，不计作单位主体美术。

因此，如果按“主体模型来源”统计：

| 对象 | 外部模型为主体 | 完全程序生成 | 混合/补充程序几何 |
|---|---:|---:|---:|
| 9 种可玩单位/建筑 | 9（100%） | 0（0%） | 1 种明确包含补充几何 |

### 2.2 UI

`assets/ui` 共有 213 个 PNG：

| 类别 | 数量 | 归类 | 使用情况 |
|---|---:|---|---|
| `kenney-crosshairs` | 200 | 外部导入；目录名指向 Kenney | 当前只发现 `crosshair062.png` 被点击反馈引用 |
| 单位/建筑/资源图标 | 11 | 仓库工具生成 | 由 `IconRenderBooth.gd` 截取场景渲染结果生成 |
| `icons/texture_01.png` | 1 | 来源待确认 | 用于图标渲染台背景/构图 |
| `background.png` | 1 | 来源待确认 | 主菜单背景 |

在可确认来源的 211 个 UI PNG 中，200 个为外部导入，11 个为仓库工具生成。若以全部 213 个文件为分母：

- 可确认外部导入：200，约 93.9%；
- 可确认程序/工具生成：11，约 5.2%；
- 来源待确认：2，约 0.9%。

这个比例容易产生误解：外部 Kenney 准星整包有 200 张，但运行中只使用 1 张；按“文件数量”外部素材占比很高，按“实际界面面积/控件数量”则不是如此。

当前界面的大部分结构由 Godot `Control` 场景或脚本构成：按钮、标签、面板、容器、进度条、颜色块、小地图单位标记等主要是引擎原生控件。CampaignMenu、CampaignController、Options、Play、Minimap 和 AICommandHUD 还会在运行时创建控件。因此：

- UI 布局/交互结构主要是程序和 Godot 场景构成；
- UI 位图文件主要是外部素材包，另有从外部模型渲染生成的图标；
- 目前没有足够证据把主菜单背景和 `texture_01.png` 归给团队原创或某个外部作者。

## 4. 图标生成链路

`source/utils/IconRenderBooth.tscn` 建立 11 个渲染对象：ResourceA、ResourceB、五种建筑和四种移动单位。`IconRenderBooth.gd` 逐个切换对象可见性，从 SubViewport 读取图像并写入 `assets/ui/icons/<Name>.png`。

因此这些图标属于“程序生成的派生文件”，但图标中呈现的模型仍来自外部 Kenney 素材。后续更换模型时可以复用该工具重新生成占位图标；正式 UI 图标是否继续使用这一方案，应等待 UI 设计评审。

## 5. 授权与来源风险

仓库 Credits 明确列出 `3D Space Kit by Kenney.nl`，但模型目录没有随附单独的许可证文件。项目负责人确认模型和准星来自 Kenney 官方资产页面；2026-08-12 复核 Kenney 官方 Support：其资产页面上的游戏素材为 CC0/Public Domain，可用于商业项目且不要求署名。官方 Crosshair Pack 页面也明确标注 CC0，并与仓库中的 200 张准星数量一致。

Kenney 素材当前授权风险较低，但仍建议为可追溯性补充来源记录：

- 每一素材包的来源链接、作者、版本和许可证；
- 许可证版本/官方 CC0 说明快照；
- 当前无需署名、允许修改和商业使用；
- 生成图标等派生文件的许可条件；
- 无法确认来源的文件应补证据或替换。

主菜单背景和 `texture_01.png` 仍未找到来源说明，需补证据或后续替换。本次记录不构成法律意见。

## 6. AI 副官 UI 与输入约束

- 冻结期为 AI 副官界面提供显示/隐藏按钮和持久化选项；
- 普通对局默认不显示 Legacy AI HUD；
- 隐藏状态不得遮挡地图，也不得继续响应其专属快捷键；
- 建立集中按键管理服务和 `user://controls.cfg`；
- 输入按 Global、Camera、Selection、UnitCommand、BuildPlacement、Menu/TextInput、LegacyAgent 等上下文管理；
- 第一阶段只做功能性配置、冲突检查和恢复默认，不投入额外 UI 视觉设计。

## 8. 测试与缺陷归因要求

重构切片的测试报告必须记录：

- 测试的旧提交与新提交；
- 相同场景、配置和操作步骤；
- 重构前是否能够稳定复现；
- 实际结果属于旧缺陷、迁移回归、有意改变还是未验证；
- 是否阻断当前接口迁移；
- 后续缺陷任务链接。

重构完成后需要覆盖传统 RTS 完整闭环，包括地面/空中单位、选择、移动、攻击、采集、建造、生产、集结点、战争迷雾、小地图、镜头输入上下文、规则 AI、任务流程和胜负。旧缺陷可以在阶段中暂留，但最终验收报告不能把它们隐藏在“迁移完成”结论中。
