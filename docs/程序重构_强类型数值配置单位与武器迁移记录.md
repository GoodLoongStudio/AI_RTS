## 1. 本轮结果

单位实例进入 Match 时，不再从 `Constants.Match.Units.DEFAULT_PROPERTIES` 按脚本路径复制基础属性。`BalanceConfigRuntime` 依据实例的 PackedScene 映射稳定 `UnitTypeId`，一次性注入该局不可变配置快照。

| 范围 | 当前权威字段 |
|---|---|
| 类型与生存 | `UnitTypeId`、`MaxHp`、`SightRangeMeters` |
| 移动 | `Domain`、`SpeedMetersPerSecond`、倒车倍率与能力、移动射击能力/射界 |
| Worker | `CarryCapacity`、`WorkPerTick` |
| 主武器 | `WeaponDefinitionId`、伤害、冷却毫秒、射程、目标域、交付方式 |
| 命中 | `WarheadDefinitionId`、选择模式、半径、友伤倍率 |
| 表现 | asset manifest 中的 Projectile PackedScene |

HP 当前在单位生成时初始化为配置的 `MaxHp`。施工中建筑的既有带伤进度逻辑仍可在生成后通过非伤害 HP 写入覆盖当前值，没有改变受击事件语义。

## 2. 武器发射快照

`ProjectileRuntime` 不再接受 GDScript 提供的投射物路径、伤害、范围或友伤参数。发射时按来源单位的稳定类型解析唯一主武器，并冻结：

- 武器交付方式与基础伤害；
- 弹头半径、友伤倍率和命中选择方式；
- asset manifest 中已预加载的投射物场景；
- 来源玩家、目标身份和发射时瞄准点。

因此发射单位随后停火、停止、死亡或退出 SceneTree，已经发出的炮弹/导弹仍按发射快照完成视觉与伤害结算。对地强制攻击仍在实际落点按 `Area` 语义查询，即使当前 Demo 半径为零。

当前 Legacy 执行器只支持每种单位一件主武器。配置模型继续允许多武器列表，为未来武器挂点和调度器预留接口；如果现阶段给运行单位配置多件武器，启动该单位时会明确失败，不会静默选择错误武器。

## 3. 空间半径保持解耦

本轮没有改动或合并：

- `NavigationAgent3D` 导航/避障半径；
- `NavigationObstacle3D` 建筑障碍几何；
- 选择圈与点击选择范围；
- 投射物命中候选使用的单位 footprint；
- 建筑放置 footprint 与视觉模型尺寸。

这些数值语义不同。导航振荡缺陷继续留在专项分支处理，不能借配置迁移改变寻路行为。

## 4. 兼容边界

- HUD 和规则 AI 仍读取 `DEFAULT_PROPERTIES` 显示生命、伤害、射程等说明，属于 `ECO-007D`；它们不再能覆盖真实单位数值。
- 主菜单预加载器仍读取旧 `PROJECTILES` 路径集合，实际发射已经只使用 manifest；该预加载兼容项在 `ECO-007D` 删除。
- `Unit.gd` 暂时保留 Legacy 属性名称，使现有 Action 和 HUD 无需同时重写；属性的值已经来自 Catalog。
- Beam、Instant、地雷、多武器调度和新增 AoE 数值不在本轮实现。

## 6. 人工验收建议

1. 检查 Tank、Helicopter、两类炮塔的射程、伤害节奏和可攻击目标域；
2. 检查 Tank/Worker/Drone/Helicopter 的移动速度和空地移动域没有变化；
3. 检查 Tank 仍可倒车撤退、移动射击和对地强制攻击；
4. 检查 Worker 仍携带两点资源，施工速度与迁移前一致；
5. 检查九种单位/建筑初始 HP、视野和战争迷雾表现没有变化；
6. 检查停火或发射者死亡后，已发射投射物仍正常命中一次。
