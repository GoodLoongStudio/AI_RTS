# 施工初始化误报受击语音缺陷记录

> 缺陷 ID：`ECO-010`
>
> 状态：已定位，延期至 `ECO-004` 施工生命周期或战斗反馈事件迁移时处理
>
> 首次确认：2026-08-14

## 1. 表现

Human 放置一个新建筑并开始施工时，即使周围没有敌人、没有投射物命中，语音系统也可能播放“建筑/基地正在被攻击”。

该现象不是 `ECO-001` 资源扣款失败，也不是权威账户造成的余额或建筑重复生成问题。

## 2. 已确认调用链

1. `Match._setup_and_spawn_unit()` 对新 `Structure` 调用 `mark_as_under_construction()`；
2. 此时节点尚未 Ready，`Structure.mark_as_under_construction()` 在 `hp == null` 时等待 `ready`；
3. 节点进入 SceneTree 后，`Unit._ready()` 从 `MatchConstants` 写入默认 `hp/hp_max`，建筑暂时成为默认满血；
4. 等待恢复后，`mark_as_under_construction()` 执行 `hp = 1`；
5. `Unit._set_hp()` 只判断“旧 HP 非空且新 HP 更低”，因此发出全局 `MatchSignals.unit_damaged`；
6. `VoiceNarratorController._on_unit_damaged()` 发现该单位属于 Human 且是 `Structure`，将事件映射为 `BASE_UNDER_ATTACK` 语音。

施工之后按进度执行的 `hp += 1` 不会触发 `unit_damaged`。误报发生在默认满血被重设为施工初始 1 HP 的下降阶段。

## 3. 根因分类

这是两个 Legacy 语义混用叠加产生的问题：

- 生命周期顺序：先应用普通单位默认满血，再把建筑改成施工初始血量；
- 事件语义：属性 setter 把所有 HP 下降都当成战斗伤害，没有伤害来源、攻击实例、变化原因或初始化标志。

语音控制器本身只消费 `unit_damaged`，没有足够信息区分真实攻击与施工初始化，因此当前表现符合错误事件输入，并非语音素材选择错误。

## 4. 后续处理原则

不建议在语音层简单增加 `not unit.is_constructed()` 过滤。施工中的建筑未来确实可能受到敌军攻击，这样会同时屏蔽真实预警。

后续重构建议：

1. 建筑在发布可观察事件前就以正确的施工初始 HP 建立，避免“默认满血后再降为 1”；
2. 将 `SetHealth/InitializeHealth/AdvanceConstructionHealth` 与真实 `ApplyDamage` 分开；
3. 只有真实伤害结算发布带来源的 `DamageApplied` 或等价权威事件；
4. 事件至少预留目标、伤害量、伤害来源/攻击实例和模拟 Tick；
5. 语音反馈监听真实伤害事件，再按所属玩家、目标类型、冷却和未来信息权限决定是否播放；
6. 自动测试覆盖施工初始化不预警、施工中真实受击会预警、10 秒语音冷却不回归。

## 5. 处理时机

该缺陷当前不阻塞资源账户与基础建造操作。实施修复需要同时确认施工 HP 生命周期和战斗伤害事件边界，计划随 `ECO-004` 或对应战斗反馈迁移切片处理；当前重构分支只保留记录，不修改运行时代码。
