# 集结点接口评审稿

> 日期：2026-08-15
>
> 工作项：`ECO-006`
>
> 状态：待接口评审

## 1. 目标与边界

本项把生产建筑的集结点从 `RallyPoint.gd` 可变节点迁移为 C# 权威状态和公共命令，使 Human、规则 AI、未来 Agent 与战役脚本可以通过同一入口设置、查询和清除集结点。

本项只定义“单位成功出厂后接收哪一个初始任务”。它不修改生产计时、退款和部署结果；不实现路径算法、编队、复杂出厂动画、巡逻路线、多个路点或战斗目标优先级。

## 2. 当前 Legacy 行为

当前行为分散在三个位置：

- `UnitActionsController.gd`：Human 右键地面或实体时直接修改选中建筑下的 `RallyPoint`；
- `RallyPoint.gd`：同时保存目标、跟随目标位置、控制标记显隐，并在目标退出 SceneTree 时重置；
- `ProductionQueue.gd`：单位生成后发出 `navigate_unit_to_rally_point`，再由 Human 控制器按上下文决定移动、跟随或采集。

现有语义：

1. 选中多座带 `RallyPoint` 的己方生产建筑，右键地面会为它们设置同一世界坐标；
2. 可以把集结目标设置为同一玩家的单位或建筑，也可以设置为资源节点；
3. 当前拒绝敌方实体，以免通过战争迷雾持续暴露敌方位置；
4. 实体目标移动时，标记节点每个物理帧跟随；目标退出 SceneTree 后集结点重置到生产建筑自身；
5. Worker 出厂并以资源节点为目标时会开始采集；对友军实体通常会跟随；地面坐标执行普通移动；
6. 地面集结位置与生产建筑位置相同时，被当作“没有集结点”的隐式哨兵值；
7. 当前没有单独的清除命令、稳定版本、所有权回执或 AI 公共入口。

## 3. 当前风险

1. `Node3D.global_position` 和 `target_unit` 同时承担权威状态与视觉表现，无法保存稳定快照；
2. Human 输入直接写节点，规则 AI 和未来 Agent 无法复用同一权限校验；
3. 出厂任务由 Human 控制器解释，即使单位属于其他控制者，也缺少明确的发行者身份；
4. 出厂后的移动/跟随可能直接创建 Legacy Action，绕过公共命令回执和订单记录；
5. 通过“坐标等于建筑坐标”表示清除，无法区分合法但无意义的位置与真正未设置状态；
6. 实体引用没有稳定 ID；目标失效、建筑失效和重复命令没有权威事件；
7. 生产完成流程需要知道 Legacy `RallyPoint` 节点，形成不必要的生产—UI 耦合。

## 4. 建议模型

建议使用显式联合目标：

```csharp
public abstract record RallyTarget;

public sealed record RallyPositionTarget(
    WorldPosition Position) : RallyTarget;

public sealed record RallyUnitTarget(
    UnitId TargetUnitId) : RallyTarget;

public sealed record RallyResourceTarget(
    ResourceNodeId TargetResourceId) : RallyTarget;

public sealed record RallyPointSnapshot(
    UnitId ProducerId,
    PlayerId OwnerId,
    RallyTarget Target,
    long Version,
    long UpdatedAtTick);
```

未设置状态由仓库中不存在快照表示，不再借用生产建筑坐标。位置、友军实体和资源节点保持强类型，避免把资源节点伪装成普通单位 ID。

首轮不保存队列式路径点。每座生产建筑至多一个当前集结目标，新命令原子替换旧目标。

## 5. 命令与回执

建议三个明确命令：

```csharp
public sealed record SetRallyPositionCommand(
    IReadOnlyList<UnitId> ProducerIds,
    WorldPosition Destination);

public sealed record SetRallyTargetCommand(
    IReadOnlyList<UnitId> ProducerIds,
    RallyTarget Target);

public sealed record ClearRallyPointCommand(
    IReadOnlyList<UnitId> ProducerIds);
```

批量命令对每座建筑独立返回，沿用 `Accepted / PartiallyAccepted / Rejected` 和逐实体错误。建议至少区分：

- Producer 不存在、已失效、不属于发行者或未完成施工；
- Producer 不支持集结点；
- 世界坐标无效或不在可用地图范围；
- 实体目标不存在、已失效、类型不允许或对发行者不可观察；
- 目标为敌方实体；
- 执行端或仓库不可用。

设置集结点不改变当前已出厂单位，也不影响生产队列。重复设置相同目标可以返回 Accepted，但只有快照真正变化时增加 Version 并发布事件，避免重复 UI 和语音。

## 6. 生产建筑资格

首轮只有当前 CommandCenter、VehicleFactory、AircraftFactory 支持集结点。能力由 `IRallyProducerRepository` 明确提供，不能由 Human HUD 是否显示按钮决定。

生产建筑必须存在、存活、已完成施工并属于命令发行者。未来若某种移动母舰或临时召唤建筑也支持集结点，只需在能力仓库注册，不修改命令 DTO。

## 7. 位置目标

位置目标应满足有限数值和地图范围校验。首轮允许玩家把地面集结点设置在战争迷雾内，因为这是位置意图，不读取隐藏实体信息。

不建议在设置时要求目标点当前可达：地形、桥梁和导航可能在生产完成前变化。出厂时普通移动命令仍可能因导航不可用而失败，但这不回滚生产完成，也不退款。

位置与生产建筑当前位置相同仍是一个显式有效状态；清除必须使用 `ClearRallyPointCommand`。

## 8. 实体目标与战争迷雾

为保持现有行为，首轮建议仅允许：

- 同一玩家拥有的单位或建筑；
- 当前可作为采集目标的资源节点。

不允许敌方实体作为集结目标。未来若需要“出厂后攻击该目标”，应使用生产计划或攻击任务接口，不能借集结点绕过战争迷雾和攻击权限。

实体命令是否可提交，应通过观察/权限端口判断；不能只相信 Human 已经点到了目标。这样未来大模型 AI 也会受相同信息边界限制。

目标在出厂前失效时，建议立即清除该生产建筑的集结点并发布 `RallyPointCleared(TargetLost)`。后续出厂单位保持待机，不自动前往目标最后位置。已经出厂并开始跟随或采集的单位由自己的订单生命周期处理，不受集结点后续变化影响。

## 9. 出厂任务分派

`UnitProductionCompleted` 只表示单位已成功部署。独立的 `RallyDispatchService` 订阅完成事件并读取该 Producer 的当前快照：

```text
UnitProductionCompleted
          │
          ▼
 RallyDispatchService ── 无集结点 ──> 单位待机
          │
          ├─ Position ──> 普通 Move
          ├─ Friendly Unit/Structure ──> Follow / MoveToEntity
          ├─ Resource + Worker ──> Gather
          └─ Resource + Other Unit ──> MoveToEntity
```

生产服务不读取 `RallyPoint` Node，不依赖 Human 控制器。分派失败只产生 `RallyDispatchFailed` 结果或事件；生产项目仍保持 Completed，单位留在合法出生位置。

首轮 Godot Adapter 可以继续兼容现有 Follow/MoveToEntity Action，但位置移动和 Worker 采集应优先复用已迁移的公共命令服务。后续对应单位任务完成迁移后再移除 Legacy 适配。

## 10. 事件

建议权威事件：

- `RallyPointChanged`：包含 ProducerId、新快照、旧目标是否存在和 Tick；
- `RallyPointCleared`：包含 ProducerId、原因 `Explicit / TargetLost / ProducerLost` 和 Tick；
- `RallyOrderDispatched`：包含 ProducerId、ProducedUnitId、目标快照和任务接收结果；
- `RallyDispatchFailed`：包含稳定失败原因，但不改变生产完成结果。

未来大模型 AI 是否能直接观察这些事件，由观察权限层过滤，不因为它调用了生产接口就自动获得完成或目标状态通知。

## 11. 视觉适配

现有绿色 `RallyPoint.tscn` 可以继续作为视图：

- 位置目标：显示在权威坐标；
- 实体目标：沿用目标高亮，标记本身隐藏；
- 清除或 ProducerLost：隐藏并释放绑定；
- 选择建筑时只读取权威快照，不反向修改状态。

本项不重新设计 UI 美术。建议增加一个暂时可调用的“清除集结点”入口或测试按键；正式按钮和交互由后续 UI 设计决定。

## 12. 自动验证建议

纯 C#：

1. 所有权、能力、施工完成状态和批量部分成功；
2. 位置有限值、地图范围和不要求即时可达；
3. 友军、资源、敌军、不可观察目标的资格；
4. 同目标幂等、替换目标和显式清除；
5. TargetLost、ProducerLost 清理及事件只发布一次；
6. 生产完成时读取最新快照并只分派一次；
7. 无集结点或分派失败不改变 Completed 生产结果。

Godot：

1. 多座生产建筑设置同一位置但状态彼此独立；
2. 出厂 Worker/Tank/Helicopter/Drone 前往位置目标；
3. Worker 以资源节点为目标时开始采集；
4. 友军移动目标可被跟随，目标失效后后续单位待机；
5. 敌方实体不能被设置为集结目标；
6. 清除后新出厂单位留在出生位置；
7. 不重复分派，不影响生产队列和退款。

## 13. 首轮不处理

- 多路点、巡逻、循环路线和路径拖拽；
- 共享全局集结点或多个工厂自动编队；
- 敌方攻击目标、护航、维修、装载或驻军等复杂出厂任务；
- 集结点可达性预计算和导航优化；
- 正式 UI、美术、动画和音效设计；
- 已经出厂单位随集结点修改而重定向；
- 联盟系统；首轮“友军”仅指同一玩家。
