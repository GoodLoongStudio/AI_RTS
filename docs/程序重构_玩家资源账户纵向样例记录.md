# 玩家资源账户纵向样例记录

## 1. 范围

`ECO-001` 将玩家余额从 `Player.gd` 的可写字段迁移为 Match 范围的 C# 权威账户，并保持现有采集、建造、生产和 HUD 行为可用。

本切片实现：

- 32 位整数 A/B 余额，任何对局均禁止负数；
- 一笔交易包含多种资源，并保证全部应用或全部拒绝；
- `ResourceTransactionId` 幂等和内容冲突检测；
- 初始余额、Worker 交付、建造/生产扣款及取消退款的强类型原因；
- Match 范围权威余额变化事件；
- `Player.resource_a/resource_b` 迁移期只读镜像；
- Human 与 SimpleClairvoyantAI 共用同一账户入口。

任务奖励、被动经济建筑和未来渐进支付只预留交易原因或边界，不在本切片实现。

## 2. C# 权威账户

Domain 新增 `ResourceAmount`、`ResourceDelta`、`ResourceAccountSnapshot` 和 `ResourceChangeReason`；公共身份新增 `ResourceTransactionId`。

Application 新增：

- `OpenResourceAccount`：为一个 `PlayerId` 幂等建立账户并导入非负初始余额；
- `ApplyResourceTransaction`：提交普通收入或支出；
- `ResourceTransactionResult/Status`：稳定区分成功、重放、余额不足、非法交易、溢出和 ID 冲突；
- `ResourceBalanceChanged`：每笔成功交易只发布一次；
- `IResourceAccountService` 与 `InMemoryResourceAccountService`。

多资源支出先在临时副本中完成全部 `checked` 运算；任一余额不足或溢出时，原账户完全不变。成功后账户版本只增加一次。

只保存成功交易的幂等记录。相同 ID 和相同内容重放返回 `AlreadyApplied`，不重复修改余额或发布事件；相同 ID 但内容不同返回 `TransactionConflict`。

## 3. Godot 适配与身份

`EconomyRuntime` 是 `Match.tscn` 的唯一经济组合根，负责：

- 注册 Player 并导入场景初始 A/B；
- 把 Legacy `resource_a/resource_b` 字典转换为强类型交易；
- 将成功快照同步回 Player 镜像；
- 向 Godot 发布 `BalanceChanged`；
- 为桥接期测试提供只读快照查询。

新增 `GodotStableIdentity`，使命令系统与经济系统读取相同 Metadata，并对同一 Player Node 使用同一 `PlayerId`。提供来源 Node 时，经济适配器使用其稳定 UnitId 作为可选 `SourceId`；没有稳定来源的交易允许为空。

`Player.gd` 仍保留原方法签名以降低迁移冲突，但 `add_resources/subtract_resources/has_resources` 已委托给 `EconomyRuntime`。账户初始化后，直接写入 Player 余额镜像会被拒绝；成功交易一次性更新 A/B 并发出一次 Legacy `changed`。

## 4. 已迁移调用点

| 调用点 | 交易原因 | 当前规则 |
|---|---|---|
| Worker 抵达 CommandCenter | `WorkerDelivery` | 交付成功后清空载荷；途中死亡不入账 |
| Human 放置建筑 | `ConstructionCost` | A/B 全部足够才生成建筑 |
| 三个规则 AI 建造控制器 | `ConstructionCost` | 资源请求满足后仍以原子交易最终确认 |
| 取消施工 | `ConstructionRefund` | 暂时全额退款 |
| 单位进入生产队列 | `ProductionCost` | 余额不足则不入队，不部分扣款 |
| 取消生产 | `ProductionRefund` | 暂时全额退款 |

旧 `allow_resources_deficit_spending` 已删除。需要资源的测试必须提供初始余额或提交 `ScriptedAdjustment` 调试交易，不能通过负余额绕过规则。

Legacy 施工节点还增加了取消标记：同一节点在 `queue_free` 真正退出前重复收到取消调用时，最多提交一次退款，避免迁移期每次包装调用都会生成新交易 ID 而形成重复退款。

## 6. 已知边界

- `Player.resource_a/resource_b` 仍存在于 GDScript 和场景序列化中，只作为迁移兼容镜像；HUD 迁移后才能删除；
- 当前 Legacy Adapter 为每次旧调用生成新交易 ID；未来跨语言或网络调用应由调用者携带稳定 ID，才能在重试时获得幂等保护；
- 生产队列项、任务和被动资源建筑尚无稳定身份时，`SourceId` 可以为空；
- 资源节点存量和 Worker 自身载荷仍属于 Legacy 执行层；
- 当前建造/生产必须预先拥有全部成本。余额不足时先排队、按收入渐进支付及资源分配策略已登记为 `ECO-009`；
- 受到攻击后的施工退款比例、资源上限和新经济来源需要后续策划评审。

## 7. 人工验收

运行 `tests/manual/TestAllUnits.tscn`：

1. 确认初始资源条没有负数；
2. 让 Worker 采集并完成一次交付，确认资源条只在交付后增长；
3. 余额不足时尝试生产或放置建筑，确认请求被拒绝且 A/B 都不被部分扣除；
4. 采集到足够资源后加入一个生产项，确认完整成本一次扣除；
5. 取消该生产项，确认按当前规则全额退款。

2026-08-14 部分人工验收通过：资源不足时无法建造，符合当前原子支付规则；Worker 交付已有前序人工结果。生产入队扣款与取消退款仍待人工检查。

验收期间发现的“新建筑开始施工时误播正在被攻击”已登记为 `ECO-010`。它来自 Legacy 施工 HP 初始化与受击事件混用，不属于资源账户扣款失败或余额分叉，本切片不修改。
