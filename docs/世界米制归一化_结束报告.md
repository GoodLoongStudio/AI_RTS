## 2. 迁移范围与契约

**契约**：`UnitRoot scale = 1`；美术缩放只出现在 Visual 分支（`Geometry`，炮塔在 `DetachTransform/Geometry`）；
碰撞 / 移动 / 障碍 / 出生点等玩法节点直接使用**世界米**；玩法代码不得从视觉缩放反推半径。

- 19 个场景：5 栋建筑 `3 → 1`、3 座炮塔 `2 → 1`、11 个机动单位 `2 / 1.35 → 1`
- 原根缩放系数被**忠实折算**进 Visual 分支（例：建筑 3.0、坦克 1.2、步兵 1.35），世界视觉外缘不变
- 唯一非 1 的保留项：`APC/GroundFootprint = 2` —— 经与 git HEAD 比对，是迁移前 `root=2` 的忠实折算（世界尺寸未变）
- 代码侧：`MovementObstacle` 的 carve 顶点改为**按世界 radius 直接生成**（`carve_vertices_from_radius`）；
  计划明令禁止的 `1/父缩放` 补偿结构（`_normalize_scale_for_carve`，0 调用点死代码）**已删除**

## 6. 未决项（需要用户拍板 / 仍在收尾）

1. **【需用户拍板】矿场占地 9.8m 是否为设计意图**：平衡表 `footprintRadiusMeters` 在工作树中由 **6.0 改成 9.8**（改动时间 09-29 01:22，早于本轮）。
   影响：carve 洞 = 9.8 + 2.8 = **12.6m**，而矿场"报到点下界" = 9.8+2.0+0.6 = **12.40m** ⇒ **余量≈0 甚至为负**（迁移前：洞 6.5~6.8m vs 报到点 8.60m，余量 1.8m）。
2. **【需用户拍板】密流"允许软重叠"是否可接受**：软通行实验位把 200 单位对向交叉从 **133–161s 降到 45–56s**（默认 **OFF**，位 `FLOW_BIT_SOFT=16`，
   软开时既有 `local-avoidance` 仍 0 failure）。它与"不得叠在同一点"的口径存在取舍；替代路线是**缩小接触半径 / 加大编队间距**
   （密度单因素：r=2.0 → 135s、r=1.5 → 110s、**r=1.0 → 36–38s**，自由行进地板 30s）。
3. **【收尾中】矿井可达性判据**：`map_get_closest_point` 不足以判定可达 —— 实测某矿点"就在网格上"（XZ 距离 0.00m）
   但落在**不连通的网格碎片**上，移动令**同一帧** Unreachable、工人位移 0。判据须用 `NavigationServer3D.map_get_path`（末点距 target > ~1m 即不可达）。
   refinery-engineer 正在把连通性并入"只服务可达矿"，并新增玩家可见指标**首次交付**（当前实测 7.1 / 15.1 / 35.7s）。
4. **【收尾中】残留清理**：`source/` 下 TEMP-DIAG 活跃打印已从 22 处降到 **16 处**，由 refinery-engineer 用精确编辑继续撤净
   （教训：禁止用正则批量删代码 —— 本轮曾因此留下 3 处孤儿续行，导致全项目解析失败约 9 分钟）。

## 7.6 矿井经济最后一块：连通性复核（领队补完）

问题B 冻结版（rule①「离最近可走点 XZ ≤ carve 净空 + 2.0m」）已把 ore-refinery 从 3 FAIL 打到 **0 FAIL**；
但 refinery-engineer 诚实报告：把 `map_get_path` 连通性复核**朴素地**接进 `is_ore_reachable()` 会让失败 **0 → 10**
（起点用了矿场自己的位置 —— 矿场坐在自己的 carve 洞里，从那里出发的路径对任何矿点都是空的），已按不劣化纪律回滚。

**领队补完**：把判定移到申领循环、**起点改用候选工人自己**（`_worker_can_reach_serviceable_ore`，
末点 XZ 容差 1.5m），A/B：ore-refinery **0 failure（62.0s）**、refinery-free-miner / production-queue / economy-account 全 rc=0 ✓。

> 意义：覆盖"在网格上但不连通"的矿点（实测 off-mesh = 0.00m 仍同帧 Unreachable）——
> 正是可见单机里"矿车停在远处矿点 6m 外、carry 恒 0"的成因。
