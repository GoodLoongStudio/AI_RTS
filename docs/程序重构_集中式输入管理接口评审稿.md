# 程序重构：集中式输入管理接口评审稿

## 1. 本轮结论

本轮只建立输入动作、键位配置、上下文仲裁和焦点隔离，不制作改键按钮、设置页面或其他按键 UI。正式 UI 由后续 UI 与操作策划评审。

传统单位命令仍通过既有按钮测试。没有玩家键位的动作可声明为“按钮/系统专用”，不得通过 `controls.cfg` 变成玩家可直接触发的功能。

## 2. 首版组合键规则

- 支持单独普通键，或一个 `Shift`、`Ctrl`、`Alt` 加一个普通键。
- 精确组合键优先：按下 `Ctrl+1` 时只解析 `Ctrl+1`，不会同时触发单独的 `1`。
- 首版拒绝 `Ctrl+Shift+X` 等多修饰键组合，避免在策划确定三键优先级前形成事实标准。
- 暂不规定 `Shift`、`Ctrl`、`Alt` 彼此的优先级；首版每个组合最多只含其中一个。
- 配置按批次原子应用：任一项非法或发生同上下文冲突，整批配置都不生效。

## 3. 输入上下文

优先级由高到低为：

1. `MenuTextInput`
2. `BuildPlacement`
3. `LegacyAgent`
4. `UnitCommand`
5. `Selection`
6. `Camera`
7. `Global`
8. `Debug`

同一按键可在不同上下文复用，但一次物理按键只分派给当前最高优先级动作。示例：

- Legacy AI 副官显示时，`Q` 触发其旧命令，不再旋转镜头；隐藏后恢复镜头语义。
- 建筑放置时，`R` 旋转蓝图，不触发 Legacy AI 侦察命令。
- 文本框获得焦点后，临时挂起进入前的游戏上下文；退出焦点时恢复快照，防止打字触发镜头、编组、建造或命令。

## 4. 配置与接口

- 权威定义：`DefaultInputBindings.Create()`。
- 纯 C# 规则：`IInputBindingService`，负责解析、冲突检查、覆盖与恢复默认。
- Godot 网关：Match 下的 `InputBindingRuntime`，负责物理键事件、上下文、按下状态和 `user://controls.cfg`。
- 本地配置包含 `schema_version=1`，不进入 Git；首版没有编辑 UI。
- 最小查询入口包括 `GetBinding`、`IsActionPressed`、`GetAxis` 和修饰键状态，便于人工测试与后续适配。

## 5. 当前默认键位与迁移范围

- 镜头：`W/S/A/D` 平移，`Q/E` 旋转。
- 编组：`1`～`9` 访问，`Ctrl+1`～`Ctrl+9` 保存。
- 建筑放置：`R` 旋转。
- Legacy AI 副官：仅在界面显示时启用原有 `F1`、`Enter`、`1`～`3`、`Q/W/E/R/D/F`。
- 传统单位命令栏的强制移动、强制攻击、停止、撤退、移动并攻击和姿态切换目前保持按钮/系统专用。

## 6. 验收重点

- `Ctrl+1` 保存编组但不访问编组，单独 `1` 仍可访问。
- AI 副官隐藏后，其旧快捷键完全失效。
- 输入聊天内容时，字母不移动/旋转镜头，也不触发编组或命令；`Escape` 只退出文本焦点。
- 建筑放置期间 `R` 只旋转蓝图。
- `controls.cfg` 存在非法、多修饰键或同上下文冲突时，整份覆盖被拒绝并保留默认值。

## 7. 延后事项

- 改键与冲突提示 UI。
- 两个以上修饰键、修饰键之间的优先级和更复杂的和弦序列。
- 鼠标按键、双击、长按以及不同硬件布局的完整可配置化。
- 正式玩家键位方案；当前默认值仅服务 Demo 与重构验证。
