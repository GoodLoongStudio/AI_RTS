# AI 副官 DGX3 推理后端计划（暂缓）

本文件记录后续把 DGX3 接入现有 AI 副官的方案。当前阶段不切换推理后端，先完成现有 Hermes 副官的控制链修复和无头对局闭环验证。

## 目标架构

```text
公网服务器
├─ Hermes 副官进程
├─ AI_RTS 游戏与 DebugControlServer
└─ LLM 路由
   ├─ 首选：Tailscale -> DGX3 推理 API
   └─ 备用：现有云端 API
```

公网服务器继续负责 Hermes、游戏和权威控制。DGX3 只负责模型推理，不直接运行 `rts_ctl.py`，也不直接修改游戏状态。

## DGX3 接入方式

- DGX3：`100.64.170.74`（Tailscale 地址，以实际状态为准）。
- 在 DGX3 上运行兼容 OpenAI API 的推理服务。
- 公网服务器通过 Tailscale 访问 DGX3 的私有 API。
- 推理服务只监听 Tailscale 网卡，并用 Tailscale ACL 和 API 认证限制访问。
- 现有 API 配置保留，作为故障切换路径。

## 分阶段切换

1. **基准**：继续使用现有 API，记录每轮耗时、命令成功率和对局结果。
2. **旁路**：把相同副官请求发送给 DGX3，但不使用其结果控制游戏，比较延迟、JSON 稳定性和策略差异。
3. **小流量接管**：DGX3 作为首选；超时、断线或非法 JSON 时自动切回现有 API。
4. **正式运行**：DGX3 首选，现有 API 长期保留为备用。

## 必测指标

- 公网服务器到 DGX3 的 Tailscale RTT。
- DGX3 首 token 延迟和完整响应耗时。
- 连续运行 1 小时的请求成功率。
- 多轮副官循环是否出现重复下单、错误生产者或非法攻击目标。
- DGX3 掉线后是否能自动回退 API，且不影响游戏控制循环。

## 控制链约束

模型推理结果只负责提出决策。`accepted`、`PendingAuthority`、生产队列变化、单位位置和对局结算仍必须以公网服务器上的权威游戏状态为准。
