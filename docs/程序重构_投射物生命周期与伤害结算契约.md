# 投射物生命周期与伤害结算契约

对应进度：`CMD-028`

## 1. 已确认规则

任何已经完成“发射”的攻击都获得独立生命周期：

- Stop、切换命令、切换交战姿态或开火策略，不删除已经发射的投射物；
- 发射单位阵亡或退出 SceneTree，不删除在途炮弹、导弹或其他攻击；
- 发射时快照本次攻击所需的伤害、阵营/来源 ID、目标或落点等数据，命中时不再依赖发射单位 Node；
- 伤害在视觉命中或约定的命中时刻结算，避免“先扣血、炮弹后到”的表现分裂；
- 已经发射的攻击不因来源失效而取消，允许单位阵亡前留下最后一发有效攻击；
- 目标先行死亡或失效时，投射物继续到最后有效位置完成合理的末端视觉，但不得访问失效 Node 或重复结算伤害；
- 后续 AoE、友伤比例、护甲等规则只改变命中结算，不改变投射物的独立生命周期。

## 2. 当前代码审计

当前 Legacy 实现不满足上述契约：

| 实现 | 当前行为 | 风险 |
|---|---|---|
| `CannonShell` | 作为发射单位子节点；在 `_ready()` 立即扣除实体目标 HP | 发射者死亡会删除视觉；伤害早于视觉命中 |
| `Rocket` | 作为发射单位子节点；命中动画回调读取父单位 `attack_damage` | 发射者死亡会删除导弹并失去结算来源 |
| `Rocket` 目标退出 | 直接 `queue_free()` | 在途导弹瞬间消失，缺少末端视觉 |
| 地面 ForceAttack | Action 先直接结算落点伤害，再创建发射者子节点视觉 | Stop/阵亡后视觉可能消失，伤害与视觉生命周期分离 |

因此，“Stop 后允许在途弹继续命中”目前只在部分即时伤害路径上表现为伤害已经发生，并不代表独立投射物契约已经实现。

## 3. 重构边界

`CMD-028` 应建立独立的投射物生成/结算入口，由 Match 级容器或专用服务持有投射物，而不是把投射物挂在发射单位下。发射事件至少应携带不可变快照：

- 来源稳定 ID 与阵营；
- 基础伤害及必要的伤害类型；
- 发射世界坐标和视觉朝向；
- 实体目标稳定 ID 或地面落点；
- 发射时模拟 Tick；
- 后续友伤、AoE 和护甲计算所需的版本化数值引用。

本切片不与 Stop 提交混合，避免在修订命令语义时同时改变全项目伤害时机。实施时必须覆盖 CannonShell、Rocket、地面 ForceAttack，以及“发射后来源阵亡”和“飞行中目标先失效”两类自动测试。
