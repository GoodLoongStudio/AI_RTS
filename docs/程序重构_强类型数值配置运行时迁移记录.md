## 1. 本轮目标与结果

本轮把资源采集时间、生产定义和施工定义切换到同一份 Match 配置快照，并建立 Godot 资源映射。运行链路为：

```text
demo.balance.v1.json ──严格加载──► IGameBalanceCatalog
                                            │
demo.assets.v1.json ──校验并预加载──► GodotAssetManifest
                                            │
                                            ▼
                    采集 / 生产 / 建筑放置与施工 Adapter
```

`BalanceConfigRuntime` 是 Match 的配置组合根，在其他运行时节点初始化前加载一次。任一 JSON 无效、引用悬空、资源缺失或映射不完整都会阻止对局启动，不会带着部分配置继续运行。对局开始后使用不可变快照，磁盘文件变化不会影响本局。

## 2. 已迁移内容

| 范围 | 迁移前 | 当前权威来源 |
|---|---|---|
| Resource A/B 采集时间 | GDScript 常量 | `ResourceDefinition.CollectionDurationMilliseconds` |
| 产品成本、工期、生产资格 | `GodotProductionDefinitionRepository` 硬编码字典 | `ProductionDefinition` |
| 每座生产建筑队列上限 | `ProductionService` 全局常量 | Producer 类型的 `QueueLimit` |
| 建筑成本、施工工作量、放置 footprint | GDScript 字典、场景临时实例与硬编码工作量 | `StructureConstructionDefinition` |
| 产品、蓝图和投射物场景 | 资源路径字典或代码目录 | `config/godot/demo.assets.v1.json` |

生产和施工继续调用既有玩家资源账户，不把经济收入与采集绑定。免费生产/施工定义允许空成本，并且不会构造空交易。主动取消退款、被摧毁不退款、队列隔离、施工带伤保留和多 Worker 行为没有有意改变。

## 3. 兼容边界

- `StructurePlacementRuntime.Evaluate/Place` 暂时保留第四个 Legacy 成本参数，便于 HUD 与规则 AI 分步迁移；参数已被忽略，不能覆盖 Catalog 成本。
- 现有 HUD 与规则 AI 仍可能读取 `Constants.Match.Units` 来决定按钮显示或尝试下单；它们将在 `ECO-007D` 切换后删除旧字典。
- 单位 HP、视野、移动和当前主武器运行值尚未迁移，属于 `ECO-007C`。
- 导航、碰撞、选择、命中和视觉半径没有合并；本轮只迁移明确属于建筑放置 footprint 的数值。
- 未增加对局内热更新，也未改变任何平衡数值。

## 4. Godot asset manifest 规则

`demo.assets.v1.json` 使用稳定 `UnitTypeId` / `WeaponDefinitionId` 映射 PackedScene。Loader 会检查：

- schema、必填字段、未知字段和重复 ID；
- ID 是否存在于同局 Balance Catalog；
- `res://` 路径是否存在且可作为 `PackedScene` 加载；
- 每个单位是否有生成场景、每个建筑是否有蓝图、每个 Projectile 武器是否有投射物场景；
- 一个单位场景不能映射到多个实体类型。

更换模型、蓝图或投射物表现只修改 manifest，不需要改平衡 JSON；修改成本、工期和采集速度则只修改 balance JSON。
