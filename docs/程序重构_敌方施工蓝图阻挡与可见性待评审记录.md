# 敌方施工蓝图阻挡与可见性待评审记录

> 日期：2026-08-15
>
> 状态：待策划评审，不在当前重构分支修改
>
> 工作项：`ECO-013`

## 1. 观察到的现象

项目负责人从 Main 进入自定义战斗时确认：传统敌人 AI 可以在远处直接放置建筑施工现场，并利用尚未真正开始施工的蓝图阻挡道路。敌方玩家目前还能看到这类蓝图。

这会产生两类尚未确定的玩法问题：

1. 零施工进度或 Worker 尚未到场时，建筑是否应该拥有实体碰撞和导航阻挡；
2. 玩家是否应该看见战争迷雾内、尚未开工或尚未侦察到的敌方施工计划。

本记录不把该现象直接定性为程序缺陷，因为“预占地”“工程准备阶段”“敌方情报可见性”和“用建筑封路”都需要策划规则支持。

## 2. 当前技术原因

当前放置成功后会立即生成完整 Structure 节点，再调用 `mark_as_under_construction()` 将施工进度设为零。该方法目前只执行：

- 切换为施工材质；
- 将初始 HP 设置为 1；
- 等待 Worker 贡献权威施工工作量。

建筑场景自带的 `CollisionShape3D`、导航障碍及其他空间组件没有随“未开工/施工中”阶段关闭。因此施工现场即使尚无 Worker 实际贡献，也已经可以参与碰撞或形成路径阻挡。

同时，当前状态模型只有“施工中”和“已完成”，没有独立的 `PlannedBlueprint`、`ReservedSite` 或 `ConstructionStarted` 阶段。放置预览是本地 Human UI 表现；规则 AI 调用公共 Place 后创建的则已经是实际战场实体，并非单纯的预览节点。

## 3. 策划需要确认的规则

后续专项评审至少需要回答：

| 议题 | 待确认选项 |
|---|---|
| 阻挡开始时机 | 放置即阻挡；首个 Worker 到场后；首次产生施工工作量后；达到进度阈值后 |
| 移动单位处理 | 未开工蓝图允许穿过；仅友军穿过；全部驱逐；敌军可占位阻止开工 |
| 导航预留 | 完全不影响导航；只做软成本；形成硬障碍 |
| 敌方可见性 | 永不显示计划蓝图；只有视野内显示；施工开始后显示；需要侦察能力 |
| 战争迷雾记忆 | 离开视野后隐藏、保留最后情报，或只保留已开工实体 |
| 可攻击性 | 未开工不可攻击；可清除蓝图；按 1 HP 实体攻击 |
| 退款与摧毁 | 取消、敌方清除、开工前失败分别如何退款 |
| 封路战术 | 完工建筑封路合理；未开工或低进度封路是否允许 |

## 4. 实现约束建议

- Human、传统规则 AI 和未来大模型 AI 必须调用同一 Place/Construction 接口，不能只限制传统 AI 的远程放置；
- 可见性由观察权限和战争迷雾查询决定，不能因 AI 内部拥有实体引用就直接显示给玩家；
- 碰撞、导航障碍、选择、可攻击性和视觉应由明确施工阶段分别控制，不能只绑定一个 `visible` 或 `is_constructed()`；
- 若增加 `PlannedBlueprint` 阶段，需要定义稳定状态、转换事件和存档/回放语义；
- 完工建筑通过围堵形成封路仍是已确认的合理战术，本项只讨论未开工及施工早期阶段。

## 5. 当前处理

当前重构分支不修改碰撞、导航、战争迷雾、AI 放置权限或施工状态机。后续在策划确认规则后建立独立需求分支；若只修复实现偏离既定规则，则建立独立缺陷分支。传统敌人 AI 的进一步运营与战术细化也不并入本项。
