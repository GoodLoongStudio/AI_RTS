# 程序重构：敌方建筑 LastKnown 观察纵向样例记录

## 1. 完成规则

- 只有普通会话通过 `ScanCircle` 实际观察过的敌方实体才建立记忆；知道场景中存在某个 Node 不等于观察者知道它。
- 当前 Demo 建筑的 `RetainsLastKnownWhenHidden=true`，失去视野后范围查询返回 `LastKnown`。
- 移动单位和资源节点默认不保留残影。
- 建筑在视野外被摧毁时，查询不能立即泄漏真实销毁状态，残影继续存在。
- 观察者重新获得最后确认位置的视野，并在包含该位置的范围查询中确认实体不存在后，残影自动清除且不会复活。
- 全知调试会话始终返回当前 `VisibleNow` 数据，不建立或污染普通会话记忆。

## 2. 时间语义

`QueryResult.ObservationRevision` 表示本次世界快照版本；`EntityObservation.ObservedRevision` 表示该实体字段最后被会话实际观察的版本：

- `Owned`、`VisibleNow` 的两个版本相同；
- `LastKnown.ObservedRevision` 保持最初或最近一次看到建筑时的版本；
- 调用方必须结合 `State` 和 `ObservedRevision` 判断信息是否过时，不能把残影 HP 当成当前 HP。

## 3. 视野与清除

Godot Adapter 现在为每个观察者复制当前圆形视野区域，不再依赖当前画面玩家的 `Node.visible`。清除残影需要同时满足：

1. 最后位置位于本次 `ScanCircle` 请求范围内；
2. 最后位置当前处于该观察者真实视野区域；
3. 本次范围结果中没有同一稳定实体。

仅请求一个仍处于战争迷雾中的区域不会清除残影。

## 4. 会话隔离

当前记忆按 `QuerySessionId` 隔离：

- 调试会话看到视野外单位不会给普通会话增加情报；
- 不同权限粒度的 Agent 不会通过共享缓存间接获得高权限字段；
- 未来如需玩家与盟友共享情报，应新增经过评审的共享知识域，不能直接合并会话字典。

## 5. 可扩展性

是否保留残影由权威快照字段 `RetainsLastKnownWhenHidden` 决定，而不是永久写死为 `Structure` 类型。因此未来移动要塞、伪装建筑、临时蓝图或阵营特殊单位可以通过强类型配置选择记忆策略。当前 Godot Demo 暂把已完成/施工建筑映射为保留残影，移动单位与资源映射为不保留。

## 6. 自动验证

纯 C# 新增两项生命周期测试：

- 敌方建筑失去视野后成为 `LastKnown`，同区域移动敌军不会产生残影；
- 建筑在视野外消失时残影保留，重新侦察空位置后清除且不会复活。

Godot 查询冒烟进一步验证真实 Match 场景中的建立记忆、失去视野、视野外销毁、全知会话差异和重侦察清除。

- 共享盟友视野和共享情报记忆；
- 伪装、隐形、间谍和错误识别信息；
