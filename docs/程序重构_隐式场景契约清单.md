# 程序重构：隐式场景契约清单

> 文档状态：重构前第一版清点
>
> 清点日期：2026-08-12
>
> 用途：在 GDScript 与 C# 并存迁移期间，识别不能无意改名或删除的运行时契约

## 1. 总览

当前仓库至少有以下高风险隐式依赖：

- 7 个 Autoload；
- 47 个脚本 Signal；
- 142 处 `find_child`；
- 18 处 `find_parent`；
- 大量场景组、固定节点名称、NodePath、场景资源路径和 InputMap Action。

这些契约没有编译期保护。迁移时应先由适配器保持兼容，再逐步替换为 C# 接口、导出引用、唯一节点名或强类型 ID。

## 2. Autoload 契约

| 名称 | 资源 | 当前职责 | 迁移规则 |
|---|---|---|---|
| FeatureFlags | `source/FeatureFlags.tscn` | 功能开关 | 可保留为装配配置，避免领域层直接引用 |
| Constants | `source/Constants.gd` | 聚合常量/数值/路径 | 迁移为强类型配置和稳定 ID |
| Globals | `source/Globals.gd` | 设置、缓存、God Mode | 拆为设置、调试、缓存服务 |
| MatchSignals | `source/match/MatchSignals.gd` | 比赛事件总线 | 区分 Command、Domain Event 和表现 Signal |
| Signals | `source/Signals.gd` | 通用事件 | 清点发布者/订阅者后收缩 |
| Utils | `source/Utils.gd` | 集合、节点、比赛工具 | 纯逻辑进入 C#；节点工具留 Godot Adapter |
| MCPRuntimeProbe | Godot MCP addon | 开发工具探针 | 不进入游戏领域或发布逻辑 |

## 3. 场景组契约

核心组名包括：

| 组名 | 含义/使用者 | 迁移风险 |
|---|---|---|
| `players` | Match、HUD、AI、调试、胜负 | 玩家顺序还被用于 `visible_player` 索引 |
| `units` | 选择、可见性、AI、胜负、动作 | 当前相当于全局实体注册表 |
| `controlled_units` | Human 可控单位 | 权限判断与 UI 同时依赖 |
| `adversary_units` | 当前 Human 的敌方单位 | 只适合单观察者语境，不是通用阵营模型 |
| `selected_units` | Human 本地选择 | 不应进入权威模拟状态 |
| `revealed_units` | 可见性/战争迷雾 | 与观察者权限耦合 |
| `resource_units` | 资源点 | 经济命令和小地图依赖 |
| `campaign_hero` | 战役英雄 | 应迁移为英雄身份/标签查询 |
| `unit_group_1..9` | 玩家控制组 | 本地应用状态，不应作为单位领域身份 |
| `terrain_navigation_input` | 地面导航烘焙输入 | Godot Navigation Adapter 内部契约 |
| `air_navigation_input` | 空中导航域 | Godot Navigation Adapter 内部契约 |

在替代接口合并前禁止直接改名。新增 C# 代码不得把这些字符串散落到领域层，应集中在 Legacy/Godot Adapter 常量中。

## 4. Match 根场景节点契约

`Match.gd` 及其子系统依赖以下稳定节点或路径：

- `Navigation`；
- `FogOfWar`；
- `IsometricCamera3D`；
- `Players`；
- `Terrain`；
- `HUD`；
- `HUD/AICommandHUD`（Legacy）；
- `HUD/MarginContainer/Minimap/...`；
- `Menu`；
- 动态挂载的 `Map`；
- 动态挂载的 `CampaignController`。

战役还依赖：

- `Map/CampaignZones/SignalGate`；
- `PerimeterCamp`；
- `AbandonedConvoy`；
- `EmergencyExtraction`；
- `CommunicationStation`；
- `TunnelExtraction`。

这些区域名目前既是关卡编辑标识也是任务逻辑键。迁移时应使用稳定 Objective/Marker ID，并由地图适配器解析到 Node。

## 5. 单位视觉与功能节点契约

统一视觉契约建议采用：

```text
UnitRoot
├─ VisualRoot
├─ CollisionRoot
├─ SelectionAnchor
├─ HealthBarAnchor
├─ GroundFootprint
├─ MuzzleAnchors
└─ OptionalAnimationRoot
```

迁移期间需要兼容的现有节点名包括：

- `Geometry` / `DetachTransform/Geometry`；
- `CollisionShape3D`；
- `Movement`；
- `Selection`；
- `Highlight`；
- `Targetability`；
- `HealthBar`；
- `MovementObstacle`；
- `ProductionQueue`；
- `RallyPoint`；
- `ProjectileOrigin`；
- `AnimationPlayer`、`AudioStreamPlayer`、`Timer`。

高风险特例：炮塔脚本通过导入 GLB 内部深层路径定位可旋转节点；替换模型时必须由 Visual Adapter 显式提供旋转根和炮口挂点，业务代码不得继续依赖 GLB 内部层级。

## 6. 场景资源路径契约

当前以下路径被当作类型 ID、配置键或动态加载入口：

- 九种单位/建筑 `.tscn`；
- 投射物场景；
- `Match.tscn`；
- 地图场景与 `MatchConstants.MAPS`；
- Human/AI 玩家控制器场景；
- 单人任务地图和英雄场景；
- 单位默认数值、生产成本、生产时间、投射物映射中的资源路径键。

重构时先引入 `UnitTypeId`、`StructureTypeId`、`MapId`、`ProjectileTypeId`，再由 Catalog/Factory 将稳定 ID 映射到 Godot 资源路径。重命名资源文件不应改变领域身份或存档数据。

## 7. InputMap 契约

已确认的主要 Action：

- 镜头：`move_map_up/down/left/right`、`rotate_map_clockwise/counterclockwise`；
- 选择：`shift_selecting`；
- 控制组：`unit_groups_set_1..9`、`unit_groups_access_1..9`；
- 建造：`rotate_structure`；
- 菜单：`toggle_match_menu`；
- 调试：`toggle_god_mode`、`god_mode_delete_units`、`toggle_frame_incrementer`、`frame_incrementer_step`、`toggle_diagnostic_mode`。

Legacy AICommandHUD 还直接使用物理键 `F1`、`1/2/3`、`Enter`、`Q/W/E/R/D/F`，没有经过 InputMap；其中 Q/E 与镜头旋转冲突。

新 `IInputBindingService` 应以稳定 Action ID 管理，并按 Camera、Selection、UnitCommand、BuildPlacement、Menu/TextInput、LegacyAgent 上下文启停。迁移完成前保留现有 Godot Action 名作为适配键。

## 8. Signal 契约

`MatchSignals` 的主要事件包括：

- 选择/目标：`deselect_all_units`、`terrain_targeted`、`unit_targeted`、`unit_selected/deselected`；
- 生命周期：`setup_and_spawn_unit`、`unit_spawned/damaged/died`；
- 生产建造：`place_structure`、`unit_production_started/finished`、`unit_construction_finished`；
- 资源失败：`not_enough_resources_for_production/construction`；
- 导航：`schedule_navigation_rebake`、`navigate_unit_to_rally_point`；
- 比赛：`match_started/aborted/finished_with_victory/defeat`。

迁移原则：请求行为改成有返回值的 Command；已经发生的状态变化改成 Domain Event；HUD、动画和音频需要的通知再桥接为 Godot Signal。

## 9. 配置与用户文件契约

- Godot Options Resource：现有窗口与鼠标设置；
- `user://camera.cfg`：镜头参数；
- 计划新增 `user://controls.cfg`：按键配置、版本和覆盖；
- 后续存档/数据库不得直接序列化 NodePath、Instance ID 或场景树引用。

配置格式必须带版本；稳定 ID 的重命名需要显式迁移，而不是静默失效。

### 9.1 C# 导出属性序列化

Godot 4.7 Mono 的 C# `[Export]` 属性在文本场景中按 C# 属性名序列化。例如 `VisualRootPath` 在 `.tscn` 中必须写作 `VisualRootPath`，不能按 GDScript 习惯写作 `visual_root_path`。手工修改 C# 场景绑定后必须进行一次无头实例化测试，不能只依赖 C# 编译通过。

## 10. 迁移检查规则

每个迁移 PR/本地切片在改动场景前回答：

1. 是否改动了本清单中的 Node 名、组名、Signal、Input Action 或资源路径？
2. 哪些旧调用者仍依赖它？
3. 是否提供兼容适配器或一次性迁移？
4. 自动化测试是否覆盖契约断裂？
5. 手动场景是否需要重存，是否会制造无关差异？

本清单是第一版，后续应在迁移每个子系统时补充更细的发布者/订阅者和场景路径表。
