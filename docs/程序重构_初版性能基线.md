# 程序重构：初版性能基线

## 1. 目的与边界

QA-006 只建立可重复运行、可比较的初版测量方法，不设置性能验收门槛，也不授权实施多线程、并发、Flow Field 等复杂优化。

本基线使用 `TestPlayerVsAI` 完整对局夹具，覆盖己方初始单位、传统敌人 AI、经济、建造、生产、战斗、导航、战争迷雾和 HUD 等当前 Demo 运行链路。它适合发现同一环境下的明显性能回退，但不代表正式玩家画面的渲染帧率或大规模单位上限。

## 2. 测量方法

| 项目 | 固定设置 |
|---|---|
| 场景 | `res://tests/performance/PlayerVsAiPerformanceBaseline.tscn` |
| 对局夹具 | `res://tests/manual/TestPlayerVsAI.tscn` |
| 运行模式 | Godot .NET，无头模式，固定模拟频率 60 Hz |
| 预热 | 300 帧，即 5 秒模拟时间 |
| 正式测量 | 1800 帧，即 30 秒模拟时间 |
| 终局处理 | 测量期间关闭终局暂停，保证样本帧数完整 |
| 输出 | 单行 JSON、原始 stdout/stderr、带机器信息的 `summary.json` |

测量内容包括：

- 每帧实际墙钟耗时的平均值、p50、p95、p99 和最大值；
- 模拟时间与墙钟时间之比；
- Godot `Performance` 的 process、physics process、navigation process 监视器；
- 静态内存、Object、Node、孤儿 Node 和单位数量峰值；
- Godot、.NET SDK、操作系统、处理器、逻辑处理器数和 Git commit。

## 3. 运行方法

在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\run_performance_baseline.ps1
```

如果已经单独执行并通过 `dotnet build`，可以使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\run_performance_baseline.ps1 -SkipBuild
```

结果写入 `.test-results/performance/<时间戳>/`。该目录只保存在本地并由 Git 忽略；需要长期保留的基线摘要应复制到本文档或后续性能报告中。

## 5. 结果解释规则

1. 只比较 Godot 版本、构建配置、固定频率、场景、预热帧和测量帧一致的结果。
2. 优先比较模拟/墙钟倍率、墙钟 p95/p99、内存峰值和单位峰值；单次最大帧容易受启动、资源加载和操作系统调度影响。
3. 无头模式使用 Dummy renderer，因此本结果不能判断 GPU、材质、阴影、粒子、UI 绘制或玩家窗口帧率。
4. 当前只有 14～17 个单位，不代表大规模多单位、复杂障碍导航和群体避让性能。
5. 发现回退后应先建立可复现样例并归因，再决定是否优化；复杂并发优化必须另行评审。
