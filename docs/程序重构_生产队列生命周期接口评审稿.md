# 生产队列生命周期接口评审稿

> 日期：2026-08-15
>
> 工作项：`ECO-005`
>
> 状态：待接口评审

## 1. 目标与边界

本项迁移已经完成施工的生产建筑所持有的单位生产队列：入队、原子扣款、顺序推进、取消退款、生产完成、出口部署和生产建筑失效。

集结点命令属于 `ECO-006`；强类型数值配置属于 `ECO-007`；渐进支付和资源分配属于 `ECO-009`；导航网格、局部避障、维修、占领和拆除不在本项实现。

## 2. 当前 Legacy 行为与风险

`ProductionQueue.gd` 当前同时负责资源扣款、浮点计时、队列对象、取消退款、寻找出生点、生成单位、全局事件和集结点移动。

主要问题：

1. 队列项只是内部 `Resource` 对象，没有稳定 ID、版本、终态或可审计快照；
2. Human、规则 AI 和未来 Agent 没有公共生产命令；规则 AI 可通过 `ignore_limit=true` 绕过队列上限；
3. “某建筑可以生产哪些单位”只由 UI 菜单和 AI 调用约定限制，Application 层没有能力校验；
4. `_process(delta)` 直接推进浮点秒数。发生长帧时，完成一个项目后没有正确计算剩余 delta，可能让后续多个项目重复消费同一帧时间；
5. 完成时立即同步搜索出生点，搜索上限极大，无法表达“已生产完成但出口暂时被阻挡”；
6. 生产建筑被摧毁时，队列随 Node 消失，没有逐项终态、退款原因或事件；
7. `unit_production_started` 在项目入队时发布，即使项目还排在队尾，名称与真实开始生产的时刻不一致；
8. `cancel_all()`、HUD 点击和规则 AI 直接持有 Legacy 队列对象，难以保证幂等退款。

## 3. 建议分层

```text
Human 菜单 / 规则 AI / 未来 Agent / 战役脚本
                         │
                         ▼
              ProductionService
       ├─ Enqueue / Cancel / CancelAll 回执
       ├─ 每 Producer 的顺序队列与稳定 ItemId
       ├─ 每 SimulationTick 的整数工作量
       ├─ 原子扣款、幂等退款与 ProducerLost
       └─ Queued / Producing / AwaitingDeployment / 终态事件
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
 IProductionDefinitionRepository  IProductionDeploymentPort
 生产资格、成本、时间、领域       出生空间、生成 Node、Legacy Signal
```

Domain/Application 不引用 `PackedScene`、Node、SceneTree、导航 RID、`delta` 或 HUD；Godot Adapter 负责定义与场景的映射、出生位置检查、节点生成和旧 Signal 兼容。

## 4. 稳定身份与快照

建议新增：

```csharp
public readonly record struct ProductionItemId(Guid Value);
public readonly record struct ProductionDefinitionId(string Value);

public sealed record ProductionItemSnapshot(
    ProductionItemId ItemId,
    UnitId ProducerId,
    PlayerId OwnerId,
    ProductionDefinitionId DefinitionId,
    int RequiredWork,
    int CompletedWork,
    IReadOnlyList<ResourceAmount> PaidCost,
    ProductionItemState State,
    long Version);
```

队列顺序由 Producer 下的稳定 `ProductionItemId` 列表表达，不把易变化的 `QueueIndex` 作为身份。查询时可以返回当前索引。

## 5. 状态机

建议状态：

```csharp
public enum ProductionItemState
{
    Queued,
    Producing,
    AwaitingDeployment,
    Completed,
    Cancelled,
    ProducerLost
}
```

- `Queued`：已扣款并入队，尚未获得生产线；
- `Producing`：位于队首并推进整数工作量；
- `AwaitingDeployment`：工作量完成，但当前无法安全生成单位；
- `Completed`：单位已成功生成；
- `Cancelled`：拥有者主动取消并完成一次退款；
- `ProducerLost`：生产建筑失效，是否退款由本次评审决定。

所有终态不可逆。`AwaitingDeployment` 仍占用队首和生产线，避免出口被封锁时后台无限生产、最终瞬间堆叠大量单位。

## 6. 命令与回执

```csharp
public sealed record EnqueueProductionCommand(
    UnitId ProducerId,
    ProductionDefinitionId DefinitionId);

public sealed record CancelProductionItemCommand(
    ProductionItemId ItemId);
```

Enqueue 同步回执至少区分：

- `Accepted`，并返回新 `ProductionItemId`；
- Producer 不存在、不属于命令发出者、未完成施工或已失效；
- Producer 不具备目标单位生产能力；
- 定义不存在或不可用；
- 队列已满；
- 资源不足或账户服务不可用。

Accepted 只表示扣款和入队完成，不表示已经开始生产或已经生成单位。未来多选生产建筑可以由批量网关逐 Producer 返回部分成功，不改变单队列核心命令。

Cancel 通过稳定 ItemId 定位，不接受 Legacy `Resource` 引用或队列索引。`CancelAll` 是对当时队列 ItemId 快照逐项取消的便捷命令，并返回逐项结果。

## 7. 生产资格与队列容量

建议由 `IProductionDefinitionRepository` 明确保存：

- 稳定产品定义 ID；
- 成本；
- RequiredWork；
- 产品移动领域和部署 Adapter 键；
- 哪些 ProducerDefinitionId 可以生产该产品。

首轮把当前 3 秒/6 秒换算为 180/360 个 60 Hz 物理 Tick。具体值后续迁至 `ECO-007`。

当前 Human 队列上限是 5，规则 AI 可以绕过。建议首轮统一为每个 Producer 最多 5 项，Human、规则 AI 和未来 Agent 一致。若战役脚本需要无视上限，应使用单独的授权上下文，而不是公开 `ignore_limit` 布尔参数。

## 8. 推进、暂停与顺序

每个 Producer 同时只有队首一项处于 `Producing` 或 `AwaitingDeployment`，其余为 `Queued`。每个物理 Tick 只推进一次整数工作量，不使用帧 `delta`。

本轮不增加玩家手动暂停生产按钮。未来停电、瘫痪、占领过渡或剧情冻结可通过 Producer 可运行状态使队首暂时不贡献工作量，但不改变 ItemId 或已支付成本。

## 9. 完成与部署

工作量达到 RequiredWork 时，项目进入 `AwaitingDeployment`，由部署端口尝试：

1. 按产品移动领域查找合法出生位置；
2. 成功后生成单位并取得稳定 UnitId；
3. 项目进入 Completed；
4. 发布权威完成/部署事件；
5. 下一队列项在后续 Tick 进入 Producing。

若出口被阻挡或导航空间暂不可用，项目保持 `AwaitingDeployment`，后续低频或每 Tick 重试，但不得重复生成、重复完成或让后续队列越过。

现有集结点移动只作为 Completed 后的兼容 Adapter 调用，正式 `SetRallyPointCommand` 留给 `ECO-006`。

## 10. 扣款、取消、建筑失效

沿用已确认经济规则：

- 入队时所有资源足够才以一笔原子交易完整扣款；
- 主动取消 Queued、Producing 或 AwaitingDeployment 项目，首轮均全额退款；
- 每个项目保存扣款与退款的稳定交易身份，重复取消不得重复入账；
- Completed 项目不能取消或退款；
- 退款来源使用 ProductionItemId，不再只记录 Producer Node。

生产建筑被摧毁需要本次评审决定。建议首轮所有未完成项目进入 `ProducerLost` 且不退款，与“施工中建筑被摧毁不退款”一致，并保留进攻摧毁经济目标的收益。玩家主动拆除、出售或占领属于不同原因，后续可以配置不同退款/转移规则。

## 11. 事件与 AI 信息边界

建议权威事件分为：

- `ProductionQueued`：扣款并入队；
- `ProductionStarted`：项目首次成为队首并开始推进；
- `ProductionAwaitingDeployment`：工作完成但尚未生成；
- `UnitProductionCompleted`：生成成功，包含 ItemId、ProducerId、ProducedUnitId、DefinitionId、Tick；
- `ProductionTerminated`：Cancelled 或 ProducerLost。

现有 `unit_production_started/finished` 由 Godot Adapter 兼容发布。同步命令回执和异步事件分离；未来大模型 AI 是否能观察这些事件，仍由观察/权限层过滤。

## 12. 自动验证建议

纯 C#：

1. 生产资格、所有权、施工完成状态与资源不足校验；
2. 队列上限对 Human/规则 AI 一致；
3. 多资源原子扣款和 ItemId 关联；
4. 只有队首推进，长 Tick/重复 Tick 不重复计算；
5. 3 秒/6 秒定义换算后的完成顺序；
6. 部署受阻保持 AwaitingDeployment 并阻塞后续项目；
7. 重试成功只生成一次并发布一次完成事件；
8. 取消任意位置项目全额、幂等退款；
9. ProducerLost 的全部逐项终态与退款规则；
10. 快照不可反向修改内部队列。

Godot：

1. CommandCenter、VehicleFactory、AircraftFactory 只接受各自合法单位；
2. Human HUD 入队、进度、点击取消与退款；
3. 规则 AI 不再绕过统一队列上限；
4. Worker、Tank、Helicopter、Drone 正确按移动领域部署；
5. 出口阻挡时不堆叠、不丢失、不重复生成，解除后完成；
6. 生产建筑被摧毁后的队列终态与资源结果；
7. 完成后现有集结点兼容行为不回归；
8. 开始、完成和资源不足语音不重复。

## 13. 首轮不处理

- 并行生产线、多工厂共享全局队列或工厂加速；
- 渐进支付、低余额预下单和资源分配优先级；
- 玩家手动暂停、调整队列顺序、拖拽或批量重复生产 UI；
- 单位升级、科技前置、人口上限与维护费；
- 生产建筑占领、出售、拆除及队列转移；
- 导航网格与局部避障算法优化；
- 正式集结点命令与复杂出厂动画。
