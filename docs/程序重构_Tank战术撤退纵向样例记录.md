# Tank 战术撤退纵向样例记录

> 日期：2026-08-12  
> 范围：Tank 撤退命令、路径相对倒车朝向、停止语义及移动射界约束

## 1. 已确认规则

- 撤退不锁定命令下达瞬间的朝向；
- 有倒车能力的单位将车尾对齐导航系统本帧给出的安全移动方向；
- 路径转弯、避障或重寻路时，车体按局部路径切线连续调整；
- 无倒车能力但可移动的单位退化为普通移动，不要求玩家拆分选择并重复下令；
- 不可移动单位逐单位拒绝，批量命令保留部分成功语义；
- 撤退仍创建 `TacticalWithdraw` 订单，退化执行不丢失玩家原始意图；
- “停止”暂停正在执行的撤退订单。

## 2. 攻击约束

撤退不是强制攻击授权。单位只有同时满足以下条件才会在移动中开火：

1. `FirePolicy` 允许开火；
2. 单位具备移动射击能力；
3. 目标位于射程和可攻击域内；
4. 目标位于武器相对底盘的移动射界内。

Tank 灰盒配置当前声明可移动射击，移动射界暂设为车头方向总计 120°。这些值属于迁移期能力参数，后续应进入版本化单位数值配置，不能作为最终平衡值。

## 3. 实现边界

Application 命令和订单为 C#；Godot 导航、底盘旋转及当前武器 Action 仍由 Legacy GDScript Adapter 承接。底盘使用导航 `safe_velocity`，而不是“当前位置到最终目的地”的直线向量，因此路径转弯语义不依赖 UI 计算。

## 4. 验证

- `CSharpCommandSmokeTest`：倒车能力分流、普通移动退化及订单分类；
- `TankTacticalWithdrawSmokeTest`：命令接收、实际位移、车头与撤退位移反向、停止暂停订单；
- `TraditionalUnitCommandHudSmokeTest`：撤退按钮可用、进入和取消一次性目标模式；
- `tests/manual/TestTacticalWithdraw.tscn`：人工观察路径转弯、射界和停火表现。

当前未加入复杂动态障碍和多段固定路线的确定性自动测试；路径转弯视觉先由人工场景验收，之后随导航测试夹具补齐。
