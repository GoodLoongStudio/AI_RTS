# 程序重构：订单异步状态事件契约

日期：2026-08-14

## 1. 目的

统一移动、攻击、停止、替换、目标失效和单位损失产生的异步订单事实，避免各 Godot Signal、HUD 或 AI 控制器分别解释订单生命周期。

## 2. 核心契约

核心程序集定义：

```csharp
public sealed record UnitOrderStateChanged(
    UnitOrderSnapshot? Previous,
    UnitOrderSnapshot Current);
```

`IUnitOrderStore.StateChanged` 是进程内权威事件源：

- 创建事件的 `Previous` 为 `null`；
- 状态转换事件同时携带前后快照；
- 只有存储成功写入后才发布；
- 重复状态不发布；
- 事件不包含 Godot 类型。

## 3. 状态含义

| 状态 | 含义 | 是否终态 |
|---|---|---|
| `Accepted` | 命令校验与端口初步接收成功 | 否 |
| `InProgress` | 执行层正在执行 | 否 |
| `Suspended` | 任务保留，但不会自动恢复 | 否 |
| `Arrived` | 移动订单到达 | 是 |
| `Unreachable` | 稳定重新寻路后确认不可达 | 是 |
| `TargetLost` | 依赖的实体目标失效 | 是 |
| `Cancelled` | 被新命令替换或被明确取消 | 是 |
| `UnitLost` | 执行单位失效 | 是 |

旧订单被替换时，`ReplacedByCommandId` 保存新命令 ID。暂停本身不是终态，因此后续新命令仍能将其转换为 `Cancelled`。

## 4. Godot 适配

Match 唯一 `CommandRuntime` 订阅核心事件并发布 `OrderStateChanged` Signal。GDScript 使用显式 C# Signal 名称连接：

```gdscript
command_runtime.connect("OrderStateChanged", callback)
```

不得假设 C# Signal 会自动暴露为 snake_case 属性。

`UnitCommandGateway.GetOrderSnapshot(order_id)` 提供迁移期查询接口。Signal 适合及时响应，快照查询适合重连、UI 刷新和测试，两者共享同一订单存储。

## 5. 可观察性与安全

该事件是内部权威事实，不是直接提供给所有命令来源的公共观察流。未来流程必须为：

```text
OrderStateChanged
    → Query / Feedback Policy
    → Human UI/Voice、Rule AI 或 LLM 可见结果
```

过滤层负责战争迷雾、所有权、操作点、信息时效性和反馈粒度。尤其是大模型适配器不得直接订阅原始 Match Signal。

## 6. 验证

- 纯 C# 核心测试：创建、执行、暂停、取消及重复状态抑制；
- `TankCommandBridgeSmokeTest`：到达、暂停、迟到完成、替换和 `UnitLost`；
- `TankForceAttackSmokeTest`：目标死亡发布 `TargetLost`；
- `GetOrderSnapshot`：订单类型、状态和替换命令 ID 与事件一致。

`Unreachable` 的导航判定延期到导航专项分支，但事件与状态接口已经稳定预留。
