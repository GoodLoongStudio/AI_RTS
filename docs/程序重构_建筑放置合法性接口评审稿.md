# 建筑放置合法性接口评审稿

> 状态：2026-08-15 接口评审完成；首轮代码与自动测试已实现
>
> 对应工作项：`ECO-003`
>
> 本稿确定建筑放置预览、权威复验和 Godot 空间查询边界；施工进度、Worker 工作任务、取消退款和完成事件仍属于 `ECO-004`。

## 1. 当前实现

Human 放置流程集中在 `StructurePlacementHandler.gd`：

1. Worker 菜单通过全局 `MatchSignals.place_structure` 发送 `PackedScene`；
2. Handler 根据 `STRUCTURE_BLUEPRINTS` 创建表现蓝图；
3. 每次鼠标移动依次检查中心点是否在地图、资源是否足够、圆形半径是否碰撞、九个采样点是否位于 NavMesh；
4. 鼠标释放时重新检查一次；合法则扣款、实例化建筑并通过全局 Signal 生成；
5. `UnitActionsController` 监听任意新单位生成，再把当时仍被选中的 Worker 直接设为 Legacy Constructing Action。

规则 AI 不经过 Human Handler。三个 AI Controller 分别调用径向找点工具、扣款并直接生成建筑，随后 `ConstructionWorksController` 再随机指定 Worker。因此 Human 与规则 AI 没有共享同一权威放置规则或回执。

## 2. 已发现风险

| 风险 | 当前表现 | 重构约束 |
|---|---|---|
| 身份泄漏 | 以 Godot `PackedScene.resource_path` 作为建筑类型 | 公共接口使用稳定 `StructureDefinitionId`，场景路径只留在 Adapter |
| 地图边界 | 只检查建筑中心点 | 完整 footprint 必须包含在可建造区域内 |
| 形状精度 | 所有建筑与阻挡物都简化为圆形 radius | 契约允许圆、定向矩形或凸多边形；首轮 Adapter 可继续圆形 |
| 导航耦合 | NavMesh 九点采样同时代表“地面可建造” | Domain 只认识可建造表面；Godot NavMesh 只能是迁移期实现手段 |
| 旋转 | 合法性基本忽略朝向 | Candidate 必须包含规范化 Yaw；定向 footprint 按旋转后形状判断 |
| 错误遮蔽 | 资源不足时不再检查碰撞和表面 | 预览返回完整问题集合，并提供稳定 PrimaryIssue |
| 最终竞态 | 预览合法后另行扣款和生成 | 最终 Place 必须再次复验，不能信任旧预览 |
| 信息泄漏 | 隐藏敌军也参与蓝图碰撞并改变颜色 | 权威阻挡仍生效，但反馈不能返回隐藏实体身份；后续接查询权限过滤 |
| 控制器分叉 | Human 与规则 AI 使用不同找点/生成路径 | Human、规则 AI 和未来 Agent 使用同一评估与最终提交入口 |
| Worker 耦合 | 放置信号不含发出者或 Builder；生成后读取“当前选择” | 放置与施工命令分离，不能让 SceneTree 当前选择成为权威事实 |

另有独立 UI 缺陷：`_rotate_blueprint_towards_mouse_pos()` 使用 `Vector3(-999, 0, -999)` 处理蓝图位置，导致旋转死区距离失真。登记为 `ECO-011`，不在接口评审阶段顺手修改。

## 3. 职责分层

```text
Human 蓝图 / 规则 AI 选点 / 未来 Agent
                    │
                    ▼
     Application StructurePlacementService
       ├─ 结构、权限与定义检查
       ├─ 调用权威空间评估端口
       ├─ 读取资源账户快照用于预览
       └─ 最终 Place 时重新评估并提交
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
 IStructurePlacementWorldPort  IResourceAccountService
          │
          ▼
 Godot 地图/表面/占用/footprint 查询
```

- Domain/Application 不引用 Node、RID、NavMesh、PackedScene、Geometry2D 或物理层 Mask。
- Godot Adapter 把稳定定义映射为场景和 footprint，并读取当前世界阻挡状态。
- UI 蓝图颜色、标签和鼠标状态属于表现层，不进入权威服务。
- 规则 AI 的径向搜索是“如何选择 Candidate”的策略，不属于合法性服务。

## 4. 稳定定义与 Candidate

建议新增：

```csharp
namespace AI_RTS.Domain.Common;

/// <summary>标识一个可建造结构定义，不暴露 Godot 场景路径。</summary>
/// <param name="Value">项目内稳定且非空的定义键。</param>
public readonly record struct StructureDefinitionId(string Value);
```

首轮可使用 `command_center`、`vehicle_factory` 等稳定键，由 Godot Definition Registry 映射到 PackedScene、蓝图资源、成本、移动领域和 footprint。后续 `ECO-007` 把该 Registry 的数值迁移为强类型配置，接口 ID 不变。

```csharp
/// <summary>描述一次不含引擎对象的建筑放置候选。</summary>
public sealed record StructurePlacementCandidate(
    StructureDefinitionId DefinitionId,
    WorldPosition Position,
    float YawRadians);
```

约束：

- Position 和 Yaw 必须为有限值；
- Yaw 在服务边界规范化到 `[0, 2π)`；
- Y 高度由 Godot 可建造表面解析和校正，控制器不能用任意高度绕过地面规则；
- Candidate 不携带蓝图 Node、碰撞 Shape 或本地化文本。

## 5. Footprint 契约

结构定义应提供完整放置 footprint，而不是由 UI 临时实例化建筑再读取 radius。建议用判别类型表达：

```csharp
/// <summary>表示一个不依赖引擎的建筑占地形状。</summary>
public abstract record StructurePlacementFootprint;

/// <summary>表示圆形占地。</summary>
public sealed record CirclePlacementFootprint(float Radius)
    : StructurePlacementFootprint;

/// <summary>表示会随 Candidate Yaw 旋转的矩形占地。</summary>
public sealed record BoxPlacementFootprint(float HalfWidth, float HalfDepth)
    : StructurePlacementFootprint;

/// <summary>表示以结构原点为局部坐标的凸多边形占地。</summary>
public sealed record ConvexPlacementFootprint(
    IReadOnlyList<PlanarPoint> Vertices)
    : StructurePlacementFootprint;
```

首轮为降低风险，可以把现有 radius 导入 `CirclePlacementFootprint`。契约先允许矩形/多边形，后续替换外部模型或调整碰撞时不需要修改 Application 接口。

完整 footprint 用于：

- 可建造区域包含判断；
- 与己方、敌方、资源节点和其他建筑的占用相交判断；
- 生成前净空复验；
- 后续 NavMesh/RVO footprint 统一工作的输入。

视觉模型尺寸不能自动成为权威 footprint；应由统一单位视觉契约中的明确绑定提供并经过校验。

## 6. 评估结果

```csharp
/// <summary>表示建筑放置候选存在的稳定问题。</summary>
public enum StructurePlacementIssue
{
    /// <summary>建筑定义不存在或当前版本不支持。</summary>
    UnknownDefinition,
    /// <summary>位置或旋转包含非法数值。</summary>
    InvalidTransform,
    /// <summary>发出者当前没有建造该定义的权限。</summary>
    NotAuthorized,
    /// <summary>完整 footprint 未处于当前玩家的有效视野内。</summary>
    NotVisible,
    /// <summary>完整 footprint 超出地图或当前可建造区域。</summary>
    OutOfBounds,
    /// <summary>地形、坡度、水域或规则区域不允许建造。</summary>
    SurfaceNotBuildable,
    /// <summary>footprint 与当前权威阻挡物相交。</summary>
    Occupied,
    /// <summary>重叠友军无法全部分配安全驱逐落点。</summary>
    FriendlyDisplacementUnavailable,
    /// <summary>玩家当前不能支付完整成本。</summary>
    InsufficientResources,
    /// <summary>Godot 空间或定义适配器暂时无法完成评估。</summary>
    ValidationUnavailable
}

/// <summary>返回一次只读放置评估及稳定主问题。</summary>
public sealed record StructurePlacementEvaluation(
    StructurePlacementCandidate Candidate,
    bool IsValid,
    StructurePlacementIssue? PrimaryIssue,
    IReadOnlyList<StructurePlacementIssue> Issues,
    long? ObservedAccountVersion);
```

建议返回能够安全判断的全部问题并去重，按固定优先级排序：

1. `UnknownDefinition / InvalidTransform / NotAuthorized`；
2. `ValidationUnavailable`；
3. `NotVisible`；
4. `OutOfBounds`；
5. `SurfaceNotBuildable`；
6. `Occupied / FriendlyDisplacementUnavailable`；
7. `InsufficientResources`。

UI 使用 `PrimaryIssue` 选择一种主要颜色/文本，诊断和测试可读取完整 `Issues`。资源不足不会再阻止系统发现明显的越界或碰撞。

## 7. 查询与端口

```csharp
/// <summary>请求只读评估一个建筑放置候选。</summary>
public sealed record EvaluateStructurePlacementQuery(
    MatchId MatchId,
    PlayerId PlayerId,
    StructurePlacementCandidate Candidate);

/// <summary>提供不依赖具体引擎的建筑定义查询。</summary>
public interface IStructurePlacementDefinitionRepository
{
    /// <summary>查询定义、成本和权威 footprint；不存在时返回 null。</summary>
    StructurePlacementDefinition? Find(StructureDefinitionId definitionId);
}

/// <summary>查询当前世界是否允许指定 footprint 放置在候选位置。</summary>
public interface IStructurePlacementWorldPort
{
    /// <summary>返回完整边界、表面和占用问题，不泄漏阻挡实体身份。</summary>
    StructurePlacementWorldResult Evaluate(
        MatchId matchId,
        PlayerId playerId,
        StructurePlacementCandidate candidate,
        StructurePlacementFootprint footprint);
}
```

`IStructurePlacementWorldPort` 只返回空间问题，不检查玩家余额。Godot Adapter 首轮可以继续使用 NavMesh 判断地表是否存在，但必须把它翻译为 `SurfaceNotBuildable`，不能把 RID 或“必须在 NavMesh 上”写入公共规则。

## 8. Preview 与最终 Place

Preview 是高频、只读、非承诺查询：

- 鼠标移动、旋转或 AI 搜索 Candidate 时均可调用；
- 不扣资源、不创建订单、不锁定位置；
- `ObservedAccountVersion` 只供 UI/诊断，不是提交令牌；
- Adapter 可按物理帧节流和缓存相同 Candidate，但不能返回过期权威结果作为最终提交依据。

后续最终 `PlaceStructureCommand` 必须在同一主模拟线程处理中：

1. 再次读取定义、权限和完整成本；
2. 再次调用权威空间评估；
3. 以 `ConstructionCost` 原子扣款；
4. 创建一个带稳定 `UnitId` 的施工现场；
5. 返回同步回执。`Accepted` 只表示现场已经合法创建，不表示建筑完工；
6. 如果扣款后引擎创建失败，必须执行与原交易关联的补偿退款，不能吞掉资源。

`ECO-003` 的迁移期 Adapter 已实现最终 Place 复验、扣款、现场生成失败补偿和友军驱逐；施工现场进度、多 Worker、暂停/完成事件及正式 `ConstructStructureCommand` 生命周期仍在 `ECO-004` 完成。

## 9. 放置与 Worker 施工解耦

建议把以下两种意图区分：

- `PlaceStructureCommand`：支付成本并创建施工现场；
- `ConstructStructureCommand`：命令一个或多个 Worker 前往指定现场并施工。

这样可以处理 Worker 在蓝图阶段死亡、施工中途停止、多个 Worker 协作、现场长期无人施工，以及规则 AI 后续重新分配 Worker。SceneTree 的“当前选中单位”不能作为 Place 成功后的权威 Builder 列表。

为保持当前 Human 体验，Godot 输入 Adapter 可以在 Place 成功后，针对进入蓝图模式时捕获的合格 Worker IDs 再发 Construct；若这些 Worker 已失效，现场仍存在并等待后续施工命令。详细 Stop、暂停与协作规则由 `ECO-004` 评审。

## 10. 占用、战争迷雾与道路封锁

建议首轮权威占用规则：

- 己方建筑、敌方建筑、施工现场和资源节点都阻挡放置；
- 敌方地面移动单位阻挡地面建筑放置，使“占位阻止建造”成为有效战术；
- 己方地面移动单位不直接否决地面建筑 Candidate，但最终 Place 必须先得到一份可执行的安全驱逐计划；不能安全驱逐时应在扣款和生成前拒绝；
- 空中单位不阻挡地面建筑，也不参与地面驱逐；未来海上、空中建筑通过结构定义的放置环境与移动领域关系扩展，不能硬编码成“全部单位均阻挡”；
- 装饰物只有声明为 Placement Blocker 时才阻挡；
- Preview 与最终提交都不返回具体阻挡实体 ID；
- 完整 footprint 必须处于发出者的有效视野内；视野不足时返回 `NotVisible`，并停止占用和驱逐评估，因此完整 `Issues` 也不会泄漏雾中是否存在敌军；
- footprint 已有完整视野后，范围内敌军属于正常可见占用并返回泛化 `Occupied`；
- 全知调试 AI 可以通过独立查询权限获得更多信息，不能从放置服务绕过战争迷雾。

当前 Demo 已存在战争迷雾意义上的隐藏敌军：`PER_PLAYER` 模式会由 `UnitVisibilityHandler` 把视野外敌军设为不可见；但尚未发现独立的隐形、伪装或间谍规则。当前 Legacy 放置检查直接读取 SceneTree 中全部 `units`，因此视野外敌军也会改变蓝图颜色，形成位置探测侧信道。评审决定用“完整 footprint 必须有视野”消除此冲突；特殊隐形、伪装和已探索建筑假体的详细交互等待策划评审。

### 10.1 友军驱逐的实现边界

现有代码没有驱逐流程，单位 `Area3D` 的 `collision_mask` 为 0，不能依靠物理碰撞把单位自然推出；结构生成后还会加入 `NavigationObstacle3D` 并触发 NavMesh 重烘焙。若直接允许重叠生成，位于新障碍内部的 `NavigationAgent3D` 可能无法稳定找到出口。因此驱逐属于中等难度的显式系统行为，而不是关闭一次碰撞检查即可完成。

建议最终 Place 采用以下顺序：

1. 收集与 footprint 重叠的己方、同移动领域、可移动单位；
2. 在建筑 footprint 外围计算互不重叠且可导航的驱逐落点，并在本次提交内临时保留这些位置；
3. 任一单位没有安全落点时，在扣款和创建现场前拒绝放置；
4. 原子扣款并创建施工现场；
5. 通过独立的 `IUnitDisplacementPort` 发出系统驱逐，不把它伪装成玩家 Move；
6. Godot Adapter 处理 NavigationObstacle/重烘焙时序，并保证单位不会永久留在建筑 footprint 内。

公共 Preview 结果不返回重叠友军 ID。最终服务内部可以获得仅限己方的稳定 Unit IDs 和驱逐落点，不能借此获得隐藏敌军信息。

评审确认系统驱逐取代当前移动、攻击、采集或施工任务，旧活动订单进入 `Cancelled`；驱逐完成后待命且不自动恢复。这样与当前已经确定的“暂停且不自动恢复”原则一致，也避免恢复任务时目标已经失效。未来若希望驱逐后恢复任务，需要新增可暂停、可恢复的通用任务栈并另行评审。

建筑可能被用于围墙和封路。建议合法性服务不执行“放置后地图必须全局连通”的昂贵检查；只验证 footprint、表面和显式禁建区。地图或任务若禁止封锁关键道路，应提供 Build Exclusion Zone，而不是把全局寻路算法固化进放置接口。

## 11. 自动验证建议

纯 C#：

1. 非有限位置/Yaw 和未知定义稳定拒绝；
2. Issues 去重、排序与 PrimaryIssue 稳定；
3. 资源不足和空间问题可以同时返回；
4. Preview 不修改账户或世界；
5. Definition Repository 与 World Port 失败映射为稳定问题；
6. Human、规则 AI 使用相同 Query 得到相同权威空间结果。

Godot：

1. 建筑中心在地图内但 footprint 越界时拒绝；
2. 与敌方移动单位、建筑、施工现场或资源节点相交时拒绝；
3. 与己方地面移动单位相交时生成安全驱逐计划；无可用落点时拒绝且不扣款；
4. 空旷可建造表面接受；
5. 圆形首轮 footprint 与现有 radius 表现不回归；
6. 旋转 Candidate 能稳定传递，后续矩形 footprint 按朝向生效；
7. 预览合法后插入阻挡物，最终 Place 复验应拒绝且不扣款；
8. 余额在 Preview 后变化，最终 Place 按最新账户决定；
9. 隐藏阻挡物不会通过结果泄漏实体身份。

## 12. 首轮不处理

- 施工进度、暂停施工、多 Worker 协作和完成事件；
- 建造队列、渐进支付和 AI 副官资源分配；
- 新 UI 设计和蓝图美术；
- 复杂多边形物理优化、并发查询或多线程；
- 全局道路连通性、导航脱困和 NavMesh 专项优化；
- 完整战争迷雾查询策略；本轮只禁止返回阻挡实体身份并预留过滤边界。
