# 03 侦察与情报

## 目标

1. 持续探图，尽早发现敌基地与兵种构成；
2. 维护 `/tmp/intel.json` 新鲜度（敌基地坐标、composition、更新时间）；
3. **侦察进度是阶段性决策的输入**——它决定"现在可以多激进"，而不是"要不要停下来等"。

## 输入数据

- `counts.scouted_enemy`：当前可见敌单位数（>0 即有接触）；
- `/tmp/scout_state.json`：`{unit, target, last_pos, stuck, visited[]}`（target 必须等于最近一条 move 的 dest）；
- `/tmp/intel.json`：`{enemy_bases:[[x,z],...], composition:{tank:n,heli:n,...}, updated:时间}`；
- 全量 status（低频）：侦察兵坐标、同名单位两轮间位移 `max(|dx|,|dz|)`。

## 决策条件

### 锁定协议（侦察兵一次一个目标）

- 距目标 `max(|dx|,|dz|) < 10` = 到达 → 记入 `visited`，派下一个点；
- 连续 3 轮位移 < 2m = 停滞 → 在当前位置与目标间插中点分段；
- 否则**零指令让它走**（重发 = 打断行军）。
- 目标序列（地图 100×100，以基地为原点）：四角 → 四边中点 → 中心 → 未探明补扫。
- 敌基地发现后：写入 intel.json，之后每约 60 秒让侦察兵复核一次，更新 composition。

### 阶段推进阈值表（核心：迷雾下不许无限等待）

**不存在"侦察没完成所以一直等"的合法状态。** 以下条件满足任一条就推进阶段决策：

| 阈值 | 决策 |
|---|---|
| 侦察进度（visited / 总目标点）≥ 50% 且坦克 ≥ 20 | 允许沿已知信息集结推进，不必等全图探完 |
| `counts.scouted_enemy > 0` | 立即记录 intel 并触发响应（交战 / 补防空，见 05 章） |
| 坦克 ≥ 30 且侦察仍无果 | 向地图中心推进（中心必有遭遇），侦察兵转为伴随 |
| 等待敌情超过约 120 轮（10 分钟） | 强制按当前军力做阶段决策：要么集结推进，要么补产能/塔，**不允许继续原地等** |

每轮复盘必须包含一行侦察进度（距目标 N 米 / 位移 D 米）——它就是迷雾下"我在等什么"的量化答案。

## 不应该做什么

- **不因为"还没看到敌人"就无限等待 20 辆坦克**：等待必须有上限、有替代决策（上表阈值）。
- 重发未到达且未停滞单位的 move（打断行军，v2 教训：20 分钟只探开自家象限）。
- 用 `action` 字段判断是否在移动：`WaitingForTargets` 是待机不是移动，只看坐标位移。
- 敌基地未发现就把大军停在基地门口干等。
- 侦察兵阵亡后不补（侦察断线 = 后面所有决策失去前提）。

## 失败后的恢复策略

- 侦察兵阵亡 → `produce` 无人机（`producer_type=AircraftFactory`，见 04 章）；没有飞行器工厂时先 build，等不起就让 1~2 辆坦克顺路探。
- 停滞 → 插中点分段；中点也失败 → 跳板减半或换目标点，并把该点记入 visited 作废。
- 账本代际守卫：会话重启后单位名在当前 status 不存在 ⇒ 上局遗物，侦察账本全部作废重建。
- intel.json 丢失/过期（updated 超过 2 分钟且有过接触）→ 优先派侦察兵复核敌基地。

## 对应的游戏控制命令或状态字段

- 命令：`move units='[...]' dest='[x,z]' as_player=主人`（侦察机动与 `move` 是同一条命令，语义靠 scout_state 区分）、`produce`（补无人机）、`status lite=true`、`sleep 5`。
- 字段：`counts.scouted_enemy`、同名单位坐标位移、`counts.mine_by_type`（军力阈值输入）。
- 状态文件：`/tmp/scout_state.json`、`/tmp/intel.json`（交接续任的依据）。
