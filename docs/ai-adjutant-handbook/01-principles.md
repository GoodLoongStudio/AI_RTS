# 01 决策原则：回执语义与数据纪律

## 目标

让每一轮决策都满足三个性质：**有数据依据**（本轮 status，不是记忆）、**有回执校验**（每条命令的结果可分类）、**可恢复**（会话重启后能接着干）。副官所有管理器（生产/工人/侦察/军队/交战）共用这一章的语义。

## 输入数据

每轮唯一的事实来源是本轮 `status`（默认 `lite=true`），脚本落盘到 `last_status.json`：

| 字段 | 用途 |
|---|---|
| `match` | 是否在对局中；false 则先 `start with_ai=true` |
| `players[]` | `human:true` 的玩家 = 主人（`as_player` 的值从这里来） |
| `balance.a / balance.b` | 我方资金（双资源制，生产条件判断用） |
| `counts.mine` / `counts.mine_by_type` | 我方单位总数 / 按兵种计数（工人数、坦克数从这来） |
| `counts.scouted_enemy` | 可见敌方单位数（情报触发器） |
| `production[]` | 我方全部生产建筑快照（选 producer、判队列空闲的唯一依据，见 04 章） |
| `outcome` | 结算出现 → 汇报胜负，会话可结束 |

纪律：**一律用 `lite=true`**。全量 status（带 `units[]`）只在需要具体单位名/坐标时低频使用（侦察派点、attack 选目标、核查位移），单位过百时全量要 60 秒+，会拖瘫决策循环。

## 决策条件：回执三分法

每条命令的回执必须归入以下三类之一，**未归类的回执按"拒绝"处理**：

### 1. 接受：`accepted=true`（通常伴随 `ok=true`）

命令已被权威逻辑接受。此时才允许：记入账本、更新状态文件、把它当作"已生效的开始"。接受 ≠ 瞬时完成——坦克生产要等 `production.items` 里出现并推进，移动要等坐标位移。

### 2. 待确认：`status=PendingAuthority`

命令已经转发给服务器权威端，但**还没有确认结果**。

- 它**不是成功**：不能记入"已下单完成"账本，不能基于它做后续派生决策。
- 正确做法：**等待下一次 status**，用事实验证——
  - produce：`production[].items` 是否出现新条目；
  - move：同名单位两轮间是否有坐标位移（`max(|dx|,|dz|)`）；
  - build：单位列表是否出现新建筑。
- **绝不立即重复下单**（会产生双份订单/双份队列）。连续 3 轮 PendingAuthority 且事实无任何变化，才允许重发一次。

### 3. 拒绝：`ok=false` / 带 `reason` / 错误码

明确失败。按 `reason` 分类换策略（见各章"失败后的恢复策略"），同一命令**最多原地重试 1 次**，之后必须换路。

## 不应该做什么

- 不凭上一轮的记忆或账本直接下令；本轮决策必须引用本轮 `last_status.json` 的字段值。
- 不把 `PendingAuthority` 当成功记账、不当成交付。
- 不在收到拒绝后无限重试同一命令。
- 不用全量 status 做高频轮询。
- 不因为"还没看到敌人"而搁置所有阶段性决策（见 03 章阈值表）。
- 不猜测 API 形态：units 永远是数组，没有 `unit=` 单数形式（produce 例外，其参数名就是 `unit=`，指向生产建筑，见 06 章）。

## 失败后的恢复策略

- **TCP 断开 / 调用失败**：`rts_ctl.py` 会打印 `调用失败: ...`。sleep 5 后重试一次；再失败则检查 status 是否可达，仍不可达就持续 sleep 等待链路恢复，不结束会话。
- **会话被看门狗重开**：先读 `/tmp/scout_state.json`、`/tmp/wing_state.json`、`/tmp/intel.json` 续任。**代际守卫**：账本里的单位名在当前 `last_status.json` 中不存在 ⇒ 账本是上局遗物，全部作废删除、从摸底重建——指挥幽灵单位比不指挥更糟。
- **回执丢失**（请求发出但没收到响应）：按 PendingAuthority 处理——等下一轮 status 用事实验证，不盲目重发。

## 对应的游戏控制命令或状态字段

- 命令：`status`（`lite=true`）、`sleep 5`（轮与轮之间的唯一等待方式，也是保持会话的工具调用）。
- 字段：`accepted` / `ok` / `status` / `reason` / `PendingAuthority`。
- 命令语法细节见 06 章。
