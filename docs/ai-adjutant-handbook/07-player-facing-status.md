# 07 面向玩家的状态汇报

## 目标

每轮复盘文字让**玩家**看懂副官在做什么、为什么、结果如何。玩家不认识 `PendingAuthority`、`last_status.json`、`/tmp/intel.json`——这些词一律不得出现在给玩家的文字里。

## 输入数据

本轮决策所依据的数据（counts / balance / 侦察进度）与每条命令的回执结果（accepted / PendingAuthority / reason）。

## 决策条件：状态措辞映射表

副官的"当前阶段"必须使用下列措辞之一（与游戏内副官面板一致）：

| 阶段 | 对玩家说 | 对应协议信号 |
|---|---|---|
| 观察中 | 正在观察战况 | 每轮 `status lite=true` 采样 |
| 等待服务器确认 | 已提交命令，正在等服务器确认 | 回执 `status=PendingAuthority` |
| 资源不足 | 资源不足，暂缓执行 | 回执 `InsufficientResources` |
| 队列已满 | 生产队列已满，等当前项目完成 | 回执 `QueueFull` |
| 侦察中 | 正在侦察（目的地可说"东北角"等方位词） | `move`（scout_state 锁定中） |
| 机动中 | 部队正在机动（可说"向中部推进"） | `move`（军队行军） |
| 建造中 | 正在建造（建筑名用中文名：车辆工厂等） | `build` |
| 生产中 | 正在生产（可说"在生产坦克"） | `produce` |
| 发展经济 | 工人正在持续采矿 | `gather` |
| 交战中 | 正在交战（可说"正在集火敌方坦克"） | `attack` |
| 撤退中 | 部队正在撤退重组 | 优先级 2 触发后的 `move` |
| 回防中 | 基地受袭，部队正在回防 | 优先级 1 触发 |

每轮复盘模板（一行起）：

```
侦察距目标 N 米（或：侦察进度 x%）；产能：满/空闲；军力：坦克 n；本轮决策：<一句话>。
```

## 不应该做什么

- **不把 raw 日志、JSON 回执、内部脚本路径当玩家可读解释**：
  - 禁止出现：`/tmp/...`、`last_status.json`、`scripts/rts_ctl.py`、`res://...`、`as_player=...`、`units='[...]'`、整段回执 JSON、AI_RTS_DBGPORT 等内部名词。
  - 给玩家的文字永远是翻译后的中文状态，不是原始记录。
- 不向玩家提问、不等待玩家答复（无人值守模式）。
- 不刷屏：没有新信息时输出最小复盘一行；连续多轮无变化时，汇报一次阶段总结而不是重复十遍。
- 不夸大：`PendingAuthority` 时说"正在等服务器确认"，不说"已经造好了"。

## 失败后的恢复策略

- 完全没有新信息 → 输出最小复盘："侦察推进中，产能满，无异常。"
- 连续失败（链路断/大量拒绝）→ 如实说"指挥链路不稳，正在重试"，并降低指令频率，不编造进展。
- 结算出现 → 用一句话报胜负，会话结束。

## 对应的游戏控制命令或状态字段

- 本章不新增命令；它约束每条回复的**文字部分**（与工具调用同一条回复输出）。
- 措辞来源即协议信号：`status`（观察）、`PendingAuthority`（等待服务器确认）、`InsufficientResources`（资源不足）、`QueueFull`（队列已满）、`move`（侦察/机动）、`gather`（发展经济）、`build`（建造）、`produce`（生产）、`attack`（交战）。
