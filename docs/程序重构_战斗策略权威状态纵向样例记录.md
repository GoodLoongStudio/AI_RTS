# 战斗策略权威状态纵向样例记录

> 日期：2026-08-12  
> 范围：`EngagementStance`、`FirePolicy` 领域状态与设置命令；不接入 Legacy 攻击 Action 和最终 UI

## 1. 本次实现

- 新增 `AI_RTS.Domain.Combat.EngagementStance`：`Aggressive`、`Guard`、`HoldGround`；
- 新增 `AI_RTS.Domain.Combat.FirePolicy`：`FireAtWill`、`HoldFire`；
- 新增 Match 生命周期内共享的 `InMemoryCombatPolicyStore`；
- 默认策略为 `Aggressive + FireAtWill`，保持现有 Demo 行为；
- 新增 `SetEngagementStanceCommand` 与 `SetFirePolicyCommand`；
- 姿态和开火策略正交保存，修改任一项不会覆盖另一项；
- 设置命令逐单位校验存在性和所有权，可返回部分成功；
- 设置持续策略不创建 `UnitOrderId`，因为它不是一次性执行订单；
- `CommandRuntime` 与 `UnitCommandGateway` 提供设置和查询入口，但传统 HUD 尚未增加按钮。

## 2. 架构边界

策略 Store 目前只保存权威值，不驱动 `WaitingForTargets`。这是刻意的两阶段迁移：先让 Human、规则 AI 和未来外部 Adapter 能通过同一接口读写状态，再让攻击感知和追击算法消费状态。否则 UI 按钮会再次直接决定 Legacy Action。

`ForceAttack` 的临时开火授权不写入 `FirePolicy`。后续攻击订单自行持有临时授权，结束后自然回到 Store 中持续保存的策略。

## 3. 验证

- `dotnet build`：成功，0 warning，0 error；
- `CSharpCommandSmokeTest` 增加所有权部分成功、默认策略以及两个策略轴独立保存测试。
- `TankCommandBridgeSmokeTest` 验证两个 Gateway 共享同一 Match 的 Guard/HoldFire 权威状态。
