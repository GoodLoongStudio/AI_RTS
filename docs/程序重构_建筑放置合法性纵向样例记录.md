# 建筑放置合法性纵向样例记录

> 日期：2026-08-15
>
> 工作项：`ECO-003`
>
> 状态：代码与自动测试完成，待人工验收

## 1. 本轮目标

把 Human 蓝图、传统规则 AI 和未来 Agent 都约束到同一套建筑放置规则，消除各控制器自行检查、扣款和生成造成的分叉。首轮继续使用现有圆形 radius，但公共契约允许未来定向矩形和凸多边形 footprint。

## 2. 已实现边界

纯 C# Domain/Application 新增：

- 稳定 `StructureDefinitionId` 与可扩展 `PlacementEnvironmentId`；
- `CirclePlacementFootprint`、`BoxPlacementFootprint`、`ConvexPlacementFootprint`；
- 不含 Node、PackedScene、RID 或 NavMesh 的 `StructurePlacementCandidate`；
- `StructurePlacementService` 统一组合定义、权限、世界空间和资源账户；
- Preview 返回去重、固定排序的完整安全问题与 `PrimaryIssue`，不修改账户或世界。

Godot Adapter 新增 Match 级 `StructurePlacementRuntime`：

- Human 蓝图鼠标移动调用统一 Preview；
- 最终点击重新读取视野、完整地图边界、地表导航、占用、友军驱逐可行性和最新账户；
- 复验成功后原子扣除完整成本并创建施工现场；生成异常时用关联现场身份执行补偿退款；
- 三个 `simple-clairvoyant-ai` 建造控制器不再自行扣款和生成，最终均调用同一 Runtime；
- 当前径向找点仍是规则 AI 自身策略，不属于权威合法性规则。

## 3. 视野与战争迷雾

完整 footprint 必须被当前玩家自己的有效视野覆盖。首轮以中心和 16 个圆周点采样，己方移动单位及已完成建筑可以提供视野，未完成建筑不能提供视野。

若视野不足：

- 返回 `NotVisible`；
- 不执行单位、建筑和资源占用查询；
- 完整 `Issues` 中也不会出现 `Occupied`；
- 因而不能用蓝图颜色或诊断集合探测战争迷雾中的敌军。

隐形、伪装、间谍和已探索建筑假体的特殊规则不在本轮实现。

## 4. 友军驱逐

地面建筑与己方地面移动单位重叠时不直接拒绝。Godot 世界端口会：

1. 按稳定 UnitId 排序重叠友军；
2. 在 footprint 外围分环搜索可导航、互不重叠的安全落点；
3. 任一单位没有落点时返回 `FriendlyDisplacementUnavailable`，不扣款、不生成；
4. 放置成功后取消这些单位的旧活动订单并执行系统驱逐；
5. 驱逐完成后单位待命，不自动恢复旧任务。

敌方地面移动单位仍返回 `Occupied`，使占位阻止建造成为有效战术。空中单位不阻挡地面建筑，也不参与地面驱逐。

现有单位 `Area3D.collision_mask = 0`，不能依赖物理推挤；结构还会创建 `NavigationObstacle3D` 并触发重烘焙，因此本轮使用显式安全落点和移动行为。

## 5. 迁移期兼容

- 建筑定义首次使用时由 Adapter 把现有 PackedScene、Legacy 成本和 radius 注册到稳定定义仓库；场景路径不会进入 Domain/Application。
- Human 仍可在放置成功后让未被驱逐的已选 Worker 进入 Legacy 施工；被驱逐 Worker 会跳过该隐式绑定，避免施工动作立即覆盖驱逐。
- 放置与正式 `ConstructStructureCommand` 的彻底拆分、多 Worker 加速、无人施工现场和施工暂停属于 `ECO-004`。
- `terrain.surface` 已作为数据化环境键；海面、空中和天然气喷口等以后增加定义与世界端口规则，不修改放置服务签名。

## 7. 人工验收重点

人工验收以《程序重构_手动功能验收清单》的 `ECO-003` 九项为准，重点观察：

- 蓝图跨出己方视野时的反馈是否符合直觉；
- 多个友军被同一建筑覆盖时能否平稳分散；
- 建筑生成与 NavMesh 重烘焙期间单位是否出现振荡或长期卡住；
- 敌方地面占位、空中单位不阻挡以及规则 AI 建造是否符合预期。
