## 1. 怎么用这份清单

后续完善时按下面顺序走：

1. 先做「A. 未完成」和「B. 已实现但冲突」里的必须项。
2. 再做「C. 已实现但不完善」里的必须项。
3. 不要把「D. 已完成」和「E. 不做 / 暂缓」当成本阶段开发任务。
4. 每一项都对应矩阵行号，改完后回写该项状态。

当前必须项统计（以矩阵为准，代码复核后未改分类）：

| 未完成 | 7 | 完全没有正式实现 |

| 不完善 | 16 | 核心能力在，缺闭环、通用化或正式接入 |

## 7. 建议的逐步完善顺序

按表格后续开工时，建议分成 8 个工作包。每个工作包做完再勾矩阵对应行。

### 工作包 1：输入同步

覆盖行：4、5、7、6（Space 可先做事件记录骨架）

1. 定 `F` 是 Stop 还是 HaltMovement。
2. 默认绑定 `R/F/G/C/X/Z`。
3. Tab 切换两套 HUD，去掉仅按钮切换的主路径。
4. F10 开暂停菜单，Esc 取消/返回。
5. 清掉 AI HUD 对 Q/W/E/R/D/F 和 1/2/3 的正式占用。

### 工作包 2：停止语义与 Targeting 边界

覆盖行：23、19、21

1. HUD「停止移动」改 `HaltMovement`。
2. 完整 Stop 保留独立入口。
3. ForceMove / 撤退只接受合法地面目标。

### 工作包 3：命令终态回传

覆盖行：25、30、43、44

1. 执行端补 Arrived / Unreachable / TargetLost / Cancelled / UnitLost。
2. 死亡后选择、编队、命令、战斗目标、AI 引用一起验收。

### 工作包 4：统一战局模拟时间

覆盖行：36、87、88、89

1. 攻击间隔、战役计时、任务坚守全部改模拟时间。
2. 暂停后单位、战斗、AI、任务都停。

### 工作包 5：AI 副官接正式 RTS

覆盖行：58、62、63、64、65、66、67、68、69、70、59、61

1. 签发 Agent QuerySession，只用合法情报。
2. Move / Attack / AttackMove / Withdraw / Stop / 姿态全部走 Gateway。
3. 小队改为正式 ControlGroup。
4. 反馈只用 `CommandResult`。
5. 文字输入接大模型；语音 V 放这个包的最后。

### 工作包 6：最小通用战役任务运行时

覆盖行：72–79、6 的事件源

1. 到达、消灭、保护、坚守、撤离做成数据条件。
2. 战场事件推进任务，不再写死 objective index。
3. 必须能失败。

### 工作包 7：战役胜负统一

覆盖行：81–85

1. 战役 Victory / Defeat 进 `MatchOutcome`。
2. 结果只锁定一次。
3. 结算 UI 可留，数据源统一。
4. 增加重开当前战役。

### 工作包 8：导航稳定性（不重构）

覆盖行：27、28、29

1. 不换导航架构。
2. 重点测拥挤、窄路、不可达、多单位分散。

## 8. 后续逐项开工时的验收写法

每改一项，至少写清：

```text
矩阵行：
工作包：
改前状态：未完成 / 冲突 / 不完善
改动文件：
怎么验：
是否回写矩阵：
```

未完成项优先补「能玩 + 能验」；不完善项优先补闭环，不扩新玩法；冲突项优先改语义，不并行加功能。
