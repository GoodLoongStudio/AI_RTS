## 4. 架构（2026-09-11 定调，别改方向）

```
战略层  LLM（慢·异步 14~45s）  → 出"目标/优先级"
战术层  LLM / 规则（慢·异步）  → 把目标分派到单位
微操层  ★行为树（每 tick·快）★ → 单位级即时执行、打断、避战
```

**用户方针（原话）**："**不要卡 4s 啊，微操其实要靠行为树的**"。即：
- 微操必须由行为树承担，LLM 只出意图，**LLM 慢不是问题**（runner 按 tick 间隔节流、不阻塞主循环）；
- 所以绝不要再把 LLM 掐在 4s。

**分工（避免两套逻辑打架）**：
| 层 | 负责 |
|---|---|
| `rules_fallback.development_intents`（已测试） | **造什么/产什么**（建筑阶梯、生产阶梯、兵种组合、落点） |
| `graph/behavior_tree.py` ★行为树★ | **谁去、优先级、打断**：让权 / 劣势撤离 / 就近交火 / 采集兜底 |

行为树纪律（Selector 顺序即优先级）：玩家接管→让权 > 劣势→撤离 > 分派目标→攻击 > 作战单位→就近交火 > 工人→采集 > （可选）空闲集结。
单测：`tests/test_behavior_tree.py`（12 例）。

## 5. 已修好（**有证据，别回退**）

1. **`num_ctx=8192` 超窗截断** → 换 `minicpm5-adj-16k`（16384）。此前真实对局里战略/战术契约几乎全失败，改后 `model_smoke` 战略+战术契约**全绿**。
2. **关思考**：只要端点在本机（127.0.0.1/localhost）就**必须**下发 `openai_reasoning_effort="none"`（`_is_local_endpoint`）。不要再按模型名判断。
3. **战略输出被截断**：`max_tokens` 原一刀切 512，`StrategyPlan`（嵌套 `tasks[]`）放不下 → 按角色：战术 512 / **战略 1280**。
4. **建造阶梯"并集判据"**：原 `if not actions & set(DEVELOPMENT_ACTIONS)` 只要模型产了 produce/produce/attack 任一，整条阶梯就被跳过 → 改为**按类别逐项补**。
5. **抢占兜底"两角色同时为空"**：基地天然是空闲生产者，导致该条件恒为 False → 改为**逐角色**判定。
6. **`PREEMPTIBLE_ACTIONS`**：可被抢占性按**优先级语义**定义（gather/scout/move/hold），不要按单一动作名硬编码。
7. **`intent_id` 必须带 tick**：游戏按 `intent_id` 幂等缓存回执，固定 id 会让重试永远命中最早那次回执（"改了参数却毫无变化"的真凶）。
8. **build 落点**：命令包络必须透传 `params["pos"]`；落点取基地附近 5m 并按 tick 轮换方位（否则全部落 (0,0) 被游戏拒）。

- 一局 90s 内只见 `gather` / `produce` 被下发，**没有任何 `build` 到游戏**。

  ```

  ```
- 所以**断点在"运行时喂给阶梯的 state"**，不在阶梯算法。
- 我加了诊断打点 `_log(ctx, state, "micro_empty", ...)`，但**它没出现在 `runner.out` 里** —— 怀疑 `_log` 的落点不是 runner 日志。**先查清 `_log` 写到哪**。

### 具体动作顺序

1. 查 `_log` 实现与落点，把 ladder 的输入（`idle_builders` / `idle_producers` / `preemptible` / `own_types` / `ai_units` / `active_intents`）落到**能看到的地方**。
