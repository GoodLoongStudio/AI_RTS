# AI 副官长期主线与决策地图接入纠偏（交给 DeepSeek）

## 问题判断

当前 LangGraph 具备打断、恢复、任务账本和 `active_plan`，但这不等于拥有“整局主线”。如果图只保存当前 plan/task，战略请求只产生一次性 patch，打断后仅恢复旧任务，就会出现“会插队、不会发展”：没有阶段推进、没有里程碑、没有基地扩张链，也没有把决策地图编译成可执行工作流。

## 必须实现的语义

把 `docs/策划文档/AI副官决策手册/01-总则与决策地图.md` 及其经济建造、侦察、军事章节接入运行时。不要让模型每轮重新发明整局计划，也不要把 Markdown 原文塞进每次 prompt。

新增或扩展持久化的 `campaign_state`（字段名可适配现有代码）：

- `phase`: 摸底→立足→扩张→施压→收束；
- `mainline_id` / `mainline_version`；
- `milestones`: 主基地稳定、产能建筑、首支作战队、分基地/分矿、持续施压等；
- `tracks`: economy/build/scout/military 四条并行线及各自当前任务；
- 每个里程碑的 `preconditions`、`success_evidence`、`exit/failure`、`retry/backoff`、`priority`；
- `next_frontier`：当前最值得推进的一个主线节点；
- `interrupt_stack`：紧急事件临时任务及恢复点。

每局开局必须由程序根据地图、资源、可用建筑和决策地图创建一个可执行的默认主线；模型只在低频战略节点选择主线分支和参数。即使模型关闭，规则也要沿主线推进：采集→产能→兵力→扩张选址→建分基地/分矿→防守/施压。规则不得擅自创造决策地图之外的战略动作，但必须负责把已选节点拆成施工、生产、移动和保护任务。

## LangGraph 正确用法

图的长期状态必须跨 tick/checkpoint 保留，而不是只保留最后一批意图。建议节点语义：`observe -> update_campaign_state -> retrieve_decision_map_candidates -> baseline_tracks -> strategic_patch -> reconcile -> dispatch -> receipts -> advance_milestones -> checkpoint`。

紧急事件只压入 `interrupt_stack`，处理完成、失败或过期后弹出并回到原 `mainline` 和四条 track；玩家局部接管只暂停受影响对象，不清空主线。战略模型超时、空输出、非法输出时，继续执行当前主线和已有任务。

模型上下文必须明确展示：当前阶段、主线目标、已完成/阻塞里程碑、四条线任务、下一前沿、可选决策地图节点及其前置条件。模型输出仍使用四列稀疏 patch；没有明确选择时沿用当前主线，不能把空输出解释为“无战略”。

## 最低验收

1. 无模型连续对局：阶段和里程碑真实推进，至少出现产能建筑、兵力增长、扩张候选；满足条件后实际建成第二基地/分矿，不能只产生日志。
2. 模型开启与关闭同起点：模型可改变分支，但基础主线不因等待模型停止。
3. 连续注入基地受袭、玩家局部接管、路径失败：紧急任务完成后恢复原主线，未完成里程碑不丢失、不重置。
4. 每个里程碑必须有权威回执证据；禁止以“生成了 plan/task”代替游戏内完成。
5. 报告区分代码推断、日志证据和真实游戏结果。

先检查现有 `active_plan`、`PlanStore`、`task_progress`、LangGraph checkpoint 和规则中台，优先扩展现有入口，不新建第二套平行战略系统。实现、连续测试、失败修复和阶段报告自动闭环，不等待用户再次说“继续”。
