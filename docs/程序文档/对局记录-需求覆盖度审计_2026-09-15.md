## 二、本轮新增字段

### 1. 单位统计 11 项 —— `combat.unit_stats`

`produced` / `lost` / `alive` / `survival_rate` / `kills` / `kill_loss_ratio` /
`damage_per_unit` / `damage_taken_per_unit` / `avg_lifetime_s` / `unique_types` / `scout_units`

推导统一由 `MatchReportSchema.derive_unit_stats(rows)` 提供（Demo 与真实对局**共用一份**，禁止第二条实现）。
`combat.units` 是逐类型明细表，本轮补了 `alive` 列（该记录模板现为 11 个字段）。

**三条推导纪律**：

1. 空明细 ⇒ 全 `null`（"未测量"不是 0；否则玩家会看到"阵亡 0 人 / 存活率 100%"）
2. **逐列独立判"是否测量过"** —— 真实对局 recorder 的行只有 `produced/lost`，没有 `killed/damage_*`，此时给 `null` 而不是 0
3. 判空用 `entry.get(k, null) != null` 而非 `has()` —— 归一化过的行会把缺失键补成 `null`，`int(null)` 会炸

### 2. 建设统计 +6 项

`build_started` / `build_cancelled` / `avg_build_time_s` / `rebuild_count` / `repair_spent` / `peak_concurrent_builds`

自洽约束：**开工 = 落成 + 取消**（`build_cancelled` 只取一次随机数供两项共用，避免出现三个互相矛盾的数字）。

### 3. 总览 +1 项

`overview.peak_army_value` —— 峰值军力（同时在场战斗单位价值最高值，只算非 `economy` 单位）。

## 四、机器判据

`tools/probe_match_history.gd` 的 `_check_requirement_coverage()` 把上表所有数量固化成断言，另含：

- `derive_unit_stats([])` ⇒ 11 项全 `null`
- 明细缺 `killed/damage_*` ⇒ 对应项为 `null`（不编造 0）
- 归一化行（缺失键 = `null`）⇒ 不崩、已测量列照常汇总
- Demo 十场：11 项单位统计全有值、与 `units` 表**同源**（重新推导零不一致）、建设 +6 项全有值、`开工 = 落成 + 取消`
- UI：战斗页 / 生产与建设页 / 总览页确实渲染出上述新项

## 六、顺带修掉的一个假红（非本轮改动引入）

`match-history` 走官方 runner 时长期判 `Forbidden output matched: Parse Error`，但探针本身 0 错误。
根因：runner 用 `-match` 比对禁用词表，而 **`-match` 是正则且大小写不敏感**，
探针自己的断言文案里写了「为 null 说明脚本有 **parse error**」⇒ 自己把自己判红。
已把 5 处**会被打印**的文案改成「脚本加载失败」，并在探针文件头写明这条禁用词纪律。
