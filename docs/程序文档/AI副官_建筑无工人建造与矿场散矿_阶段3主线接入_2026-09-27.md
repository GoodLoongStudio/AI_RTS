## 0. 一句话

阶段 0 记的「矿场在规则层被三重静默门槛夹死、主线里根本没有矿场节点」这一层，本轮补上了：
**建造阶梯不再把"先空出一个工人"当开工前置**、**分矿成为可独立判定的里程碑（M08）且只认实际交付**、
**没有合法远端矿时留下具体原因而不是静默跳过**。

## 1. 施工进度源贯通到规则视图

`AdjutantObservationRuntime.cs` 的 `constructions` 导出新增两个字段：

```csharp
["construction_progress_source"] = ... "automatic" | "hybrid" | "worker",
["automatic_work_per_tick"]      = construction.AutomaticWorkPerTick,
```

`observation_view.normalized_units` 同步新增 `refinery` 加法字段（权威端
`OreRefinery.delivery_stats()` 的形状），让副官第一次能**从观测里读到矿场的实际交付计数**，
而不是"存在一座矿场"。

## 2. 建造阶梯去掉 Worker 硬前置（阶段 0 断点 C-1）

`rules_fallback.py` 阶梯 1 原来是：

```python
builders = list(idle_builders)
...
if not builders:
    continue          # ← 没有空闲工人就整级跳过，不产任何意图、不留任何痕
```

现在按施工进度源决定（新增 `construction_progress_source(rules, building)` 与
`NO_BUILDER_REQUIRED_SOURCES = ("automatic", "hybrid")`）：

- 源为 `automatic`/`hybrid` 且没有空闲工人时，从**未挂起**的己方单位里取一个**命令载体**
  （优先真正空闲者），**不**调用 `release_unit_for_expansion_cc`，因此不打断任何采集订单；
  权威端 `AssignBuildersAfterPlacement` 会按同一进度源短路，载体不会被真拉上工地。
- 源为 `worker`（以及规则视图**没带**该字段时）保持旧语义：没有建造者就不建。
  默认值取保守方向，绝不把未声明过的路径悄悄放开。
- 真的连载体都没有时，写 `_note(state, "build_skipped_no_builder", ...)` 留痕后再跳过。

## 3. 分矿里程碑 M08（提示词阶段 3 第 3 条）

`campaign.py` 新增 M08「分矿（远端矿场）」，判据是**矿场完工 + 至少一次真实交付**：

```python
if built > 0 and delivered > 0: return True,  "矿场 N 座已完工，累计交付 X 次 / Y 矿"
if built > 0:                   return False, "矿场已完工 N 座，但尚无任何实际交付（接管 K 人）"
if counts.ore_refinery > 0:     return False, "矿场工地已出现，尚未完工"
return False, "尚无矿场（远端可见矿点 N 处）"
```

同时把 M05 从「分基地/分矿」**改名为「分基地」**，其判据仍只看指挥中心座数 ——
阶段 0 断点 D 记录的"分基地与分矿互相冒充"就此拆开：M05 完成**不会**把 M08 标成完成。

### 3.1 M08 必须并行，否则会把主线挡死

把 M08 直接排进前沿（优先级 46，介于 M05 与 M06 之间）实测会让
`test_rule_floor_develops_along_mainline_without_model` 的阶段轨迹从 3 段掉到不足 3 段：
矿场交付依赖真实对局里的远端矿与工人往返，在证据到手之前 M06/M07 永远轮不到前沿。
这正是提示词要求消灭的「矿场分支被永久挡死」的**镜像**问题（这次是矿场挡住别人）。

所以 M08 带 `"parallel": True`，`_recompute_frontier` 选前沿时跳过并行节点：
它参与判定与汇报（`summary()["done"]` 里有它），但不占前沿、不挡后续节点。

## 4. 没有合法远端矿时留痕（提示词阶段 3 第 6 条）

`command_center` 与 `ore_refinery` 两条扩张路径原来都是裸 `continue`，整局不扩张/不建矿场
**无从归因**（阶段 0 报告：全模块唯一的 `build_spot_exhausted` 记账点在基地旁路径 `:954`，
扩张路径一个都没有）。现在各写一条 `expansion_spot_exhausted`，带
`building / min_distance_m / visible_resources`。
