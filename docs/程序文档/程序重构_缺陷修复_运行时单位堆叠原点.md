# 缺陷修复：运行时单位与建筑堆叠到原点

日期：2026-08-13

## 现象

Godot 3D 编辑器中，测试场景内的 Tank、敌方单位和建筑具有不同坐标；运行场景后，它们却全部堆叠到地图左上角。该问题严重干扰移动、攻击、射程和姿态差异的人工验收。

## 根因

地面导航网格在运行时烘焙后，只修改了 `NavigationMesh` Resource，但旧的自赋值方式没有可靠地把更新提交给 Godot 4.7 的 `NavigationServer3D` 区域。因此地图查询暂时没有有效导航区域。

`Movement` 与 `MovementObstacle` 随后调用 `map_get_closest_point()` 并无条件写回结果。导航查询失败时 Godot 返回 `Vector3.ZERO`，再减去 `path_height_offset` 后形成 `(0, -0.6, 0)`，导致单位和建筑统一堆叠。

## 修复

- 运行时烘焙完成后，使用 `NavigationServer3D.region_set_navigation_mesh()` 把更新后的网格显式提交给区域；
- `Movement` 与 `MovementObstacle` 在吸附前调用 `map_get_closest_point_owner()`；没有有效 owner 时保留场景或生成器给出的坐标，不再把零向量哨兵当成有效位置；
- 保留静态碰撞体导航源方案，避免运行时读取 GPU 渲染网格；
- 普通 Attack 测试等待时间由 0.25 秒调整为 0.8 秒，因为修复后攻击者需要从真实场景位置完成追近，不再从原点重叠位置立即开火。

## 自动化验证

- `RuntimePlacementSmokeTest`：Tank 保持 `(13.263, 0, 12.637)`，敌方建筑保持 `(20, 0, 12.637)`，双方不重叠；
- `TankGroundAttackMoveSmokeTest`：0 failure，验证导航移动仍然有效；
- `TankEntityAttackMoveSmokeTest`：0 failure，验证实体目标追踪和开火；
- `TankOrdinaryAttackSmokeTest`：0 failure，验证真实部署距离下追近并攻击；
- 既有 RID/ObjectDB 退出泄漏仍存在，不属于本缺陷修复范围。

## 人工复验

建议重新运行 `TestCombatPolicies`、`TestGroundAttackMove`、`TestEntityAttackMove` 和 `TestOrdinaryAttack`，确认场景运行坐标与 3D 编辑器布置一致，并重点观察侵略、警戒与固守在真实距离下的表现。
