## 1. 项目背景与硬约束

- 游戏：AI RTS（Godot 4.7 mono；C# 侧权威结算/战斗/寻路，GDScript 侧表现与 HUD；
  100×100 米地图，战争迷雾，最多 4 玩家）。
- 目标形态：**打包给比赛评委**（10 月 1 日前），**纯本地运行**（不依赖任何云 API）。
- 用户已明确的架构决定：
  - LLM 默认**开**（MiniCPM5-2B，本地 Ollama），担任战略层；
  - 选择层用 Laya（HuggingFace `convaiinnovations/laya`，mmBERT-base 多语言版，
    322M 参数，一次前向回答全部问题，支持 choice/score/noul 三种题）；
  - Hermes 暂时不用；
  - 副官要**擅长"移动并攻击"（attack-move）这类命令**，不要每次只点兵；
  - 单位默认攻击射击范围内敌人这块功能也有问题，要修；
  - 先做到"和简单电脑对打能赢"，再谈爬难度。

### 当前三层混合（设计文档口径）

| 层 | 实现 | 频率 | 职责 |
|---|---|---|---|
| 规则中台 | `behavior_tree.py` + `rules_fallback.py`（发展阶梯 + 多轨并行填充） | 每 tick（~10Hz） | 常驻产出 baseline：采集/生产/建造/防守/施压 |
| System 1 选择层 | `laya_provider.py` → `pydantic_agents._propose_via_laya` | ~4Hz | 在程序给的候选表上做**选择**（任务/执行者/目标/参数/分支） |
| System 2 生成层 | MiniCPM5-2B（Ollama）`_propose_via_model` + 战略层 | 快路兜底 + 战略 30s | 四列任务补丁生成 + 战役计划/分支 |

- 两层模型输出共用同一个契约：**四列接口**
  `{"u": [[actor_ref, skill_ref, target_ref, params_ref]], "g": branch_ref}`，
  一次补丁实际只有 1 行；逐行过既有校验（ref 表、技能-目标类别、能力、落点），
  非原子、逐项回执。

## 2. 控制流真相（我们认为这是最需要检讨的部分）

设计文档写"三层混合"，但一天实测把**真实权力分布**照出来了：

1. **规则中台每 tick 常驻下发**，模型只能在其上做稀疏覆盖。
   训练数据（817 条记录的 1031 个 task 标签）的分布：

   | task 标签 | 全体 | 教师局(2B) | 学生局(laya) |
   |---|---|---|---|
   | GAT 采集 | 594 (58%) | 162 (44%) | 432 (65%) |
   | PROD 生产 | 389 (38%) | 160 (43%) | 229 (35%) |
   | BLD 建造 | 42 (4%) | 42 (11%) | 0 |
   | DEF 防守 | 6 (0.6%) | 6 (2%) | 0 |
   | **ATTACK/AMOV 进攻** | **0** | **0** | **0** |

2. **模型的决策空间被候选表+校验挤得很窄**：可打的技能、可派的人、可打的目标
   都由程序先筛一遍，模型只在剩下的里选。它的上限被规则层的过滤质量锁死。
3. **移动闸门有最终否决权**：模型/规则发出的每条移动意图还要过
   `movement.plan_safe_route`（边界→路径→中继点→侦察确认→局部战力）。
   修复前一局 413 次推进只放行 56 次（详见 §3.3）。
4. **微操 100% 是手写代码**（`AutoAttacking/GroundAttackMoving/AttackingWhileInRange/
   WaitingForTargets` + C# 战斗结算），两个模型都不参与。
5. 战略层（2B，30s）只负责战役阶段/里程碑/分支走向，**不到单位级**。

**一句话：最快最笨的层（规则）对每个单位每 tick 有最终发言权，最聪明的层（2B）
每 30 秒只有一个比特级影响力，Laya 在中间捡两者剩下的决策。**

### 3.3 今天定位并修复的三个真 bug（都不是模型问题）

**P0-1 双 runner 接管风暴（最严重）**
- 现象：整局 `rule-attack` 0 条、`rule-advance` 0 条，只有 589 条生产令；
  `ai_controlled_units` 只剩 9 个**建筑**，112 个机动单位全在
  `player_controlled_units` 里 → 军事轨/侦察轨没有执行者。
- 根因：游戏加载页按 `auto_takeover` **预热了第二个 runner**（连客户端 DCS），
  它的命令经客户端转发链触发局服 `_rpc_command` 的
  `_notify_adjutant_player_override`——这条路径**没有副官来源守卫**
  （DCS 侧 `notify_player_override` 有 `_adjutant_executing` 守卫，NetSync 这条没有），
  于是副官每下发一条命令，受令单位就被当成"玩家手动接管"踢出托管。
- 修复：① harness 显式 `AIRTS_ADJ_AUTO_TAKEOVER=0`；
  ② NetSync 加 `ADJUTANT_SOURCE_MARKER`（随转发命令 extra 前缀带到局服，
  `_rpc_command` 摘前缀后跳过 override 通知；手动玩家命令语义完全不变）。
- 效果：客户端转发命令 271 → **0**；`rule-fill-attack` 0 → **492**。

**P0-2 威胁闸门把大军逐个拦散**
- 现象：413 次推进只放行 56 次，`threat_too_high` 拦 222 次，
  90:31 的优势兵力超时亡。
- 根因：`local_force` 只数**已经进 30m 接触圈**的单位，60 个兵被逐个评估——
  每个单位只看得见先到的战友，永远凑不齐 `ENGAGE_ADVANTAGE_RATIO=1.2`。
  **这不是"保守"，是集结动作从未完成。**
- 修复：`movement.committed_support`——战区=接触圈内的敌人，路线台账里 target
  落在任一战区敌人接触圈内的己方作战单位**算即时战力**（"正在赶来打这一仗"的部队；
  200m 外看戏的友军仍然不算，纪律不变）。第二道判据：已拦下的单位若援军已在赶来，
  降级动作从 retreat 改 hold（后撤会把集结中的大军逐个抽走）。
- 效果：放行率 13.6% → **85%**；`threat_too_high` 222→44；
  attack_move 167 → **602** 条且全部 Accepted。

**P1-3 分支教师标签陈旧**
- 现象：v10 里 101/186 条 branch 标签指向**已完成里程碑**绑定的节点
  （D12←M06 已完成），Laya 采纳后全被 `note_model_branch` 以 `branch_done`
  驳回（10 次）——等于教模型做一个必然无效的选择。
- 根因：`_mainline_node_id` 读的前沿 key 写错（战役状态里叫 `next_frontier`，
  `frontier` 只存在于派生视图）→ 每次都走进回退分支；回退又取"最近已完成"里程碑。
- 修复：前沿取 `next_frontier`；回退改为**优先级最高且未完成**的里程碑绑定节点；
  全完成则不给标签。守门测试 4 例（含"标签必须真能被 note_model_branch 采纳"的闭环断言）。

### 3.4 仍未解决的问题

**P1-4 打不动敌方建筑（兵种射程的数学问题）**
- demo 平衡表：步兵步枪 0.5 伤 / 6m 射程；反地炮塔 2.0 伤 / 16m 射程；
  坦克炮 3.5 伤 / 7.5m；重坦克炮 5.0 伤 / 16m。
- 敌方 4 座炮塔 + 3 指挥中心是机炮要塞，**纯步兵海在射程上就冲不上去**
  （进射程前就被点名）。而我们一局 0 辆坦克（发展阶梯先兵营后车厂，240s 内没走到）。
- 叠加**两线作战**：我们的分基地开在 (80,83)，紧挨敌情 (83,77)——扩张开进了
  敌家脸上下，一半兵力在家防守、一半在东北救分基地，始终形不成一拳。

**P1-5 训练数据的战略维度为 0**（见 §3.1 表格与 §7.5）

## 6. 我们准备改但还没做的

### 6.1 数据与训练侧（不依赖参谋结论，可直接做）

### 6.2 架构侧（想改，但等参谋意见再动）

1. **给 Laya 加"单位级微操题"**：一次前向里批量问 N 个单位
   （集火谁 / 是否风筝 / 是否后撤 / 是否前压），这正是它"一次前向回答全部问题"

2. **四列接口升级为小队级**：一行可带多个 unit，让单次决策能指挥一个班

3. **重划三层权威**：规则只保留硬安全不变量（保护单位/建造合法性），

4. **闸门权威降级**：模型下发的小队指令，闸门只在安全必要时否决
   （现在闸门对一切移动意图有最终否决权，模型再好也被拦）。

## 7. 架构层面的反思（我们的怀疑，请独立验证）

### 7.1 Laya 的角色与频率可能用错了

- 现状：~4Hz 问 5-6 道**军级粗题**（这一拍全军该干什么），候选表和校验都由程序先筛。
  它的容量（322M、批量问答）花在"某个工人该采集还是该生产"上；
  而这类决策规则阶梯每 tick 都在免费做，模型只是**追认**（95% 标签是 GAT/PROD）。
- 怀疑：判别式模型的优势是**在显式选项里做高频、可解释的选择**。
  应该把它用在"规则明显做不好"的选择上（集火目标、风筝时机、撤退时机、
  侦察优先级），而不是追认规则已经做好的事。

### 7.2 微操层完全没有模型参与（对照 Jev 视频）

- 现状：微操 100% 手写（追击/绕射/瞄准/开火/待机索敌），
  Laya 和 2B 都不碰单位级行为。
- 用户指出 Jev 在 RTS 里展示了很好的微操（视频链接见 §0）。
- 我们的架构里，**唯一适合做微操的层（一次前向回答全部问题的判别引擎）
  被放在了最粗的粒度上**。Laya 的题天生适合"20 个单位 × 3 个微操选项"
  这种批量结构，我们从未试过。

### 7.3 2B 的频率与接口可能也没发挥优势

- 现状：2B 要么在快路被 Laya 顶掉后兜底（一次一行四列补丁），
  要么 30s 一次做战役计划。前者被接口扼住（见 7.4），后者带宽太低。
- 生成模型的优势是**组合式产出多对象计划 + 自然语言推理**。
  更合适的可能是：2B 以 1-5s 周期生成**班组级指令**
  （"A 班 attack-move 到 (x,z) 激进姿态；B 班守家；C 班补产能"），
  Laya 以 4-10Hz 做单位级微操选择，规则只保安全不变量。
- 我们现在恰好是反的：规则做全部班组决策，2B 做阶段决策，Laya 追认。

### 7.4 四列接口与闸门的双重扼制

- 四列接口一次一行、逐行校验、非原子；每条移动意图还要过闸门
  （边界/路径/中继点/侦察确认/局部战力）。修复前闸门拦掉 86% 的推进，
  **模型输出得再对也会被重新审理**。
- 后果：模型无法表达"这一个班一起去打那个建筑"，只能细流式下单。
- 值得检讨：接口是否应升级为小队级？闸门是否应对模型指令只保留安全否决？

### 7.5 自对局训练目标设计

- 现状：让 Laya 模仿"实际下发链"，而该链 95% 是规则阶梯。
  **模仿规则 = 零价值**（规则每 tick 免费在跑）。
- 2B 教师数据只有 156 条，且同样 87% 是采集/生产（因为它看到的牌桌
  确实什么都没发生——112 个单位当时已被接管风暴踢出托管）。
- 无任何结果信号：分不清教师的哪个决定是好的。
- 需要参谋：选择层的正确学习目标到底是什么？
  (a) 模仿 2B 的战略决策？(b) 从结果学（离线 RL/偏好对）？
  (c) 直接学微操策略（那里规则明显弱）？(d) 干脆换强化学习路线？

### 7.6 评估缺口

- 目前唯一指标是 val 准确率，且分布退化（ATTACK 0 样本）。
- 没有任何指标把模型决策和对局结果（胜率/伤害/战损/建筑损伤）关联起来。
- 没有 A/B 能力区分"这一局是模型的功劳还是规则的功劳"
  （虽然 harness 有 `AIRTS_S1_BACKEND=off/model/laya` 开关，但没做成对照实验）。

## 8. 请参谋方重点回答的问题

1. **三层分工**：规则（10Hz 全量）/ Laya（4Hz 选择）/ 2B（30s 生成）
   这个串行结构，权威分配是否本末倒置？正确的权威切法是什么？
2. **Laya 的最佳粒度**：军级粗选（现状）/ 班组级 / 单位级微操批量问答，
   哪个才配得上一个"一次前向回答全部问题"的 322M 判别模型？
   如果要学 Jev 式微操，训练数据和接口要怎么设计？
3. **2B 的最佳位置**：继续做 30s 战略 + 快路兜底？还是提到 1-5s 班组指令生成？
   四列接口是否该废掉/升级？
4. **训练目标**：模仿下发链（现状，95% 是规则）显然是错的。
   选择层应该向谁学、学什么？结果信号要怎么进训练循环？
5. **规则层的定位**：规则中台应该收缩到"硬安全不变量"，还是继续保持
   "每 tick 全量 baseline + 模型稀疏覆盖"？后者是否注定让模型只能追认？
6. **微操是否需要模型**：还是说微操就应该是手写状态机/行为树
   （AutoAttacking 这类已经写了三年的代码），模型只配做上层选择？
   如果微操值得模型做，Laya 的延迟预算（我们实测 p50 47-63ms）够不够 10Hz？
7. **验证方法论**：在"模型决策被规则和闸门双重扼制"的现状下，
   怎么设计实验才能干净地测出"模型的贡献"？
8. **我们最大的盲区可能在哪**？（例如：是不是从一开始就不该用
   "四列接口 + 校验"这种为约束小文本模型设计的契约去套一个判别式引擎？）
9. 如果推翻重来，**给你同样的两个模型 + 本地纯运行约束 + RTS 场景**，
   你会怎么设计这个架构？（这是最重要的一题）
