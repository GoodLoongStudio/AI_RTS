## 2. 当前运行架构

当前运行时**不再是“只有一个 MiniCPM5-2B 决策模型”**。

主干已经具备：

```text
权威观测 / 事件
   ↓
副官协调器（状态、任务、接管、generation、TTL、候选）
   ↓
Laya System 1（可配置）
   ↓ 失败 / 不可用
MiniCPM5-2B System 2（本地 Ollama）
   ↓ 超时 / 失败
规则 baseline
   ↓
Task Patch / Intent
   ↓
程序硬校验
   ↓
Godot 权威命令入口
   ↓
行为树 / 寻路 / 战斗 / 经济持续执行
```

其中：

- Laya 是判别式快速选择层，不是第二个生成式指挥官；
- MiniCPM5-2B 负责较复杂的策略和组合判断；
- 规则层保证模型不可用时对局仍能继续；
- 行为树和底层执行器处理寻路、射程、CD、持续交战、采集、建造和生产；
- 玩家命令拥有最高控制权，旧模型结果不得跨 generation / TTL 复活。

## 3. 当前最重要的开发方向

### P0-A：先建立可玩的规则基线

近期自对局已经证明：基础链路能产生大量 attack_move，但仍曾出现“敌方建筑伤害为 0”。

在继续扩大模型训练前，先固定一条 EASY doctrine：

- 早车厂；
- 明确坦克 / 反建筑兵力配额；
- 主力优先单线集中；
- 扩张不得贴敌方主阵地；
- 目标优先级可审计；
- 同种子纯规则局至少能稳定造成建筑伤害，并能走到真实胜负。

### P0-B：SquadOrder + 订单租约

四列 Task Patch 继续作为内部落地格式，但模型主要表达升级为原子小队订单。

有效订单在 TTL 内拥有战术优先权：

```text
紧急安全事件
 > 玩家命令
 > 有效模型小队订单
 > 战略计划展开订单
 > 无订单规则 baseline
```

规则层可以做安全拒绝和路径修正，不能每 tick 无理由覆盖仍有效的模型订单。

### P0-C：模型贡献必须可测

统一做：

- R0：规则战略 + 规则战术；
- R1：2B 战略 + 规则战术；
- R2：固定战略 + Laya 战术；
- R3：2B 战略 + Laya 战术。

至少比较：胜负、建筑伤害、战损、首次建筑受损时间、订单完成率、模型接受率、规则替换率、安全拒绝率和空转时间。

### P0-D：战役产品闭环

已有胜负、结算、重开和成长，但仍要补通用 Objective Runtime：

- 消灭目标；
- 保护目标；
- 到达 / 撤离；
- 存活计时；
- 事件触发；
- Objective → MatchOutcome。

该项优先于继续扩成长树内容。

## 4. 当前已落地、不得回退的能力

- 玩家接管优先、逐单位 generation、显式交还；
- 请求 / 任务 TTL 与旧结果失效；
- 模型超时不阻塞已有任务；
- 多线经济 / 建造 / 侦察 / 军事；
- arrival / path_failed 等执行反馈；
- Laya provider、健康熔断和回退；
- MiniCPM5-2B 本地运行；
- 游戏侧本地模型服务拉起与预热；
- 自对局 harness、训练数据与模型 / 规则开关；
- 传统规则 AI、程序化地图、成长系统和联机 Demo 已有实现。

架构升级时必须复用这些成果，禁止因为旧方案标题带“最终架构”“重构”而从零重写。
