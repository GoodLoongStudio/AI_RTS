## 2. 结果：600s 对局从"0 胜"变成"3/4 胜"——但这不是打法变强，是**判错**

| 局 | verdict | 首次伤建 | 摧毁建筑 | 我军 | 敌军 | 终局时刻 |
|---|---|---|---|---|---|---|
| r9_1 | **win**（复盘归档日志认定） | 174s | 9 | 82 | 1 | 375s |
| r9_2 | **win** | **50s** | **39** | 59 | 3 | 324s |
| r9_3 | **win** | 70s | 10 | 46 | 7 | 491s |
| r9_4 | timeout | 104s | 31 | 23 | 20 | 611s |

上一轮记的"600s 三局 0 胜"**是假的**。真相分两层：

**第一层（harness 失明）**：`selfplay_match.py` 每 10s 轮询一次战术观测，失败就
**静默丢弃**，且照样把 deadline 空转到 600s。于是"对局在第 375s 结束"在结果 JSON 里
长得跟"打满 600s 没打完"一模一样。

**第二层（verdict 判错）**：终局判定只认 `forces_log` 最后一条（30s 一刷），
而它在终局前就停止更新了；同时专用服在广播结果后 **5 秒主动 `quit()`**，
harness 把这次正常退出当成"游戏崩了"。

实测证据（`state_r9_1/selfplay_server.out`，本轮新加的日志留档）：

```
[对局] 已广播结果: 胜利, 5 秒后回收专用服
```

r9_1 在 375s 敌军全灭（`en_alive=0`）、386s 广播胜利、391s 服务端退出。
旧 harness 记 `verdict=aborted`、`enemy=1`（死亡前最后一次 forces 轮询的陈旧值），
**白丢一场胜局**。

harness 修复（`selfplay_match.py`）：

- 采样失败全部留痕进 `sampling_log`（ts + error）；
- 连续 3 次拿不到观测即收尾，并**先读日志里的权威结算**再决定性质：
  有结算 = 正常终局回收，没结算 = 真异常（`game_died_at_s` + `verdict=aborted`）；
- verdict **以游戏自己广播的结算为第一依据**（`match_result`），单位计数只作兜底；
- 每局把 `selfplay_server.out` / `selfplay_client.out` 复制进 `state_<tag>/`
  ——这两个文件本来每局被 truncate 覆盖，**事故现场正好被下一局擦掉**。

> ⚠ 归因纪律：副官规则层**从不设置警戒姿态**（coordinator 里没有任何
> `SetEngagementStance(Guard)`），所以这 3 场胜利**与本轮警戒修复无关**，
> 完全是测量修正的结果。警戒修复是给玩家手动开警戒时用的（见下节）。

## 3. 警戒模式的四个 BUG（用户口径逐条对上）

用户原话拆成两条行为规则：**敌人进本单位视野 → 主动跑去打**；
**敌人离开视野 / 追得太远 → 回原位**。旧实现四条全违反：

| # | BUG | 旧代码位置 | 用户可见症状 |
|---|---|---|---|
| A | 索敌圆心取**岗位点**而不是本单位位置 | `_get_units_to_attack()` 里 `detection_origin = guard_anchor` | 单位一旦离开岗位（归途中/被命令挪动），贴着它身边的敌人进不了索敌圈，**站着挨打** |
| B | 主循环**先判回家再判敌人** | `_on_timer_timeout()` 第一句就是 `_try_returning_to_guard_anchor()` | 敌人就在眼前也照样往家走 |
| C | 启程回家时**摘掉轮询计时器** | `_try_returning_to_guard_anchor()` 里 `_timer.timeout.disconnect(...)` | 整段归途对敌人完全无反应，白挨打一路走回家 |
| D | 警戒 leash 只看"敌人离岗位多远" | `AutoAttacking._enforce_combat_policy()` | 敌人同速逃跑时刚被拖到岗位视野边缘就收手，永远打不到一个在逃的敌人（被风筝） |

修复（`WaitingForTargets.gd` + `AutoAttacking.gd`）：

- 索敌圆心 = **本单位自己的位置**，与"敌人进视野就打"同口径；
- 主循环改为**先看敌人再决定回家**，归途中敌人进视野立即 `_abort_return_home()` 转身接战；
- 归途**不再摘计时器**（`_returning_home` 标记 + 打断入口），归途全程可被打断；
- leash 两条并列（任一满足即收手）：**敌人逃出本单位视野**（看不见了还追是瞎追）
  或**本单位追离岗位超过 `视野 × 1.5`**；同一常量 `GUARD_MAX_CHASE_FACTOR`
  同时给"追逐收手"和"追太远不再接新战"用——两边不同源就会在边界上
  "收手→眼前又有人→再追"反复抽搐，永远回不了岗位点。

## 4. 新回归测试（`UnitGuardStanceSmokeTest`，3 幕 9 断言）

| 幕 | 场景 | 断言 |
|---|---|---|
| 1 | 敌人在本单位视野内 | 主动接战 + 真正开火掉血 + 不处于空闲待命 |
| 2 | 归途途中敌人在单位身边出现 | **打断归途并接战开火**（这一条就是 BUG C 的判据） |
| 3 | 单位已被甩出岗位 3× 视野 | 不接视野内的新目标 + 持续向岗位点移动（防边界抽搐） |

**判别力验证**：把两个文件临时回退到修复前逻辑后重跑，第 2 幕精确报红
（"警戒：归途中敌人进视野应打断归途并接战开火"），恢复后 0 failure。
（敌方指挥中心带武器会还击，测试单位每幕之间回满血，否则撑不完三幕。）

## 5. 全量回归跑不起来的真因（本轮顺带修掉）

`tools/run_full_regression.ps1` 的 `Assert-Manifest` 要求 `tests/automated/` 下每个
`.tscn` 都必须登记在 manifest 里，否则**整锅抛异常、一个测试都不跑**。实测有 10 个
场景未登记——也就是说这套全量回归已经有一段时间无法执行了。本轮：

- 登记 7 个真实冒烟测试（含此前完全没进过回归的 `UnitAutoAttackSmokeTest`、
  `GroundAttackMoveArrivalSmokeTest`、`GrowthModifiersSmokeTest` 等）；
- 3 个非断言型诊断脚本（`AiOverlapBuildCheck` / `GroundingScreenshotTest` /
  `NoEnemyAdjutantRepro`）按 manifest 既有约定进 `excluded_scenes`；
- 95 例（92 Godot + build/core/audit）实际跑通。

另：该脚本是 UTF-8 无 BOM，Windows PowerShell 5.1 按 ANSI 读会直接 parse error
（本轮第一次调用就撞上），临时用 BOM 副本跑完即删，未改动原文件。

## 6. 回归结论（与改动前基线逐例对比，非"我觉得没问题"）

| 口径 | 结果 |
|---|---|
| 两侧都失败（既有失败） | **50 例，失败原因逐字一致**（退出期 RID/ObjectDB 泄漏、SCRIPT ERROR、超时等） |
| 仅修复侧失败 | **0 例** |
| 仅基线侧失败 | 0 例 |
| 抖动 | `local-avoidance` 在同一份代码下连跑 3 次得到 3/3/0 failure，与本次改动无关 |
| 本次改动直接相关的既有测试 | `unit-auto-attack`、`ground-attack-move-arrival`、`tank-ground-attack-move` 全 PASS |
| 本次新增测试 | `unit-guard-stance` PASS（9.2s） |

默认姿态是 `Aggressive`（`CombatPolicyStore.DefaultPolicy`），本轮的 Guard 分支
对未显式设置警戒的单位是**空操作**——这也是既有战斗测试全绿的原因。
