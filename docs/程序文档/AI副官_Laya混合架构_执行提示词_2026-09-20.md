## 0. 你的角色与最终目标

你是本仓库（AI_RTS）的**代理工程师**。目标：把游戏内「AI 副官」的实时决策层，从**生成式小模型（MiniCPM5-2B，慢，秒级）**升级为**判别式决策引擎 Laya（非自回归，33ms 级）**，形成三层混合架构：

```
规则层（已有，不动）        →  执行：物理 / 寻路 / 技能 CD / 动画 / 单位行为树
System 1：Laya（本次要做）  →  选择：进攻还是撤退？优先打谁？要不要治疗？危险度多高？
System 2：MiniCPM5-2B（保留）→  生成/规划：战略方向、长期计划、对局外对话
```

一句话原则：**规则用 Code，选择用 Laya，生成用 LLM。**
**必须遵守**：Laya 是**新增的一层**，不得破坏现有链路；现有 2B 链路必须保留为可回退选项。

- 副官与游戏进程通过 DCS（DebugControlServer，裸 TCP + 一行 JSON）通信

### 1.2 现有副官的决策机制（改造的对象）
- **实时链路唯一决策入口**：`graph/pydantic_agents.py` 的 `PydanticAITaskPatchAgent`（约 672 行起）。
  `system_prompt = NEW_SYSTEM_PROMPT`、`output_type = str`（**纯文本输出**，结构由程序自己解析；实测本机 2B 在带 schema 指令时容易返回空，故不用 PromptedOutput）。
- **输出格式（四列接口）**：模型只输出
  `{"u":[[actor_ref, skill_ref, target_ref, params_ref], ...], "g": "<决策地图节点号，如 D3>"}`
  所有 ref 必须来自程序给出的候选表，**模型只做选择，不能自造**。
- **候选表构造**：`graph/task_patch.py` 的 `DecisionFrame`（actor/target/params 三张 ref 表 + `SKILL_ALLOWED_TARGETS` 技能→允许目标类别）。
  解析与校验：同文件 `TaskPatchBatch` / `TaskModification` / `RowRejection`。
- **候选菜单（决策地图）**：`graph/decision_map.py`，节点 D1…D15，`candidates` 形如 `{"skill": "GAT", "target": "resource"}`。
- **触发节流**：`graph/interrupts.py::is_tactics_due`，参数 `tactics_interval_ticks`（默认 30 tick ≈ 0.5s；事件节流 `--event-interval` 默认 20）。
- **规则中台（地板）**：`graph/rules_fallback.py`（模型不可用/超时/输出非法时仍持续工作——这是既有设计，必须保持）。
- **超时配置**（`.env.local`）：`LLM_TIMEOUT_SECONDS=25`、`STRATEGY_TIMEOUT_SECONDS=45`。

### 1.3 痛点（为什么要换）
真实对局上下文（几十个单位 + 资源 + 事件）下，2B 生成模型经常**答不完**（历史日志里大量 `ModelTimeout` 降级），导致副官"只会造兵"、决策频率上不去。**问题不在模型大小，而在生成式架构的延迟量级。**

### 1.4 Laya 是什么（权威事实，来自 HuggingFace `convaiinnovations/laya`）
- **非自回归判别式决策引擎**：ModernBERT-large 421M（英文）/ mmBERT-base 322M（多语言）+ 决策头；**不生成文本**，输出只有概率与数值 ⇒ 结构上不可能输出非法 JSON、无幻觉。
- **三种原语**：
  - `choice`：从请求时定义的选项中选一个，返回选项 + 校准概率
  - `score`：在序数刻度上打分（返回期望档位 + 分布）
  - `noul`：二值判断，返回 P(true)∈[0,1]
- **一次前向回答全部问题**（所有问题共享一次 forward）。
- **速度**：T4 单题 33ms（≈30 次/秒）；10 题批处理 72ms（7.2ms/题）；CPU 193~464ms。
- **体积**：英文 808MB；多语言 647MB（`subfolder="multilingual"`）。Apache 2.0，可离线自托管。
- **上下文**：英文 512 token；多语言默认 1024（编码器经 RoPE 最高 8k）；决策头选项描述预算 `head_max_len=256`。
- **用法**：
  ```python
  import laya
  agent = laya.load("convaiinnovations/laya", subfolder="multilingual")  # 或 Router(preload=True)
  state = {"units": "...", "resources": "...", "events": "..."}   # dict/文本/JSON
  questions = {
      "task":   {"type": "choice", "instructions": "这一拍该做什么？",
                 "criteria": {"GAT": "去采矿", "ATK": "去打敌方", "BLD": "去建造", ...}},
      "actor":  {"type": "choice", "instructions": "派谁去？", "criteria": {...}},
      "target": {"type": "choice", "instructions": "目标选哪个？", "criteria": {...}},
      "risk":   {"type": "score",  "instructions": "当前危险程度？", "criteria": ["安全","警戒","危急"]},
  }
  res = agent.predict(state, questions)   # 一次前向
  res["answers"]["task"]["choice"]        # -> ("ATK", 0.87) 形式，含校准置信度
  ```
- **已知限制（必须正视）**：
  1. **零样本接近随机**（官方 typed-decisions 零样本 0.362 vs 随机 0.318）⇒ **必须用项目自己的数据做少样本提示或微调**，否则不如现模型。
  2. **选项数 >20 明显退化**（77 选项仅 0.425）⇒ 必须**分两级（粗→细）**或每问 ≤20 项。
  3. 需温度校准才能直接使用置信度（本项目可先用相对排序，不做门控）。
  4. 非拉丁文本必须用 `multilingual` 版本（英文 base 会把中文切碎且"自信地错"）。
  5. **不能走 Ollama 的 chat 接口**——必须在 Python 进程内直接 `import laya`（新 provider 层）。

### 1.5 参考架构（已被行业实践验证，可对照）
实时游戏决策的分工：`Game State → 决策模型 → Action`，其中
- 决策模型**不看画面**，读**结构化状态**；
- 频率约 **10 次/秒** 量级（不是每帧），"这几秒该怎么打"而非"每帧怎么动"；
- 不要每帧调用模型：`游戏照常跑 → 关键事件/Tick → 决策一次 → 行为树执行一段时间`；
- 落地四要素：**延迟、成本、状态设计、Fallback**。
Laya 相对该类方案的比较优势：更快（33ms vs 百毫秒级）、$0 成本（本地离线）、体积小、无幻觉；代价是**需要专业化训练**。

## 2. 目标架构（本次要实现）

```
                    ┌───────────────────────────────────────────┐
   DCS 观测 ───────▶│  DecisionFrame（已有）                    │
                    │  actor/target/params ref 表 + 候选菜单     │
                    └───────────────┬───────────────────────────┘
                                    │
                 ┌──────────────────┴───────────────────┐
                 │  System 1 决策（新增，可开关）        │
                 │  Laya（进程内，一次前向多问）         │
                 │   Q1 任务类型  choice                 │
                 │   Q2 执行者    choice（>20 分两级）    │
                 │   Q3 目标      choice（分两级）        │
                 │   Q4 参数/风险 score / choice         │
                 └──────────────────┬───────────────────┘
                                    │ 选择结果 → 展开成四列
                                    ▼
        ┌────────────────────────────────────────────────────────┐
        │ 既有落地面：TaskPatchBatch 校验 → 命令下发（不动）       │
        │ 回退：Laya 不可用/超时/低置信 → 现有 2B 链路 或 规则中台 │
        └────────────────────────────────────────────────────────┘
```

**关键设计约束**：
- Laya 的输出**必须经既有校验链**（`task_patch.py` 的 ref 表 + `SKILL_ALLOWED_TARGETS`），不得绕过。
- 开关建议：环境变量 `AIRTS_S1_BACKEND = laya | model | off`（默认 `model`，保证现状不变，需显式开启）。
- **Fallback 顺序**：Laya（若开启且成功）→ 现有模型 → 规则中台（已有）。
