> 人工验收：2026-08-12 已通过；强制移动与停止移动均返回接受，视觉表现正常。

## 1. 本次目标

建立不依赖 Legacy `AICommandHUD`、控制组或作战小队的传统 RTS 命令入口。该入口直接读取当前 Selection，并通过共享 C# `CommandRuntime` 提交命令。

本次仅提供灰盒交互：

- `强制移动`：进入一次性目标确认状态，下一次右键地面提交命令；
- `停止移动`：立即对当前选中且已迁移的 Tank 提交 `HaltMovement`；
- 反馈文字：显示接受数、拒绝数及 `Accepted` / `PartiallyAccepted` / `Rejected`；
- 未迁移单位计入拒绝数，不绕过命令边界直接写入 Action。

## 2. 接口与语义调整

原纵向样例中的泛化命名 `MoveUnitsCommand` 已统一为评审通过的 `ForceMoveUnitsCommand`：

```text
TraditionalUnitCommandHUD
  -> UnitActionsController
  -> UnitCommandGateway.ForceMoveUnits / HaltMovement
  -> Match/CommandRuntime
  -> IUnitCommandService.ForceMove / HaltMovement
  -> LegacyMovementPort（迁移期适配）
```

当前编队落点计算仍由既有 `crowd_moved_to_new_pivot` 完成，因此每个 Tank 暂时分别提交一个目标点。完整 Formation 系统实现后，应把“同一次玩家命令”和“各单位分配的落点”合并为一个批量命令及同一 `CommandId`。

`HaltMovement` 调整为幂等操作：单位具备 Movement 时，即使当前没有执行 `Moving`，仍返回接受且不修改攻击等其他 Action。这符合“只停止导航，不取消攻击或任务”的评审语义。

## 3. 场景契约

- Match 存在 Human 时，在 `HUD/TraditionalUnitCommandHUD` 创建传统命令栏；
- HUD 必须绑定该 Human 的 `UnitActionsController`；
- Legacy `AICommandHUD` 仍默认隐藏，两套 HUD 不共享作战小队状态；
- 当前只把 Tank 视为已迁移命令单位，其余单位等待各自任务语义评审。

## 5. 手动验收步骤

1. 运行 `tests/manual/TestOneUnit.tscn`；
2. 单击选择 Tank，不加入任何作战小队；
3. 点击底部中央 `强制移动`，确认提示要求右键指定地面；
4. 右键地图，确认 Tank 移动且反馈显示“接受 1”；
5. 点击 `停止移动`，确认 Tank 停止且反馈显示“接受 1”；
6. 再次点击停止，确认不会报失败；
7. 确认左上角 Legacy AI 副官仍默认隐藏，显示它也不应改变传统 HUD 的 Selection 来源。

## 6. 已知边界与下一步

- 2026-08-12 起普通右键移动已使用独立 `MoveUnitsCommand` / `UnitOrderKind.Move`；显式按钮仍使用 `ForceMove`，二者复用导航执行端口但不再混淆订单意图；
- 多单位目标目前是多个独立命令结果，尚不能提供统一 `CommandId`；
- 非 Tank 单位仍走旧普通右键路径，传统 HUD 不对其下达显式命令；
- 下一步建议实现 `ForceAttack` 的“单位目标/地面目标”双目标契约，再开始攻击链路纵向样例；
- InputMap/按键管理类尚未建立，因此灰盒按钮没有硬编码新快捷键，避免制造新的按键冲突。
