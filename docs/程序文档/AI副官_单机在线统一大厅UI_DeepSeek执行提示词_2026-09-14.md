你现在负责直接修改并验证 `G:\AIRTS\AI_RTS`，完成单机与在线匹配 UI 的真正统一。不要只写方案，不要只加一个地图下拉框；必须修改 Godot 场景/脚本并启动验证。

## 当前问题

当前有两套页面：

- `source/main-menu/Play.tscn` + `Play.gd`：单机页面是左侧地图列表、右侧玩家下拉框；
- `source/main-menu/Online.tscn` + `Online.gd`：在线页面是大厅槽位卡片、右侧地图卡、准备/房主开局。

现在两者虽然部分共用了地图数据，但视觉结构仍完全不同。目标是让用户一眼看出它们属于同一套产品。

## 目标界面

以在线大厅的卡片式布局为统一基准：

- 顶部：页面标题、在线昵称；
- 中部左侧：4 个玩家槽位卡片；
- 中部右侧：地图预览、地图名称、人数、尺寸和地图选择；
- 底部：准备、开始/立即开局、返回。

单机页面也使用完全相同的布局和视觉语言，但：

- 默认本机房主；
- 隐藏服务器地址、端口、连接状态和在线准备流程；
- 玩家槽位仍可选择 Human、Simple AI、None；
- 地图仍可切换；
- 点击开始继续使用原来的 `NetSession.host()` + `Loading.tscn` 单机流程。

在线页面：

- 保留连接状态、昵称、准备、房主立即开局、槽位增删 AI；
- 地图下拉框只允许房主修改，其他客户端只读；
- 地图选择使用 `Constants.Match.ALL_MAPS`，禁止硬编码 Plain & Simple；
- 房主选择地图后通过服务器权威状态同步给所有客户端；
- 开局时服务器和所有客户端必须加载同一个地图路径。

## 实现要求

### 1. 共享 UI

- 抽取共享的地图列表、地图信息、地图预览、玩家槽位和底部操作区域；
- 推荐新增一个共享场景或共享构建脚本，例如 `MatchSetupPage.tscn` / `MatchSetupPage.gd`；
- `Play.tscn` 与 `Online.tscn` 应通过模式参数复用同一套布局，而不是继续复制两份布局；
- 不要通过运行时把旧页面控件强行挪位置来假装统一，场景结构本身要统一。

### 2. 单机行为

- 单机模式参数为 `offline`；
- 视觉上与在线大厅一致；
- 隐藏 Host、Port、Join、Ready、连接状态等在线控件；
- 保留地图选择和四个玩家槽位；
- 将单机原来的玩家下拉选择转换为大厅槽位卡片中的选择控件；
- Start 按钮仍调用原有 `_create_match_settings()` 和 `Loading.tscn` 流程。

### 3. 在线行为

- 在线模式参数为 `online`；
- 保留昵称、连接状态、加入服务器、准备、房主立即开局和 AI 槽位切换；
- 地图选择仅房主可编辑；
- 客户端收到地图同步后更新地图名称、人数、尺寸和预览，不能覆盖服务器状态；
- 不允许未连接时显示可操作的房间槽位或开始按钮。

### 4. 地图与协议

- 继续使用 `MatchSetupShared.map_entries()`、`map_label()`、`map_summary()`；
- 不得在 `.tscn` 中写死地图名称、人数和尺寸；
- `NetSession.selected_map_path` 在断开时恢复默认值；
- `_rpc_start_match` 必须携带最终地图路径；
- 服务器必须校验地图路径存在且属于 `Constants.Match.ALL_MAPS`；
- 非法路径回退默认地图，不得崩溃。

### 5. 视觉要求

- 单机和在线使用相同的 Panel、圆角、边框、间距、字体层级和按钮尺寸；
- 玩家槽位卡片颜色沿用 `Constants.Player.COLORS`；
- 地图预览在两种模式中位置一致；
- 底部主按钮宽度、顺序和垂直间距一致；
- 1280×720、1920×1080 和窗口缩小时不裁剪主要控件；
- 中文文字不能溢出或遮挡下拉框。
