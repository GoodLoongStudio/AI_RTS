# 投射物生命周期与伤害结算纵向样例记录

日期：2026-08-14

对应进度：`CMD-028`

状态：已完成并通过人工视觉验收

## 1. 本轮目标

把已有 CannonShell、Rocket 和 Tank 地面 ForceAttack 从“依赖发射单位 Node”迁移为独立攻击实例，保证 Stop、停火、换命令或发射者阵亡后，已经发出的攻击仍按视觉命中时刻结算。

本轮没有新增导弹 AoE、追踪性能、步兵子弹、激光或地雷玩法，也没有擅自设定爆炸半径与友伤减免数值。

## 2. 结构变化

| 层级 | 实现 | 职责 |
|---|---|---|
| Domain | `AttackInstanceId`、`AttackLaunchSnapshot`、Delivery/Beam/Impact 枚举 | 表达不可变发射数据与未来武器扩展边界 |
| Application | `IWarheadDamageResolver`、`WarheadDamageResolver` | 纯 C# 计算实际爆点、footprint、友伤倍率、稳定排序与去重 |
| GodotAdapter | `ProjectileRuntime` | 保存活动快照和目标弱引用，生成投射物，并在视觉命中时应用一次伤害 |
| Scene | Match 下 `ProjectileRuntime`、`Projectiles` | 使在途投射物生命周期独立于发射单位 |
| Legacy 适配 | `AttackingWhileInRange`、`ExplicitGroundForceAttacking` | 暂时把现有 GDScript Action 接入统一投射物入口 |

## 5. 人工验收建议

在 `TestForceAttack.tscn` 中重点观察：

1. Tank 发射炮弹后立即 Stop，已离开发射点的炮弹仍应完成表现并在抵达时扣血；
2. HoldFire 下 ForceAttack 仍可发射，Stop 后保持 HoldFire，且在途弹命中后不再出现后续新炮弹；
3. 地面 ForceAttack 的目标点伤害与炮弹视觉到达时刻一致；
4. 普通攻击 Stop 后，如仍处于自由开火，单位可按既有自主索敌规则再次建立攻击，但旧订单已经取消。

发射者阵亡和 Rocket 目标失效目前由 `ProjectileLifecycleSmokeTest.tscn` 自动覆盖；若后续需要逐帧人工观察，再单独增加不自动退出的可视化测试面板，避免把临时测试 UI 混入正式 HUD。
