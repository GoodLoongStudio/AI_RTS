# 程序重构：传统 AI 外置配置约束

## 1. 状态

本文件只记录后续架构约束。当前重构保留既有传统 AI 行为，不实现新的 AI 指挥官、地图脚本或玩法 AI。

## 2. 必须满足的边界

- 传统 AI 的战术参数和策略选择不得写死在执行代码中。
- 配置至少需要表达阵营、AI 指挥官、地图和玩法四类差异。
- 同一阵营可以有多个具备不同性格与战术侧重的 AI 指挥官。
- 特殊地图可以提供覆盖配置；塔防、推进、混战等玩法也可以选择或覆盖策略。
- AI 仍通过与玩家相同的命令接口操作游戏，不得直接修改单位、资源或建筑内部状态。

## 3. 建议的后续组合方式

后续细化 AI 分支可采用“基础配置 + 有序覆盖”的组合方式：

`全局默认 → 阵营 → 指挥官 → 玩法 → 地图`

加载阶段应进行版本、引用、取值范围和兼容性校验，成功后生成只读运行时快照。地图覆盖不应复制整套 AI，而只描述必要差异。具体覆盖优先级仍需策划评审，本文件不将建议固化为正式规则。

## 4. 预留标识

后续配置契约建议预留稳定的 `ProfileId`、`FactionId`、`CommanderId`、`GameModeId` 与 `MapId`，并允许一个配置声明兼容范围。配置格式可沿用当前版本化 JSON 与严格校验方案，但需在 AI 细化分支单独评审。
