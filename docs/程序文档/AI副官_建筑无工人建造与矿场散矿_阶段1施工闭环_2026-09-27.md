## 0. 先说血缘判定（提示词第一节明令不许伪造）

**历史文档里不存在「建筑施工不需要 Worker」这条计划**，恰恰相反，三处明文要求派工人：
`docs/plan/AI-plan.md:80`（2026-08-30，「扩张蓝图的施工由现有 `ConstructionWorksController`
自动派工人完成」）、`决策手册/03-策略库-经济与建造.md:99/145/167`（`can_build`、
「禁止条件: 无可用建造者」）、`01-总则与决策地图.md:62`（「建造线由余额与建造者空闲驱动」）。

因此按提示词第 65 行的口径记录为：

> **分矿计划有正式来源**（`docs/mapgen/plan/4p-seeded-mapgen-plan.md:151,176,222,263`）；
> **零工人施工要求由当前用户重新确认并作为当前需求执行**，不冒充旧计划。

本阶段是**新增一条产品语义**，不是「恢复丢失的计划」。

## 1. 结果：施工不再以 Worker 为前置

| 项 | 修前 | 修后 |
|---|---|---|
| 进度唯一来源 | Worker 的 `Construct` 分配（`ConstructionService.cs:184-203`） | 分配 **+** 权威 Tick 自动工作量，二者按配置叠加 |
| 零 builder 的现场 | **静默停摆**：不推进、不标暂停、不拒绝，HP 永远停在 1 | `automatic`/`hybrid` 每 Tick 自动推进直到完工 |
| 放置时抓 Worker | `AssignBuildersAfterPlacement` 无条件从选中集抓人，`ConstructionService.cs:140-143` 把在采的 Gather 订单 `Cancelled` | 按 `constructionProgressSource` 决定：`automatic` 一个都不派；`hybrid` 只借真正空闲的；`worker` 保留旧行为 |
| 取消退款 | 恒为**全额**，与已完成工作量无关 | 按剩余工作量折算；`CompletedWork=0` 时折算系数 1，与旧行为逐分一致 |
| 口径来源 | 只能靠建筑名猜 | balance 配置逐类声明，**无一处按名称硬编码** |

## 2. 实现

### 2.1 新增配置字段（唯一事实来源）

`config/balance/{demo,adjutant-e2e}.balance.v1.json` 的 **全部 8 条 `constructions`** 都加了：

```json
"constructionProgressSource": "automatic",
"automaticWorkPerTick": 1
```

`automaticWorkPerTick=1` 配 `requiredWork=200` ⇒ 200 物理 Tick（60 Hz 约 3.3 秒）完工，
**与旧口径「一个 Worker 单独施工」的耗时逐 Tick 相同**，不改动经济节奏。

字段贯通 5 处（缺任一处都会因 `BalanceConfigErrorCode.UnknownProperty` 让整份配置加载失败）：
`BalanceConfigDtos.cs`（DTO）→ `BalanceConfigLoader.ValidateConstructions`（枚举 + 非 worker 源必须
声明正整数速率）→ `BalanceConfigLoader` 映射 → `BalanceDefinitions.StructureConstructionDefinition`
→ `StructurePlacement.ConstructionSiteSnapshot`。

### 2.2 进度源语义（`Domain/Construction/StructurePlacement.cs`）

```csharp
public enum ConstructionProgressSource { Automatic, Worker, Hybrid }
```

- `Automatic`：权威 Tick 自动推进；放置不抓 Worker。
- `Worker`：旧兼容口径，进度只来自分配。
- `Hybrid`：自动推进为主，Worker 只提供加速，绝不构成开工前置。

`ConstructionService.Advance` 先给 `Automatic|Hybrid` 的 Active 现场记上自动工作量，再叠加
分配工作量；尾部 `ApplyProgress`/`Complete`/`_lastAdvancedTick` 幂等全部复用，所以完成事件、
导航障碍解锁、生产解锁、半透明表现、断线/摧毁清理路径一行都没改。

### 2.3 不再抢采矿工人（`CommandRuntime.AssignBuildersAfterPlacement`）

在**权威端**按现场进度源短路，因此 GDScript 的三个调用方（`StructurePlacementHandler.gd:240`、
`NetSync.gd:759`、`DebugControlServer.gd:645`）与规则 AI 的 `RuleAiCommandGateway.PlaceStructure`
全部自动受管，不必逐个改：

```csharp
if (progressSource == ConstructionProgressSource.Automatic) return;
var eligible = progressSource == ConstructionProgressSource.Hybrid
    ? workerNodes.Where(w => !IsBusyOnOtherTask(_units.Register(w)))
    : workerNodes;
```

`IsBusyOnOtherTask` 的判据是「还挂着任何活动订单」——采集、移动、战斗、施工都算，
对应提示词第四节「只接管没有玩家订单、没有施工、没有高优先级军事任务的 Worker」。

### 2.4 退款折算

```csharp
var remainingRatio = (double)Math.Max(0, site.RequiredWork - site.CompletedWork) / site.RequiredWork;
// 每个 cost 折算后过滤 0 值；全部为 0 时跳过交易（账户层禁止零量交易）
```

自动施工让「已投入工作量」不再为零，仍按全额退就等于白送钱：造 200 工事的建筑推进到
199 点后取消、拿回全款，是无限刷钱漏洞。
