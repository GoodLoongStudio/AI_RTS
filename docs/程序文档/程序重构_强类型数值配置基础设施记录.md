## 1. 本轮结果

本轮建立了不依赖 Godot 的配置链路：

```text
demo.balance.v1.json
        │ System.Text.Json 严格解析
        ▼
可表达缺失/错误的 DTO
        │ 全量 Validator
        ▼ 零错误时才继续
不可变 Domain Definition + Frozen Catalog
```

新增内容：

- `config/balance/demo.balance.v1.json`：保存当前 Demo 的资源、九种实体、四件主武器、弹头、四种生产定义和五种建筑施工定义；
- `UnitTypeId`、`WeaponDefinitionId`、`WarheadDefinitionId`：取代场景路径作为配置身份；
- `UnitTypeDefinition`：用 Movement、Weapons、Gatherer、Constructor、Producer 可选能力组合描述移动单位和建筑；
- `BalanceConfigLoader`：严格区分字段大小写，拒绝注释、尾随逗号、无效 JSON 和未知字段；
- `IGameBalanceCatalog`：按稳定 ID 只读查询单位、武器、弹头、生产、施工和资源定义；
- `BalanceConfigRequirements`：由 Match 组合根声明必须存在的内容，通用 schema 不把具体关卡阵容写死；
- SHA-256 内容摘要：相同 UTF-8 配置内容得到相同指纹，供缺陷复现和未来回放记录使用。

## 2. 数值语义

- 资源、成本、载荷、生产/施工工作量保持整数；
- 攻击与采集间隔使用整数毫秒；
- HP、伤害、距离、速度、角度和倍率使用经过有限值与范围检查的 `float`；
- 免费项目允许 `cost: []`，但不允许省略 `cost`；
- 生产定义显式保存 `ProductTypeId`，不再要求产品 ID 必须从场景路径推导；
- 友伤倍率当前保持 `1.0`，没有改变现有完整友伤基线；
- Tooltip 的疑似 DPS 公式未在本轮修改。

Demo JSON 除《数值与配置基线》外，还记录了现有场景中的 Tank/Worker 移动速度、Tank 倒车与 120° 移动射界，以及迁移期 `RequiredWork`。这些数据目前仅进入新 Catalog，尚未改变运行态来源。

## 3. 失败语义

以下问题均返回稳定错误码和 JSONPath 风格位置：

- JSON 无效或字段类型错误；
- schema 不支持、必填值缺失或出现未知字段；
- ID 非法、重复定义或重复装配；
- NaN、Infinity、负数、非法零值或越界倍率；
- 非法资源、攻击域、武器交付方式或命中模式；
- Weapon、Warhead、Product、Producer、Construction 的悬空引用；
- 重复资源成本或互相矛盾的移动射击能力；
- 当前 Demo 组合根要求的定义缺失。

Validator 尽量一次返回全部相互独立的问题。只要存在一个错误，`BalanceConfigLoadResult.Catalog` 就为 null，不生成部分 Catalog，也不使用隐藏默认值。

## 4. 自动验证

纯 C# 新增 9 项配置测试，覆盖：

1. Demo 基线构造完整 Catalog 并逐项检查关键数值；
2. 相同内容产生相同 SHA-256；
3. 未知字段拒绝整个 Catalog；
4. 不支持的 schema 被拒绝；
5. 重复稳定 ID 不会后值覆盖前值；
6. 非法数值与非法 enum 可在一次加载中共同报告；
7. 悬空引用和重复资源成本被拒绝；
8. Match 配置档案缺少必需定义时被拒绝；
9. 无效 JSON 不向调用方泄漏异常且不产生 Catalog。

验证结果：

- `dotnet build OpenRTS.csproj`：0 warning，0 error；
- `dotnet run --project tests/core/AI_RTS.Core.Tests.csproj`：原有 45 项与新增 9 项，共 54 项通过、0 项失败。
