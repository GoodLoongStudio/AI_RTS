## 3. 本次验证新查出的根因（影响玩家与 AI 建造）

PlainAndSimple 上主基地 MovementObstacle 在导航网格里挖出的洞半径是 **24.0m**，
而正确值应为 footprint 7.0 + navmesh `agent_radius` 2.8 = 9.8m。

A/B 实测（同一张图、同一位置）：

| 配置 | +X 方向洞边界 |
|---|---|
| 原始（`affect_navigation_mesh=true`，带 CollisionShape3D） | **24.0m** |
| `affect_navigation_mesh=false` | 6.0~7.0m |
| 移除 CC 的 `CollisionShape3D`（并真正重烘） | 6.0m |
| 只改 `MovementObstacle.radius`（7.0 ↔ 2.333） | 24.0m（无变化） |

物理侧是正确的：射线穿过主基地时在距圆心 **-7.00m** 处命中（2.333 × 3，scale 只算一次）。
因此只有 navmesh 烘焙把 root scale 多算了一次：2.333 × 3 × 3 = 21.0，再加 agent 2.8 = 23.8 ≈ 24.0m。

真机数值印证：主基地作为远程锚点（无相邻要求，只剩可建性）在 +28m 可建、+26m 不可建。
其探环半径 = footprint 7.0 × 0.5 = 3.5m ⇒ 27.5m 处的探环内缘正好落在 24m 洞界上。

**后果**：任何建筑的相邻窗口（半径和 + 0.75 ≈ 13.3~14.4m）都落在 24m 洞内，
所以"贴着己方建筑放第二个建筑"在这张图上必然 `SurfaceNotBuildable`，自动选址也必然找不到点；
同一个 24m 洞也是出生点回归里矿车被推到 24.45m 的直接原因。

**已修复（2026-09-29 当日）**：给五栋建筑的 `MovementObstacle` 归一化 local scale
（`scale = Vector3(1/3, 1/3, 1/3)`，即 `1/root scale`），并在 `MovementObstacle.gd::_enter_tree()`
加了幂等兜底（只对 local scale≈1 且父缩放>1 的节点生效，覆盖以后新增的建筑）。归一化后
`obstacle.global_scale = 1.0`，carve 回到 `radius(世界 footprint) + agent_radius`。

主基地 carve 实测：修复前 **24.0m**，修复后 **6.0m**（+X 方向探环边界）。
