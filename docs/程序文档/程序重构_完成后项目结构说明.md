## 1. 文档目的

本文描述重构完成时仓库的实际结构、依赖方向、运行入口和仍然保留的 Legacy 文件。它是新程序员理解项目、定位改动范围和评审跨层依赖的首要结构文档。

重构前结构与功能基线见《程序重构_现有仓库结构与运行基线.md》；具体接口和新增内容流程见《程序重构_接口与扩展开发指南.md》。

## 2. 必须遵守的架构边界

> **强制规则：`source/csharp/Domain` 与 `source/csharp/Application` 禁止引用 Godot、OpenRTS 程序集、GodotAdapter、场景 Node 或任何 GDScript 类型。**

该规则不是建议，而是通过以下机制执行的仓库门禁：

1. `AI_RTS.Core.csproj` 使用普通 `Microsoft.NET.Sdk`，只编译 Domain 与 Application；
2. `OpenRTS.csproj` 使用 `Godot.NET.Sdk`，只编译 GodotAdapter 和 Godot 自动测试，并引用 `AI_RTS.Core`；
3. `tools/audit_core_engine_boundary.ps1` 检查项目 SDK、项目引用、PackageReference 和源码中的 Godot 命名空间；
4. `tools/run_full_regression.ps1` 默认执行该审计，违反边界时完整回归失败。

允许的依赖方向为：

```text
Godot 场景 / Legacy GDScript / Human / Rule AI
                         │
                         ▼
              GodotAdapter 与 Runtime
                         │
                         ▼
                  Application
                         │
                         ▼
                     Domain
```

禁止反向依赖。外部 Python、LLM、数据库或网络服务将来必须从单独的 Infrastructure/Adapter 侧接入，不能放入 Domain/Application，也不能直接操作 Godot Node。

## 4. 启动流程与每局组合根

Godot主入口是 `project.godot` 中的 `res://source/Main.tscn`：

```text
source/Main.tscn
  → Logo
  → source/main-menu/Main.tscn
      ├─ 自定义对局：Play → Loading → Map + Match
      ├─ 战役原型：CampaignMenu → Loading → Map + Match + CampaignController
      ├─ Options
      └─ Credits
```

`source/match/Match.tscn` 是每局游戏的组合根。其核心C# Runtime按场景树顺序装配：

| Match子节点 | 主要职责 |
|---|---|
| `BalanceConfigRuntime` | 先加载并校验平衡Catalog与Godot资源映射 |
| `InputBindingRuntime` | 解析输入上下文、组合键和`user://controls.cfg` |
| `WorldQueryRuntime` | 签发受权限查询会话并构造只读观察服务 |
| `CommandRuntime` | 持有稳定ID注册表、订单、战斗策略和单位命令服务 |
| `EconomyRuntime` | 持有每局资源账户服务并镜像Legacy玩家资源显示 |
| `StructurePlacementRuntime` | 建筑位置评估、扣款、蓝图生成和驱逐协作 |
| `ProductionRuntime` | 每建筑独立生产队列、扣款、进度、取消和部署 |
| `RallyPointRuntime` | 集结目标、清除及出厂单位后续命令 |
| `ProjectileRuntime` | 发射时捕获伤害快照并在投射物命中后结算 |
| `MatchOutcomeRuntime` | 玩家/战斗实体注册及最后存活阵营判定 |
| `ControlGroupRuntime` | 稳定ID控制组保存、召回和失效成员清理 |

同一场对局只能存在一套这些Runtime。Human、规则AI和未来Agent必须共享它们，禁止私自创建Registry、OrderStore、资源账户或命令服务。

## 6. C# Domain层

路径：`source/csharp/Domain/`；命名空间：`AI_RTS.Domain.*`。

Domain只保存引擎无关的值对象、枚举和不可变快照：

| 子目录 | 内容 |
|---|---|
| `Common/` | `MatchId`、`PlayerId`、`UnitId`、各类稳定ID及`WorldPosition` |
| `Combat/` | 交战姿态、开火策略、目标域、武器交付和弹头命中模型 |
| `Configuration/` | 单位、武器、弹头、资源、施工和生产的强类型定义 |
| `Construction/` | 建筑footprint、放置定义和施工现场快照 |
| `Economy/` | 资源种类、金额、账户快照和变更原因 |
| `Input/` | 输入上下文、修饰键、组合键和解析结果 |
| `Match/` | 参战方、战斗实体和比赛结算结果 |
| `Production/` | 产品定义、队列项目和生产者快照 |
| `Queries/` | 观察状态、字段掩码、实体观察、范围请求和经济观察 |
| `Rally/` | 地面、单位、资源集结目标和清除原因 |
| `Selection/` | 控制组编号等本地选择值对象 |

Domain不得读取JSON、访问文件、生成Godot资源、查询场景树或发出Signal。

## 7. C# Application层

路径：`source/csharp/Application/`；命名空间：`AI_RTS.Application.*`。

Application实现用例、校验、状态机和面向Adapter的端口：

| 子目录 | 权威职责 | 主要公共边界 |
|---|---|---|
| `Commands/` | Move、AttackMove、Withdraw、Stop、Attack、ForceAttack、Gather等批量命令 | `IUnitCommandService`、`CommandResult` |
| `Orders/` | 单位订单身份、替换和异步状态 | `IUnitOrderStore` |
| `Combat/` | 持续战斗策略和弹头伤害选择 | `ICombatPolicyStore`、`IWarheadDamageResolver` |
| `Economy/` | 多资源原子交易、幂等交易和余额事件 | `IResourceAccountService` |
| `Construction/` | 放置合法性、施工分配、进度、取消和摧毁 | `IStructurePlacementService`、`IConstructionService` |
| `Production/` | 每建筑队列、预扣款、退款、工作量和部署 | `IProductionService` |
| `Rally/` | 集结目标校验、变更和失效清除 | `IRallyPointService` |
| `Selection/` | 按玩家和编号保存/召回稳定ID控制组 | `IControlGroupService` |
| `Input/` | 默认Action、上下文优先级、组合键和原子覆盖 | `IInputBindingService` |
| `Queries/` | 查询会话、视野/字段过滤、LastKnown和成功空结果 | `IWorldQueryService`、`IBudgetedWorldQueryService` |
| `Configuration/` | JSON反序列化、全量校验、不可变Catalog和内容哈希 | `IGameBalanceCatalog`、`BalanceConfigLoader` |
| `Match/` | 自定义对局最后存活方规则 | `IMatchOutcomeService` |
| `Units/` | 导航、攻击、停止、采集和实体仓库端口 | `IUnitMovementPort`等 |

Application可以依赖Domain和.NET标准库；不得依赖Godot。所有引擎动作通过端口完成。

| `Queries/` | 从场景捕获观察快照并向GDScript提供只读字典Envelope |
| `Economy/` | 账户Runtime、资源节点注册表与Legacy采集执行端 |
| `Construction/` | 世界放置检查、施工现场注册和Legacy Worker施工端口 |
| `Production/` | 生产定义/建筑注册、队列Runtime和Godot部署端口 |
| `Rally/` | 集结仓库和表现同步Runtime |

| `Navigation/` | `IUnitMovementPort`到Godot Navigation/Legacy Action的桥接 |

## 12. Debug与Release差异

Debug用于开发和自动测试，可以由可信测试代码取得标准或全知查询会话，并取得己方实体稳定引用。Release会硬关闭以下测试入口：

- `WorldQueryRuntime.GetStandardSessionForTests`返回空字符串；
- `WorldQueryRuntime.GetDebugSessionForTests`返回空字符串；
- `WorldQueryRuntime.GetOwnEntityReferenceForTests`返回空字典；
- Release不创建`OmniscientDebug`查询授权。

这些入口不是玩家、传统AI或未来Agent的正式API。不得为了让Release代码“方便测试”取消该限制；应在组合根中为正式调用者签发专用、最小权限会话。

## 13. Godot生成文件和UID规则

- `.godot/`和旧`.import/`是可重建缓存，必须忽略；
- `*.import`旁车文件记录素材导入设置，仓库现有策略下应随源素材维护；
- Godot 4.7为文本脚本生成的`*.uid`是稳定资源身份，不等于导入缓存，应提交；
- 删除脚本时同步删除对应`.uid`；新脚本第一次由Godot识别后提交其`.uid`；
- `user://controls.cfg`和`user://camera.cfg`是每位开发者/玩家的本地文件，不进入仓库。

## 15. 维护规则

1. 新规则先进入Domain/Application及纯C#测试，再增加GodotAdapter和场景表现；
2. 新的Human、AI或外部调用者只能调用公共命令与查询边界；
3. 修改节点名、组名、Signal、资源路径或C#导出属性前，检查《程序重构_隐式场景契约清单.md》；
4. 修改Legacy权威写入必须同步允许清单，并说明为什么不能进入C#核心；
5. 一个需求或缺陷使用独立分支，提交中不混入无关场景重存或素材移动；
6. 所有代码、接口、缺陷和验收操作必须留下文档记录。
