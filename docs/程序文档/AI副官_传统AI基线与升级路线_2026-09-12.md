# AI 副官：以传统行为树 AI 为「地板」的升级路线

日期：2026-09-12
背景：用户指出"现在连传统行为树 AI 的能力都没达到，之前的计划像空中楼阁"。
本文件回答两件事：**① 为什么会这样；② 怎么在传统 AI 基础上做真正的升级**。

---

## 一、现状对照（同一件事，两边各有什么）

| 能力 | 传统 AI `source/match/players/simple-clairvoyant-ai/` | 现在的副官 |
|---|---|---|
| 工人数量 | `EconomyController._enforce_number_of_workers`（工人数 = CC 数 × 常数） | 模型偶尔回一条 PROD（无恒定策略） |
| 闲置工人 | `_assign_idle_workers_to_resources`：每 0.5s 把闲人派去采集 | ❌ 无人负责（截图里钱多却有人闲置） |
| 矿点分配 | `_find_visible_resource`：**人少优先 + 同拥挤取最近 + A/B 均衡** | 今天才移植（此前是"各自取最近"→ 3 人挤一矿） |
| 未完工工地 | `ConstructionWorksController`：给 `active_builder_count==0` 的工地派人（`Construct`） | 缺路由（阻塞 A），工地靠"派回工地"绕过 |
| 扩张 | `_find_expansion_site`：≥20m 外最远资源簇 → 开分矿 | ❌ 没有 |
| 防御 / 进攻 / 侦察 | `DefenseController` / `OffenseController` / `IntelligenceController`（含目标价值序、集结、撤退） | 行为树有雏形（交火/撤离/侦察航点），无价值序与兵力规划 |
| 决策节奏 | 每 0.5s 全量重规划（纯规则、确定性） | 模型异步低频 + 阶梯兜底（不稳） |

**结论**：传统 AI 是一套**完整、常驻、可确定复现的运营规则引擎**；副官目前只把"选谁干什么"换成了模型，
却**没有重新实现运营层**，所以严格弱于它。这不是模型不行，是**架构缺了一层**。

---

## 二、正确的定位：不是"用 LLM 替换行为树 AI"，而是三层分工

```
③ 模型层（战略/意图选择）     ← LLM 的真正价值在这里
     扩张还是补兵 / 打哪、守哪 / 何时撤 / 兵力构成 / 多队协同 / 玩家意图解读
     ── 只输出"意图与参数"，不碰坐标与元数据
─────────────────────────────────────────────
② 中台层（分配与运营规则）    ← 传统 AI 的强项，必须移植（**底线**）
     工人数/闲置补位/矿点分配/工地派人/扩张选址/防御轮转/进攻批次/目标价值序
     ── 产出"意图"，走**同一条权威链**（不另建命令网关）
─────────────────────────────────────────────
① 执行层（不变）              ← 继续复用
     游戏行为树/状态机：寻路、避障、持续交战、施工推进、自卫
```

**核心原则（两个"必须"）**：
1. **规则是地板**：无论模型是否可用、是否回得好，②层照常运转 → 副官**永远不会弱于传统 AI**。
   开关控制的只是"最终选择权交给模型还是规则"，而不是"有没有规则"。
2. **只有一条权威链**：②层不许用自己的命令网关直下（传统 AI 那样会形成第二个指挥中心），
   必须产出意图 → 仲裁/预留/代际/TTL/逐项回执（计划 §三）。

---

## 三、为什么之前的计划像空中楼阁（诚实归因，避免重犯）

1. 计划写了"程序提供候选/小队/任务生命周期"（§二/§三），但**没说这层从哪来**——
   而答案就摆在 `simple-clairvoyant-ai/`，没人去接；
2. 实现先做了模型侧（四列接口、提示词、A/B 评测），把"程序中台"当成已存在 →
   **模型再准也不会有动作**（今天实测：跑通复核后才发现"零发展"是程序侧没有分配层）；
3. 评测指标与目标错位：只测"结构/语义合法率、延迟"，**没测"整局是否比传统 AI 强"** →
   指标全绿但玩家看到的是"只采矿"。

---

## 四、升级路线（每步都可验证，不做无证据的大改）

### P0 达到传统 AI 水平（地板，**先做**）
- 新增 `graph/baseline_policy.py`：把 `EconomyController` / `ConstructionWorksController` /
  `DefenseController` / `IntelligenceController` 的决策**移植为纯函数**，每轮产出意图；
- 接入既有仲裁与权威链；runner 增 `--policy baseline|hybrid|model`；
- **验收**：跑整局，与"把单位交给传统 AI"对比核心曲线（经济、首发展时延、建筑/兵力、
  玩家介入响应）——**基线必须打平**。

### P1 模型在基线上做选择（LLM 的增量价值）
- 基线提供**候选**（扩张/科技/骚扰/防守/撤退），模型选 + 给参数（打哪、几队、何时撤）；
- 模型不选时 = 维持基线选择（不是"什么都不做"）；
- **验收**：同一起点 A/B（纯基线 vs 基线+模型），比多队并行数、任务覆盖、无效空闲、
  玩家介入响应时延、胜率/关键指标；**只有赢过地板的部分才保留**。

### P2 把"差异"变成训练数据（务实版微调）
- 记录"基线会怎么做 vs 模型选了怎么做"（含双方合法性与结果）→ 天然是
  "可见状态 → 方案"的标注集，且**基线答案可作参照**（不是模型自产自销）；
- 这比凭空造 2000 条样本可靠（计划 §四 的样本来源问题由此解决）。

### P3 长期：多小队协同与意图确认
- 在基线之上加"多队编组/协同"与玩家意图确认（计划 §三），仍遵守单模型、单权威链。

---

## 五、立即执行清单（本会话内推进）
1. 移植"闲置补位"（`_assign_idle_workers_to_resources`）→ 不变量：**有钱且可采集时不得有闲人**；
2. 移植"工地派建造者"（`ConstructionWorksController`）→ 与阻塞 A 的 `construct` 路由一并解决；
3. 移植"扩张选址"（`_find_expansion_site`）→ 第二基地/分矿；
4. 把 P0 的 `baseline_policy` 框架立起来（先只接经济+建造，防御/进攻按现状保留）。
