# AI 副官 Laya 开关与回退说明（一页）

> 面向使用者。2026-09-21 混合架构定版：**三层全部默认在环、全部本地运行**——
> 规则层（每 tick）+ System 1 选择层（Laya）+ System 2 生成层（本机 2B 战略）。
> Hermes 已移除。断网/缺模型时逐级自动降级，不影响对局进行。

---

## 1. 默认架构（2026-09-21 定版，参赛打包同此配置）

| 层 | 实现 | 频率 | 开关 |
|---|---|---|---|
| 规则层 | `rules_fallback` + `behavior_tree` | 每 tick 常驻 | 不可关（地板） |
| System 1 选择层 | **Laya**（进程内判别式） | ≈4 次/秒（节流 15 tick） | `AIRTS_S1_BACKEND=laya`（默认） |
| System 2 生成层 | **本机 2B**（Ollama `minicpm5-adj-16k`） | 30 秒/次 | `--strategy-mode plan`（默认） |

全部本地：Ollama 2B + Laya 进程内模型，**不联网、不调云端**。

## 2. 开关在哪

一个环境变量（副官 `.env.local`，即 `source/adjutant_coordinator/.env.local`）：

```
AIRTS_S1_BACKEND = laya | model | off       # 默认 laya
```

| 值 | 行为 |
|---|---|
| `laya`（默认） | 先走 Laya（进程内判别式引擎，一次前向多问）；Laya 不可用/超时/输出被既有校验全拒时，**自动**退回 2B 链路；再不行由规则中台兜底。 |
| `model` | 选择层回退到 2B 四列链路（2026-09-20 验证过的行为，测试失败清单与基线相同可证）。 |
| `off` | 选择层也关，纯规则中台 + 行为树（战略层仍按 `--strategy-mode` 走）。 |

战略层开关是 runner 参数：`--strategy-mode plan`（默认开）/ `off`。

交火口径开关：`AIRTS_ENGAGE_ATTACK_MOVE=1`（默认）＝副官用"移动并攻击"走向目标
（途中遇敌就地交火）；`=0` ＝回到逐单位点攻击。

改完**必须重启 runner**（Python 侧改动不热加载）。

## 3. 用默认配置需要什么（打包给评委时逐项核对）

1. 副官 venv 已装 laya（已装好：`pip install laya`，含 torch/transformers；
   已装 **CUDA 版 torch** `2.14.0+cu126`——pip 默认是 CPU 版，GPU 延迟差 3 倍）。
2. Laya 模型在 HF 缓存里（`multilingual` 子目录，647MB）。**打包时必须带上
   `~/.cache/huggingface`**（或首次启动联网下载一次）。
3. 少样本库在位（`.env.local` 里 `AIRTS_LAYA_DEMOS` 指向
   `graph/laya_demos.jsonl`）。**不要清空它**：P0 实测零样本一致率 0%，
   带这 3 条样例才有 83%。
4. Ollama 在跑且 `minicpm5-adj-16k` 已 `ollama pull`（战略层 + 选择层回退都用它）。
5. 任一项缺失都不会白屏：Laya 挂了自动走 2B，2B 也挂了走规则中台——照常能玩。
6. 游戏侧 2026-09-21 修复（移动瘫痪 / 移动并攻击卡死 / 交火改移动并攻击）已随
   包带上；回归冒烟：`UnitAutoAttackSmokeTest`、`GroundAttackMoveArrivalSmokeTest`
   加原有 11 个冒烟全绿。

## 4. 怎么确认三层都在工作

runner 的结构化日志（`agent_runner_events_*.jsonl`）里出现这些事件即正常：

- `laya_loaded`（device=cuda）——选择层模型已加载；
- `laya_decided`（带 task/actor/target/latency_ms/accepted/rejected）——每次 Laya 决策；
- `laya_fallback` / `laya_all_rejected`——这一拍回退了（附原因，属正常降级）；
- `laya_unavailable`——依赖/模型不可用（此后每拍直接走 2B，不重试下载）；
- `strategy_request` / `plan_adopted`——生成层在工作（约 30s 一次）。

延迟参考（RTX 3080 Ti，真实对局、与游戏抢 GPU）：Laya 单次决策 p50 约 0.4~0.6s；
2B 单次 p50 约 0.7~1.2s；战略层 30s 一次（同步调用，期间主循环暂停数秒，属预期）。

## 5. Laya 健康熔断（不 healthy 自动走 2B）

单次调用超过 `AIRTS_LAYA_TIMEOUT_SECONDS`（默认 2s）只让**这一拍**回退 2B。
若 Laya **持续**不健康（弱 GPU/重争用下每拍都超时或输出全被拒），熔断器自动断开：

- 最近 10 次决策失败率 > 50%（至少 5 次样本）→ 断开：不再调 Laya、不再每拍白等 2s；
- 冷却 60s 后半开试探一次，成功即恢复；连续断开冷却翻倍（60→120→…上限 480s）；
- 事件 `laya_circuit_open/half_open/close` 进结构化日志，排查时一眼可见；
- `AIRTS_LAYA_CIRCUIT=0` 可整个关掉（回到"每拍超时才回退"的旧行为）。

真机验证（强制 50ms 超时）：5 次超时后断开、二次断开冷却升到 120s、
打开后决策 p50 从 49.7s 降到 500ms（验证报告 §4.7）。

## 6. 回退（任何情况下）

| 情况 | 操作 |
|---|---|
| 选择层想回退到 2B | `.env.local` 里 `AIRTS_S1_BACKEND=model`，重启 runner。**无需改代码、无需卸载。** |
| Laya 抽风（延迟高/决策怪） | 同上；或临时 `AIRTS_S1_BACKEND=off` 先保规则中台，再排查。 |
| 生成层想关 | runner 加 `--strategy-mode off`（或改 `agent_runner.py` 默认值）。 |
| 想彻底移除 Laya | `pip uninstall laya`（torch 等可留可卸）；代码不动——`available()` 会返回 False，链路自动走 2B。 |
| 游戏里看到异常 | 三层都有兜底；先看结构化日志里哪一层在报 `laya_*` / `strategy_*` 事件再决定回退哪层。 |

## 7. 已知限制（重要，2026-09-20/21 实测）

1. **决策质量未达标**：零样本不可用；带少样本后任务类型一致率 83%，但模型倾向
   “多半说采集”，发展类决策（造兵/建造）很少主动选——**生产启用前需用本项目数据
   微调**（详见验证报告 §5）。
2. **回退率与帧规模有关**：执行者 >20 或产品目标过多时，(任务,执行者/目标) 组合
   更容易被既有校验拒 → 回退 2B（修复后真实对局回退率约 10%~45%，见报告 §4）。
3. **显存**：模型常驻约 1GB，与游戏共用 GPU 时注意余量。
4. **首次决策慢**：进程内首次调用含模型加载（约 30s），期间由规则中台指挥，
   不影响部队。
5. **战略层是同步调用**（2026-09-21）：不走异步调度器，每次调用暂停主循环
   （2B 实测 0.5~2.4s，超时上限 15s，30s 一次）。期间单位由规则/行为树继续驱动，
   但战术结果可能延迟收取；若评委机上 2B 特别慢，可 `--strategy-mode off`。
