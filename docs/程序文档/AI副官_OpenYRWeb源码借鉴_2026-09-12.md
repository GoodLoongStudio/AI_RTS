## 0. 定位与边界（先读）

- 这是 **OpenYRWeb**：对《红警 2》的**浏览器/引擎级重建**，**不是 EA 官方红警源码**；
- 它**不是现成的大模型 AI**：它是"确定性执行 + 规则控制器"的实现，可作为**执行层参考**；
- 借鉴范围：**任务生命周期与持续执行的组织方式**；
  不得照搬它的固定脚本与高 APM 微操（本项目由行为树/状态机承担高频控制，模型只做低频选择）。

## 1. 可借鉴的具体实现

| 组件 | 作用 | 对本项目的含义 |
|---|---|---|
| `UnitOrderTrait` | 命令队列；新命令**清理旧队列**；任务展开与持续处理 | 与我们"每单位一条当前任务 + 新任务覆盖旧任务"一致；**覆盖要显式**（不能悄悄双发） |
| `Task` / `TaskRunner` | 任务启动、**子任务**、阻塞等待、完成与取消的生命周期 | 对应我们要补的任务状态机：`NotStarted/Running/Completed/Failed/Blocked/Unknown/Cancelled` |
| `GatherOreTask` / `ReturnOreTask` | 采矿 → 回矿 → **继续采矿**的持续任务模式 | 直接印证"采集是**持续任务**，不是一次性命令"：重复下令会重置进度（与本项目实测的"重复命令"问题同源） |
| `AttackMoveTask` | 移动途中**临时攻击**，攻击结束后**恢复原移动目标** | 这正是"临时攻击后恢复主任务"的执行层模式；本项目应交由执行层实现，模型不逐帧干预 |
| `ReplayRecorder` | 把**动作与回合**记录绑定，供决策/执行/结果回放对照 | 对应新要求的"区分：模型输出了什么 / 调度接受什么 / 执行什么 / 游戏最终发生什么" |
| `PathFinder` | 路径搜索结果、best-effort 路径**只是路径结果** | **路径算出来 ≠ 单位已到达**；到达必须由观测证据判定（与 `progress.py` 的"成功证据"纪律一致） |
| IraqBot | Blackboard、经济/军事分工、持续侦察路线 | 只借鉴**组织方式**（角色分工、情报持续更新）；不照搬其固定脚本与高 APM 微操 |

## 2. 与本项目架构的对应（不新增第二套执行计划）

- **执行层**（游戏行为树/状态机）：承担 `UnitOrderTrait`/`TaskRunner`/`AttackMoveTask`/
  `GatherOreTask` 式的**持续执行与子任务**（采矿往返、到位防守、移动交战、寻路脱困、归位）。
- **协调器**：只产出**意图**（四列任务修改）+ 任务生命周期镜像；
  到达/完成**必须**由观测证据或权威回执判定（禁止"发了命令=成功"）。
- **诊断**：像 `ReplayRecorder` 那样把"决策 → 接受 → 执行 → 结果"分列落盘
  （当前已由 `deploy/metrics_report.py` 起步，仍需补命令三级时间戳）。

## 3. 使用纪律

1. 本文件只提供线索；实现顺序与验收以 [当前执行入口](AI副官_当前执行入口.md) 与主计划为准；
2. 借鉴时仍走**同一条权威链**（意图 → 仲裁/预留/代际/TTL → 权威端回执），
   不允许像传统规则 AI 那样自建命令网关形成第二个指挥中心；
3. 提交若引用本文件，请在代码注释中写明"借鉴点"与"未照搬项"（便于复核）。
