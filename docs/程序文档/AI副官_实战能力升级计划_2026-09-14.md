## 1. 目标、范围与优先级

用户实测的核心问题是：整体运营和作战弱，反应慢，部队发呆或反复改令。本轮要让副官持续完成有效的 RTS 行为，达到可检验的传统规则控制器水平，再证明模型能增加策略价值。

“红警 3 级别”是体验参照，不是已经存在的量化基准。本轮采用仓库内传统 AI 与固定脚本场景建立可复现对照，不虚构对红警 3 的性能或胜率结论。

本轮范围包括规则政策、观测适配、持续任务、小队作战、导航查询、调度、生产接续、真实模型接入、必要的权威端支持、指标和场景工装。允许围绕上述问题做可逆代码修复和必要的结构收敛；不为目录改名重写系统。不改变单位价格、武器数值、视野、资源或正常军队上限来掩盖 AI 缺陷，不自动提交、推送或部署。

## 3. 必须形成的运行结构

沿现有链路收敛，不新建平行指挥系统：

```text
权威状态/事件增量
  → 单写者更新事实、任务进度和事件游标
  → 常驻规则政策：经济、建设、侦察、军事、紧急处置
  → 保留有效任务 + 非阻塞接收模型稀疏 patch
  → 统一权限/预算/代际/冲突仲裁
  → 持续执行器与 Godot 权威命令
  → 生效、进展、完成/受阻证据 → 原任务继续或明确重规划
```

职责必须明确：

- **规则政策**负责基础运营、目标候选、兵力分配和默认战略；模型从未输出时也能独立发展和作战。
- **小队/任务执行器**负责稳定成员、路线、局部接敌、自卫、撤离、恢复与命令保持；不等待模型执行下一步。
- **模型**只选战略分支、目标、优先级、编队用途和经过定义的参数档；不算精确坐标、逐个工人分配、寻路、合法目标域或生产完成。
- **框架**负责持久状态、单一在途请求、合法性与新鲜度校验、事件和证据；不能把确定性动作包装成反复询问模型。
- **Godot 权威端**仍是规则、扣费、订单及单位结果的事实来源。不得借用传统控制器内部全知对象来绕过副官视野或建立第二条发令入口。

保留约 10Hz 轻量扫描；常规协调约 2Hz，大规模允许约 0.5Hz。它们是运行参考，不是强行重复发令的理由。已有任务在协调间隔内仍须持续执行；真正紧急事件可以提前唤醒。扫描不做全图序列化、模型推理或直接写协调状态。

## 4. 本轮对旧规则的明确替换

### 4.1 路径合法与战术风险分开

保留权威导航、边界、移动域、玩家权限和情报来源的硬约束。取消“任何敌方实体进入固定半径，就无条件禁止主力推进”的通用战术结论。

每段移动先验证可达与地形，再依据任务类型评估风险：侦察优先避战；优势进攻允许沿合法路径进入交战距离；防御允许接敌；劣势撤离评估通向可生存区域的路线。敌方工人、无武器目标或无法攻击本队的单位，不应一律视为足以逼退整队的威胁。

`move / attack_move / attack / defend / retreat / regroup` 必须使用同一份任务上下文和局部战斗事实。直接 attack 引起的接近移动也要检查权限和可达性；不能改动作名绕过校验，也不能为消除绕过而让所有攻击失效。

可见目标的合法交战与未知区域的探索区别处理：主力未知路线逐段确认，侦察负责扩大视野；不能要求侦察目的地事先已被侦察。权威路径只有起点/终点时，要按可达路线和实际视野生成可用短段，不能因无中间顶点永久原地等待；禁止凭空画直线冒充权威路径。

### 4.2 等待必须能退出

等待记录阻塞原因、开始时间、重查触发条件、下次重查时间和最大等待预算。到期必须尝试可解释的替代目标/执行者/路线，或明确终止并释放占用。允许守备、玩家命令、资源不足、不可达等合理停留，但要有事实证据；不能把普通任务统一标成 hold 来规避“发呆”指标。

### 4.3 保持任务不等于永不改令

同一目标仍有效且有进展时保留当前权威订单。目标死亡、玩家接管、受袭升级、路线失效、明确受困、任务完成或高优先级合法策略变化才能中断。固定 TTL 到期、坐标微抖或 tick 变化本身不是重下同一命令的充分理由。紧急中断后要有恢复或取消原任务的结论。

### U5：真实模型只增加策略价值

- 首先证明关闭、超时、空输出、非法输出、过期结果和冷却状态下底盘正常运行。
- 真实模型启动后记录 model_enabled、模型标识、参数、请求/完成/校验/采纳/生效数量、延迟和跳过原因。`provider=real` 不足以证明调用发生；调用发生也不等于生效。
- 沿用四列稀疏 patch 和程序绑定的身份/时限，不强制回退到旧 token/行数参数。新引用表和参数档只表达高层候选。
- 模型输入提供合法候选、局部战况摘要、任务进度、阻塞和可选后继目标；不要求模型从原始大 JSON 重算全部 RTS 规则。
- 每次采纳模型 patch 记录它修改了什么及后续结果。空 patch 合法；不能把程序自主行为伪装成模型功劳，不能强迫模型为凑次数改令。
- 模型线程单一在途，不积压失效请求；玩家接管或策略代际变化后旧结果必须失效。

出口：T12、T15–T16 通过；有真实请求、返回、合法采纳和游戏效果的完整样例；再进入模型增益对照。若模型无增益，标记本阶段未达成并在候选/上下文/任务语义范围继续修复，不以更换模型或微调掩盖底盘问题。

### U6：规模、性能和公平对照

1. 同场景、同机器、同单位数和画质，对比扫描/规则/导航/归档开销；先做 20、40、60 个作战单位，再做现有配置允许的高负载。不得把正常军队上限调小作为修复。
2. 报告客户端 FPS/帧时间与权威模拟 tick 速度；专用服 FPS 不能当可见客户端帧率。记录 AI CPU、观测/导航往返、序列化、写盘和最大协调静默。
3. 复用空间索引、增量状态、路径版本缓存、编队共享计算、有界日志队列；避免 O(我方×敌方×完整场景) 的重复扫描。优化前后保持同场景，不关闭迷雾或减少敌人作弊。
4. 按第 8 节完成对照和留出测试。任何硬门失败，回到所属阶段修复并跑受影响回归。

出口：T17–T18 和全部硬门通过；性能对照可重现；基础能力与模型增益分别给出结论。

### U7：可见交付与最终复核

- CodeBuddy + DeepSeek 在实现各阶段即自行操作与看图，U7 汇总全流程证据。使用内置浏览器验证适用的页面/面板；Godot 原生窗口使用实际可用的窗口操作与截图能力，不能假定浏览器能控制原生窗口。
- 对每条用户可见主流程执行“正常入口操作 → 观察连续行为 → 截图并实际查看 → 对照预期和权威记录 → 修复偏差 → 相同步骤再测”。截图要能关联场景、关键时刻和修复前后结果，不能只截图保存而不检查，也不能只靠一张静态图宣布连续行为正常。
- 用户正常进入游戏、启用副官的入口运行，不能只靠独立 runner 工装证明产品可用；核对客户端/权威 match_id 与实际控制模式。
- 显示真实当前任务、受阻原因和有效动作；面板“运行中”必须与进程/会话一致，禁止假造“正在思考”。
- 至少一段有可见客户端的连续发展与战斗过程，附对应日志；截图只辅助观察，关键时间和任务结果来自权威事实。
- 完成项目要求的相关构建、导入和回归；未提交时明确未获得 main CI 交付验证，不编造绿色 CI。
- 交付改动清单、验收矩阵、失败/修复记录、完整档案索引、剩余项和复现命令。不能把“计划写完”“单测全绿”或某一局获胜当整个升级完成。
- 在全部条件通过前，由执行方继续自行迭代，不把阶段成果退给用户或 Codex 做第一轮查错。全部通过后提交“已完成自验、可供最终复核”的证据包，由用户转交 Codex；此声明仍需接受最终复核，不能预先声称 Codex 已认可。

## 6. 场景验收矩阵

### 测试偏差的强制纠正机制（2026-09-14 补充）

每局开始前登记简短测试卡：目标、预期可见行为、场景/敌人、控制器/模型模式、match/端口、合格前提、失败条件、观察窗口和证据位置。启动后根据实际回执与实时状态核对，配置不一致由工装明确判失败，不能继续按预期配置记成绩。

开始约 10–15 秒做一次实际操作和画面检查；长局至少每 30 秒墙钟主动看图并核对新增进展，异常事件提前检查。可执行前提成立却连续超过 10 游戏秒没有进展或恢复处置，转为失败诊断；合法长动作、守备、资源不足和预先登记的故障观察要单列，不强行打断。若画面被遮挡或副官状态矛盾，先取得有效画面并核对客户端、runner、权威端的对局和控制身份。

提前结束的是无效验收计时和成功统计，整个升级仍继续。保留现场诊断，必要时才重开自己拥有的进程；根因修复后回到原失败场景验证。同一失败连续两次后必须补充判别证据或换根因假设，不盲目重复长局。不得通过换场景、只增加时长或减少对手掩盖原失败。

T01 独立使用无敌情探索窗口；遇敌阻断单独落入 T05/T07/T13 等相应场景。修正 T01 的敌人配置不等于解决遇敌后的行动能力。model=off 的底盘场景合法；model=on 场景出现 no_tactics_model 才应判接入不符。跨阶段依赖允许提前做最小修复并标记归属，不因阶段编号机械等待，也不反复重做 U0。当前已发生的偏差和优先接续顺序详见执行提示词第零节。

以下是必须实现/复用并登记版本的验收场景，不是已经存在的测试文件名。测试用脚本敌人/固定波次，与无敌人的发展场景分开。保留既有“不在本地普通调试开启电脑 AI 敌人”的约定；不要求新开真实电脑对手才能推进。真实对手胜率与红警 3 比较单独标未验证，不拿脚本胜利替代。

| ID | 场景与变量 | 必须观察到的结果 |
|---|---|---|
| T01 | 原基地/地图回归，再换出生方位和地图比例 | 侦察持续到达至少 3 个不同可达前沿并带来新增视野，不长期重复固定点 |
| T02 | 前沿不可达/临时断路/重新烘焙，包含版本 0 | 失败原因具体；换目标或等待有效条件；恢复后继续，不能永久 no_path |

| T05 | 优势小队遇无武器工人/少量弱敌，再换成有威胁组合 | 前者不因“有敌人”被强制逼退；后者根据实际战力接战或撤离 |

| T07 | 双线作战，基地突袭，威胁解除 | 合理范围回防、及时有效响应；其他线不被无理由清空；解除后恢复任务 |
| T08 | 稳定编队穿越通路/狭口、掉队、增援、成员死亡 | 实际成队推进、集结与补位；不永久等满编，不拆成逐个送兵 |
| T09 | 双生产设施同类并产，期间阵亡/取消/设施毁坏 | 项目按 item_id 正确结算并接续，无重复扣款、幽灵占用或误认完成 |
| T10 | 正常资源开局，矿耗尽、施工完成、生产需求变化 | 工人转岗、资源/生产不互相饿死，至少完成一次有效扩张运营 |
| T11 | 5 万压力局与普通经济分别运行 | 生产遵守资源和规模约束，不把资金充足时的成绩当普通经济成绩 |
| T12 | 同场景依次 model=off/timeout/empty/invalid/stale/on | 规则与已有任务持续；真实 on 有可核对调用及采纳效果 |
| T13 | 中途目标改变、路径失效、重复 arrival、到达后下一跳 | 有进展时保持订单；完成/失败时正确后继；事件重复不重复生效 |
| T14 | 多小队同轮规划，需求超过查询配额 | 有公平轮转或跨轮验证进度，尾部小队不永久饿死 |

每个场景登记前置条件、种子、期望结果、硬断言、观察窗口、实际值、档案路径和失败原因。先用能区分修复的最短窗口（通常 10–30 秒）；达到断言立即结束。只有长生命周期、对照或结算问题才跑一次约 5 分钟集成局，且不得把已通过的短行为每轮重跑。

## 7. 指标、硬门与数值目标

先定义 eligible（当时有需求、合法执行者、资源/人口/前置与路径可用），否则不能把合理等待算停摆。每个指标保留 eligible、blocked、unknown 三类时长；未知不能从分母悄悄丢掉。无有效样本记 N/A，不记 100%。

| 指标 | 计算口径 | 本轮验收要求 |
|---|---|---|
| 有效侦察 | 新增可见区域/实际到达的不同前沿，排除原地与无理由重访 | T01 三个不同可达前沿；可达前沿存在时不因固定点停摆 |
| 生产接续 | 项目完成到下一项目实际开产的 eligible 游戏时长 | 建议初始目标 p95≤2 游戏秒；有持续队列更优；条件不足单独解释 |
| 受袭响应 | 权威事件发生→受影响部队产生有效防守/接战/撤离行为 | 建议初始目标 p95≤1 游戏秒、max≤2 秒；按规模分档，不能用命令 Accepted 计响应 |
| 重规划 | 路线失效/到达需后继→新任务实际生效 | 常规不超过选定协调周期+1 游戏秒；紧急服从受袭响应目标 |
| 无意义改令 | 未完成且无合法中断原因，却重置/替换了有效订单 | 固定确定性场景为 0；集成建议≤1%，逐条保留原因；排除幂等重放和合法中断 |
| 非法攻击域 | 规则与能力已知且未变化仍被权威域拒绝 | 固定场景为 0；能力未知/刚变化的首次拒绝单列，不能靠无限重试学习 |
| 无解释空闲 | eligible 对象没有有效任务或任务无进展且无恢复处置 | >5 游戏秒的连续段必须调查；>10 秒仍无处置不得通过 |
| 小队有效性 | 有效编队实际共同推进/接敌/撤离，含掉队和成员变化 | T08/T14 真实闭环；单次 batch 或 squad_multi 计数不能代替 |
| 战斗效果 | 脚本任务成功率、有效伤害、战损资源价值、存活与结算时间 | 按目标评价；不得靠不交战提高存活率或靠无上限生产稀释战损 |
| 帧时间与模拟速度 | 同硬件/画质/场景/实体数的 client frame ms、authority tick 速度 | AI 新版相对对应旧版，帧时间中位数建议不恶化>10%，p95不恶化>15%；基线已不可玩仍不能算通过 |

上述数值是本轮提出的初始工程目标，不是已测事实或当前实现保证。U0 先登记并冻结。只有地图移动距离、建造工期、硬件或权威规则证明目标不可比时，可在第一次候选正式验收前说明调整依据并记录原值；候选失败后不得事后降低门槛宣布通过。之后如确需修订，保留原失败和新版本，在报告中明确“原目标未达成”，并重新跑全部受影响对照。

以下是不能用均值抵消的硬门：权限/迷雾违规为 0，重复实际扣费为 0，已知非法域指令为 0，串局/旧代际结果生效为 0，模型状态不得阻塞底盘，持续任务不得无解释永久停摆。超过预算时明确降级并保留正常自卫和任务执行，不伪造成功。

## 8. 对照与模型增益证明

控制器组：B=仓库传统 AI；R0=升级前副官规则底盘；R1=升级后规则底盘（模型关闭）；R2=R1+真实模型。

先比较 B/R0/R1 定位传统能力迁移损失，再比较 R1/R2 判断模型增益。固定地图、种子、资源、出生点、单位定义、迷雾/可见信息、控制权限、脚本敌人、采样窗口和画质；只切换控制器。B 若仍有全知、不同预算或查询接口差异，必须通过标准观察适配保证一致，或者明确判定为非严格对照，不能拿它宣布不劣于传统 AI。

分批节约测试：

1. 开工保存 R0 的失败场景与至少一局发展基线。各阶段只跑受影响的场景和关键回归。
2. U4 后选“正常经济发展”“双线防守”“探索扩张并攻击脚本目标”三类代表性任务，对 B/R0/R1 各跑相同的至少 3 个固定种子；旧基线可复用，但必须源版本、配置及窗口一致。
3. U5 后 R1/R2 在相同任务/种子配对运行；补充至少一个需要改变高层目标的场景，如已发现的路线阻断或敌方兵种变化，避免模型无决策空间却声称无用。
4. U6 使用至少 2 个未用于调参的地图/种子组合做留出复核；地图适用的可达区域和任务目标事先冻结。

U0 同时登记测试机器、目标分辨率/画质、最低可玩客户端帧率与权威模拟速度目标。相对性能不退化不能替代最低可玩目标。留出场景若失败后用于修复，它就转为回归样本，须补新的未参与调参组合复核，不能继续称同一组为独立留出证据。

报告逐局原始值、成败、样本数、中位数/p95/最大值与差值，不仅展示最好的一局。少量样本只能支持工程比较，不能声称统计显著或总体胜率保证。p95 样本过少时同时突出最大值和样本数。

R1 应通过全部确定性行为场景；代表性任务成功率不得低于 B，生产/扩张/响应等关键指标相对 B 不应出现超过已登记容差的退化。建议性能以外的初始非劣容差为 10%，首次有效攻击时间另受场景目标约束；B=0/无样本时使用绝对结果，不做除零比值。

R2 应保留 R1 的硬门和基础运营质量，并在至少一个有决策空间的配对场景改善任务成功、关键目标完成时间或战损中的主要指标，其他关键指标无明显退化；初始增益目标可定为完成时间或战损中位数改善≥10%，必须报告所有种子和收益代价。未观察到收益时，结论是“底盘完成、模型增益未通过”，不能宣布全部升级完成或继续无限随机调参；按失败证据修复候选/上下文/任务契约，确实无剩余可行改动时报告具体阻塞。

## 9. 工程和证据交付纪律

- 在现有模块中实现单一规则来源。已有传统控制器逻辑可提取复用，不能再复制一套逐渐漂移的能力、距离或订单判据。
- 新参数集中登记；定义单位、默认值和作用域，避免在提示词、Python、GDScript 三处各藏一个阈值。
- 存量测试保留有意义的不变量。对被本计划明确替换的旧行为测试，可更新断言并补上新场景；例如从“任何敌人必停”改为“有合法路径且占优可接敌、真正危险时有恢复”，不能只删失败测试。
- 测试先用实际观察结构、回执和事件；纯 mock 只证明逻辑，不代替引擎导航、真实模型、权威动作和用户入口。
- 场景配置与实际数据一致；不能让测试工具偷偷禁用模型/敌人/迷雾再报告完整模式。日志脱敏，不保存凭据。
- 每局 manifest 保存源码和未提交差异标识、场景/规则/模型模式、退出原因、文件数/哈希、事件序号覆盖和缺口；维护短摘要但保留原始失败资料。
- 测试命令复用并核对现有入口：Python unittest、相关 Godot smoke、项目构建和回归工具。新增场景工具交付后提供完整可运行命令，不能在报告中引用并不存在的脚本。
- 执行进度只写配套 `AI副官_实战能力升级执行进度_2026-09-14.md`。旧 P0–P3 与 F1–F5 保留历史事实，将仍有关的项目映射到本轮 U 阶段，不丢失也不重复宣称完成。

## 10. 完成定义与停工边界

核心用户行为和硬门都有对应证据；T01–T18 逐项登记已测/未测及原因；所有已承诺的核心场景通过，相关构建与用户入口通过，才能宣布“本轮升级完成”。真实电脑 AI 胜率和红警 3 同条件比较不在当前已授权本地脚本测试的完成承诺内，仍须明确列为未验证，不能借此阻塞其他可完成工作。

有单项失败就修该项并做必要回归；不得每完成一个阶段就等用户说继续。模型服务或运行环境不可用时，记录可复现错误、完成所有不依赖它的工作，该项保持未验收；需要外部信息/服务恢复时才提出具体阻塞。尊重用户明确的暂停或停止。

最终交付必须能回答：以前为什么呆、改了哪个决策或执行环节、屏幕上现在会怎样行动、实际结果改善多少、付出了多少性能成本、模型到底贡献了什么、还有什么没验证。
