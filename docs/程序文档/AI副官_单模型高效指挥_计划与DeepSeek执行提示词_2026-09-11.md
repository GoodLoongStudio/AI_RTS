## 二、决策、调度与输出接口

**把决策地图接入运行时。** 将现有手册整理为可校验、可版本化的结构化策略库，包含适用条件、参数、能力要求、完成与退出条件。Markdown 保留解释与导航，运行时加载对应结构化数据，避免每轮读取整本手册。以当前游戏实际规则为准，不引入未实现的电力、人口或科技机制。

- 程序提供授权小队、合法目标、预算、生产关系、任务反馈和可选方案。候选保留合理竞争选项与“维持”，由模型选择方案并调整参数。不得提前指定唯一答案，也不得用固定敌我数量比较代替战术判断。
- 合并为一个模型决策入口，一次输出相关任务修改；不再强制“战略模型先想、战术模型再想”。HUD 提供全局“快速 / 深度”切换，两个模式都由同一个模型决策。
- 初始推理配置：上下文窗口 4096、温度 0；验证关闭思考参数的实际作用。快速模式输入预算约 1024 token、输出上限 96 token，以最多 4 条紧凑任务修改为起点；深度模式输入约 2048 token、输出上限 256 token，以最多 8 条为起点，处理相关小队配合和后续安排。紧急任务优先，不强制填满输出。预算包含提示词及结构定义，允许依据实测压缩；输出容量必须用真实 tokenizer 和模型响应验证。
- 两种模式通过信息范围和决策范围区分，不要求输出长篇推理。快速模式总期限初始 1.5 秒、深度模式 3 秒；快速模式不追加模型修复，深度模式最多一次且计入总期限。截断或非法输出不得执行。
- 使用真正异步的调用与单一状态提交入口，每局最多一个实际在途推理。观测、玩家事件、回执和执行独立推进；普通事件合并，紧急事件优先，同级轮转，等待时间参与优先级，防止经济和其他小队长期得不到处理。
- 新增紧凑的任务修改输出：小队 / 执行者 ID、方案 ID、目标 ID，以及必要的路线、阵型、节奏和参数变化。未提及的任务继续执行；模型不枚举全军单位或生成权威元数据。基于现有 `DirectiveBatch` 做明确版本升级，并同步训练、验证和转换接口。
- 权威观测增加稳定小队 ID、成员版本、逐对象控制代际、任务进度和失败原因；每个请求绑定这些信息。模式切换、玩家接管和关键条件变化使相关旧结果失效。普通快照推进不应使所有结果失效。
- 复用并核验现有批量入口，一批命令可以让多个小队同时执行。逐项校验、逐项回执，正确处理部分拒绝；生产和建造不能随意合并。取消客户端等待后，必须验证服务端是否仍在推理，禁止通过不断新建请求制造积压。
- PydanticAI 直连本地 Ollama，核验当前版本对结构化输出的支持。优先验证 `NativeOutput` 的 JSON Schema 路径；不兼容时使用 `PromptedOutput`。只保留一处重试策略，不默认引入工具调用或旧代理。

## 三、持续执行与玩家协作

### 3.0 混合架构硬约束（用户 2026-09-12 明确要求）

“小模型 + 智能体 + 传统决策树”必须是实际运行时的协作，不得退化为“模型直接下任务、传统规则只在模型失败时 fallback”。传统规则中台在每轮协调循环检查到期更新和事件，按独立游戏时间节拍处理工人数、闲置补位、资源分配、工地派人、扩张、生产、防御和进攻批次；行为树 / 状态机按执行节拍持续推进移动、寻路、交战和施工。不要求逐渲染帧全量规划，也不得重复下发已有任务。

MiniCPM5-2B 只做低频的战略 / 意图 / 目标 / 优先级 / 参数选择，以及对规则候选的稀疏任务修改。模型没有新结果、正在推理、超时、返回空或非法结果时，规则候选和已有任务继续执行；等待模型不得暂停游戏。模型没有明确选择的战略动作不得被程序伪装成模型决定。所有规则、模型和行为树输出必须进入同一仲裁与 Godot 权威回执链，并分别记录 `origin=baseline|model|behavior_tree`。

实施顺序固定为：先证明 `model=off` 的传统规则地板可持续发展，再注入模型超时 / 空输出验证不断线，最后才测量 `model=on` 相对地板的真实增量。不得用模型响应速度、JSON 合法率或命令数量替代采集、建造、生产、战斗和任务完成等结果指标。具体纠偏门槛见《AI副官_混合架构纠偏提示词_2026-09-12.md》。

- 建立稳定小队，默认约 12-20 个作战单位，按移动类型、角色和位置组织，避免每次观测重新分组。新单位经过权威授权后按模型批准的补员规则加入；玩家接管对象立即退出 AI 分配。
- 模型选择目标、路线意图、阵型和节奏；程序计算精确路径、阵位和速度。首批支持纵队、横队、疏散，以及协同行军、快速推进；地形迫使临时收队时记录原因，通过后恢复。
- 复用现有导航、行为树、状态机及 CommandRuntime。采用小队路径复用、空间邻域查询和分摊更新，避免逐帧全军两两计算或全员重寻路。混合速度小队正常行军保持协调；少数持续受阻成员独立恢复、追赶或报告失败，主队不能无限等待。
- 移动、攻击、防守、撤退、侦察、集结和经济工作流都有真实生命周期。重点核查防守、侦察、撤退是否仅被转换为一次移动，以及到达位置是否被错误视为完整任务结束。
- 采集、建造、生产、侦察和作战可以并行。默认策略或有效模型策略中的生产目标、配比及扩张条件，由规则中台按预算、授权和队列容量落实；不需要逐项等待模型批准。不得越过玩家约束或擅自推翻有效策略，默认规则效果与模型增量分开记录。
- 玩家有效命令在权威端立即接管实际执行者并增加代际，不等待模型。即使对象从未建立 AI 租约，也必须记录玩家控制。部分接管不暂停其他小队；命令完成后保持玩家控制和正常自卫，不自动交回。
- 重大干预保留最新一条确认，支持“确认建议目标 / 我来指挥 / 误触交回”，旧按钮不得影响新命令。连续操作合并，模型只解释程序识别的重大意图变化，不对每次点击推理。确认只授权明确涉及的对象，单队回防不得扩大为全军撤退。
- 启用副官时，各资源预留取余额的 20% 向下取整，并固定为绝对额度，直到玩家调整。AI 支出统一检查预留、未扣款承诺及幂等记录；玩家可使用预留，玩家订单优先，不取消玩家任务或占满生产队列。已发生的支出按游戏原有取消和退款规则处理。
- 所有模型、恢复和规则命令经过同一权威入口，检查权限、能力、目标类型、视野、预算和冲突。区分结果接收期限和任务执行寿命，禁止为旧结果刷新代际或期限，也不能用多单位最大代际掩盖差异。
- 故障期间继续有效任务，仅对仍授权对象执行明确标记的保守降级。HUD 显示真实模式、阶段目标、任务进度、玩家控制、确认与降级状态。核查现有模拟回复的运行接线，只有执行回执或实际状态变化才能显示相应进度。
- 执行器可以做路径避障、正常自卫和已批准的撤退条件等局部反应；这些动作必须与模型新决策分别记录。模型的新任务与已有规则不得形成两个互相抢控制权的指挥中心。
- 沿用正常 HUD 开关启动本地 runner，核验自定义对局的权威身份、对局 ID 和实际连接目标；退出对局只清理本次运行，不得通过结束其他推理进程解决问题。

## 四、项目专用微调

**微调用于提高判断、缩短表达和减少失败重试；不能承诺自动提高生成 token/s。** 先完成可运行链路与基线，再使用相同接口训练和比较。

- 首先验证 MiniCPM5-2B 对应可训练权重、许可证、tokenizer、聊天模板及导出路径。Ollama 中能运行的量化文件不等于可直接训练。
- 优先采用兼容环境中的 Transformers、PEFT、TRL 与 4-bit QLoRA。先用小样本跑通训练、合并、导出、Ollama 加载及输出对照，再扩大训练；训练与游戏性能测试分开运行。
- 第一批目标为至少 2000 条经过验证的“可见战场状态 -> 方案及参数”样本，覆盖快速 / 深度、经济取舍、多队配合、撤退、玩家介入和受阻反馈。真实对局与合成样本标明来源，不能把模型自身未经检查的答案直接作为标准。
- 按对局和场景家族划分训练、验证、测试集，比例 70% / 15% / 15%；相近变体不得跨集合泄漏。DeepSeek 依据规则标注，程序验证合法性，多解场景允许多个合理方案。输入与标签不得借用玩家视野以外的敌情。
- 比较原模型、接入手册后的模型、微调模型。检查任务效果、合法率、延迟、输出长度与异常恢复；只有整体通过验收才替换默认模型，运行时仍只加载一个决策模型。
- 本地训练或导出确实不兼容时，记录可复现证据并继续其他开发，明确微调尚未完成。不得擅自付费训练、调用云端模型或更换基础模型。Diffusion 不进入本轮主线，它需要另外验证模型与推理实现，无法直接作为 MiniCPM 的提速开关。

## 五、验收与循环迭代

按“基线与埋点 -> 异步与批量权威闭环 -> 小队持续执行 -> 策略库及双模式 -> 微调 -> 整局验收”推进，每阶段保持可运行。

### 1. 响应测试

两个模式各至少 100 个不同真实观测或明确标注的回放请求。游戏同时运行时，从事件进入权威端计时，到相关单位实际进入模型指定的新任务；包含排队、推理、校验和下发。

- 快速目标：P50 <= 1 秒、P95 <= 1.5 秒。
- 深度目标：P50 <= 2 秒、P95 <= 3 秒。
- 冷启动单列，超时和无有效命令不能从统计中删除。分别报告排队、输入处理、生成、权威提交与实际生效时间。
- 测试多事件同时发生与已有请求在途时的响应，不能只测空闲模型。记录全局模式切换期间的等待与旧结果处理。

### 2. 判断测试

首次结构合法率 >= 99%、语义合法率 >= 95%，同时检查必要任务覆盖和实际收益。改变威胁、预算、兵种组成做反事实测试，并随机交换候选顺序；不能用“候选增加后选择没变”直接判定模型没有决策。报告修复次数、超时率和所有失败原因。

### 3. 规模测试

100、200 单位验证，300 单位压力测试。记录模型有效任务修改频率、任务覆盖单位、小队并行数、无故空闲时间、规则占比和帧耗时。不得靠重复命令提高统计；200 单位时，副官新增 CPU 工作的 P95 初始预算为 2ms / 帧，并测量 GPU 推理对整体帧率的影响。

模型任务覆盖与实际执行进展分开统计。保持防守或等待预算可以是合理状态，不能为了刷“活跃”不断重置任务；长期空闲、任务失败和无进展必须有原因及处理记录。

### 4. 执行测试

检查位置变化、伤害、采集增长、建筑完成、单位产出，以及混速行军、窄口通过、阵型恢复、个别单位卡住。覆盖目标死亡、路径失败、预算不足、重复请求；`Accepted` 不算完成。

### 5. 协作与故障

从真实玩家 UI 测试移动、攻击、停止、采集、建造和生产接管；验证其他小队继续执行、未确认不抢回、交回生效、旧结果无效。慢响应、断连、runner 重启和退出重开不能冻结游戏、重复扣费或恢复已撤销权限。

### 6. 整局验收

从正常自定义对局入口至少完成两场各 15 分钟测试，分别覆盖快速和深度模式及模式切换；看到经济发展、多小队作战、编队移动、玩家介入与交回。保存录像或连续状态证据，并提供普通用户可复现的启动步骤。用于规模测试的预置部队不能替代从正常开局发展经济的证明。

### 7. 迭代规则

- 每轮选择一个有证据的主要瓶颈，修改后先做相关回归，再用固定条件比较，保留最佳通过版本。
- 同一方向连续三轮无改善，重新检查原因并换方法；有证据且可修复的问题继续处理。禁止降低验收门槛、污染测试集或将规则效果计作模型提升。
- 将每轮假设、修改、测试条件、结果和下一步写入迭代记录。不要只留下“继续优化”“全部通过”之类无法复核的结论。
- 可以自主调整模块拆分、数据组织和实现细节。涉及玩家控制原则、完整职责范围、基础模型或费用的重大改变，须说明证据和影响，不得静默变更。
- 只回退自己引入且已确认失败的修改，保留用户及其他开发者的改动。不要为了满足“不断重试”重复没有新信息的操作。
- 最终交付代码、更新后的手册与接口说明、原始评测数据、训练配置与产物信息、实机证据、使用方法和未解决问题。遇到硬件、训练兼容性或模型能力上限时明确报告差距；只有达到验收条件才声明完成。

## 七、全网优秀案例借鉴清单（执行时必须落实）

这不是凭空设计的附加想法，而是对公开代码 / 论文的实现核验后形成的改动要求。完整证据、边界和来源见配套《AI副官_单模型高效指挥_技术实现设计_2026-09-11.md》第 8 节。

### 1. 采用的核心模式

- **SwarmBrain**：借鉴“LLM 做低频宏观决策，条件—响应状态机做快速战术”；不复制第二个战略 LLM，也不把其未随仓库发布的自验证模块当成现成能力。
- **Vimy**：借鉴“LLM 输出 doctrine / 权重，编译器把它变成边界受限、可验证、确定触发的规则”；AI_RTS 中对应 `DirectiveBatch` 编译与权威校验。
- **OpenRA-RL**：借鉴有界异步队列、可丢弃旧观测、单独记录推理和执行时间、逐局 transcript / replay；明确保留其对 2 s LLM 和低战斗分数的诚实限制。
- **TextStarCraft / LLM-PySC2**：借鉴观测摘要、显式动作空间、动作抽取和宏观指标；只保留一个决策模型，不引入多个 SubAgent 指挥中心。
- **Voyager**：借鉴带前置条件、版本、检索描述、执行错误和成功证据的技能 / 决策案例库；未经程序验证的模型答案不得入库或训练。
- **0 A.D. Petra**：借鉴 attack plan 的准备—执行—完成 / 失败—清理生命周期、单位归属、集结点、可达性和生产补员关系。

### 2. 必须删除或禁止的误用

- 不允许模型每帧直接下单位级命令；单位移动、避障、队形和正常自卫由行为树 / 状态机执行。
- 不允许用“增加战略模型 + 战术模型”掩盖延迟；本轮运行时只有一个 MiniCPM5-2B 决策模型。
- 不允许把外部案例的胜负、token/s、演示视频或单局结果写成 AI_RTS 已达标证据。
- 不允许把 TextStarCraft 的单 PvZ 文本环境、Voyager 的 Minecraft JavaScript 技能或 SIMA 的键鼠控制直接移植为 Godot 权威命令。

### 3. DeepSeek 实施顺序新增门槛

1. 先实现并记录 `DirectiveBatch` -> 规则 / 工作流编译 -> 权威校验 -> 逐项回执的闭环。
2. 再实现有界异步调度：单一在途请求、普通观测合并、紧急事件优先、过期结果拒绝、失败退避。
3. 再实现稳定小队和 Petra 式任务生命周期，证明防守、侦察、撤退、采集、建造、生产不是一次移动即结束。
4. 再接入压缩观测、候选菜单和可检索决策地图 / 成功案例库；记录命中、合法、完成和失败字段。
5. 最后才做微调与整局验收。外部案例只能指导机制，不能替代本项目真实 Godot 对局证据。


### 4. 外部层级案例的边界

- HIMA / Society of Mind 的高层 LLM + 专长模仿模型和 TextSC2-ALL 评测可参考职责分层与测试集设计，但其三模型 / race 和约 20 分钟单局不符合本项目单 MiniCPM5-2B 约束。
- AlphaStar / 模块化 SC2 AI 只能提供动作分解和按时间尺度评测的研究背景，不能作为 LLM 架构或本地性能承诺。
