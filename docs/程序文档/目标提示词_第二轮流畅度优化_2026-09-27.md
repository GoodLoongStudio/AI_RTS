## 4. 任务 A：GroundAttackMoving 扫描接入网格（核心）

现状（先读代码确认行号）：`GroundAttackMoving.gd` 的 `_pick_target()`（:93 附近）按姿态取
detection_range（HoldGround→attack_range、Guard→min(sight, attack×1.25)，普通=sight），
然后 `get_tree().get_nodes_in_group("units").filter(_is_legal_target)` 全场扫描 + `sort_custom`
按距离取最近。Timer `TARGET_REFRESH_INTERVAL`=1/6s（:10，:39-42）。

做法（照抄第一轮 WaitingForTargets 的成熟模式）：
1. `@onready` 解析 `Match/TargetAcquisitionGrid`（参考 `WaitingForTargets.gd:35`）。
2. `_pick_target()` 里用 `_target_grid.acquire_candidates(_unit.global_position_yless, detection_range)`
   替换全场组扫描；**精确过滤 `_is_legal_target` 原样保留**（敌我/域/可见性/有效性都在里面）；
   排序语义不变。
3. 包上 `_target_grid.note_scan(candidates.size(), 耗时)`——**这会让 g4move200 场景第一次出现
   索敌计数**，move200/battle200 的 A/B 对照才有数字。
4. `AIRTS_TARGETING` 增加档位：`nomovinggrid` = 本动作回退全场扫描（B 对照用）；未设 = 网格（默认交付）。
   注意与已有档位组合：`basestats`/`baseline` 时同样回退。
5. Guard/HoldGround 的 detection_range 分支、`sort_custom` 最近目标、断线/重连行为一律不动。

**验收**：① g4move200 A/B 对照：候选检查数大幅下降（计数器首次出现）、索敌耗时下降、
帧时 P95/P99 变化如实报告；② g4battle200 同场复测（混战中 attack-move 单位的扫描也走网格）；
③ 行为一致性：rule-ai/attack-move 相关套件项无新增失败。

## 5. 任务 B：FogOfWar.gd:201 sight_range 空值根因修复

现象：`_map_unit_to_new_circles` 里 `unit.sight_range * texture_units_per_world_unit` 报
"Nil 与 int 相乘"，一次 rule-ai-expansion 测试日志里 21,660 次（改动前就有）；伴随
`_sync_circles_to_unit` 字典访问失败。根因：`Unit.gd:92 sight_range = null` 是默认值，
只有 C# `BalanceConfigRuntime.cs:180 unit.Set("sight_range", definition.SightRangeMeters)`
会给**目录里存在的类型**赋值；目录外类型（曾实测 Scout 不在 demo.balance.v1.json）恒为 null。
第一轮已把测试里的 Scout 换成 Sniper 绕开，但根因还在。

做法：
1. 先复现定位：在 rule-ai-expansion 测试或 200 单位场景里打印 `sight_range == null` 的单位的
   `type_id`/脚本名，确认到底是哪些类型缺目录定义。
2. 修根因（按你查到的结果二选一或都做）：
   - 给 `config/balance/demo.balance.v1.json` 补缺失类型的 `unitTypes` 定义（带合理 sight_range）；
   - 或在 `Unit.gd`/出生链路给 sight_range 一个非 null 兜底默认值（不得改变已定义单位的数值）。
3. 验收：FogOfWar.gd:201/213 报错归零；迷雾圈对这些单位正常出现。
