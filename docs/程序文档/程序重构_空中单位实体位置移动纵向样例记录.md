# 空中单位实体位置移动纵向样例记录

## 1. 目标

`CMD-030` 处理无交互空中单位普通右键地面实体时的停止位置。Helicopter 点击矿石等中立地面实体时没有攻击、跟随、采集或施工语义，应移动到鼠标实际点击位置上空，而不是复用地面 `MovingToUnit` 的双方 footprint 相接距离。

## 2. 交互优先级

普通实体右键按以下优先级解释：

1. Worker 采集或交付资源；
2. 合法敌方目标的普通 Attack；
3. Worker 施工；
4. 己方/敌方单位的既有 Follow 语义；
5. 无以上交互且移动域为 AIR 时，按实体表面的世界点击位置执行普通 Move；
6. TERRAIN 单位继续使用 `MovingToUnit`，按双方 footprint 保持合法距离。

因此，新分支不会让 HoldFire 下的 Helicopter 通过“移动”绕过敌方目标拒绝，也不会覆盖 Attack、Follow、采集或施工。

## 3. 多单位与命令边界

无交互 AIR 单位先按现有 `crowd_moved_to_new_pivot` 分配各自目标，避免多选单位全部堆到同一点。已迁移的 Tank/Helicopter 通过公共 `MoveUnits` 提交并产生普通 `Move` 订单；尚未迁移的 AIR 单位暂时保留 Legacy `Moving` 适配，等待其独立纵向切片。

本项不修改 AIR NavMesh、飞行高度或避障算法，也不改变 TERRAIN 单位的 footprint 规则。

## 4. 自动验证

新增 `tests/automated/AirEntityMoveSmokeTest.tscn`，覆盖：

- Helicopter 点击矿石产生普通 `Move` 订单；
- Action 为 `Moving`，NavigationAgent 的水平目标等于实体表面点击位置；
- 即时反馈为 `Accepted`；
- Tank 点击同一矿石仍使用 `MovingToUnit`；
- Helicopter 普通右键敌方建筑仍产生 `Attack`，实体交互优先级未被覆盖。

2026-08-14 Godot 4.7 Mono 无头测试通过，输出 `Air entity move smoke test completed: 0 failure(s)`。退出时仍报告已登记的 RID/ObjectDB 清理告警，与功能断言分开处理。

## 5. 人工验收

运行 `tests/manual/TestHelicopterCommands.tscn`：

1. 单选 Helicopter，普通右键一个距离较远的矿石模型；
2. Helicopter 应飞到鼠标点击位置上空，不再停在矿石旁；
3. 普通右键红方建筑，确认仍执行 Attack；
4. 单选 Tank 普通右键矿石，确认仍停在地面 footprint 外侧。
