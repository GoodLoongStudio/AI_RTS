## 5. 环境陷阱（前一个 AI 全部踩过，别再踩）

1. **tscn ext_resource 按 uid 优先解析**：换资源路径必须连 uid 一起换（或删掉 uid 属性），否则静默加载旧资源
   （曾导致三轮"G4"测试实际跑在 PlainAndSimple 上）。模板行尾还有 `id="..."` 属性，整行匹配会失配，只替换 uid+path 片段。
2. **GeneratedTerrain.gd 的跨度已拆分**：`_water_span`=语义（高度场坐标，sample_height/桥面用），`_world_span`=map.size（世界，采样水/细网格/寻路格距/遮罩用）。
   `sample_height` 吃**局部**坐标；世界坐标一律走 `sample_world_height`（to_local/to_global 变换感知）。别再合并这两个变量。
3. **tscn 根节点 size 键重复**时最后一个生效（手工编辑 map_*.tscn 后要检查重复键）。
4. **tscn 根节点名可能与文件名不同**（Sniper.tscn/Rocketeer.tscn 的根叫 "Infantry"）——按"第一个无 parent 的 node 块"定位根。
5. **呈现限速**：本机 ToDesk 远程桌面 + 143Hz 刷新，不限帧时轻负载 FPS 会被钳在 ~143 或 ~60（已实测复现，锁 SM/显存时钟都无效）。
   FPS 结论只做同窗交错比较；"FPS 相同"不能直接当 CPU 瓶颈证据——用计数器（候选检查数/索敌耗时）与 GPU 余量（此前 nvidia-smi 实测战斗中 GPU 利用率仅 22-36%）共同判定。
6. **背景负载**：LoL/ToDesk/QQMusic/ollama 可能占用 CPU/GPU；不关闭、不锁时钟；交错运行 + 计数器指标抗干扰。混合"有/无后台游戏"的数据无效。
7. 单位放大后，测试里固定坐标的几何要同步（参考 `UnitGuardStanceSmokeTest.gd` 的修法：把"视野内敌人"放到 tank 背侧 +4m，避免 ×2 碰撞体卡住回岗路线）。
8. `Performance.TIME_PROCESS` 在高帧率下读数超过帧时间（监控口径缺陷），只做参考，别用于瓶颈判定。

## 10. 自动化循环迭代流程（照此运转，这是本项目做任何优化的标准方法）

每轮优化 = **一个假设**走完一圈六道门，用数据决定下一轮。不许一次改多件事、不许跳门。

```
假设（一句话，可证伪）
  → ① 最小实现（一次只改一个变量）
  → ② 正确性门（目标冒烟 0 失败）
  → ③ 回归门（全套件 96 项，差分"既有 vs 新增"）
  → ④ 性能门（A/B/C 交错矩阵，计数器优先）
  → ⑤ 实战门（带图形的真实对局，肉眼+截图）
  → ⑥ 报告与决策（改/回退/下一轮假设）
```

### 10.1 ① 最小实现
- 一次只动一个变量。要对照多个变量（如本轮的"网格"与"错峰"），给每个变量留运行时开关
  （本项目惯例：`AIRTS_TARGETING` 环境变量选 A/B/C 版本），**默认值 = 交付形态**，开关仅供测量。
- 临时装置（测量脚本/场景生成器）放独立目录，交付后可整目录删除；已提交的文件不要因"临时"而删。

### 10.2 ② 正确性门
- 为新机制写最小冒烟场景（仿 `tests/automated/TargetAcquisitionGridSmokeTest.tscn` 的结构：
  根 Node + 脚本，`SmokeTestExit.request(get_tree(), 0 if _failures == 0 else 1)` 结束，
  套件以 `expected_marker: "<名字> smoke test completed: 0 failure(s)"` 断言）。
- 关键要求：**固定种子随机样本 + 把旧算法留作测试参照**做大规模一致性对比
  （本轮是 500 组随机查询，网格+精确过滤 与 旧全场扫描+精确过滤 集合相等）；
  旧算法只许活在测试里，正式运行时禁止兜底（否则会掩盖索引错误）。
- 生命周期边界必须逐项测：出生/死亡/移除/跨格移动/传送/归属变化/换局清理/姿态开关（HoldFire/ReturnToBase/Guard/HoldGround）。

### 10.3 ③ 回归门（差分法，这是本项目判定"有没有改坏"的标准动作）
```bash
cd /g/AIRTS/AI_RTS && python tests/perfgrid/run_regression.py   # 96 项，断点续跑
```
- 全量跑完后**必然有一批失败**（历史遗留 ~24 个，与本任务无关）。判定法：
  对每个失败项用**改动前的等价形态**重跑（本轮用 `AIRTS_TARGETING=baseline`，即不建网格节点）：
  - 基线也失败 → **既有失败**，记录，不阻塞；
  - 基线通过、新版失败 → **真回归**，必须修（本轮零新增；unit-guard-stance 的修法见 §5.7）。
- 注意 flaky：同测试两次结果不同（如 performance-governor 失败数 5→13 波动）按环境噪声处理，标注即可。
- 新增测试要注册进 `config/full_regression_suite.json`（id + scene + expected_marker + timeout_seconds）。

### 10.4 ④ 性能门（A/B/C 交错矩阵）
```bash
cd /g/AIRTS/AI_RTS && python tests/perfgrid/run_perf_grid.py [max_runs]
```
- **协议**：每场景 ≥3 次重复 × 每版本，A→B→C 交错（抗时间漂移）；预热 20s、采样 60s；
  唯一 run_id（含日期戳），JSON 不覆盖，作废数据移 `invalid_v*/` 子目录归档（永不删原始数据）。
- **指标优先级**：计数器（调用数/候选检查数/累计耗时/单帧峰值）> 帧时 P95/P99/1%low > 平均 FPS。
  计数器不受背景负载与呈现限速污染，是"优化是否生效"的第一证据。
- **呈现限速**：本机 ToDesk 远程 + 143Hz，不限帧 FPS 会被钳位（143/60 档）。FPS 只做同窗交错比较，
  "FPS 相同"≠无 CPU 瓶颈——用"降分辨率/改算法后计数器变化但 FPS 不变"来证伪 GPU 瓶颈。
- **负载一致性**：战斗场景记录 units_start/end；A/B/C 起止兵力差 >10% 的样本判无效（本轮战斗用
  出场后 HP×80 保持兵力，不用每帧回血）。
- **后台分块纪律**：Bash 后台任务有 10 分钟上限 → 驱动脚本必须支持断点续跑（跳过已存在的 run_id JSON）
  + `max_runs` 参数，一块一块喂；崩溃/超时的 godot 进程要先 `Stop-Process` 清掉再续。
- **场景构建**：`gen_perfgrid_scenes.py` 生成固定 tscn（单位摆位/构成/地图写死）——不要在运行时拼场景
  （节点 owned 语义会坏）。

### 10.6 ⑥ 报告与决策
- 每轮报告直接回复用户（9 节格式，见 §6）；用词纪律：无证据不承诺百分比；
  "局部有效"与"整体流畅"分开说；既有失败/新失败/已修复三张清单分开列。
- 决策：假设成立 → 保留默认生效，写下一轮假设；假设证伪 → 回退（删自己的改动）或留开关默认关；
  发现更大热点 → 记录计时证据，开下一轮，不在本轮无限扩大。
- 数据归档：`G:/AIRTS/tmp_logs/<主题>_<日期>/`；作废批次移 `invalid_v*/` 子目录并在报告注明口径演变原因。

### 10.7 可模仿的完整范例（本轮网格优化时间线）
1. 假设："索敌全场扫描是 N² 增长热点 + Timer 同帧对齐是尖峰源"。
2. 诊断：给 WaitingForTargets 加 note_scan 计数器，跑 idle200 基线 → 实测 60s 内 1428 万次候选检查、
   单帧索敌峰值 25-32ms（确认热点成立）。
3. 最小实现：TargetAcquisitionGrid（一次只做网格）→ 冒烟 9 组全绿 → 全套件差分零新增 → A/B 对照
   （候选检查 -81%、索敌耗时 -76%）→ 再加错峰（C 版）→ 再对照。
4. 中途踩坑即修即测：uid 解析陷阱（3 轮假数据作废归档）、地图根 size 重复键、相机边缘滚动拖走镜头、
   单位放大后测试几何失配——每个坑都变成了 §5 的一条陷阱记录。
5. 收尾：报告 + 已知缺陷清单（rule-ai-expansion 适配）+ 下一轮假设（GroundAttackMoving.gd:102 扫描复用网格）。
