## 2. 关键技术结论（已核实的省事点）

### 2.1 **不需要改游戏代码** —— 靠配置注入即可
副官启动器 `source/ui/AdjutantRunnerLauncher.gd` 的配置读取顺序是：
`user://adjutant_local.cfg`（覆盖项）→ 仓库约定布局（缺失项补齐）→ 空（则提示"未找到配置"）。

导出包中"仓库布局探测"必然失败，**但只要写好这个 cfg 就能启动**：

```ini
[runner]
python="<包根>/python/python.exe"
src_root="<包根>/agent/source"
work_dir="<包根>/agent/source"
env_file="<包根>/agent/source/adjutant_coordinator/.env.local"
authority_port=24579
player=""
```
写入位置：`%APPDATA%\Godot\app_userdata\Open RTS\adjutant_local.cfg`
（launcher 用 `OS.create_process(python, [bootstrap])` 启动，导出版可用；停止用 `taskkill /F /T`。）

### 2.2 **必须排除 torch**：现 venv 4.5GB 里 4GB 是无用依赖
`临时文件夹\airts_agent_venv` = 4,521 MB / 47,750 文件，其中 **torch 4,045 MB**。
副官的 `requirements-graph.txt` **不含 torch**（副官通过 HTTP 调 Ollama，不做本地推理）⇒ 包装时用干净环境。

而且**现 venv 不可直接移植**（`pyvenv.cfg` 硬编码基础 Python 路径）⇒ 用**官方 embeddable Python**：
```text
python-3.12.x-embed-amd64.zip（~11MB）
  → 解压到 <包根>/python/
  → <包根>/python/python.exe -m pip install -r requirements-graph.txt
     （langgraph 1.2.11 / pydantic-ai 2.42.0 / httpx / aiosqlite / pydantic 等 8 个直接依赖）
```

### 2.3 **模型只需 1 个**：本机 12.5GB 里只拷 2.7GB
`E:\Model` 共 12,523 MB（多模型共存）。打包只取 `minicpm5-adj-16k` 的那份 GGUF blob，
在包内目录用 `OLLAMA_MODELS=<包根>/models` + `ollama create` 重建同名标签（Modelfile 内容见 `PACKAGING.md` §7）。

### 2.4 其他已核实事实
- 游戏 exe 产物形态：`Open RTS.exe` + `data_OpenRTS_windows_x86_64/`（**必须整个文件夹**，缺 data 目录会启动即崩）
- DCS 端口：正常游玩时游戏监听 `24579`（副官从这里取权威口）
- 副官日志/握手目录：`user://adjutant_logs`（`%APPDATA%\Godot\app_userdata\Open RTS\adjutant_logs`）
- Ollama 本机版本 0.34.2；4060 8GB 上跑 2.7GB(Q8) 模型 + 游戏（Forward+）显存估算 ~5.7GB，可行

## 3. 打包步骤（严格按序）

### P0 【最高优先，先验证再打包】
**在现有 `build/` 包上验证"导出版能否拉起副官"** —— 这是本方案最大的未验证假设：
1. 用**本机现有** venv 写一份 `adjutant_local.cfg`（指向仓库外的 venv 与源码）；
2. 双击 `build/Open RTS.exe` → 进对局 → 点「副官 → 接管」；
3. 判据：面板变为已接管 + `%APPDATA%\Godot\app_userdata\Open RTS\adjutant_logs\` 出现 `*.jsonl` 事件 + pidfile；
4. **若不通过**：说明导出版启动链有问题 → 先修 `AdjutantRunnerLauncher`（属副官代码，允许改）**再继续**。

### P1 准备干净 Python 环境
- 下载 Python 3.12 embeddable → 解压 → 装 pip → `pip install -r requirements-graph.txt`
- 自检：`<包根>/python/python.exe -c "from adjutant_coordinator.deploy.agent_runner import main"`（在 `src_root` 下）
- ⚠️ 禁止把现 venv 整目录拷入

### P2 准备 Ollama + 模型
- 下载官方便携 zip → 解压到 `<包根>/ollama/`
- 建 `<包根>/models/`，用 `OLLAMA_MODELS` 指向它 → `ollama create minicpm5-adj-16k -f Modelfile`（FROM 指向拷来的 GGUF）
- 自检：`OLLAMA_MODELS=<包根>/models ollama list` 能看到 `minicpm5-adj-16k` 且大小 ~2.7GB

### P3 组装目录树
```
AIRTS_Demo/
├── 启动游戏.bat                 # 起 Ollama → 等就绪 → 起 game/Open RTS.exe
├── 使用说明.txt
├── game/    Open RTS.exe + data_OpenRTS_windows_x86_64/
├── agent/   source/adjutant_coordinator/**（含 .env.local）
├── python/  python.exe + Lib/site-packages
├── ollama/  ollama.exe + lib/
├── models/  blobs/ manifests/
└── tools/   first_run.ps1（写 adjutant_local.cfg；建日志目录）
```

### P4 脚本与说明
- `启动游戏.bat`：设 `OLLAMA_MODELS=%~dp0models` → 后台起 `ollama serve` → 轮询 `ollama list` 就绪 → 起游戏
- `first_run.ps1`：写 `%APPDATA%\Godot\app_userdata\Open RTS\adjutant_local.cfg`（按实际安装路径生成）
- `使用说明.txt`：启动方式、副官体验步骤（点接管 → 看它指挥）、故障排查、杀软白名单指引

## 5. 风险与回退

| 风险 | 影响 | 对策 |
|---|---|---|
| 导出版副官启动链不通（P0） | 核心卖点不可用 | P0 先验证；不通则修 launcher 再打包 |
| 显存不足（模型+游戏） | 掉帧/崩溃 | 4060 8GB 估算够；备选 q4 量化（~1.5GB，质量降级） |
| 5.3GB 下载太重 | 评委不愿下 | 备"轻量版"（只游戏 625MB）与"完整版"两档 |
| 未签名 exe 被 SmartScreen/杀软拦 | 打不开 | 说明书加"更多信息→仍要运行"+ 白名单指引 |
| Ollama 首次加载模型慢（冷启动） | 副官第一分钟无响应 | 启动脚本里预热（`ollama run` 一次空调用） |

## 6. 需要拍板的 4 件事

1. **分发形态**：7z 自解压（推荐，最简单）／ Inno Setup 安装程序（有开始菜单与卸载）？
2. **模型是否随包**：随包 +2.7GB（推荐，评委零操作）／ 让评委自己 `ollama pull`？
3. **是否做两档**：轻量版（只游戏，625MB）+ 完整版（5.3GB）？
4. **成品放哪**：本机哪个目录？是否需要上传（网盘 / GitHub Release）？
