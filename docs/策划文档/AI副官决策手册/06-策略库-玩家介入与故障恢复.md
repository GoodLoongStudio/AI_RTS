# 06 · 策略库：玩家介入与故障恢复

> 覆盖：玩家介入与显式交回、任务失败、模型故障、对局结束。
> 本章大部分是**硬约束**（程序保证），模型只负责"解释意图"这一小块。

## 1. 玩家有效命令 → 立即让位（硬约束）

```yaml
id: PLY-01
name: 玩家命令立即优先
触发: 玩家下达有效命令（移动/攻击/停止/采集/建造/生产及其取消）
程序行为（不由模型决定）:
  - 命令在权威端**立即生效**，不等待 Python/模型
  - 实际**成功受令对象**退出冲突的 AI 任务（不是"当前选中单位"）
  - 对象移入 player_controlled_units，控制代际 +1
  - 相关 AI 意图作废（旧意图不得复活）
模型行为:
  - 下一轮上下文中这些单位出现在 player_controlled_units
  - **模型不得再对其下发任何指令**（已由仲裁层 lease_owner_player 兜底丢弃）
```

**关键区别**：仅"选中单位"不等于下达命令；只有**有效命令**才触发让位。

## 2. 意图确认（三选一按钮）

```yaml
id: PLY-02
name: 明显改变计划时的意图确认
触发条件（程序识别，不由模型每轮问）:
  - 明显改变任务方向：撤军、改守、取消关键建造等
  - 连续操作合并为一次询问（普通微操不逐次询问）
证据示例:
  - 玩家把一队从前线拉回基地 → 程序识别为“方向改变”
  - 模型给出**局部意图解释**（如“你是想让这队回防基地吗？”）
必选项（玩家按钮）:
  - 确认目标      → 授权副官按确认目标指挥涉及单位
  - 我来指挥      → 继续保留玩家控制
  - 误触，交回副官 → 重新授权副官依据**当前战场**接续任务，**不盲目恢复旧命令**
硬约束:
  - 确认绑定：事件 ID + 涉及对象 + 控制代际
  - 新玩家命令 / 对局切换 / 对象失效 → **旧按钮必须失效**
  - 模型解释**不得阻塞**玩家操作（异步，不挡 UI）
  - **仅真实玩家确认事件**才能授权接管；模型或 runner 传 reacquire=true 一律不放行
未确认时的行为:
  - 继续执行玩家命令；完成后**保持位置与正常自卫**，不自动交回
  - 单队回防**不得**被推断为全军撤退
参数:
  confirm_cooldown: 待实测   # 连续操作合并窗口
```

## 3. 局部 vs 全军（硬约束）

| 情形 | 正确 | 错误 |
|---|---|---|
| 一队被玩家接管 | 其余对象**继续工作** | 全军暂停 |
| 一支小队被打 | 就近单位响应 | 全军回防 |
| 一个任务失败 | 只重评该任务 | 清空全部计划 |

```yaml
id: PLY-03
name: 局部接管不清空计划
适用条件:
  - 部分对象被玩家接管（player_controlled_units 非空）
  - 或部分任务被玩家打断
程序行为（不由模型决定）:
  - 计划版本 plan_version 保持不变（不因局部接管而整体作废）
  - 仅把受影响任务标记为 partially_overridden / waiting_for_player
  - 其余任务状态不变，继续执行
模型行为:
  - 只对未被接管的单位继续派活
  - 不要因为局部接管而提出"全军撤退/重新规划"
禁止条件: 无
成功证据: 未被接管的单位仍有可观测进展
失败分支: 若接管范围扩大到全部单位 → 转为 waiting_for_player，副官只保留经济类保守动作
退出条件: 玩家确认目标 / 交回 / 新计划采纳
重新评估条件: 每次玩家事件
parameters: {}
```

## 4. 故障恢复

### FAIL-01 · 任务失败

```yaml
id: FAIL-01
name: 任务失败处理
适用条件（程序判定，见 08）:
  - 连续多轮观测无进展（stalled）
  - 目标长时间不可见（超过宽限）
  - 单位全灭
禁止条件: 无
可选任务（模型视角看到 degraded 原因后）:
  - 换目标 / 换路径 / 换单位重新执行
  - 或放弃该任务，转其它线（经济/侦察/防守）
成功证据: 新任务产生可观测进展
失败分支: 连续失败 → 降级为规则兜底（只做可判定的事）
退出条件: 任务闭环（completed / failed / interrupted / expired）
重新评估条件: 每轮
parameters:
  stall_limit_observations: 3      # 见 graph/progress.py，可配置
  lost_sight_grace_ticks: 600      # 约 10 秒
  lost_sight_fail_ticks: 2400      # 约 40 秒后判失败
```

### FAIL-02 · 模型故障（超时/非法/不可用）

```yaml
id: FAIL-02
name: 模型故障不冻结对局
硬约束:
  - 模型超时/失败**不阻塞** tick，不冻结游戏
  - 有效任务**继续执行**（长期采集/防守不因一次推理期限结束而中断）
  - 对仍授权给 AI 的对象提供**保守规则降级**
  - **明确区分**“模型决策”与“规则降级”，不得把规则演示当模型能力证明
  - 超时后不得靠“不断新建线程”重发（避免推理堆积）
  - 连续失败进冷却：此时战略不应独占路由，应让位给战术层
已知现状（见 11 章）:
  - 规则兜底当前**只做** 工人采集 / 基地补工人 / 其余待命 → 天然不会发展
  - 本手册的 BLD-01 发展阶梯应作为**规则兜底的扩展**实现（确定性、可单测）
```

### FAIL-03 · 对局结束

```yaml
id: FAIL-03
name: 对局结束与重开
硬约束:
  - 结果由游戏权威端判定；副官不得声明胜负
  - 对局结束/重开时**清空**：在途请求、待确认意图、旧按钮、旧订单
  - runner 重启后从游戏权威端**重新同步**；本地 checkpoint **不得覆盖**更新后的玩家控制权
  - 资源预留按**新对局**重新按余额 20% 初始化
```

## 5. 硬约束清单（程序保证，模型无权改变）

| # | 约束 |
|---|---|
| 1 | 玩家 `player_controlled_units` 永不被下发（仲裁层 `lease_owner_player`） |
| 2 | 未确认/未交回前，不因超时、任务完成或模型建议抢回 |
| 3 | 仅真实玩家确认事件可授权接管（`reacquire=true` 不足以放行） |
| 4 | 旧结果不得凭"提交时填最新代际"复活 |
| 5 | 预留额度仅玩家可改；AI 不得突破（`0` = 不预留） |
| 6 | 玩家生产/建造订单优先，副官不取消、不占满队列 |
| 7 | 目标引用必须来自观测/规则视图，不得构造路径 |
| 8 | 请求绑定对局 ID / 快照 / 对象控制代际；过期与长期任务有效期分离 |
