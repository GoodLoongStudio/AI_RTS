# 09 · 技术接入说明（程序侧）

> 本章面向程序。说明"手册怎么变成模型能用的东西"，以及**当前代码里必须整改的地方**。
> ⚠️ 本轮**只写文档，不改代码**。以下"建议"均未实施。

## 1. 接入原则

| 原则 | 说明 |
|---|---|
| 文档供人维护，程序按需筛选 | 未来由程序加载/缓存，**按局势筛少量相关策略**喂模型 |
| 不让模型遍历目录 | **禁止**模型每轮通过工具读整本手册 |
| 首期无向量库/无额外检索模型 | 用**规则化筛选**（事实字段命中）即可 |
| 元数据用 YAML/JSON 区块 | 不发明需要 `eval` 的条件语言；条件只用**事实字段 + 简单比较** |

## 2. 建议的加载与筛选流程

```
启动时（一次）
  ├─ 扫描 docs/策划文档/AI副官决策手册/*.md
  ├─ 解析每个 ```yaml 区块 → Strategy{id, 适用条件, 禁止条件, 可选任务, parameters...}
  └─ 建索引：strategy_id → Strategy（内存缓存，不落盘）

每轮（每 tick）
  ├─ ① 从观测提取事实：idle_workers / has_barracks / enemies_visible / ...
  ├─ ② 按 适用条件 & 禁止条件 过滤出候选策略
  ├─ ③ 硬约束预剔除：玩家控管对象、能力不匹配、预算不足、目标非法
  ├─ ④ 截断到 N 条（建议 3~6），按优先级排序
  └─ ⑤ 装配进 build_tactics_context() 的**新增字段**（见 §3），再调模型
```

**YAML 区块示例**（与策略库一致，程序只解析这些键）：

```yaml
id: BLD-01
适用条件: [...]
禁止条件: [...]
可选任务: [...]
parameters: {key: 待实测}
```

**条件表达式的约定（不要发明语言）**：

- 允许：`字段 存在/非空`、`数量 > 数量`、`含某类型`、`事件含某 kind`
- 禁止：`评估战力`、`加权评分`、`若 X 则 Y 否则 Z 的嵌套推导`
- 理由：2B 模型与筛选器都只可靠地处理**单步比较**。

## 3. 与现有上下文的衔接（**重要：字段是新增，不是现有**）

**现有** `build_tactics_context()` 已输出（可直接用）：

```
own_units, visible_resources, visible_enemy_ids,
production_options, build_options, buildable, production_relations,
active_intents, pending_requests, ai_controlled_units, player_controlled_units,
current_plan, active_tasks, events, tactical_summary, hint
```

**本手册建议新增**（当前**不存在**，属待办）：

| 建议新增字段 | 内容 | 放哪 |
|---|---|---|
| `candidate_tasks[]` | 候选任务（含 `strategy_id/label/action/options/blocked_by`） | 战术上下文 |
| `phase` | 全局发展阶段 | 战术上下文 |
| `track_states` | 四条线的当前任务与状态 | 战术上下文 |
| `own_units[].hp / hp_max` | 我方血量（敌方已有） | `own_units[]` |
| `constructed` | 建筑是否完工 | `own_units[]` |
| `production[]` | 生产队列明细 | 战术上下文 |

**新增字段必须与模型输出严格分离**：模型只回 `DirectiveBatch`，不回上述任何字段。

## 4. 已核验的**待整改项**（写进这里供后续开发）

| # | 问题 | 证据 | 建议方向 |
|---|---|---|---|
| R1 | **按"每工人 × 每建筑"展开候选会造成输入膨胀** | 实测 `build_options` 单项 3848 B（4 建造 × 8 工人），删 `cost` 后降到约 1/3 | 改为 `{building, builders:[...]}` 紧凑形；或只给"当前该级"的 1~2 项 |
| R2 | **只按敌我数量决定攻退**，忽略兵种、目标域、血量、地形 | `visible_enemy_ids` 只有 id，无 hp/domain/地形 | 补 `hp / weapons[].target_domains`；撤退判据至少纳入 hp |
| R3 | **强制所有单位每轮派活**，可能覆盖有效任务 | 提示词"其余单位不得空转闲置" + 模型对玩家接管单位下发（需靠仲裁层兜底） | 候选里**必须留"维持现有任务"**；对已下达持续任务的单位不下发新指令 |
| R4 | **规则兜底不做发展** | `rules_fallback.py` 自述"只做采集/补工人/待命" | 把 BLD-01 发展阶梯做成**确定性**兜底（可单测） |
| R5 | **策略层（strategy）长期超时** | 实测 `strategy_model_ModelTimeout` 反复出现 → `active_plan` 常为空 | 压缩战略上下文；或允许"无计划"下由候选驱动（BLD-01 正是为此） |
| R6 | `truncated` 语义易被误用 | 候选生成若按"不在观测=消失"会误判 | 筛选器必须在 `truncated=true` 时禁用"消失即完成"类判断 |

## 5. 输出与控制流衔接（当前真实路径）

```
DirectiveBatch（模型）
  → directives_to_intents()          # 程序补 plan_version/snapshot/tick/ttl/generation
  → IntentBatch
  → arbitrate_intents()              # 校验/去重/TTL夹紧/预算/代际/玩家优先
  → node_dispatch_to_godot()         # 经权威通道提交
  → Godot 权威端 op=adjutant_intent  # 再校验（身份/规则版本/快照/TTL/代际/目标/租约/幂等）
  → 执行器（寻路/持续交战/采集往返）
  → 观测回传 → graph/progress.py 差分 → 任务状态
```

**双端校验是刻意的**：程序侧拦"语义违规"，游戏侧拦"执行不可能"。

## 6. 参数登记（禁止硬编码）

所有 `待实测` 参数应由**配置**注入（推荐 `GraphConfig` 或 `.env`），
并在评测通过后再固化为默认值。**禁止**在代码里写死"20 坦克""60 上限"这类数字。

建议配置键（命名示例，**尚未实现**）：

```ini
ADJ_WORKER_TARGET=4
ADJ_RALLY_POINT=...
ADJ_ATTACK_THRESHOLD=...
ADJ_STALL_LIMIT=3
ADJ_LOST_SIGHT_GRACE_TICKS=600
```
