# 03 · 策略库：经济与建造

> 覆盖：开局摸底与中途开启副官、工人与资源分配、经济恢复、建造与扩产。
> 模板字段含义见 [01 §2 三层分工](01-总则与决策地图.md)。
> **所有 `parameters` 都标 `待实测`**，不得当硬约束。
> 策略参考；接口和执行边界以 [当前执行入口](../../程序文档/AI副官_当前执行入口.md) 对应方案为准。下文动作由模型从竞争候选中选择，程序不能另行决定扩张或换兵种。

## 1. 经济线的三条判断

| 判断 | 依据（只能用上下文事实） | 结论 |
|---|---|---|
| 有闲工吗 | `own_units` 中 `can_gather=true` 且不在有效任务/在途请求中 | 生成采集、建造等能力匹配候选及“维持”，由模型取舍 |
| 还缺工人吗 | `own_units` 里 `can_gather=true` 的**数量** | 少于目标 → 可 `produce` 工人 |
| 该换矿点吗 | `visible_resources[]` 的数量与位置 | 就近采集；资源消失则改派 |

**注意**：`active_intents` 里已有 `gather` 的单位**不要重复下发**——
执行器会持续往返采集，重复下发只会重置任务。

## ECO-01 · 开工摸底（首轮 / 中途开启副官）

```yaml
id: ECO-01
name: 开工摸底
适用条件:
  - 无 current_plan 或 plan_version 为空
  - 或 active_intents 为空（副官刚被开启）
必需事实:
  - own_units（尤其 can_gather / can_produce / can_build）
  - visible_resources
  - production_options / build_options
禁止条件:
  - 已存在完整摸底结果且无需要重评的变化（已有采集任务不禁止评估建造候选）
可选任务:
  - 给每个空闲工人 → gather（就近资源）
  - 若 can_produce 单位空闲且 production_options 含 worker → produce worker
  - 若有空闲 can_build 单位且 build_options 非空 → 视情况 build（见 BLD-01）
资源与控制范围: 仅 AI 授权对象；空闲对象优先，改派已有任务必须由模型明确选择，不使用玩家接管单位
成功证据:
  - 每个工人收到接受回执（accepted=true）
  - 下一轮观测中工人位置朝资源点移动 / 余额上升
失败分支:
  - 无可见资源 → 转 SCT-01（先探矿）
  - 资源点不可达 → 记录，改派其它资源点
退出条件: 已为授权对象分配合理任务或记录维持、等待的原因，不能强迫所有工人采集而阻断建造
重新评估条件: 出现新事件（受袭/资源耗尽/玩家介入）
parameters:
  worker_target: 待实测   # 参考区间 4~6；不要写死为硬约束
```

**开局与中途开启的差别（重要）**

| | 开局摸底 | 中途开启副官 |
|---|---|---|
| 已知信息 | 几乎为空 | 可能有既有战局、已有建筑/部队 |
| 首批动作 | 派工人采集 + 补工人 | **先维持现状 + 补齐空闲单位**，不要推翻已有部署 |
| 侦察 | 通常先探矿/探路 | 直接按 SCT-02 补敌情 |

## ECO-02 · 经济恢复（被打击后）

```yaml
id: ECO-02
name: 经济恢复
适用条件:
  - 事件含 base_under_attack 或 unit_lost，且事件已处理完毕
  - 或 can_gather 的单位数明显低于既有水平
必需事实:
  - own_units（现存工人数）
  - production_options（能否补工人）
禁止条件:
  - 基地仍在受袭 → 先走 DEF-01，不要派人出去采集
可选任务:
  - 补工人（produce worker）
  - 幸存的空闲工人 → gather
  - 视余额补塔（BLD-03）
资源与控制范围: 保留额度之外；不得动用预留
成功证据: 工人数回升且余额恢复上升段
失败分支: 生产建筑被毁且无法重建 → 记录并转 BLD-02（重建产能）
退出条件: 工人数达到 worker_target 且余额上升
重新评估条件: 再次受袭 / 玩家介入
parameters:
  recovery_worker_target: 待实测
```

## BLD-01 · 推进发展阶梯（**解决“只会采集”的核心策略**）

> 这是**程序筛出的候选**，不是长段自然语言训导。
> 历史测试曾发现长政策提示引入回归；采用紧凑候选和明确事实，并以当前版本重新评估收益。

```yaml
id: BLD-01
name: 发展候选（按局势提供有竞争关系的合法选项）
适用条件:
  - 有空闲（或即将空闲）的 can_build 单位
  - 且预算充足（可花费额度 >= 未扣款的目标成本；由程序判定，不交给模型算）
必需事实:
  - build_options（可用 builder+building 组合）
  - production_options（可用 producer+product 组合）
  - 现有建筑类型（own_units[].type）——用于判断“是否已有该建筑”
禁止条件:
  - 对象无授权、能力不符、预算不足或落点非法
  - 已有同一目标的有效任务或未结算订单（避免重复下单）；扩产价值仍由模型决定
可选任务（程序提供若干竞争候选及“维持”；并行修改条数按快速/深度预算）:
  1. 无 barracks 且 barracks ∈ build_options → build barracks
  2. 无 vehicle_factory 且预算允许 → build vehicle_factory
  3. 有 barracks 且对应生产建筑空闲 → produce 作战单位（见 ARM-01）
  4. 危急（受袭且无塔）→ build anti_ground_turret
  - 或者：维持现有任务（发展不急）
资源与控制范围: 一个建造者；不动用预留
成功证据:
  - 建造类：后续观测出现该 unit_type 的建筑实体，且最终 constructed
  - 生产类：队列出现对应 item，且**之后观测到新单位**（**队列项消失 ≠ 生产成功**）
失败分支:
  - 建造被拒（位置被占/不可建）→ 换位置或换建筑
  - 建造者阵亡 → 重新选 builder
退出条件: 该建筑完工 / 该产品已部署
重新评估条件: 每轮；阶梯条件可能因新建筑出现而改变
parameters:
  barracks_before_factory: true   # 待实测：是否必须先兵营再车厂
  second_barracks_when: 待实测
```

**关键纪律（防止重蹈“没有发展”）**

- 程序根据已有产能、预算、威胁和任务反馈生成候选；序号是示例展示顺序，不是固定建造顺序。
  保留补兵、扩产、防御和“维持”等合理竞争项，不能只留下预定的唯一发展答案。
- 候选里**必须留“维持现有任务”**这个选项，避免模型被迫在无意义时也下命令。
- 模型已批准的生产目标可以持续落实；模型未选择的建筑、兵种和进攻不得由“发展阶梯”补出。故障期间仅维持有效任务及明确授权的保守降级。

## BLD-02 · 重建产能

```yaml
id: BLD-02
name: 重建产能
适用条件:
  - 关键生产建筑被摧毁（如 barracks / vehicle_factory 消失）
  - 且 build_options 中仍可选该建筑
必需事实: build_options、余额与预留、可用的 can_build 单位
禁止条件: 基地仍受袭
可选任务: build <被毁建筑>；若没有建造者则先 produce worker（command_center）
资源与控制范围: 不动用预留；不得抢占玩家的生产队列
成功证据: 建筑实体重新出现并 finished
失败分支: 连续无法建造 → 降级为“只维持经济”，并上报 degraded 原因
退出条件: 关键建筑恢复
重新评估条件: 每轮
parameters: {}
```

## BLD-03 · 补防御塔

```yaml
id: BLD-03
name: 补防御塔
适用条件:
  - 曾发生 base_under_attack，或已知敌情接近基地
  - 且 build_options 含 anti_ground_turret / anti_air_turret
必需事实: build_options、已知敌情类型（对地对空）、余额
禁止条件: 无可用建造者
可选任务: build anti_ground_turret（对地威胁）/ anti_air_turret（对空威胁）
资源与控制范围: 不动用预留
成功证据: 塔建成且位于基地朝向敌情一侧
失败分支: 位置被占 → 换位置
退出条件: 已建成计划数量的塔
重新评估条件: 敌情类型变化
parameters:
  towers_near_base: 待实测
```

## 4. 玩家订单优先（硬约束，程序保证）

- 玩家已提交的生产/建造订单**优先**；副官不得取消玩家订单。
- 副官**不得把生产队列占满**（`queueLimit = 5`，应留空位给玩家）。
  建议候选筛选时限制"同一生产建筑的在途 AI 队列项 ≤ 2"（`待实测`）。
- 玩家正在操作的工人/建筑可被接管（`player_controlled_units`），副官立即不再下发。
