## 2. 历史动作词表与目标约束

编写时 `ALLOWED_ACTIONS`（12 个，**原序**）。当前模型输出为四列任务修改，词表、参数及映射按技术设计和版本化契约升级；下表描述程序解码后的语义，不要求模型直接生成坐标或单位列表。

```
move, attack, attack_move, defend, retreat, scout, hold, regroup,   ← HIGH_LEVEL_ACTIONS
gather, stop, produce, build                                        ← GODOT_ACTIONS
```

`ALLOWED_TARGET_KEYS`：

```
entity_id, pos, scene, producer, resource, dest, area
```

| 动作 | 目标要求 | 说明 |
|---|---|---|
| `attack` | 必须 `target.entity_id` | 只能打 `visible_enemy_ids` 里的 |
| `move` / `attack_move` / `defend` / `retreat` / `scout` / `regroup` | 必须 `target.pos` | `[x,z]` 数字坐标 |
| `gather` | `target.entity_id` 取自 `visible_resources[].entity_id` | |
| `produce` | `target.scene` = 产品类型 id + `target.producer` | **整条取自 `production_options`** |
| `build` | `target.scene` = 建造 id + `target.producer` | **整条取自 `build_options`** |
| `stop` / `hold` | 无 | `hold` 对游戏侧 ≈ 原地不动，通常无需下发 |

`ABORT_CONDITIONS`（中止条件词表）：`enemy_spotted, base_under_attack, unit_lost,
target_dead, path_failed, task_completed, timeout, player_override, low_hp`。

## 3. 硬约束（100% 由程序保证，模型不可改变）

| 约束 | 规则 |
|---|---|
| **玩家优先权** | `player_controlled_units` 里的单位**绝不能被下发**；程序在仲裁层强制丢弃（`lease_owner_player`） |
| **资源预留** | 首次开启副官时按**当时余额 20% 向下取整**为**固定绝对值**；之后只由玩家调整，**不按剩余余额重算**；`0` 表示不预留 |
| **预算** | AI 可花费 = 余额 − 预留 − **未扣款承诺**，下限 0；已扣款不得重复预扣。同批逐项提交统一核算，玩家订单优先，幂等重试不重复花费 |
| **能力匹配** | `gather` 用 `can_gather`；`build` 用 `can_build`；`produce` 用 `can_produce`；移动用 `can_move` |
| **合法目标** | 场景必须来自规则视图；实体必须来自观测；不得构造 `res://` 路径 |
| **幂等** | 同一 `command_id`/`intent_id` 重复提交返回原回执，不重复扣费/生产/建造 |
| **控制代际** | 请求发出时绑定代际；**旧结果不能靠提交时填最新代际复活** |
| **期限** | 请求接收期限与长期任务寿命分离；结果到期即拒绝，不能更新 tick 或期限后重新放行 |
| **元数据** | 请求的 `DecisionFrame` 固定对局、规则、快照、逐对象代际、小队成员和任务版本；程序据此填写元数据，模型不得输出，提交时不得替换为最新值 |

## 5. 场景路径形式（`demo.assets.v1.json`）

`unitAssets[] = {unitTypeId, scenePath, blueprintScenePath?}`，例：

- `tank` → `res://source/match/units/Tank.tscn`
- `soldier` → `res://source/match/units/Infantry.tscn`（**注意 id ≠ 文件名**）
- `vehicle_factory` → `res://source/match/units/VehicleFactory.tscn`
  + `blueprintScenePath res://source/match/structure-geometries/VehicleFactory.tscn`

模型只使用请求中提供的执行者、方案和目标引用；程序解析为类型 id（如 `barracks`）并通过规则索引取得场景路径。

## 6. 编写时记录的事实缺口（须复核当前状态）

以下事实对策略判断必要，是编写时的缺口记录；开发 AI 须先核对当前代码、结构化观测及迭代记录，保留已经接入的实现，补齐仍缺失部分。

| 缺失事实 | 影响的策略 | 建议 |
|---|---|---|
| 单位当前 `hp / hp_max`（自己方） | 撤退、补兵、集火优先级 | 加入战术上下文（敌方已有 `hp`） |
| 建筑是否**已完工**（`constructed`） | 判定"兵营可用" | 已有字段，需进上下文 |
| 生产队列明细（`items[]`、`completed_work`） | 避免重复下单、判断产能 | 已有 `production[]`，需进上下文 |
| 武器域 / 对空对地 | 兵种配比、防空 | 规则视图有 `weapons[].target_domains` |
| 已侦察区域的**覆盖率** | 侦察目标选择 | 已有 `covered` 部分字段 |
| 敌方**最后目击位置与时间** | 进攻目标、追击 | `visible_enemy_ids` 只给 id |
