# 05 · 策略库：军事与作战

> 覆盖：军队组成、补兵、前线快集结、前压、基地防守、局部回防、进攻、撤退、重组、再次出击。
> **所有数字都是 `待实测`**，禁止写成硬约束。
> **禁止全军集火 / 全军回防**——只对**实际受影响对象**生效。

## 1. 军事线的判断（只能用单步比较）

2B 模型**做不了多步运算**（实测："敌人数量 ≥ 我方×2 就撤"无效；
改成"敌人数量**多于**我方作战单位数量就撤"才生效）。因此：

| 判断 | 允许的写法 | 禁止的写法 |
|---|---|---|
| 该不该撤 | `visible_enemy_ids 数量 > 我方作战单位数量` | `敌人 ≥ 我方×2`、`综合战力评估` |
| 该不该进攻 | `visible_enemy_ids 非空` 或已有敌情，且我方未劣势 | 先回家攒到固定人数再出门 |
| 谁去防守 | 受威胁单位附近的**少数**作战单位 | 全军回防 |

## ARM-01 · 补兵（产能匹配）

```yaml
id: ARM-01
name: 补兵
适用条件:
  - 已有 barracks / vehicle_factory / aircraft_factory
  - 对应生产建筑空闲（queue 无在途 AI 项）
  - 且不在受袭中
必需事实: production_options、own_units（已有作战单位构成）、production_relations
禁止条件:
  - 生产队列已被玩家订单占满
  - 基地受袭（先 DEF-01）
可选任务:
  - produce soldier（barracks → soldier，A 150，work 120）
  - produce tank（vehicle_factory → tank，A 500，work 360）
  - produce helicopter（aircraft_factory → helicopter，A 700，work 360）
  - 维持现有任务
资源与控制范围: 不动用预留；同一生产建筑在途 AI 项 ≤ 2（待实测）
成功证据: **观测到新单位实体**（队列项消失本身不算成功）
失败分支:
  - 队列项消失但无新单位 → 判失败（不得当成功）
  - 资源不足 → 回到经济线
退出条件: 已下单一支目标规模的部队
重新评估条件: 每次集结判断 / 战损后
parameters:
  army_mix_soldier_tank: 待实测   # 参考“2:1”来自旧文档，未在当前平衡验证
  keep_queue_slot_free: 1        # 待实测：为玩家留空位
```

**兵种注意（已核验的平衡事实）**：

- `drone` **没有武器** → 只能侦察/骚扰视野，不得当作战单位。
- 对空/对地：`anti_air_turret_rocket` 打空中；`anti_ground_turret_cannon` 打地面。
  派兵前需确认目标域（当前上下文**未提供**敌方单位域，属 [02 §6](02-事实与硬约束.md) 待补事实）。

## DEF-01 · 基地防守（受袭时）

```yaml
id: DEF-01
name: 基地防守
适用条件:
  - 事件含 base_under_attack，或己方建筑附近出现 visible_enemy_ids，或己方建筑掉血
必需事实: own_units（现存作战单位）、visible_enemy_ids、基地/建筑位置
禁止条件: 无（受袭时最高优先，可打断其它非玩家任务）
可选任务:
  - 调动**基地附近**的作战单位 → attack_move / defend 到基地附近坐标
  - 回防圈内没有作战单位时，召回距基地最近的少量作战单位（默认最多 3）
  - 采集中的工人**不必回防**（工人回防基本等于送死，且断经济）
  - 有防空塔则保持原位靠塔防守
资源与控制范围: 附近单位 + 补足配额的最近野外单位；其余远处线继续原任务（不全军回防）
成功证据:
  - 敌方单位从观测中消失 或 confirmed_dead
  - 基地未再收到 base_under_attack 事件，建筑附近无可见敌人
失败分支:
  - 敌人数量多于我方作战单位 → 转 RET-01（撤离并保存兵力）；回防单位仍先回家，不在野外逃离
  - 关键建筑已失 → 转 ECO-02（经济恢复）+ BLD-02（重建产能）
退出条件: 威胁解除
重新评估条件: 每轮；威胁数量变化时立即重评
parameters:
  defense_radius: 待实测
  defend_recall_max: 3
```

## ATK-01 · 前线快集结

```yaml
id: ATK-01
name: 前线快集结
适用条件:
  - 已有作战单位
  - 队形散开（彼此离得远）
  - 且不在基地受袭中
必需事实: own_units（作战单位位置）、前线集结点、visible_enemy_ids / 上次敌情
禁止条件:
  - 正在防守（先 DEF-01）
  - 把主基地门口当集结点
可选任务:
  - 散落单位 → attack_move / regroup 到**前线集结点**（敌情方向 / 小队中心 / 地图内侧）
  - 已在集结点的单位 → 维持后立即转 ADV-01 / ATK-02
资源与控制范围: 我方作战单位
成功证据: 作战单位在前线集结点附近聚集（位置接近目标，且目标不是主基地）
失败分支: 集结点被敌占据 → 改到更安全的前线点
退出条件: 队形收拢后立即前压或进攻；不在主基地等待满编
重新评估条件: 每轮；敌情出现时重评
parameters:
  rally_point: 前线/上次敌情方向/小队中心（禁止主基地坐标）
  attack_threshold: 小队规模（当前与 SQUAD_ACTION_MIN 同口径，待实测）
```

**纪律：不得“添油”** —— 指不要把单个单位送进人数更多的可见敌军。
不是“先回家攒大军”。2 人小队收拢后就该行动。

## ADV-01 · 前压

```yaml
id: ADV-01
name: 前压
适用条件:
  - 已有作战单位
  - 无可见敌人
  - 且不在基地受袭中
必需事实: 前线点 / 地图内侧 / 上次敌情
禁止条件:
  - 正在防守（先 DEF-01）
  - 围着主基地 15–40m 转圈当作前压
可选任务:
  - 作战单位 → attack_move 到前线点（朝敌情或地图中心）
资源与控制范围: 我方作战单位；不影响工人与专职侦察
成功证据: 单位离开主基地回防圈，朝内侧/敌情推进
失败分支: 路径受阻 → 换方向；遇劣势接触 → 转 RET-01
退出条件: 发现可打敌人 → ATK-02；队形散开 → ATK-01
重新评估条件: 每轮
parameters:
  search_radius: 待实测
```

## ATK-02 · 进攻

```yaml
id: ATK-02
name: 进攻
适用条件:
  - 已有作战单位
  - 且 visible_enemy_ids 非空，或已有敌方情报点
  - 且不属于 base_under_attack 中
必需事实: visible_enemy_ids 或 enemy_intel、我方作战单位、敌方位置
禁止条件:
  - 无敌情（此时应 ADV-01 前压或 SCT-02 侦察）
  - 目标域不匹配（如只带对地兵种去打空中目标）
  - 可见敌人数多于我方作战单位（先 RET-01）
可选任务:
  - 作战单位 → attack（target_id 取自 visible_enemy_ids）
  - 或 → attack_move 到敌方目标区域 target_pos
资源与控制范围: 我方作战单位；**不影响**经济/侦察单位
成功证据:
  - 敌方单位 confirmed_dead 或从观测消失
  - 敌方建筑受损/被毁（需观测支持，见 [02 §6](02-事实与硬约束.md)）
失败分支:
  - 我方作战单位数 < 敌方可见数 → 转 RET-01
  - 目标失去视野 → 任务 interrupted（不是失败），等目标重现或改目标
退出条件: 目标被消灭 / 视野内无敌可打
重新评估条件: 每轮
parameters:
  commit_distance: 待实测
```

## RET-01 · 撤退

```yaml
id: RET-01
name: 撤退
适用条件:
  - visible_enemy_ids 数量 > 我方作战单位数量（**单步比较**）
  - 或我方单位 `hp` 极低（需 [02 §6](02-事实与硬约束.md) 补 hp 事实）
必需事实: visible_enemy_ids、own_units（含位置）、我方主基地方向
禁止条件: 无（保存兵力优先于一切非玩家任务）
可选任务:
  - retreat 或 move → target_pos = **脱离点**（远离最近敌人；可朝主基地方向，但不得落在主基地门口）
  - 已经在安全方向移动的单位 → 维持
资源与控制范围: 仅处于劣势的单位，不牵连其它单位
成功证据:
  - 与最近敌人的距离**增大**（可由执行层距离判定）
  - 或我方单位脱离敌人视野
失败分支:
  - 被追击且无法脱离 → 允许边打边走向脱离点
退出条件: 脱离接触 / 到达前线集结点（不是主基地门口）
重新评估条件: 每轮；敌人数量减少则回 ATK-02
parameters:
  safe_distance: 待实测
```

**注意（实测教训）**：2B 模型在压力场景下会把撤退写成 `scout`（方向对但动作名错）。
**执行层应按位置语义执行移动类动作**，不要因动作名不同而拒绝（见 [09](09-技术接入说明.md)）。

## REG-01 · 重组与再次出击

```yaml
id: REG-01
name: 重组
适用条件:
  - 刚完成一次撤退或一次交战（我方有战损）
  - 且当前安全
必需事实: own_units（剩余作战单位）、production_options（能否补兵）
禁止条件: 仍在受袭
可选任务:
  - 存活单位 → 回到**前线集结点**（move / attack_move）
  - 补兵（ARM-01）
  - 补塔（BLD-03）若刚被打过基地
资源与控制范围: 我方作战单位 + 生产建筑
成功证据: 兵力回升且重新集结到前线集结点
失败分支: 产能不足 → 转 ECO-02 先恢复经济
退出条件: 小队可行动 → 回 ATK-02 或 ADV-01
重新评估条件: 每轮
parameters: {}
```

## 2. 反模式（不要做）

| 反模式 | 为什么错 |
|---|---|
| 全军集火一个目标 | 会放弃其它方向的防守，且忽视目标域 |
| 全军回防 | 局部威胁扩大成全军行动（违反产品约束） |
| 未达规模就进攻（添油） | 单兵送进人数更多的可见敌军；不是“先回家攒大军才许动” |
| 空闲作战单位集结主基地 | 新兵已在家门口，回家不占图、不施压 |
| 每轮重复下发同一条攻击命令 | 会重置攻击/寻路进度（历史明确记录的缺陷） |
| 只按数量比决定攻退 | 忽略兵种、目标域、血量、地形（见 [09](09-技术接入说明.md) 待整改） |
| 用固定数字当门槛 | 未经当前平衡验证，参数必须标 `待实测` |
