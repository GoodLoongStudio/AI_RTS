# 策划文档_指令与命令执行规则

> 状态：待评审  
> 本文定义：单位收到命令后的接受、执行、覆盖、结束、失败，以及玩家命令与 AI 命令之间的优先关系。  
> 本文不定义：基础按键、UI 表现、寻路算法、伤害公式、技能具体效果、Targeting 完整流程。  
> 前置规则：《策划文档_基础交互逻辑文档》。

---

# 1. 核心原则

一句话核心规则：

> **同一单位同一时间只执行一个主要命令；新的有效玩家直接命令默认覆盖当前主要命令。**

命令来源分为：

1. 玩家 Direct Control；
2. Unit AI；
3. System AI。

玩家直接命令优先于 AI 自动命令。

---

# 2. 基础命令

当前基础命令包括：

| 命令 | 含义 |
|---|---|
| Move | 移动到指定位置 |
| Attack | 攻击指定目标 |
| Attack Move | 向指定位置推进并处理途中敌人 |
| Follow / Approach | 跟随 / 靠近指定友方 |
| Interact | 与目标执行默认交互 |
| Stop | 停止当前主要命令 |
| Hold Position | 保持当前位置，不主动追击 |
| Patrol | 在指定路径 / 区域巡逻 |
| Skill Command | 执行技能产生的命令 |
| AI Command | Unit AI / System AI 下发的具体执行命令 |

---

# 3. 命令执行流程

统一流程：

```text
命令产生
↓
合法性检查
↓
接受 / 拒绝
↓
执行
↓
完成 / 被覆盖 / 失败
```

命令只允许处于以下结果之一：

- 执行中；
- 已完成；
- 被覆盖；
- 执行失败。

---

# 4. 命令覆盖规则

## 4.1 玩家直接命令

新的有效玩家直接命令默认覆盖当前主要命令。

例如：

```text
Attack
→ 玩家下达 Move
→ Attack 被覆盖
→ 执行 Move
```

```text
Patrol
→ 玩家下达 Attack
→ Patrol 被覆盖
→ 执行 Attack
```

当前不支持 Shift 命令队列。

因此连续下达：

```text
Move A
Move B
Move C
```

最终以最后一个有效命令 `Move C` 为当前主要命令。

## 4.2 重复命令

连续重复同一个命令不得产生额外命令堆积或异常状态。

例如：

- 连续 Stop；
- 连续 Hold Position；
- 连续右键同一位置；
- 连续攻击同一目标。

系统只保持最终合法状态。

---

# 5. Stop 与 Hold Position

## 5.1 Stop

Stop：

- 立即中止当前主要命令；
- 单位停止当前移动、攻击、跟随、巡逻等行为；
- 单位进入无直接命令状态。

Stop 本身不取消单位已经配置的 Unit AI 行为。

如果 Unit AI 仍然有效，后续是否重新产生 AI 命令，按第 6 节规则处理。

## 5.2 Hold Position

Hold Position：

- 停止主动移动；
- 保持当前位置；
- 可以处理当前允许范围内的目标；
- 不主动追击超出当前位置允许范围的目标。

Hold Position 是玩家直接命令，不等同于 Unit AI 的“稳守维持”。

---

# 6. 玩家命令与 Unit AI

已配置的 Unit AI 行为与当前玩家 Direct Control 操作层是两个不同概念。

核心规则：

> **玩家直接命令执行期间，Unit AI 必须让权；玩家直接命令正常结束后，原 Unit AI 行为继续生效。**

例如：

```text
Unit AI：主动进攻
↓
玩家下达 Move B
↓
Unit AI 暂时让权
↓
单位执行 Move B
↓
Move 完成
↓
Unit AI：主动进攻继续生效
```

玩家直接命令不会默认永久取消 Unit AI 行为。

如果玩家希望改变 Unit AI 行为，应通过 Unit AI Command 明确修改。

---

# 7. 玩家命令与 System AI

玩家选择任意己方单位 / 小队后，默认操作层进入该对象的 Direct Control。

当玩家对具体单位下达直接命令时：

- 玩家命令优先；
- System AI 不得立即覆盖该命令；
- 当前具体单位优先完成玩家直接命令。

System AI 的全局姿态是否继续对其他单位生效，不受该单位直接命令影响。

具体单位完成玩家直接命令后，是否重新进入 System AI 调度，由后续 System AI 规则决定；本文不扩展该部分。

---

# 8. 命令结束与失败

## 8.1 正常完成

满足命令自身完成条件时，命令结束。

例如：

- Move 到达有效目标位置；
- Attack 的目标被消灭；
- Interact 完成交互；
- Patrol 被新的有效命令覆盖。

## 8.2 目标失效

| 情况 | 游戏处理 | 玩家反馈 | 原状态 |
|---|---|---|---|
| Attack 目标死亡 / 销毁 | 当前 Attack 结束 | 基础战斗反馈 | 回到合法状态 |
| Follow 目标失效 | Follow 结束 | 可轻量提示 | 回到合法状态 |
| Interact 目标失效 | Interact 失败 | 轻量失败反馈 | 回到合法状态 |
| Skill 目标失效 | 按技能 / Targeting 规则处理 | 对应失败反馈 | 不进入非法状态 |

## 8.3 位置无效

| 情况 | 游戏处理 | 玩家反馈 | 原状态 |
|---|---|---|---|
| Move 目标位置不可达 | 命令失败 | 轻量无效反馈 | 回到合法状态 |
| Attack Move 目标位置不可达 | 命令失败 | 轻量无效反馈 | 回到合法状态 |
| Patrol 路径无有效点 | 不进入 Patrol | 轻量无效反馈 | 保持原状态 |

## 8.4 单位失效

单位死亡、销毁或离场时：

- 清除当前命令；
- 不再接收后续命令；
- UI、AI 和选择系统必须在下一次合法状态刷新时移除该对象。

---

# 9. 冲突与优先级

当多个命令来源同时要求控制同一单位时，默认优先级：

```text
玩家当前直接命令
>
明确的玩家模式切换
>
当前合法控制对象
>
Unit AI / System AI 自动命令
>
默认 Idle 行为
```

具体原则：

- 玩家直接命令不能被 AI 在下一帧立即覆盖；
- 新的有效玩家直接命令默认覆盖旧主要命令；
- Unit AI 行为不会因为一次 Direct Command 被永久取消；
- 无效命令不得覆盖当前合法命令；
- 对象失效后必须收敛到合法状态；
- 重复输入必须产生可预测结果。
