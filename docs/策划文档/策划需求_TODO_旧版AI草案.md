# AI RTS｜策划需求 TODO

> 状态：持续维护  
> 用途：记录策划侧需要补充的内容、策划工具建设需求，以及程序模块完成后策划必须提供、配置和验收的交付物。  
> 核心原则：**策划尽量通过数据、资源和编辑器完成内容生产，程序负责提供稳定的通用能力，而不是每增加一个单位、技能或关卡都重新改硬编码。**

---

# 0. 使用方式

这份文档同时承担 4 个作用：

1. **策划 TODO**：还有哪些规则、内容、数值没有定义。
2. **工具 TODO**：哪些内容应该逐渐变成策划可自行编辑的工具。
3. **程序完成后的策划交付清单**：程序功能写完后，策划还需要补什么，功能才算真正完成。
4. **验收标准**：避免“程序能运行 = 功能完成”的情况。

推荐状态：

- `[ ]` 未开始
- `[~]` 进行中
- `[x]` 已完成并验收
- `[!]` 已实现但仍缺策划配置 / 验收

> 一个系统只有同时具备 **程序能力 + 策划配置 + 实际内容 + 验收标准**，才算真正完成。

# 2. 一个程序任务完成后，策划还需要提供什么？

除了世界观和兵种设定，策划真正需要持续提供的是：

> **规则、数据、内容、交互、边界情况和验收标准。**

程序完成一个“系统能力”，只代表底层可用了；策划必须继续把它变成真正可以玩的游戏内容。

## 2.1 必须补齐的 10 类策划交付物

| 交付物 | 策划需要回答的问题 | 示例 |
|---|---|---|
| 功能目的 | 为什么需要这个系统？ | F1 是为了让玩家随时回到主英雄 |
| 操作规则 | 玩家怎么触发？ | 单击 F1 选中，双击 F1 锁定镜头 |
| 状态规则 | 系统有哪些状态？ | 未锁定 / 跟随中 / 英雄失效 |
| 边界规则 | 异常情况怎么办？ | 英雄死亡、切场景、UI 输入占用 |
| UI / 反馈 | 玩家怎么知道发生了什么？ | 头像卡显示“跟随中” |
| 数据配置 | 参数是多少？ | 双击间隔、技能 CD、伤害、射程 |
| 内容配置 | 实际放什么内容？ | 第一关用哪辆坦克、哪几个技能 |
| AI 规则 | AI 什么时候能使用？ | AI 是否能自行撤退 / 放技能 |
| 美术 / 音频需求 | 需要哪些资源？ | 图标、特效、音效、单位状态动画 |
| 验收标准 | 什么情况算做完？ | 连续移动 30 秒镜头保持跟随且可缩放 |

# 4. 策划工具建设原则

编辑工具的目标不是“做一个看起来专业的编辑器”，而是：

> **让策划可以不改代码，独立完成大部分游戏内容。**

所有策划工具尽量满足：

- 数据驱动；
- 可视化；
- 实时或快速预览；
- 配置错误检查；
- 支持复制和模板；
- 适合 Git 版本控制；
- 运行时与编辑器读取同一套数据；
- 参数有默认值和说明；
- 支持一键进入测试场景；
- 重要数据可以批量编辑；
- 尽量避免把内容写死在 GDScript。

推荐总体结构：

```text
策划编辑工具
    ↓
Resource / 配置数据
    ↓
通用运行时系统
    ↓
单位 / 技能 / AI / 地图 / 战役
```

## 工具是否值得做的判断

如果某种内容：

- 只会出现 1～2 次：优先直接配置，不急着造工具；
- 会出现 10 次以上：考虑模板 / Inspector 增强；
- 会出现几十到几百次：应该优先工具化和批量化。

# 10. 科技 / “突破”编辑方案 TODO

本项目不是传统“一级科技 → 二级科技 → 三级科技”，而是：

```text
战役事件 / 科研成果
        ↓
获得一次突破
        ↓
新规则 / 新能力 / 新单位
        ↓
旧单位可能发生变化
        ↓
后续战役产生新解法
```

## 10.1 突破需要配置

- [ ] Breakthrough ID
- [ ] 名称
- [ ] 世界观说明
- [ ] 获取条件
- [ ] 解锁单位
- [ ] 解锁技能
- [ ] 解锁英雄模块
- [ ] 解锁 AI 权限
- [ ] 修改旧单位
- [ ] 修改生产 / 能源 / 通信规则
- [ ] 影响后续任务的状态

## 10.2 设计原则

每次关键突破尽量至少改变一种**玩法规则**，而不只是：

> 攻击力 +10%。

例如：

- 通信突破 → AI 可以跨区域协同；
- AI 突破 → 可托管更多小队；
- 能源突破 → 解锁高耗能战略武器；
- 材料突破 → 某些单位获得新的形态；
- 基础科学突破 → 解锁过去不存在的移动 / 武器机制。

# 16. 第一战役当前最重要的策划交付

第一战役不需要等待全部工具完成。

优先把真实内容做出来，再决定哪些地方值得工具化。

## 必须补齐

- [ ] 第一战役 20～30 分钟完整流程
- [ ] 每个 Objective 的目标、位置、触发条件
- [ ] 主要敌军类型和数量
- [ ] 敌军出现逻辑
- [ ] 玩家英雄的基础数据
- [ ] 英雄第一批能力
- [ ] F1 英雄操作正式规则
- [ ] AI 副官每个阶段知道的情报
- [ ] AI 副官每个阶段的建议
- [ ] 战役剧情节点
- [ ] 失败条件
- [ ] 结束条件
- [ ] 第一次“突破”的伏笔

## 第一战役重点验证的问题

不是验证最终 AAA 内容量，而是验证：

> **“一个英雄 + 少量小队 + AI 副官 + RTS 战场”到底好不好玩。**

重点观察：

- [ ] 玩家是否自然使用 AI 副官
- [ ] 玩家何时愿意自己微操
- [ ] AI 是否真的减轻操作负担
- [ ] 战场情报是否足够清晰
- [ ] 英雄是否有存在感但不过度 MOBA 化
- [ ] 小队加入以后是否比单英雄阶段更有战略感
- [ ] 玩家是否能感受到“指挥战争”而不是“控制所有单位”

# 17. 当前工具建设推荐顺序

不要同时开发所有编辑器。

建议顺序：

```text
① 单位数据标准
       ↓
② 技能数据 / 简易技能编辑
       ↓
③ 地图逻辑节点与可视化
       ↓
④ 任务 / Trigger 数据化
       ↓
⑤ 用第一战役完整跑通
       ↓
⑥ 根据实际需求设计行为树编辑器
       ↓
⑦ 科技 / 突破编辑器
       ↓
⑧ Agent 权限与战区 AI 工具
       ↓
⑨ 数值和平衡自动化工具
```

原因：

> **先解决内容生产的真实瓶颈，再造工具。**

避免为了“以后也许会用”提前做一个复杂但无人使用的万能编辑器。
