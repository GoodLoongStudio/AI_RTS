## 1. 产品定位

AI_RTS 是一个以**“指挥而不是高频微操”**为核心体验的即时战略项目。

当前产品由五个主要部分组成：

1. **RTS 基础对局**：资源、生产、建造、单位战斗、战争迷雾、地图、胜负结算。
2. **传统规则 AI**：作为电脑对手，负责独立经济、扩张、侦察、进攻、防守和撤退。
3. **AI 副官「岚」**：替玩家承担持续运营与局部指挥，玩家可随时接管具体单位或重新交回。
4. **战役 / 成长层**：已有战役胜负、结算、重开、成长点与成长树；通用任务目标运行时仍需补齐。
5. **程序化地图与联机 Demo**：已有地图生成工具链与 2–4 人服务器权威联机基础，均作为产品能力继续保留。

当前阶段的最高优先级不是继续横向堆系统，而是把这些已经存在的能力收敛成一个**可稳定完成一局、能体现 AI 副官价值、能交付给非开发者体验**的产品闭环。

## 3. AI 副官当前真实架构

当前代码已经不是 2026-09-11/14 文档里的“单 MiniCPM5-2B + 四列输出”单一路线。

当前实际能力可概括为：

```text
Godot 权威观测 / 事件
        │
        ▼
副官协调器：状态、任务、玩家接管、代际、TTL、候选
        │
        ├── Laya System 1（可选/快速判别）
        │        ↓ 失败或不可用
        ├── MiniCPM5-2B System 2（本地 Ollama）
        │        ↓ 超时或失败
        └── 规则 baseline
                 │
                 ▼
Task Patch / Intent 编译
        │
        ▼
程序硬校验：权限、预算、目标、代际、期限、能力、幂等
        │
        ▼
Godot 权威命令入口
        │
        ▼
行为树 / 寻路 / 射程 / 开火 / 采集 / 建造 / 生产持续执行
```

### 3.1 已经确定的边界

**永远由程序保证：**

- 玩家控制权和显式交还；
- 合法目标、地图边界、单位能力、资源/生产/建造合法性；
- generation、TTL、幂等、旧结果失效；
- 寻路、射程、碰撞、攻击 CD、动画、持续任务执行；
- 模型失败不能让整支部队停机。

**应该逐步交给模型做的选择：**

- 主攻方向；
- 小队分配与集中/分兵；
- 局部交战姿态；
- 目标优先级和集火；
- 等待增援、撤退或继续推进；
- 经济/扩张/生产之间的高层取舍。

## 4. AI 副官需要从“当前实现”继续演进的方向

### 4.1 从四列单行升级为小队订单

当前 `task_patch.py` 已经有 squad 概念，但仍主要以短行修改作为落地格式。

下一阶段的策划目标是引入原子的小队订单：

```json
{
  "squad": "main",
  "units": ["U1", "U2", "U3"],
  "mode": "attack_move",
  "target_policy": "production_then_turret",
  "stance": "aggressive",
  "ttl": 80,
  "cancel_when": ["target_dead", "base_under_attack"]
}
```

四列结构可以继续作为内部展开格式，但不再限制模型的主要表达能力。

### 4.2 引入“订单租约”

当前规则层能力很强，已经能够独立生产、扩张、侦察、推进和防守。
这保证了模型失效时游戏仍能运行，但也产生了一个新问题：**规则可能把模型刚做出的正确战术选择重新覆盖。**

目标优先级统一为：

```text
紧急安全事件
  > 有效玩家命令
  > 有效 AI 小队订单
  > 战略计划展开订单
  > 无订单时的规则 baseline
```

订单未过期、目标仍合法、取消条件未触发时，规则层可以修路径和安全参数，但不能擅自把战略目标改掉。

### 4.3 Laya 的职责

Laya 不负责逐帧坐标和底层移动。

Laya 的优先使用场景：

- 主攻目标选择；
- 局部交战姿态；
- 集火 / 换靶；
- 等待增援 / 推进 / 撤退；
- 远程单位保持距离；
- 小队支援关系。

经济采集、固定生产等规则已经能稳定完成的多数类行为，不应继续成为 Laya 训练数据的绝大多数。

### 4.4 MiniCPM5-2B 的职责

2B 模型更适合：

- 秒级到十几秒级的多小队组合计划；
- 经济、扩张、生产和主攻方向的取舍；
- 复杂局势的解释；
- 玩家自然语言意图理解；
- 重大事件触发的异步重规划。

模型推理期间继续执行上一份有效订单，不允许阻塞实时战斗。

## 5. 当前已知产品偏差

| 优先级 | 偏差 | 当前事实 | 策划处理 |
|---|---|---|---|
| P0 | 规则能运行，但基线实战仍不稳定 | 最近自对局曾出现敌方建筑伤害为 0 | 先固定一条能造成稳定建筑伤害的 EASY doctrine，再继续扩大模型训练 |
| P0 | 模型价值无法独立证明 | 规则、Laya、2B 同时参与，旧指标主要看 val accuracy | 使用 R0/R1/R2/R3 对照实验 |
| P0 | 小队动作仍受单行接口限制 | Laya/2B 最终仍大量落成 Task Patch | 实现 SquadOrder + 订单租约 |
| P0 | 战役任务系统不足 | 已有胜负、结算、重开，但通用“消灭目标 / 保护目标”等 Objective Runtime 仍不完整 | 战役闭环优先于继续扩成长树 |
| P0 | 交付文档与新模型架构冲突 | 旧完整包认为 Python 无需 torch；Laya 路径实际需要额外 ML 依赖 | 区分“2B 轻量 AI 包”和“Laya 完整 AI 包”，重新核算依赖与体积 |
| P1 | AI 对话仍含关键词解析和模板回复 | HUD 中仍存在本地 contains 解析和 mock 命名 | 文本逐步统一走真实副官语义层 |
| P1 | 语音指挥尚未接入 | 有播报音频，无麦克风/STT 输入实现 | 文本链稳定后做 Push-to-talk → STT → 同一命令入口 |
| P1 | 训练标签偏多数类 | 历史数据 GAT/PROD 占比过高，ATTACK 曾为 0 | 用局部交战结果和订单结果重新构造训练集 |

## 6. 验证标准

### 6.1 RTS 可玩性基线

固定多个地图种子，至少验证：

- AI 能持续采集、生产、扩张；
- 第一支作战小队能够主动离家；
- 能对敌方建筑造成实际伤害；
- 不发生长期全军发呆；
- 战斗失败后有重组或撤退；
- 一局最终能进入真实 Victory / Defeat。

### 6.2 AI 副官贡献验证

统一使用四组：

| 组 | 战略 | 局部战术 | 目的 |
|---|---|---|---|
| R0 | 规则 | 规则 | 可玩的确定性基线 |
| R1 | 2B | 规则 | 测 2B 的战略增益 |
| R2 | 固定战略 | Laya | 测 Laya 的局部战术增益 |
| R3 | 2B | Laya | 测完整 AI 副官 |

每局至少记录：

- 胜负；
- 首次建筑受损时间；
- 建筑伤害 / 分钟；
- 击杀 / 损失；
- 主攻兵力集中度；
- 小队订单完成率；
- 模型订单接受率；
- 规则替换率；
- 安全拒绝率；
- 空转时间；
- 撤退后存活率。

聚合 val accuracy 只能作为训练指标，不能作为产品成功指标。

## 7. 战役与成长的当前优先级

### 已有

- 胜负统一；
- 结算；
- 重开；
- 战役时间；
- 成长存档；
- 胜 3 / 负 1 成长点；
- 成长树与效果；
- 洗点退款。

### 当前缺口

战役仍需要统一 Objective Runtime，至少支持：

- 消灭指定目标；
- 保护指定目标；
- 到达 / 撤离区域；
- 存活一定时间；
- 触发事件；
- 目标完成/失败驱动 MatchOutcome。

在该闭环完成前，**不再优先扩成长树节点数量**。

## 8. 文本与语音交互

当前底部对话区属于可用 UI，但其中部分命令理解仍由关键词匹配完成。

产品目标统一为：

```text
文本 / 未来语音
   ↓
玩家意图解析
   ↓
副官状态与上下文
   ↓
生成 / 选择小队订单
   ↓
程序校验
   ↓
执行
   ↓
自然语言反馈
```

语音输入不是独立玩法系统。未来 STT 只负责把语音变成文本，后续与文本命令共用一套链路。

## 9. 交付形态

短期保留两种交付：

### A. 游戏轻量包

- 游戏本体；
- 传统规则 AI；
- 地图、成长、基础战役；
- AI 副官允许退化为规则模式；
- 不要求 Laya 环境。

### B. AI 完整体验包

- 游戏本体；
- 本地 Ollama；
- MiniCPM5-2B；
- Python 副官协调器；
- 若启用 Laya，还必须包含 Laya/torch 等真实依赖；
- 启动后自动拉起并预热模型；
- 非开发者无需手动配置端口、Python 或模型路径。

## 10. 接下来开发顺序

1. **固定可赢/可拆建筑的规则基线**；
2. **实现 SquadOrder + 订单租约**；
3. **补战役 Objective Runtime**；
4. **重做 AI 对照评测 R0/R1/R2/R3**；
5. **重构 Laya 训练集，接真实结果信号**；
6. **让文本输入进入真实副官语义链**；
7. **再做语音输入**；
8. 最后再扩大成长、更多战役内容和联机产品化。
