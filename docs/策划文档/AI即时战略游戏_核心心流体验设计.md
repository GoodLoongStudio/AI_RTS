# AI 即时战略游戏核心心流体验设计

> 文档状态：核心体验提案  
> 适用阶段：首个纵向切片、UI 原型、交互验证  
> 核心命题：让玩家既能像总指挥一样表达意图，也能像传统 RTS 玩家一样亲自微操关键战斗。

## 1. 产品愿景

这不是一款“在传统 RTS 上增加聊天框”的游戏，而是一款围绕 AI 重新设计操作方式、信息结构和指挥体验的新一代即时战略游戏。

传统 RTS 要求玩家把战略意图拆解为大量机械操作：拉框、编队、切屏、点技能、安排生产、侦察、补兵和多线调度。高手能从这些操作中获得掌控感，但大量玩家会因为操作密度、信息压力和学习成本而被挡在核心乐趣之外。

本游戏希望把玩家的注意力从“如何把命令点出来”提升到“我想打出什么战术”。AI 负责理解意图、补全细节、持续执行和汇报变化；玩家负责判断局势、设定目标、做关键决策，并在想亲自接管时进行精确微操。

一句话愿景：

> 玩家说出意图，AI 组织行动；玩家看见战局，在关键时刻亲自出手。

## 2. 玩家幻想

玩家不是一个不停点击单位的操作员，而是一名真正处于战场信息中心的指挥官。

玩家应持续感受到四种力量：

1. **我的命令被理解了**：AI 能将自然语言、快捷指令或地图标记转换为明确的作战计划。
2. **部队在替我执行意图**：小队会自主寻路、保持阵型、选择目标，并在条件变化时请求或做出合理调整。
3. **我仍然拥有最终控制权**：任何时候都可以框选单位、下达精确命令、释放技能或中止 AI 行为。
4. **战场像一场正在发生的指挥现场**：重要事件被即时呈现，副官、英雄、侦察员等 Agent 角色会根据战况给出短促提醒、评价和战报，让战场既有信息密度，也有角色陪伴感。

## 3. 核心心流

核心心流由六个连续环节组成：

```text
观察局势 → 形成意图 → 下达命令 → AI 复述与执行 → 观看反馈 → 接管或调整
     ↑                                                    ↓
     └──────────────── 战场变化与新情报 ──────────────────┘
```

### 3.1 观察局势

玩家通过主战场、小地图、事件流和 AI 摘要快速理解：

- 哪里正在交战；
- 哪支小队处于危险中；
- 哪些资源、据点或路线值得争夺；
- AI 正在执行什么；
- 哪些信息仍不确定。

目标不是让玩家阅读更多数据，而是帮助玩家在数秒内回答：“现在最需要我决定什么？”

### 3.2 形成意图

玩家决定的是战术目的，例如：

- “一队正面吸引，二队绕到右侧高地。”
- “守住通信站两分钟，不要追击。”
- “派侦察单位找出敌方远程火力。”
- “如果正面损失超过三成就撤退。”

意图可以包含目标、对象、限制条件和触发条件，而不要求玩家手动规划每一个路径点。

### 3.3 下达命令

同一个战术意图可以通过四种入口表达：

| 入口 | 适合场景 | 体验目标 |
| --- | --- | --- |
| UI 快捷命令 | 高频、确定性操作 | 一点即达，不打断战斗节奏 |
| 地图直接交互 | 移动、攻击、区域防守、路线规划 | 保留传统 RTS 的空间控制感 |
| 文本输入 | 复合命令、条件命令、临时计划 | 像使用 AI 助手一样自然表达 |
| 语音输入 | 高压战斗、多线操作、免手操作 | 不停手、不切视线地指挥 |

输入方式不是互斥模式。玩家可以先用语音给出宏观命令，再用鼠标微调一个单位的位置。

### 3.4 AI 复述与执行

AI 不能只回复“好的”。每条复杂命令必须转化为可检查的执行卡片：

```text
命令：二队从右侧绕后，优先攻击敌方火炮。

AI 理解：
• 执行单位：第二小队（6）
• 路线：右侧林地 → 北部高地
• 优先目标：火炮 / 远程单位
• 交战规则：避免主动攻击沿途步兵
• 预计接敌：28 秒

[确认执行] [地图预览] [修改条件]
```

低风险、高频命令可以直接执行并用轻量反馈确认；高风险、含歧义或会消耗关键资源的命令需要复述确认。

### 3.5 观看反馈

玩家应看到 AI 的行动过程，而不只是最终结果：

- 地图上出现路线、目标区域和任务状态；
- 小队头顶显示简短意图，例如“绕后中”“固守”“撤退”；
- 事件流报告关键节点，例如“二队已抵达高地”；
- AI 在计划失效时说明原因，例如“右路被封锁，正在等待新命令”；
- 战斗结束后生成简短复盘，例如“绕后迫使敌军转向，正面小队损失降低”。

这套反馈既建立玩家对 AI 的信任，也让指挥过程本身具有观赏性。

### 3.6 接管或调整

玩家永远拥有最高控制权：

- 选中 AI 托管单位并下达手动命令，即可临时覆盖 AI；
- 可以只接管一支小队或一个英雄单位；
- 手动操作结束后，可选择“恢复原计划”或“按当前位置重新规划”；
- AI 不应与玩家争夺控制权，也不应立即覆盖玩家刚下达的命令。

核心原则：

> AI 降低操作负担，但不能降低玩家的决定权。

## 4. 三层控制模型

为了同时服务新玩家、MOBA 玩家和传统 RTS 玩家，操作设计分为三层。

### 4.1 战略指挥层

玩家通过文本、语音或任务卡表达宏观目标：进攻、防守、侦察、骚扰、撤退、占领和资源分配。

这一层提供“我是指挥官”的核心快感，适合不想进行高强度操作的玩家。

### 4.2 小队控制层

默认控制对象从单个单位提升为小队。小队类似 MOBA 中容易理解的角色组合：前排、输出、侦察、支援各自具有清楚的定位。

玩家可以：

- 点击头像或场上单位选中小队；
- 使用 Q/W/E/R/D/F 六槽快捷栏下达战斗命令；
- 指定移动点、攻击目标、防守区域和侦察方向；
- 查看小队状态、当前任务和危险提示。

这是游戏的主要操作层，借鉴 MOBA 清晰的技能栏、状态反馈和角色辨识度，降低传统 RTS 的单位管理成本。

### 4.3 精确微操层

喜欢传统 RTS 的玩家仍可：

- 框选多个单位；
- 使用控制组；
- 精确走位、集火和拉扯；
- 单独控制英雄或关键单位；
- 设置路线点和命令队列；
- 暂时关闭某支小队的自动行为。

微操带来局部优势，但不应成为体验全部内容的门槛。宏观判断正确的玩家即使操作速度一般，也应有获胜机会。

## 5. 主 UI 设计方向

主 UI 融合两种成熟心智模型：

- **ChatGPT 式 AI 工作区**：对话、上下文、建议、执行状态和可追溯历史；
- **MOBA 式战斗 HUD**：角色状态、技能快捷键、明确冷却与风险反馈、低视线移动成本。

### 5.1 布局建议

```text
┌─────────────────────────────────────────────────────────────┐
│ 任务目标 / 战况摘要               资源、人口、时间、系统状态 │
├───────────────┬───────────────────────────────┬─────────────┤
│ 小队列表       │                               │ AI 指挥频道  │
│ 头像/状态       │          3D 主战场             │ 战报与建议    │
│ 当前任务       │                               │ 角色提醒流    │
│ 托管状态       │                               │ 原因说明      │
│               │                               │             │
├───────────────┴───────────────┬───────────────┴─────────────┤
│ 小地图 / 情报图层              │ 选中对象 + 四命令 + 微操能力 │
├───────────────────────────────┴─────────────────────────────┤
│ 输入：“让二队绕右侧高地攻击火炮…”       [语音] [发送] [托管] │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 中央战场

中央战场始终占据最大面积。AI 对话不能像办公软件一样长期挤压游戏画面，右侧频道应支持展开、半展开和收起三种状态。

战场反馈尽量空间化：能够画在地图上的信息，不只写在聊天消息中。

### 5.3 左侧小队栏

左侧不是传统 RTS 的单位海，而是可快速扫视的小队状态：

- 小队头像与颜色；
- 人数和生命状态；
- 当前任务；
- AI 托管级别；
- 遭遇敌人、受阻、请求支援等异常状态。

点击切换小队，双击将镜头定位到小队。数字键 1～6 用于快速选择或调用小队，减少 MOBA 玩家进入 RTS 时的认知跨度。

### 5.4 右侧 AI 指挥频道

右侧频道同时承担 ChatGPT 式指挥对话、战报和 Agent 角色提醒三种功能，但必须控制噪声。角色提醒可以采用类似弹幕的短句、快速出现和淡出形式，但它不是社交弹幕，也不由真实观众发送。

信息分为三个优先级：

1. **必须响应**：命令歧义、关键单位濒危、计划失败；
2. **战术信息**：发现敌人、抵达位置、目标完成；
3. **角色信息**：英雄反应、副官评价、侦察员报告和精彩操作提示。

只有第一类信息可以主动抢占玩家注意力。其余信息采用弹幕式轻量呈现，并允许按角色、重要程度和消息类型过滤。

### 5.5 底部命令区

底部保留 MOBA 玩家熟悉的六槽技能栏结构，并将 `Q W E R D F` 作为主要战斗操作热区。当前阶段只确定操作层级，不提前锁死每一个键对应的最终功能：

| 热区 | 设计职责 |
| --- | --- |
| Q/W/E/R | 最高频、最需要即时响应的四项基础命令或能力 |
| D/F | 次高频战术能力、情境命令或关键交互 |

移动、攻击、防守、侦察、小队能力、占领和撤退等功能如何分配到六个槽位，应在可玩原型阶段通过测试再确定。确定后，同类小队的槽位语义应保持稳定，不得因为选择不同单位就完全重排；不可用能力保留位置并说明原因，避免破坏肌肉记忆。

每个命令必须同时支持按钮、快捷键、地图目标和自然语言调用。命令执行后显示清晰的选中态、目标和取消方式。

### 5.5.1 小队与编组键

优先保留 `1 2 3 4 5 6` 作为小队、英雄或编组的直接选择热区。当前建议交互为：

- 单击数字键：选择对应小队或编组；
- 双击数字键：选择并将镜头定位到对应小队；
- `Ctrl + 数字键`：将当前选择保存到对应编组；
- `Shift + 数字键`：将该编组加入当前选择；
- UI 中的小队卡片必须始终显示对应数字。

默认体验最多突出六支主要小队。更多单位仍可存在，但不应要求玩家依赖 `7～0` 才能完成核心战斗。

### 5.5.2 输入焦点与按键冲突

- AI 文本输入框获得焦点时，`QWERDF` 和 `1～6` 只用于输入文字，不触发游戏命令；
- 发送消息或按下 `Esc` 后立即恢复战斗快捷键；
- 语音输入不能阻塞鼠标、`QWERDF` 或数字键操作；
- 当前工程使用 WASD 移动镜头、Q/E 旋转镜头，与新战斗键位存在冲突；接入新方案时，默认镜头操作应迁移到屏幕边缘、鼠标中键拖动、方向键、滚轮和可配置备用键；
- 所有快捷键允许重映射，默认布局以 `QWERDF + 1～6` 为基础，HUD 则始终显示玩家当前实际绑定的键位。

### 5.5.3 改键功能与官方默认方案

游戏必须提供完整的改键功能，但首次启动时直接应用一套可以立即游玩的官方默认方案，不要求玩家先配置。具体键位在后期试玩和数据验证后仍可调整，以下内容属于当前默认草案，而不是不可变更的最终键表。

默认方案以战斗操作优先：

| 操作组 | 默认键位 |
| --- | --- |
| 六槽主要战斗操作 | `Q W E R D F` |
| 六槽小队/英雄/编组选择 | `1 2 3 4 5 6` |
| 保存编组 | `Ctrl + 1～6` |
| 追加选择 | `Shift + 1～6` |
| 命令队列 | 按住 `Shift` 后下达命令 |
| AI 文本输入 | `Enter` |
| 按住语音指挥 | `V` |
| 取消当前指令/关闭面板 | `Esc` 或鼠标右键 |
| 镜头平移 | 屏幕边缘、鼠标中键拖动或方向键 |
| 镜头旋转 | 中键拖动或 `Z/C` |
| 镜头缩放 | 鼠标滚轮 |

改键界面按“战斗命令、小队选择、镜头、AI 交互、UI 与系统”分组，并满足：

- 每项操作支持一个主绑定和一个备用绑定；
- 点击键位后进入捕获状态，再按下希望使用的键或鼠标按钮；
- 检测同一输入环境中的键位冲突，并让玩家选择交换、覆盖或取消；
- 允许不同输入环境复用按键，例如战斗中的 `Q` 与文本输入中的字母 `Q` 不构成冲突；
- HUD、技能栏、教程和提示文本实时读取实际绑定，不把键名写死在界面文案中；
- 支持单项清除、分组恢复默认和全部恢复默认；
- 改键结果保存到本地玩家配置，并在重新启动游戏后保留；
- 确认、取消和打开设置等基础操作必须至少保留一种有效输入方式，防止玩家把自己锁在界面外；
- 首个版本以键鼠为主，手柄使用独立映射表，不能与键鼠绑定互相覆盖。

除“现代指挥”默认方案外，后续可以提供“经典 RTS”预设，把镜头移动恢复到 WASD，并将部分战斗命令迁移到传统 RTS 键位。预设只是批量改键，不能形成两套不同的游戏规则。

### 5.5.4 标准化操作体验

需要标准化的是玩家的操作负担和肌肉记忆，而不是在设计早期固定某一张键位表。

- 绝大多数高频战斗操作应在 `QWERDF + 1～6` 内完成；
- 高频命令使用单键触发，组合键主要用于编组、追加选择和命令队列；
- 左手保持在该热区时，玩家仍能通过鼠标完成选取、指向和镜头控制；
- 六槽命令栏与六槽小队栏位置固定，视觉顺序始终与键盘顺序一致；
- 相同语义在不同小队间尽量占据相同槽位，例如基础进攻类命令不应频繁换位；
- 文本、语音、UI 点击和快捷键最终进入同一套命令系统，不能产生四套不同规则；
- 教程先教授少量稳定核心操作，再逐步开放 D/F、组合键和 AI 高级命令；
- 后期通过首次命令成功率、误触率、视线离开战场时间和玩家改键比例调整默认映射；
- 调整默认键位时优先保持槽位职责和 UI 位置稳定，避免让已有玩家重新学习整个操作体系。

体验目标是让玩家形成清晰习惯：数字键决定“我在指挥谁”，`QWERDF` 决定“我要他做什么”，鼠标决定“在哪里、对谁执行”。

### 5.6 AI 输入栏

输入栏固定在底部，支持：

- 文本输入；
- 按住说话或持续语音模式；
- 引用选中的单位、地点和目标；
- 一键插入常用条件；
- 查看 AI 解析后的结构化命令；
- 切换建议、协助和托管级别。

玩家选中了第二小队再说“绕后”，系统应自动将第二小队加入上下文，而不是要求玩家重复描述。

## 6. AI 托管等级

AI 不应只有开和关，而应提供逐级授权。

| 等级 | 玩家负责 | AI 负责 |
| --- | --- | --- |
| L0 手动 | 全部操作 | 只提供信息 |
| L1 建议 | 决策和执行 | 给出战术建议与风险提示 |
| L2 协助 | 主要命令 | 寻路、阵型、目标选择等细节 |
| L3 小队托管 | 战略目标和关键决策 | 持续控制指定小队 |
| L4 全局托管 | 观察、审批、随时接管 | 执行完整战局计划 |

托管状态必须始终可见，并提供立即接管按钮。AI 的授权范围按小队保存，允许玩家托管后方，同时亲自操作前线英雄。

## 7. Agent 角色提醒与观赏性

本游戏不需要真正的玩家弹幕或直播平台接入。“弹幕感”只是一种游戏内信息表现形式：由重要角色对应的 Agent 根据真实战场状态生成短句，以较低打扰的方式快速出现和淡出。

这些 Agent 不是无身份的系统播报器，而是游戏世界中的具体角色，例如：

- **AI 副官**：整理战况、复述命令、提示计划风险；
- **英雄或小队长**：报告自身处境、表达执行状态和战斗情绪；
- **侦察员**：报告新发现、情报可信度和视野盲区；
- **基地指挥官**：提示增援、资源、关键设施和后方风险；
- **敌方关键角色**：只在剧情或情报规则允许时提供可见反馈。

每个角色 Agent 应具有独立的身份、语气、知识范围和发言权限。同一事件由最相关的角色发言，避免所有角色重复播报。

可呈现的信息包括：

- 副官：“右侧路线暂时安全，可以执行绕后。”
- 小队长：“二队已抵达高地，等待攻击许可。”
- 侦察员：“发现敌方远程火力，情报可信度 80%。”
- 英雄：“左翼压力太大，我需要支援或撤退授权。”
- 系统事件：“成功绕后”“通信站防守完成”等短促结果提示。

Agent 发言必须基于经过校验的游戏状态。语言模型可以决定表达方式，但不能虚构未被发现的敌人、资源或任务结果；角色也不能突破战争迷雾和自身知识范围。

### 7.1 可选设置

角色提醒流是增强体验的可选项，玩家可以根据注意力负担进行配置：

| 设置 | 表现 |
| --- | --- |
| 关闭 | 只保留传统 HUD 和必须响应的系统警报 |
| 仅重要 | 只显示危险、命令失败、关键情报和任务节点 |
| 标准 | 显示重要信息与适量角色反馈，作为默认选项 |
| 丰富 | 增加角色反应、战术评价和氛围短句 |

还应提供独立的透明度、停留时间、显示区域、语音播报和角色过滤选项。关闭角色提醒后不能损失必要信息，关键内容仍应通过 HUD、地图标记或传统提示表达。

### 7.2 呈现约束

- 默认在右侧频道或战场边缘出现，不遮挡单位、目标和操作区域；
- 每条消息尽量控制在一眼可读的长度；
- 同时出现的角色消息数量有限，低优先级消息可以合并或丢弃；
- 重要消息可以点击并定位到对应角色、地点或事件；
- 角色发言与事实状态分离，玩家能够区分“情报”“建议”和“情绪表达”；
- 不上传玩家内容，不模拟真实网友，不暗示存在并不存在的在线观众。

这套设计的目的，是把复杂战局转化为由角色共同讲述的实时叙事，同时让重要角色真正以 Agent 的方式参与游戏，而不是实现一个社交弹幕系统。

## 8. AI 的可信度原则

AI 体验是否成立，关键不在于回复是否像人，而在于玩家是否敢把部队交给它。

因此必须遵循：

1. **可见**：玩家随时知道 AI 正在做什么。
2. **可解释**：重要行动能说明触发原因。
3. **可预测**：同样条件下的基础行为保持稳定。
4. **可撤销**：命令可取消，计划可中止，玩家可立即接管。
5. **有边界**：不确定时提问，不擅自消耗关键资源或牺牲关键单位。
6. **可降级**：网络或模型不可用时，核心 RTS 仍可正常游玩。

自然语言模型只负责将意图解析为受约束的结构化命令，不直接无限制操纵游戏对象。所有命令必须经过规则校验和权限校验后进入游戏模拟。

## 9. 心流节奏设计

一局游戏应在“观察—决策—执行—反馈”之间形成张弛变化。

### 9.1 低压阶段

玩家查看战报、规划路线、分配托管级别，并通过自然语言制定复合计划。AI 可以主动提供建议，但不催促玩家。

### 9.2 中压阶段

小队接敌，玩家主要通过快捷命令和小队控制进行调整。AI 过滤普通信息，只报告变化和异常。

### 9.3 高压阶段

玩家可直接微操关键单位，语音用于快速调动其他小队。UI 自动收起低优先级信息，突出技能、生命、目标与撤退路线。

### 9.4 战后阶段

AI 用数秒给出结果和原因：完成了什么、损失了什么、暴露了什么新情报。玩家无需阅读长报告即可进入下一次决策。

理想心流不是让 AI 自动赢，而是让玩家持续做有意义的判断，并减少重复、机械、低价值的操作。

## 10. 首个纵向切片

首个演示只验证核心体验，不验证完整 RTS 内容量。

第一战役的详细搜打撤、地图行动路线与资源点设计见：[《回声撤离》地图与流程设计](./第一战役_回声撤离地图与流程设计.md)。

### 10.1 演示内容

- 三支定位不同的小队；
- 移动、攻击、防守、侦察四个核心命令；
- 一条 8～10 分钟任务路线；
- 一次侦察、一次交战和一个胜利条件；
- 至少两种可稳定展示的 AI 行为，例如防守与侧翼；
- 文本与语音至少支持 15 条核心表达；
- AI 复述、执行状态和原因说明；
- 任意时刻手动接管和恢复托管；
- 模型不可用时的规则降级。

### 10.2 推荐演示片段

1. 玩家框选第一小队，使用传统方式向通信站推进。
2. 玩家通过语音命令第二小队从右侧侦察。
3. AI 发现敌方远程单位并解释风险。
4. 玩家输入“二队绕后攻击火炮，一队原地防守，不要追击”。
5. AI 展示解析结果并执行复合计划。
6. 玩家接管一个关键单位完成微操。
7. 玩家恢复小队托管，AI 完成战斗和任务结算。

这个片段必须同时证明三件事：AI 能理解、AI 值得信任、玩家仍然拥有操作乐趣。

## 11. 验收指标

纵向切片可以通过以下问题验收：

- 新玩家能否在 3 分钟内让一支小队移动、攻击和防守？
- 玩家能否不用学习固定句式就表达一条复合命令？
- AI 能否在执行前正确展示对象、目标、路线和限制条件？
- 玩家能否在 1 秒左右接管任意托管小队？
- 玩家是否能通过战场反馈理解 AI 当前意图？
- 高压战斗中，角色提醒是否不会遮挡主要操作？
- 玩家是否能明确分辨 Agent 的事实报告、战术建议和情绪表达？
- 关闭角色提醒后，玩家是否仍能获得全部必要战斗信息？
- 断网或模型失败时，游戏是否仍能完成核心流程？
- 体验结束后，玩家是否能复述一个“我做了关键指挥决策”的时刻？
- 喜欢微操的玩家是否认为 AI 在辅助自己，而不是抢走游戏？
- 不擅长传统 RTS 的玩家是否愿意继续尝试下一场战斗？

## 12. 非目标与边界

首个阶段不追求：

- 完整经济和科技树；
- 多阵营长期平衡；
- 大规模海陆空战争；
- 完整英雄装备系统；
- 开放式无限语言能力；
- AI 自动处理所有游戏内容；
- 真实玩家弹幕、虚拟网友或直播平台观众互动；
- 用大量聊天文本替代清晰的游戏 UI。

优先级始终是：

```text
清楚可控 > 智能炫技
稳定执行 > 开放表达
战场反馈 > 聊天回复
玩家决策 > AI 表演
```

## 13. 核心体验总结

这款游戏的核心不是“AI 帮玩家玩 RTS”，而是让玩家第一次真正以指挥官的方式玩 RTS。

玩家可以像使用 AI 助手一样表达复杂意图，像 MOBA 玩家一样快速理解角色和技能，像传统 RTS 玩家一样接管单位完成精确操作，也可以通过重要角色 Agent 的实时反应感受战场事件和战术高潮。

最终希望形成的体验是：

> 我不需要操作所有单位，但每一个关键决定都是我做的；AI 让我的意图变成了战场行动，而我的接管又改变了战斗结果。
