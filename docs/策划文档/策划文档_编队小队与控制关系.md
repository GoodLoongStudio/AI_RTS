# 策划文档_编队小队与控制关系

> 状态：待评审  
> 前置依赖：《策划文档_单位基础规则》《策划文档_移动与位置规则》《策划文档_指令与命令执行规则》  
> 本文定义：RTS 中多单位选择、数字编队、多单位命令分配，以及 AI 对玩家数字编队的识别与指令执行。  
> 本文不建立独立的“阵型系统”。

---

# 1. 基础对象

本文只使用三个概念：

| 概念 | 定义 |
|---|---|
| 单位 | 单个可控制战场实体 |
| 当前选择 | 玩家此刻选中的一个或多个单位 |
| 数字编队 | 保存一组单位引用，供玩家快速重新选择 |

数字编队只保存选择关系：

- 不创建新的游戏实体；
- 不改变单位自身状态；
- 不产生独立 AI；
- 不产生独立命令状态。

一个单位可以同时存在于多个数字编队中。

---

# 2. 多单位选择

玩家可以通过：

- 框选；
- Shift 追加 / 移除；
- 双击同类单位；
- 数字编队；

形成当前选择。

当前选择决定：

```text
下一条玩家命令作用于哪些单位
```

取消选择不会改变数字编队。

---

# 3. 数字编队

默认提供 `1-9` 九个数字编队。

| 输入 | 结果 |
|---|---|
| `Ctrl + 1-9` | 将当前选择覆盖保存到对应数字编队 |
| `1-9` | 重新选择对应数字编队 |
| 连按两次 `1-9` | 选择对应数字编队，并将镜头定位到有效成员 |
| `Shift + 1-9` | 将当前选择追加到对应数字编队 |

## 3.1 保存

```text
当前选择
↓
Ctrl + 数字
↓
覆盖保存
```

## 3.2 追加

```text
当前选择
↓
Shift + 数字
↓
追加到已有编队
```

同一单位不会在同一数字编队中重复保存。

## 3.3 调出

```text
按数字
↓
重新选择该编队当前有效成员
```

死亡、被摧毁、离场或失去选择资格的单位不进入实际选择结果。

## 3.4 空编队

数字编队没有有效成员时，按对应数字不改变当前合法选择状态。

# 4. 多单位命令

玩家对当前选择下达命令：

```text
玩家命令
↓
检查各单位命令资格
↓
合法单位接收命令
↓
各单位按自身规则执行
```

基础原则：

> **多选统一的是玩家意图，不要求所有单位执行完全相同的底层行为。**

单个单位不能执行某命令，不影响其他合法单位执行。

---

# 5. 常用命令分配

| 命令 | 多单位结果 |
|---|---|
| Move | 各单位获得合法移动目标 |
| Attack Move | 合法成员保持相同推进意图 |
| Attack | 具备攻击资格的成员攻击指定目标 |
| Follow | 各单位建立合法跟随关系 |
| Approach | 各单位进入对应接近范围 |
| Hold Position | 各单位保持自身位置 |
| Patrol | 合法成员使用相同巡逻意图 |
| Stop | 各单位停止当前主要命令 |
| Skill Command | 仅符合技能与目标资格的单位执行 |

具体执行由对应专项规则处理。

---

# 6. 多单位位置结果

多个单位收到同一位置类命令时：

```text
整体目标
↓
每个单位获得自己的合法位置
↓
各单位独立移动
↓
形成稳定位置结果
```

位置分配只要求：

- 合法；
- 可达；
- 满足单位占位；
- 尽量保持玩家原始目标意图；
- 减少不必要的位置交换。

本文不定义固定横队、纵队、方阵等阵型规则。

---

# 7. 数字编队与 AI

数字编队既是玩家的快速选择工具，也是 AI 可以识别的玩家组织信息。

AI 在权限允许时可以读取：

- 编队编号；
- 当前有效成员；
- 成员类型与能力；
- 当前大致位置；
- 当前状态；
- 可执行命令资格。

玩家可以直接把数字编队作为语音或文本指令对象。

例如：

```text
“1队去左边。”
“2队守住入口。”
“3队跟着我。”
“1队散开一点。”
“坦克在前，步兵跟后。”
```

AI 负责：

```text
识别玩家指定的数字编队
+
理解自然语言战术意图
+
结合地图与单位状态
+
生成对应单位命令 / 位置目标
```

基础规则：

- AI 可以理解编队编号与成员构成；
- AI 可以理解自然语言中的空间和战术关系；
- AI 不因知道数字编队而自动获得永久控制权；
- AI 不因理解“横队、散开、包围”等词语而建立新的正式阵型状态；
- AI 每次按照玩家当前明确意图生成具体执行命令；
- 修改数字编队成员，需要玩家明确的编队操作或明确语音指令；
- 玩家直接指令始终优先于 AI 自主行为。

---

# 8. 自然语言空间指令

“阵型”不作为独立策划系统，但 AI 可以理解空间指令。

例如：

```text
“散开”
→ 增加单位之间的目标间距

“靠拢”
→ 减少目标位置之间的距离

“坦克顶前面”
→ 为坦克分配更靠近推进方向的位置

“步兵跟在坦克后面”
→ 为步兵分配相对后方的位置

“从两边包过去”
→ 把合法单位分成两个移动方向

“快速通过这里”
→ 优先完成通行，不强调成员之间的位置关系
```

这些都属于：

> **AI 对玩家意图的即时解释**

而不是一个需要玩家学习和操作的固定阵型系统。

具体位置仍需满足《策划文档_地图空间与导航规则》和《策划文档_移动与位置规则》。

---

# 9. AI 权限边界

AI 对数字编队的能力分为：

```text
读取编队信息
理解玩家指令
生成具体执行命令
```

这不等于：

```text
AI 自主决定玩家编队应该做什么
```

没有玩家明确指令时，是否允许 AI 主动调度单位，由 Unit AI / System AI 的权限规则单独决定。

数字编队本身不会扩大 AI 权限。

---

# 10. 当前不包含

- 固定阵型系统；
- 横队 / 纵队 / 方阵等玩家操作界面；
- 阵型快捷键；
- 阵型宽度、朝向编辑；
- 具体寻路算法；
- 局部避障算法；
- 战斗目标选择；
- AI 战术自主决策；
- 程序实现。
