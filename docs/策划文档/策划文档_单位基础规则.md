# 策划文档_单位基础规则

> 状态：已完成  
> 本文定义当前 RTS Demo 中单位的身份、归属、基础能力、战斗资格、工作能力、生命周期与命令资格。  
> 当前版本以现有程序能力为准，不再定义独立“单位 AI”控制层。

---

# 1. 单位定义

单位是战场中具有稳定身份、所有者、位置、能力和生命周期的基础实体。

当前单位基础由以下内容组成：

- 唯一身份；
- 所属玩家；
- 稳定类型；
- 战场实体类别；
- 生命周期；
- 生命与可受伤状态；
- 移动能力；
- 攻击能力；
- 战斗域与合法攻击域；
- 倒车能力；
- 地面强制开火能力；
- 采集能力；
- 施工能力；
- 施工工作效率；
- 当前交战姿态；
- 当前开火策略；
- 当前活动命令。

---

# 2. 单位身份

当前程序使用稳定单位 ID 识别单位。

基础身份至少包括：

```text
单位 ID
所属玩家
稳定类型 ID
战场实体类别
```

单位命令、选择、编队、查询、任务和 AI 副官都应引用稳定身份，不依赖临时 UI 对象名称。

---

# 3. 所有权与控制资格

单位的所有者决定谁可以对其提交正式单位指令。

玩家直接操作单位时，至少需要满足：

```text
单位存在
+
单位属于当前玩家
+
单位具备对应能力
```

不存在独立“进入 Unit AI”资格。

AI 副官需要控制单位时，同样通过正式指令入口操作合法单位，不建立另一套单位控制状态。

---

# 4. 当前程序能力字段

当前单位命令层已经明确使用以下能力：

| 能力 | 含义 |
|---|---|
| 可移动 | 单位是否可以接受移动类指令 |
| 可攻击 | 单位是否可以进行攻击 |
| 战斗域 | 单位自身所在的战斗域 |
| 可攻击域 | 单位允许攻击的目标战斗域 |
| 可受伤 | 单位是否可以成为伤害目标 |
| 可倒车 | 战术撤退时是否可以使用倒车移动 |
| 可地面强制开火 | 是否允许强制攻击纯地面位置 |
| 可采集 | 是否可以执行采集命令 |
| 可施工 | 是否可以执行施工命令 |
| 每 Tick 施工工作量 | 单位到位后每个有效施工 Tick 的贡献 |

具体单位通过这些能力组合形成不同用途。

---

# 5. 生存状态

单位至少具有：

- 当前生命值；
- 最大生命值；
- 是否仍为有效可受伤对象。

护盾、护甲等具体结算由《策划文档_伤害计算规则》定义。

生命值降至失效条件后，单位进入死亡 / 被摧毁 / 离场处理。

---

# 6. 移动能力

可移动单位可以根据自身能力接受当前程序已有的移动类命令：

- 移动；
- 靠近目标；
- 跟随目标；
- 强制移动；
- 地面攻击移动；
- 目标攻击移动；
- 战术撤退。

是否可以倒车由单位自身能力决定。

具体移动执行规则由《策划文档_移动与位置规则》定义。

---

# 7. 战斗能力

能够攻击的单位至少需要明确：

```text
可攻击
自身战斗域
允许攻击的战斗域
是否允许地面强制开火
```

攻击目标还必须满足：

- 目标存在；
- 目标可受伤；
- 阵营关系允许攻击；
- 目标战斗域属于攻击者允许攻击的范围。

具体攻击流程由《策划文档_战斗基础规则》定义。

---

# 8. 交战姿态

普通战斗单位当前使用程序已有三种交战姿态：

| 姿态 | 含义 |
|---|---|
| 侵略 | 主动索敌并允许追击 |
| 警戒 | 围绕岗位处理敌人 |
| 固守 | 不主动移动追击，只处理射程内目标 |

交战姿态是持续战斗策略，不属于单位命令，也不属于独立“单位 AI 模式”。

---

# 9. 开火策略

当前程序已有两种开火策略：

| 状态 | 含义 |
|---|---|
| 自由开火 | 按当前交战姿态自主攻击合法目标 |
| 停止开火 | 禁止普通自主开火 |

强制攻击按照强制攻击规则单独处理。

交战姿态和开火策略相互独立。

---

# 10. 当前命令资格

单位根据自身能力接受当前正式命令。

| 命令 | 主要资格 |
|---|---|
| 移动 | 可移动 |
| 靠近目标 | 可移动 |
| 跟随目标 | 可移动 |
| 强制移动 | 可移动 |
| 地面攻击移动 | 可移动 + 可攻击 |
| 目标攻击移动 | 可移动 + 可攻击 |
| 战术撤退 | 可移动 |
| 普通攻击 | 可攻击 |
| 强制攻击 | 可攻击 |
| 地面强制攻击 | 可攻击 + 可地面强制开火 |
| 采集 | 可采集 |
| 施工 | 可施工 |

停止移动、统一停止、设置交战姿态、设置开火策略属于控制操作，不作为新的单位命令种类。

---

# 11. 工作能力

## 采集

具备采集能力的单位可以：

```text
接受资源目标
→ 执行采集
→ 返程
→ 交付
→ 持续循环
```

## 施工

具备施工能力的单位可以：

```text
接受施工现场
→ 前往现场
→ 到位
→ 按自身施工工作量持续贡献进度
```

同一施工现场可以由多个合法施工单位共同工作。

---

# 12. 单位状态

当前单位至少需要让系统能够判断：

- 是否存在；
- 是否属于当前玩家；
- 是否可以移动；
- 是否可以攻击；
- 是否可以受伤；
- 是否可以采集；
- 是否可以施工；
- 当前交战姿态；
- 当前开火策略；
- 当前活动命令。

UI、AI 副官和任务系统应从正式状态读取，不自行维护另一套单位状态。

---

# 13. 生命周期

基础生命周期：

```text
生成
→ 正常存在
→ 死亡 / 被摧毁 / 离场
→ 失效
```

单位失效后：

- 当前活动命令进入单位失效终态；
- 不再接受新的单位指令；
- 不再作为正常有效攻击、跟随、靠近、采集或施工目标；
- 从选择和控制组的有效成员中移除；
- 世界查询不再把它作为正常存活单位返回。

---

# 14. 目标资格

单位当前可以作为：

- 选择目标；
- 跟随目标；
- 靠近目标；
- 攻击目标；
- 强制攻击目标；
- 目标攻击移动的最终目标；
- 施工现场相关目标；
- AI 副官指令引用对象；
- 任务系统引用对象。

是否合法由所有权、阵营关系、生命周期和对应命令规则共同判断。

---

# 17. 当前范围

当前单位基础规则不再提前定义程序尚不存在的：

- 独立 Unit AI 控制状态；
- 独立 System AI 单位状态；
- 巡逻资格；
- 通用交互资格；
- 技能槽位与技能资源；
- 特殊移动能力体系；
- 英雄成长体系。

后续真正实现对应 RTS 能力时，再在现有单位能力结构上增加。
