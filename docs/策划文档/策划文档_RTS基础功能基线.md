# 策划文档_RTS基础功能基线

> 状态：已完成  
> 本文定义当前战役型 RTS Demo 必须具备的最小基础能力。  
> 原则：当前目标是完成几个可完整游玩的战役关卡。RTS 战斗与指挥底层必须成立；资源、建造、生产等传统经济循环当前可以暂缓，不作为本阶段验收前提。

---

# 1. RTS 最小可用闭环

当前 Demo 最终必须形成：

```text
选择 / 观察单位
→ 下达命令
→ 单位移动
→ 接敌
→ 战斗
→ 伤害与死亡
→ 战场事件 / 战役任务推进
→ AI 副官协同
→ 达成战役目标
→ 胜利 / 失败结算
```

AI 副官建立在这套 RTS 战斗底层之上。

**AI 不替代 RTS 底层。**

当前 Demo 不要求形成：

```text
资源采集
→ 建造基地
→ 生产单位
→ 扩张经济
```

以上传统 RTS 经济循环当前统一标记为【暂缓】，已有程序能力保留，不删除。

---

# 2. 输入与镜头

RTS 必须保留：

- 俯视 / 斜俯视战略镜头；
- 镜头移动；
- 镜头旋转；
- 镜头缩放；
- 单位选择；
- 框选；
- 多单位选择；
- 数字编队；
- 鼠标直接下令。

当前程序已经有正式镜头移动 / 旋转和传统单位输入体系。

---

# 3. 选择与控制组

最小可用功能：

- 单选；
- 多选；
- 框选；
- 数字编队 `1～9`；
- `Ctrl + 1～9` 覆盖保存；
- `1～9` 调用；
- 失效成员清理。

当前程序已经支持正式控制组的保存、调用、合法性过滤和失效成员清理。

以下属于扩展体验，当前 Demo 不作为基础验收：

- ~~`Shift + 1～9` 追加控制组。~~
- ~~双击数字自动定位镜头。~~
- ~~长期持久的小队阵型和小队 AI 状态。~~

---

# 4. 单位命令

当前正式单位命令包括：

- 移动；
- 靠近；
- 跟随；
- 强制移动；
- 地面攻击移动；
- 目标攻击移动；
- 战术撤退；
- 普通攻击；
- 强制攻击；
- 地面强制攻击；
- 采集；
- 施工。

控制操作包括：

- 停止移动；
- 停止；
- 设置交战姿态；
- 设置开火策略。

其中采集、施工虽然当前程序已有正式能力，但因为当前 Demo 不要求经济与建造闭环，不作为本阶段必须使用的战役功能。

当前不存在的旧能力不写成正式功能：

- ~~巡逻 Patrol。~~
- ~~通用 Interact。~~
- ~~技能命令。~~
- ~~单位 AI 命令。~~

---

# 5. 移动与导航

RTS P0 必须保证：

- 点地移动；
- 路径寻找；
- 不可达反馈；
- 动态阻挡处理；
- 多单位移动；
- 合理停止位置；
- 基本局部避让。

当前正式命令层已经具备移动、靠近、跟随、强制移动、攻击移动和战术撤退入口。

当前执行端仍需要继续提高寻路、局部避让和多单位移动稳定性。

复杂已知地图认知寻路、高级多层地形和特殊移动不属于当前最小闭环。

---

# 6. 战斗

RTS P0 必须具备：

- 普通攻击；
- 指定目标攻击；
- 攻击移动；
- 射程判断；
- 目标追踪；
- 伤害；
- 生命值；
- 死亡 / 摧毁；
- 目标失效；
- 战斗结束后的正确状态收敛。

当前程序已经存在 Attack、ForceAttack、AttackMove、弹体、交战姿态和开火策略基础。

攻击前摇、攻击后摇、复杂追击阶段等设计可以后续增强，但不能阻止先完成稳定的基础攻击闭环。

---

# 7. 交战姿态与开火策略

当前正式持续战斗策略：

交战姿态：

- 侵略；
- 警戒；
- 固守。

开火策略：

- 自由开火；
- 停火。

~~独立“单位 AI 模式”~~ 不再作为正式单位控制层。

---

# 8. 伤害与死亡

RTS P0 必须完成：

```text
攻击成立
→ 产生伤害
→ 生命值变化
→ 达到死亡条件
→ 单位失效
→ 当前命令 / 选择 / 编队 / 战斗目标正确清理
```

护甲、护盾和克制可以按当前伤害规则逐步加入，但最先保证伤害与死亡闭环稳定。

---

# 9. 战争迷雾与情报

RTS 战役 Demo 必须存在战争迷雾与合法情报边界。

至少支持：

- 未探索；
- 已探索；
- 当前可见；
- 当前合法敌军可见；
- 失去视野后不继续获得实时敌军信息；
- AI 副官读取同一套合法情报。

复杂“已知通行地图 + 未知区域探索式寻路”属于高复杂度设计：

- ~~每个控制方独立维护完整已知通行地图并只按已知阻挡寻路。~~
- ~~单位围绕未知阻挡持续探索边界直到证明目标不可达。~~

战争迷雾本身必须做；复杂认知寻路当前可以后做。

---

# 10. 资源【暂缓】

当前几个战役关卡不以经济经营为核心，因此资源系统不作为当前 Demo 验收项。

程序中已经存在的资源账户、采集命令等能力继续保留，不删除、不倒退。

当前阶段暂缓：

- 资源采集循环；
- 返程 / 交付；
- 资源点经营；
- 经济扩张；
- 资源平衡；
- 将资源系统作为战役通关必要条件。

后续某个战役明确需要资源玩法时，再按具体任务启用和补齐。

---

# 11. 建造【暂缓】

当前几个战役关卡不要求建立完整基地建设循环，因此基础建造不作为当前 Demo 验收项。

当前程序已有施工相关能力继续保留。

当前阶段暂缓：

- 玩家自由建筑放置；
- 基地扩建；
- 工人持续施工循环；
- 建筑科技树；
- 以建造作为战役主要推进方式。

如果某个具体战役只需要“修复目标 / 建成一个指定任务建筑”，可以作为关卡专项功能实现，不等于恢复完整建造系统。

---

# 12. 生产与集结点【暂缓】

当前几个战役关卡优先使用关卡预置部队、事件增援和任务脚本提供战斗单位。

因此生产系统不作为当前 Demo 验收项。

当前程序已有生产队列与集结点能力继续保留。

当前阶段暂缓：

- 玩家自由生产单位；
- 完整生产队列玩法；
- 自动补兵；
- 生产经济平衡；
- 通过基地生产形成完整扩军循环。

如果战役需要增援，优先按战役事件和关卡配置实现。

---

# 13. 战役任务、胜负与对局生命周期

当前 Demo 的核心闭环必须支持：

- 对局初始化；
- 战役任务初始化；
- 任务目标显示；
- 战场事件触发；
- 任务阶段推进；
- 战局推进；
- 暂停 / 恢复；
- 胜负判断；
- 最终结果锁定；
- 结算；
- 重开；
- 退出。

战役任务可以使用包括但不限于：

- 摧毁目标；
- 保护目标；
- 到达指定区域；
- 坚守指定时间；
- 撤离；
- 触发指定战场事件。

---

# 14. AI 副官的位置

AI 副官建立在正式 RTS 接口之上：

```text
玩家传统操作 ─┐
               ├→ 正式 RTS 指令 → RTS 底层
AI 副官指令 ───┘
```

AI 副官不得直接修改：

- 单位 Node；
- 生命值；
- 位置；
- 隐藏敌军真值；
- 不属于自身权限的单位状态。

AI 副官在当前战役 Demo 中重点服务：

- 战况理解；
- 战术建议；
- 自然语言指挥；
- 编队引用；
- 已有单位命令调用；
- 战役事件与任务上下文理解；
- 执行结果反馈。

# 16. 最终原则

**当前目标不是先做一套完整传统 RTS 经济循环，而是先做成一套战斗、指挥、情报、AI 副官和战役流程都成立的 RTS Demo。**

当前程序已有的资源、施工、生产能力继续保留；这些能力只是当前阶段【暂缓】，不作为几个战役 Demo 的验收前提。

RTS 战斗与战役必需但尚未完成的能力继续作为开发目标；与现有程序冲突的旧功能从正式规则移除；当前过于复杂的历史设计使用删除线保留。
