# 策划文档_RTS基础功能基线

> 状态：已完成  
> 本文定义当前 Demo 作为 RTS 必须具备的最小基础能力。  
> 原则：RTS 基础系统可以简化，但不能因为当前 Demo 以 AI 为核心而整体删除。

---

# 1. RTS 最小可用闭环

当前 Demo 最终必须形成：

```text
选择单位
→ 下达命令
→ 单位移动
→ 接敌
→ 战斗
→ 伤害与死亡
→ 获取资源
→ 建造
→ 生产单位
→ 扩充部队
→ 战争迷雾下侦察
→ 达成胜负条件
```

AI 副官建立在这套 RTS 底层之上。

**AI 不替代 RTS 底层。**

---

# 2. 输入与镜头

RTS 必须保留：

- 俯视 / 斜俯视战略镜头；
- 镜头移动；
- 镜头旋转；
- 镜头缩放；
- 单位选择；
- 框选；
- 多单位选择；
- 数字编队；
- 鼠标直接下令。

当前程序已经有正式镜头移动 / 旋转和传统单位输入体系。

---

# 3. 选择与控制组

最小可用功能：

- 单选；
- 多选；
- 框选；
- 数字编队 `1～9`；
- `Ctrl + 1～9` 覆盖保存；
- `1～9` 调用；
- 失效成员清理。

当前程序已经支持正式控制组的保存、调用、合法性过滤和失效成员清理。

以下属于扩展体验，当前 Demo 不作为基础验收：

- ~~`Shift + 1～9` 追加控制组。~~
- ~~双击数字自动定位镜头。~~
- ~~长期持久的小队阵型和小队 AI 状态。~~

---

# 4. 单位命令

当前正式单位命令包括：

- 移动；
- 靠近；
- 跟随；
- 强制移动；
- 地面攻击移动；
- 目标攻击移动；
- 战术撤退；
- 普通攻击；
- 强制攻击；
- 地面强制攻击；
- 采集；
- 施工。

控制操作包括：

- 停止移动；
- 停止；
- 设置交战姿态；
- 设置开火策略。

当前不存在的旧能力不写成正式功能：

- ~~巡逻 Patrol。~~
- ~~通用 Interact。~~
- ~~技能命令。~~
- ~~单位 AI 命令。~~

---

# 5. 移动与导航

RTS P0 必须保证：

- 点地移动；
- 路径寻找；
- 不可达反馈；
- 动态阻挡处理；
- 多单位移动；
- 合理停止位置；
- 基本局部避让。

当前正式命令层已经具备移动、靠近、跟随、强制移动、攻击移动和战术撤退入口。

当前执行端仍需要继续提高寻路、局部避让和多单位移动稳定性。

复杂已知地图认知寻路、高级多层地形和特殊移动不属于当前最小闭环。

---

# 6. 战斗

RTS P0 必须具备：

- 普通攻击；
- 指定目标攻击；
- 攻击移动；
- 射程判断；
- 目标追踪；
- 伤害；
- 生命值；
- 死亡 / 摧毁；
- 目标失效；
- 战斗结束后的正确状态收敛。

当前程序已经存在 Attack、ForceAttack、AttackMove、弹体、交战姿态和开火策略基础。

攻击前摇、攻击后摇、复杂追击阶段等设计可以后续增强，但不能阻止先完成稳定的基础攻击闭环。

---

# 7. 交战姿态与开火策略

当前正式持续战斗策略：

交战姿态：

- 侵略；
- 警戒；
- 固守。

开火策略：

- 自由开火；
- 停火。

~~独立“单位 AI 模式”~~ 不再作为正式单位控制层。

---

# 8. 伤害与死亡

RTS P0 必须完成：

```text
攻击成立
→ 产生伤害
→ 生命值变化
→ 达到死亡条件
→ 单位失效
→ 当前命令 / 选择 / 编队 / 战斗目标正确清理
```

护甲、护盾和克制可以按当前伤害规则逐步加入，但最先保证伤害与死亡闭环稳定。

---

# 9. 战争迷雾与情报

RTS 必须存在战争迷雾。

至少支持：

- 未探索；
- 已探索；
- 当前可见；
- 当前合法敌军可见；
- 失去视野后不继续获得实时敌军信息；
- AI 副官读取同一套合法情报。

复杂“已知通行地图 + 未知区域探索式寻路”属于高复杂度设计：

- ~~每个控制方独立维护完整已知通行地图并只按已知阻挡寻路。~~
- ~~单位围绕未知阻挡持续探索边界直到证明目标不可达。~~

战争迷雾本身必须做；复杂认知寻路当前可以后做。

---

# 10. 资源

资源基础闭环不得整体暂缓：

```text
资源点
→ 工人采集
→ 返程 / 交付
→ 玩家资源增加
→ 建造 / 生产消耗
```

当前程序已经存在资源账户和采集命令基础。

高级经济平衡、多资源复杂关系和长期战略经济可以后做。

---

# 11. 建造

基础建造必须保留：

```text
选择建筑
→ 放置
→ 扣资源
→ 形成施工现场
→ 工人施工
→ 完工
→ 建筑投入使用
```

当前程序已经存在施工任务基础。

复杂建筑科技树和高级建筑互锁后做。

---

# 12. 生产与集结点

基础生产必须保留：

```text
选择生产建筑
→ 选择单位
→ 扣资源
→ 进入生产队列
→ 完成
→ 生成单位
```

集结点属于标准 RTS 基础能力，继续保留。

高级生产策略、自动补兵和复杂生产 AI 后做。

---

# 13. 胜负与对局生命周期

必须支持：

- 对局初始化；
- 战局推进；
- 暂停 / 恢复；
- 胜负判断；
- 最终结果锁定；
- 结算；
- 重开；
- 退出。

具体任务型胜负条件可以在战役中扩展。

---

# 14. AI 副官的位置

AI 副官建立在正式 RTS 接口之上：

```text
玩家传统操作 ─┐
               ├→ 正式 RTS 指令 → RTS 底层
AI 副官指令 ───┘
```

AI 副官不得直接修改：

- 单位 Node；
- 生命值；
- 位置；
- 隐藏敌军真值；
- 不属于自身权限的单位状态。

---

# 15. 当前开发优先级

## P0：必须完成

1. 选择与控制组
2. 输入与镜头
3. 指令与单位命令
4. 移动与导航稳定性
5. 战斗
6. 伤害与死亡
7. 战争迷雾
8. 资源采集
9. 建造
10. 生产与集结点
11. 胜负与对局生命周期
12. AI 副官接入正式 RTS 接口

## P1：后续增强

- Patrol；
- 高级编队 / 阵型；
- 技能；
- 英雄成长；
- 高级克制；
- 高级经济；
- 科技；
- 补给；
- 复杂认知寻路。

---

# 16. 最终原则

**先成为完整可玩的 RTS，再让 AI 改变 RTS 的操作方式。**

当前程序已有能力正常保留；RTS 最小必要但尚未完成的能力标记为开发目标；与现有程序冲突的旧功能从正式规则移除；当前过于复杂的历史设计使用删除线保留。
