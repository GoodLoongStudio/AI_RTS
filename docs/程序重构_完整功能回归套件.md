## 1. 目标与边界

本套件提供重构分支统一的自动回归入口，覆盖：

- `global.json` 实际 SDK 选择；
- Godot C# 项目构建；
- 101 项纯 C# Domain/Application 测试；
- Legacy GDScript 权威写入审计；
- `tests/automated` 下全部 31 个 Godot 自动场景；
- 每个进程的退出码、成功标记、禁止错误文本、超时和独立日志。

它不替代视觉、听觉、复杂导航、鼠标操作或完整对局的人工验收。延期战役只验证装配与启动冒烟，不代表战役内容解冻或完成。

## 2. 文件

- `config/full_regression_suite.json`：版本化测试清单、分类、场景、成功标记和超时；
- `tools/run_full_regression.ps1`：统一运行器；
- `.test-results/full-regression/<时间>/`：本地 stdout、stderr 和机器可读 `summary.json`，由 Git 忽略。

运行器会比较清单与 `tests/automated/*.tscn`。新增自动场景但没有登记，或清单仍引用已删除场景时，会在运行测试前失败。

## 3. 使用方法

在仓库根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\run_full_regression.ps1
```

如果无法自动定位 Godot：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\run_full_regression.ps1 `
  -GodotExecutable 'C:\Program Local\Godot_v4.7-stable_mono_win64\Godot_v4.7-stable_mono_win64_console.exe'
```

只复验指定场景时使用清单中的稳定 ID：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\run_full_regression.ps1 `
  -SkipBuild -SkipCore -SkipAudit `
  -TestId tank-force-attack,projectile-lifecycle
```

`Skip` 参数仅用于局部诊断。最终验收必须运行无 `Skip` 的完整命令。

## 4. 通过规则

Godot 场景必须同时满足：

1. 在清单规定时间内主动退出；
2. 进程退出码为 0；
3. 输出包含该场景唯一成功标记；
4. 输出不包含脚本解析、资源加载、断言失败、RID/ObjectDB/资源退出残留等禁止文本。

仅有退出码 0 不算通过。从 QA-007 起，Godot 退出时出现 RID、ObjectDB 或仍在使用的资源残留也属于回归失败，完整 stderr 会保存在独立日志中用于归因。

## 5. 场景依赖与所有权

以下场景使用共享手动场景作为真实 Match fixture：

- `EconomyAccountSmokeTest`、`ProductionQueueSmokeTest`、`RallyPointSmokeTest`、`WorkerGatherSmokeTest` 使用 `TestAllUnits.tscn`；
- 传统 AI 与胜负测试使用 `TestPlayerVsAI.tscn`；
- 查询和运行时放置测试使用 `TestCombatPolicies.tscn`；
- 多单位与控制组测试使用 `TestMultiUnitCommands.tscn`。

共享场景不是可忽略依赖。场景变化导致自动测试失败时，应先判断是合法 fixture 更新、迁移回归还是测试假设过时；不得通过删除测试、弱化成功标记或把失败场景移出清单来恢复绿色结果。
