## 修复"卡在 Godot 启动页"（资源统一改造后的解析错误）
- 背景：另一 AI 会话做了"经济统一/去 B 资源"大改造（约 60 文件），C# 侧 build 干净，但游戏启动卡死在 Godot splash。
- 根因：`source/net/DebugControlServer.gd`（autoload）第 256-262 行在重构时缩进断裂——`matches_kind/distance/best_distance` 整段被挤出 `for resource in ...` 循环体，`continue` 落在循环外 → GDScript Parser Error "Cannot use continue outside of a loop" → autoload 解析失败阻塞启动。
- 修复：恢复循环体缩进（continue/matches_kind/distance 判断全部回到 for 内）。
- 验证：headless 启动 0 解析错误；窗口化跑 Loading+PlainAndSimple(Human+AI)，5s 内进入 Match 并稳定运行 40s，无 SCRIPT ERROR。
- 教训：多会话并行改代码后，让改造方跑一遍最小编译验证（gdparse/headless 启动）再交付；GDScript 没有编译门禁时 autoload 的 parse error 不会显式报错，只会卡 splash。
